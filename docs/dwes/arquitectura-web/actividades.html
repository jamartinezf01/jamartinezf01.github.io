Actividades

En esta página se recogen las actividades de cierre de la UT1. Arquitectura Web. La unidad ha servido para entender cómo funciona una aplicación web en entorno servidor antes de empezar a construir aplicaciones más completas con Spring Boot.

Durante la unidad se han trabajado ideas como cliente, servidor, HTTP, generación dinámica de páginas, servidores web, servidores de aplicaciones, tecnologías de servidor, estructura básica de un proyecto Spring Boot, controladores, rutas y parámetros en las peticiones.

Idea principal

Estas actividades no buscan que memorices definiciones largas, sino que seas capaz de explicar el funcionamiento básico de una aplicación web y reconocer qué papel tiene cada elemento dentro de una petición.

1️⃣ Actividad no evaluable: reconstruye el viaje de una petición​

Esta primera actividad sirve para repasar el recorrido completo de una petición web desde que el usuario escribe una dirección en el navegador hasta que recibe una respuesta.

No es una actividad evaluable y no requiere entrega.

🟩 Objetivo​

Identificar los elementos que intervienen en una comunicación web básica y explicar el papel de cada uno.

🟨 Contexto​

Imagina que una persona abre el navegador y escribe la siguiente dirección:

http://localhost:8080/saludo

Al pulsar Enter, el navegador no ejecuta directamente el código de la aplicación. Lo que hace es enviar una petición HTTP al servidor donde se está ejecutando Spring Boot.

🟧 Desarrollo​

Responde en tu cuaderno o en un documento de trabajo a estas preguntas:

  1. ¿Qué elemento actúa como cliente?
  2. ¿Qué elemento actúa como servidor?
  3. ¿Qué ruta se está solicitando?
  4. ¿Qué tipo de petición se está realizando?
  5. ¿Qué controlador podría atender esa petición?
  6. ¿Qué respuesta podría recibir el navegador?

Después, representa el proceso mediante un esquema sencillo.

Navegador  --->  Petición HTTP  --->  Spring Boot
Navegador  <---  Respuesta HTTP  <---  Controlador

🟥 Ejemplo orientativo​

Una posible explicación sería:

El navegador actúa como cliente y envía una petición HTTP de tipo GET
a la ruta /saludo. La aplicación Spring Boot recibe la petición y busca
un controlador que pueda atender esa ruta. El método correspondiente se
ejecuta y devuelve una respuesta, por ejemplo un texto o una página HTML.
tip

No hace falta que el esquema sea bonito. Lo importante es que se entienda el recorrido de ida y vuelta: petición hacia el servidor y respuesta hacia el cliente.

2️⃣ Actividad no evaluable: observa peticiones reales en el navegador​

Esta actividad permite comprobar que una página web real no suele cargarse mediante una única petición. Normalmente el navegador solicita varios recursos: HTML, imágenes, CSS, JavaScript, fuentes u otros archivos.

No es una actividad evaluable y no requiere entrega.

🟩 Objetivo​

Observar peticiones HTTP reales utilizando las herramientas de desarrollo del navegador.

🟨 Desarrollo​

Abre el navegador y accede a una página web sencilla, por ejemplo:

https://www.wikipedia.org/

Después, abre las herramientas de desarrollo:

F12 → pestaña Red / Network

Recarga la página con:

Ctrl + R

Observa las peticiones que aparecen en la pestaña de red.

🟧 Preguntas guiadas​

Responde a estas preguntas:

  1. ¿Cuántas peticiones aparecen aproximadamente?
  2. ¿Cuál parece ser la petición principal de la página?
  3. ¿Aparecen recursos de tipo imagen?
  4. ¿Aparecen archivos CSS o JavaScript?
  5. ¿Por qué crees que una página web necesita cargar varios recursos?

🟥 Comprobación final​

Al terminar, deberías poder explicar con tus palabras esta idea:

Cuando visitamos una web, el navegador no recibe todo de golpe como si fuera
un único archivo. Normalmente solicita una página HTML y, a partir de ella,
otros recursos necesarios para mostrar correctamente el contenido.
aviso

No hace falta entender todavía todos los detalles que aparecen en la pestaña de red. En esta unidad solo interesa reconocer que existen peticiones y respuestas HTTP reales.

3️⃣ Actividad no evaluable: clasifica tecnologías de servidor​

En esta unidad hemos visto que Spring Boot será la tecnología principal del módulo, pero no es la única opción para programar en entorno servidor.

Esta actividad permite reconocer distintas tecnologías sin profundizar todavía en su uso.

🟩 Objetivo​

Relacionar tecnologías de servidor con su lenguaje principal y su uso habitual.

🟨 Desarrollo​

Completa una tabla como la siguiente:

TecnologíaLenguaje principal¿Para qué se usa?
Spring BootJava
DjangoPython
LaravelPHP
ExpressJavaScript / Node.js
ASP.NET CoreC#

Después, responde:

  1. ¿Cuál será la tecnología principal que usaremos en este módulo?
  2. ¿Por qué es útil conocer que existen otras tecnologías?
  3. ¿Todas las tecnologías de servidor resuelven exactamente los mismos problemas?
  4. ¿Qué factores podrían influir en la elección de una tecnología u otra?

🟧 Orientación​

No se trata de aprender Django, Laravel, Express ni ASP.NET Core. La finalidad es situar Spring Boot dentro de un conjunto más amplio de herramientas de desarrollo web en servidor.

info

En el mundo profesional no existe una única tecnología válida. Las empresas eligen herramientas según el lenguaje, el equipo, el proyecto, el mantenimiento, la comunidad y las necesidades concretas de la aplicación.

4️⃣ Actividad no evaluable: diferencia @RequestParam y @PathVariable​

Esta actividad sirve para repasar las dos formas básicas de recibir datos desde una petición web que se han trabajado en la unidad.

No es evaluable y no requiere entrega.

🟩 Objetivo​

Distinguir cuándo un dato llega como parámetro de la URL y cuándo forma parte de la propia ruta.

🟨 Desarrollo​

Observa las siguientes direcciones:

http://localhost:8080/saludo?nombre=Ana
http://localhost:8080/productos/7
http://localhost:8080/buscar?texto=java
http://localhost:8080/categorias/3

Para cada una, indica:

  1. Si usarías @RequestParam o @PathVariable.
  2. Qué dato recibe el controlador.
  3. Qué respuesta sencilla podría devolver la aplicación.

🟧 Ejemplo orientativo​

Para esta dirección:

http://localhost:8080/saludo?nombre=Ana

una respuesta razonable sería:

Usaría @RequestParam porque el dato aparece después del signo ?.
El controlador recibiría el parámetro nombre con el valor Ana.
La aplicación podría responder con el texto: Hola, Ana.
tip

Una pista rápida: si aparece el signo ?, probablemente hay parámetros de consulta. Si el dato va dentro de la ruta, probablemente se trata de una variable de ruta.

5️⃣ Actividad evaluable: explica y demuestra una mini aplicación web​

Esta actividad final permite comprobar que se han entendido los conceptos básicos de arquitectura web trabajados en la unidad.

A diferencia de las actividades anteriores, esta actividad sí es evaluable.

🟩 Resultado de aprendizaje y criterios relacionados​

La actividad se vincula principalmente con el RA1:

RA principal

RA1. Selecciona las arquitecturas y tecnologías de programación web en entorno servidor, analizando sus capacidades y características propias.

Los criterios de evaluación más directamente relacionados son:

CriterioRelación con la actividad
CE1.aDiferenciar ejecución en cliente y ejecución en servidor.
CE1.bReconocer la generación dinámica de páginas o respuestas.
CE1.cIdentificar cómo se ejecuta código en el servidor.
CE1.dReconocer el papel del servidor de aplicaciones en Spring Boot.
CE1.eSituar Spring Boot como tecnología de servidor.
CE1.fVerificar la integración entre rutas, código Java y respuesta web.
CE1.gUtilizar herramientas y framework de programación en servidor.

🟨 Contexto​

Vas a crear una mini aplicación Spring Boot muy sencilla para demostrar que entiendes el recorrido básico de una petición web.

La aplicación no necesita base de datos, seguridad, formularios completos ni APIs REST. Solo debe incluir varias rutas sencillas que permitan comprobar cómo trabaja un controlador.

🟧 Requisitos mínimos​

La aplicación debe incluir:

  1. Un proyecto Spring Boot creado desde Spring Initializr.
  2. Apertura y ejecución del proyecto en IntelliJ IDEA Community.
  3. Al menos un controlador Java.
  4. Una ruta fija, por ejemplo:
/saludo
  1. Una ruta que use @RequestParam, por ejemplo:
/saludo?nombre=Ana
  1. Una ruta que use @PathVariable, por ejemplo:
/productos/7
  1. Respuestas sencillas en texto usando @ResponseBody.
  2. Una breve explicación escrita del funcionamiento de cada ruta.
aviso

En esta actividad no se pide usar base de datos, repositorios, entidades JPA, DTO, seguridad ni autenticación. Esos contenidos aparecerán más adelante.

🟪 Evidencias que deben entregarse​

La entrega debe incluir:

  1. Captura de la pantalla de Spring Initializr con la configuración del proyecto
  2. Captura del proyecto abierto en IntelliJ IDEA.
  3. Captura de la aplicación ejecutándose correctamente.
  4. Captura del navegador mostrando la ruta /saludo.
  5. Captura del navegador mostrando una ruta con @RequestParam.
  6. Captura del navegador mostrando una ruta con @PathVariable.
  7. Breve explicación escrita, con tus palabras, del recorrido de una petición en una de las rutas.

🟩 Criterios de valoración​

Aspecto valoradoIndicadores
Comprensión cliente-servidorDistingue navegador, servidor, petición y respuesta.
Uso básico de Spring BootLa aplicación arranca y responde desde el navegador.
Controladores y rutasDefine rutas claras mediante @GetMapping.
ParámetrosUsa correctamente @RequestParam y @PathVariable.
Explicación técnicaExplica el proceso con vocabulario adecuado al nivel.
Presentación de evidenciasAporta capturas claras y ordenadas.

🟨 Mejoras opcionales​

Si terminas los requisitos mínimos, puedes añadir alguna mejora sencilla:

  • Una ruta /info que devuelva información básica de la aplicación.
  • Una ruta /categoria/{nombre} que muestre el nombre de una categoría.
  • Una ruta /buscar?texto=... que devuelva un mensaje con el texto buscado.
  • Una pequeña vista Thymeleaf si el profesor lo indica.
aviso

Si se devuelve una vista Thymeleaf, no debe usarse @ResponseBody, porque entonces Spring Boot devolvería el texto literal en lugar de buscar la plantilla.

6️⃣ Checklist final de la UT1​

Antes de cerrar la unidad, revisa si puedes explicar estas ideas sin mirar los apuntes:

  • Diferencia entre cliente y servidor.
  • Qué es una petición HTTP.
  • Qué es una respuesta HTTP.
  • Para qué sirven los métodos HTTP más habituales.
  • Diferencia entre página estática y página generada dinámicamente.
  • Diferencia entre servidor web y servidor de aplicaciones.
  • Qué papel tiene Spring Boot en una aplicación web.
  • Qué hace un controlador.
  • Para qué sirve @GetMapping.
  • Cuándo se usa @ResponseBody.
  • Diferencia entre @RequestParam y @PathVariable.
tip

Si puedes explicar estos puntos con tus propias palabras y relacionarlos con una pequeña aplicación Spring Boot, tienes la base necesaria para continuar con las siguientes unidades.
