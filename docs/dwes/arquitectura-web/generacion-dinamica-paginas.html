Generación dinámica de páginas

Cuando visitamos una página web, normalmente vemos un resultado final: textos, imágenes, botones, menús o listados. Sin embargo, ese resultado puede haberse obtenido de varias formas. A veces el servidor entrega siempre el mismo archivo HTML. Otras veces, el servidor construye una página distinta según la petición, los datos disponibles o la situación del usuario.

En este apartado vamos a diferenciar tres ideas que suelen confundirse al principio: una página estática, el código que se ejecuta en el navegador y una página generada dinámicamente en el servidor.

Idea principal

Una página generada dinámicamente no tiene por qué estar escrita completa de antemano. El servidor puede construir la respuesta HTML en el momento de recibir la petición.

1️⃣ Páginas estáticas​

Una página estática es aquella que el servidor devuelve prácticamente tal y como está guardada. El archivo HTML ya existe, tiene un contenido fijo y el servidor se limita a enviarlo al navegador cuando se solicita.

🟩 Idea básica​

Imagina que tenemos un archivo llamado contacto.html con el siguiente contenido:

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Contacto</title>
</head>
<body>
  <h1>Contacto</h1>
  <p>Puedes escribirnos a contacto@ejemplo.com.</p>
</body>
</html>
en este ejemplo

Este archivo HTML contiene directamente todo lo que verá el usuario. Si diez personas visitan esta página, las diez recibirán el mismo contenido, salvo que alguien modifique manualmente el archivo.

Este tipo de páginas son sencillas, rápidas y fáciles de entender. Pueden ser adecuadas para contenidos que apenas cambian, como una página de información general, una página de presentación o una página con datos fijos.

🟨 Limitación principal​

El problema aparece cuando queremos que el contenido cambie según una situación concreta. Por ejemplo, una tienda online no puede tener escrito a mano un HTML distinto para cada estado posible del catálogo.

Sería poco práctico mantener manualmente páginas como estas:

productos-con-stock.html
productos-sin-stock.html
productos-en-oferta.html
productos-usuario-ana.html
productos-usuario-luis.html

En aplicaciones reales, normalmente los datos cambian: productos, usuarios, mensajes, reservas, noticias, notas, pedidos o comentarios. Por eso necesitamos que el servidor pueda generar respuestas de forma dinámica.

aviso

Que una página sea estática no significa que sea mala. Simplemente significa que su contenido no se genera en función de datos procesados por el servidor en cada petición.

2️⃣ Código ejecutado en el cliente​

Otra posibilidad es que el navegador reciba una página HTML y, después, ejecute código en el propio cliente. Normalmente este código será JavaScript.

🟩 Qué significa ejecutar código en el cliente​

Cuando hablamos de código ejecutado en el cliente, nos referimos a código que se ejecuta en el navegador del usuario. Ese código puede modificar lo que se muestra, reaccionar a clics, validar campos de un formulario o cambiar partes de la página sin recargarla.

Por ejemplo:

<button onclick="saludar()">Saludar</button>
<p id="mensaje"></p>

<script>
  function saludar() {
    document.getElementById("mensaje").textContent = "Hola desde el navegador";
  }
</script>
en este ejemplo

En este ejemplo, el servidor puede haber enviado el HTML inicial, pero la función saludar() se ejecuta en el navegador. El mensaje aparece porque el cliente modifica la página después de recibirla.

Este tipo de código es muy habitual en el desarrollo web. Permite crear interfaces más interactivas y mejorar la experiencia de usuario. Sin embargo, no sustituye al código de servidor.

🟨 Diferencia con el servidor​

El navegador puede ejecutar JavaScript, pero no debería encargarse de tareas propias del servidor, como aplicar reglas críticas de negocio, consultar directamente una base de datos privada o decidir si una operación importante está permitida.

Por ejemplo, un navegador puede comprobar si un campo está vacío antes de enviar un formulario. Esa comprobación mejora la experiencia del usuario. Pero el servidor deberá volver a comprobar los datos, porque el cliente puede ser manipulado.

peligro

Nunca debemos confiar en que una validación hecha solo en el navegador sea suficiente para proteger una aplicación. El servidor siempre debe comprobar los datos importantes.

3️⃣ Páginas generadas dinámicamente en el servidor​

En una página generada dinámicamente, el servidor no se limita a devolver siempre el mismo HTML fijo. Antes de responder, ejecuta código, prepara datos y construye una respuesta adaptada a la petición.

🟩 Idea general​

El proceso habitual sería este:

1. El navegador solicita una página.
2. El servidor recibe la petición.
3. La aplicación ejecuta código en el servidor.
4. Se preparan los datos necesarios.
5. El servidor genera una respuesta HTML.
6. El navegador recibe esa respuesta y la muestra.

Por ejemplo, una aplicación podría mostrar un saludo distinto según el nombre recibido en la petición:

 /saludo?nombre=Ana  →  Hola, Ana
 /saludo?nombre=Luis →  Hola, Luis

La dirección solicitada cambia ligeramente y el servidor genera una respuesta distinta.

🟨 Ejemplo sencillo con Spring Boot​

En Spring Boot podemos crear un controlador que responda con texto generado dinámicamente:

package com.example.demo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.Controller;

@Controller
public class SaludoController {

    @GetMapping("/saludo")
    public String saludar(@RequestParam(defaultValue = "alumno") String nombre) {
        return "Hola, " + nombre + ". Bienvenido a DWES.";
    }
}
en este ejemplo

La anotación @Controller indica que la clase puede atender peticiones web. @GetMapping("/saludo") asocia el método con la ruta /saludo. @RequestParam permite leer un parámetro de la petición, por ejemplo ?nombre=Ana. Como usamos @ResponseBody, el texto final se envía directamente como respuesta al navegador.

Si visitamos esta dirección:

http://localhost:8080/saludo?nombre=Ana

la respuesta será distinta a la que obtendríamos con:

http://localhost:8080/saludo?nombre=Luis

Esto ya es generación dinámica, aunque el ejemplo sea muy simple. El servidor está ejecutando código y construyendo una respuesta en función de la petición recibida.

aviso

En este ejemplo usamos @RestController porque devolvemos texto directamente. Cuando más adelante devolvamos una vista Thymeleaf, no usaremos @ResponseBody ni @RestController para esa respuesta, sino @Controller.

4️⃣ Plantillas HTML y datos del servidor​

En muchas aplicaciones web no queremos devolver solo texto plano. Lo habitual es devolver una página HTML completa, pero construida con datos preparados por el servidor. Para eso se usan motores de plantillas.

🟩 Qué es una plantilla​

Una plantilla es un archivo HTML que contiene partes fijas y partes variables. Las partes fijas son la estructura común de la página. Las partes variables se rellenan con datos que vienen del servidor.

En este módulo usaremos Thymeleaf, un motor de plantillas que se integra bien con Spring Boot.

Un ejemplo muy sencillo de plantilla podría ser:

<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
  <meta charset="UTF-8">
  <title>Saludo</title>
</head>
<body>
  <h1 th:text="'Hola, ' + ${nombre}">Hola, alumno</h1>
</body>
</html>
en este ejemplo

La plantilla tiene estructura HTML normal, pero incluye una expresión de Thymeleaf en th:text. Antes de enviar la página al navegador, el servidor sustituye ${nombre} por el valor correspondiente. El navegador no recibe la expresión de Thymeleaf, sino el HTML final ya generado.

Esta idea es importante: Thymeleaf se procesa en el servidor. El navegador recibe HTML, CSS y JavaScript, pero no ejecuta Thymeleaf.

🟨 Diferencia entre plantilla y página final​

Podemos verlo así:

Plantilla Thymeleaf en el servidor:
<h1 th:text="'Hola, ' + ${nombre}">Hola, alumno</h1>

HTML recibido por el navegador:
<h1>Hola, Ana</h1>

El archivo de plantilla puede ser el mismo, pero el resultado final puede cambiar según los datos que envíe el servidor.

tip

Una plantilla nos permite evitar repetir HTML y construir páginas adaptadas a los datos. Más adelante usaremos Thymeleaf para mostrar información, recorrer listas y crear formularios.

5️⃣ Comparación entre los tres enfoques​

Conviene no mezclar los conceptos. Una página puede tener partes estáticas, código JavaScript en el cliente y contenido generado dinámicamente por el servidor.

La imagen anterior resume visualmente las tres situaciones que hemos visto: una página estática, una interacción ejecutada en el navegador y una página HTML generada dinámicamente desde el servidor.

🟩 Resumen comparativo​

EnfoqueDónde se ejecutaQué permiteEjemplo
Página estáticaEl servidor solo entrega un archivo ya preparado.Mostrar contenido fijo.Una página de contacto con texto fijo.
Código en clienteEn el navegador.Añadir interacción a la página.Mostrar un mensaje al pulsar un botón.
Generación dinámica en servidorEn la aplicación del servidor.Crear respuestas según datos o peticiones.Mostrar productos distintos según una categoría.

🟨 Ejemplo guiado​

Imagina una página de una tienda online:

https://tienda-ejemplo.com/productos?categoria=teclados

En ese caso podrían ocurrir varias cosas:

El navegador envía una petición al servidor. La aplicación del servidor lee la categoría solicitada, prepara una lista de productos y genera una página HTML con esos datos. Después, el navegador recibe el HTML, carga el CSS, muestra las imágenes y puede ejecutar JavaScript para mejorar la interacción.

En una sola página pueden participar varias tecnologías, pero cada una tiene su papel.

Idea principal

La generación dinámica de páginas permite que una aplicación web responda de forma diferente según los datos, la petición o el usuario. Esta es una de las bases de la programación web en entorno servidor.

6️⃣ Errores frecuentes​

🟩 Pensar que todo ocurre en el navegador​

Uno de los errores más habituales es creer que el navegador lo hace todo. El navegador muestra la página y puede ejecutar JavaScript, pero muchas decisiones importantes se toman en el servidor.

Por ejemplo, si una aplicación muestra las notas de un alumno, el navegador no debería decidir qué notas puede ver. Esa decisión debe gestionarse en el servidor.

🟨 Confundir JavaScript con Java​

JavaScript y Java son lenguajes distintos. En este módulo usaremos Java con Spring Boot para programar en el servidor. JavaScript puede aparecer en el navegador, pero no será la tecnología principal de esta parte del módulo.

🟧 Creer que Thymeleaf se ejecuta en el navegador​

Thymeleaf no se ejecuta en el navegador. Thymeleaf se procesa en el servidor y genera HTML. El navegador recibe el resultado final.

aviso

Cuando inspeccionas una página en el navegador, verás HTML final. No verás las expresiones Thymeleaf originales, porque ya han sido procesadas antes de enviar la respuesta.

7️⃣ Actividad no evaluable: estático, cliente o servidor​

Lee las siguientes situaciones e indica si corresponden principalmente a una página estática, a código ejecutado en el cliente o a generación dinámica en el servidor:

SituaciónTipo
Una página contacto.html muestra siempre el mismo teléfono y correo.
Al pulsar un botón, aparece un mensaje sin recargar la página.
Una tienda muestra productos distintos según la categoría elegida.
Una página de noticias muestra las últimas noticias publicadas.
Un formulario marca en rojo un campo vacío antes de enviarlo.
Una aplicación muestra un saludo con el nombre recibido en la URL.
tip

En algunos casos puede haber más de una tecnología participando. Lo importante es identificar cuál es la parte principal del comportamiento que se está describiendo.
