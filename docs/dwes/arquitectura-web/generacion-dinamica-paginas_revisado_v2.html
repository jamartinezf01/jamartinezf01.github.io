Generación dinámica de páginas

Cuando visitamos una página web, normalmente vemos un resultado final: textos, imágenes, botones, menús o listados. Sin embargo, ese resultado puede haberse obtenido de formas muy diferentes.

A veces el servidor entrega un archivo HTML tal y como está almacenado. Otras veces, el navegador recibe una página y modifica parte de su contenido mediante JavaScript. Y en muchas aplicaciones, el servidor ejecuta código y construye una respuesta diferente según la petición o los datos disponibles.

En este apartado vamos a diferenciar estas tres situaciones para entender qué significa realmente generar contenido de forma dinámica en el servidor.

Idea principal

Una página generada dinámicamente no tiene por qué existir como un archivo HTML completo antes de recibir la petición. El servidor puede ejecutar código, preparar datos y construir la respuesta en ese momento.

1️⃣ Páginas estáticas​

Una página estática es aquella cuyo contenido ya está preparado antes de que llegue la petición. El servidor localiza el archivo solicitado y lo devuelve al cliente sin tener que generar su contenido en función de datos o condiciones.

🟩 Un ejemplo sencillo​

Imagina que tenemos un archivo llamado contacto.html:

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Contacto</title>
</head>
<body>
  <h1>Contacto</h1>
  <p>Puedes escribirnos a contacto@ejemplo.com.</p>
</body>
</html>
en este ejemplo

El contenido de la página ya está escrito en el archivo. Si varias personas solicitan contacto.html, todas recibirán esencialmente el mismo documento mientras nadie modifique ese archivo.

Este tipo de páginas resulta adecuado para contenidos que cambian poco: información corporativa, documentación sencilla, páginas de presentación o contenidos puramente informativos.

🟨 La limitación aparece cuando los datos cambian​

Supongamos ahora que queremos mostrar el catálogo de una tienda.

Los productos pueden variar, algunos pueden quedarse sin stock, otros pueden entrar en oferta y el contenido puede depender de una búsqueda realizada por la persona usuaria.

Mantener manualmente archivos diferentes para cada situación sería poco práctico:

productos-con-stock.html
productos-sin-stock.html
productos-oferta.html
productos-teclados.html
productos-ratones.html

Cuando el contenido depende de datos que cambian, necesitamos una forma de generar la respuesta en el momento en que se solicita.

aviso

Una página estática no es peor que una página dinámica. Son soluciones adecuadas para necesidades distintas. Si el contenido apenas cambia, una página estática puede ser perfectamente válida.

2️⃣ Código ejecutado en el cliente​

Una página también puede cambiar después de haber llegado al navegador.

En ese caso, parte del comportamiento se produce en el cliente, normalmente mediante JavaScript.

🟩 El navegador puede modificar la página​

Por ejemplo:

<button onclick="saludar()">Saludar</button>
<p id="mensaje"></p>

<script>
  function saludar() {
    document.getElementById("mensaje").textContent = "Hola desde el navegador";
  }
</script>
en este ejemplo

El servidor ha enviado el HTML y el código JavaScript al cliente. Al pulsar el botón, la función saludar() se ejecuta en el navegador y modifica la página que ya está cargada.

Para mostrar ese mensaje concreto no es necesario generar una nueva página en el servidor.

JavaScript puede utilizarse para muchas tareas:

  • responder a clics y otras acciones de la persona usuaria.
  • mostrar u ocultar elementos.
  • validar determinados datos antes de enviarlos.
  • modificar el contenido que ya aparece en pantalla.
  • realizar nuevas peticiones al servidor sin recargar toda la página.

🟨 Cliente dinámico no significa servidor dinámico​

Que una página cambie en pantalla no significa necesariamente que el servidor haya generado de nuevo su contenido.

Podemos tener una página inicialmente estática que después cambia gracias a código ejecutado en el navegador.

Esta diferencia es importante:

El navegador modifica la página
        ≠
El servidor genera una nueva respuesta
aviso

El código del cliente puede ser inspeccionado o manipulado por la persona usuaria. Por eso las comprobaciones importantes no deben depender únicamente del navegador.

3️⃣ Generación dinámica en el servidor​

En una página generada dinámicamente, el servidor ejecuta código antes de devolver la respuesta.

Ese código puede tomar decisiones, utilizar información recibida en la petición, consultar datos o preparar un contenido diferente para cada situación.

🟩 El proceso general​

De forma simplificada:

1. El cliente envía una petición.
2. El servidor recibe la petición.
3. Se ejecuta código en el servidor.
4. Se preparan los datos necesarios.
5. Se genera la respuesta.
6. La respuesta se envía al cliente.

Por ejemplo:

GET /productos?categoria=teclados

El servidor podría interpretar el parámetro categoria, buscar los productos correspondientes y generar una página que muestre únicamente los teclados.

Si la petición fuera:

GET /productos?categoria=ratones

la aplicación podría devolver un contenido diferente.

Idea principal

La página que recibe el navegador puede depender de los datos, de la petición recibida o de las decisiones tomadas por el código que se ejecuta en el servidor.

🟨 El navegador recibe el resultado, no el código del servidor​

Imaginemos que el servidor utiliza datos para construir este resultado:

<h1>Productos de la categoría teclados</h1>

<ul>
  <li>Teclado mecánico</li>
  <li>Teclado inalámbrico</li>
</ul>

El navegador recibe el HTML generado y lo interpreta.

No necesita conocer qué lenguaje, framework o instrucciones utilizó el servidor para construirlo.

Código del servidor
        ↓
Procesamiento
        ↓
HTML generado
        ↓
Navegador

Esta separación permite que distintas tecnologías de servidor puedan producir una respuesta similar.

4️⃣ ¿Qué puede hacer el servidor antes de responder?​

Generar una página dinámicamente no consiste únicamente en sustituir una palabra dentro de un HTML.

Antes de generar la respuesta, una aplicación de servidor puede realizar distintas tareas.

🟩 Utilizar datos recibidos en la petición​

Por ejemplo:

GET /buscar?texto=java

El servidor puede utilizar el valor java para decidir qué información debe incluir en la respuesta.

🟨 Consultar información​

Una aplicación puede obtener información almacenada antes de preparar la página.

Por ejemplo, puede consultar:

  • productos disponibles.
  • noticias publicadas.
  • reservas realizadas.
  • información de usuarios.
  • resultados de una búsqueda.

Todavía no necesitamos estudiar cómo se almacenan esos datos. Lo importante es comprender que la respuesta puede construirse a partir de información que no estaba escrita directamente en el HTML.

🟧 Aplicar lógica​

El servidor también puede tomar decisiones.

Por ejemplo:

Si hay stock      → mostrar "Disponible"
Si no hay stock   → mostrar "Agotado"

O:

Si existen resultados → mostrar el listado
Si no existen         → mostrar un mensaje informativo

Esta lógica se ejecuta antes de enviar la respuesta al cliente.

5️⃣ ¿Por qué generar páginas dinámicamente?​

La generación dinámica permite construir aplicaciones que responden a situaciones cambiantes.

Entre sus principales ventajas podemos destacar:

  • mostrar información actualizada.
  • reutilizar una misma estructura para muchos datos diferentes.
  • adaptar el contenido según la petición recibida.
  • evitar mantener manualmente numerosos archivos HTML casi iguales.
  • aplicar lógica antes de generar la respuesta.
  • integrar información procedente de distintas fuentes.

🟩 Un mismo diseño, muchos resultados​

Imagina una página destinada a mostrar información sobre productos.

La estructura visual puede ser siempre la misma:

Nombre
Descripción
Precio
Disponibilidad

Pero los datos pueden cambiar según el producto solicitado:

/productos/1
/productos/2
/productos/3

No necesitamos crear manualmente una página HTML diferente para cada producto. La aplicación puede utilizar una estructura común y rellenarla con los datos correspondientes.

tip

Una de las ideas más importantes de la generación dinámica es separar la estructura de la página de los datos concretos que se muestran.

6️⃣ Tres formas distintas de obtener el contenido​

Conviene comparar claramente las tres situaciones que hemos visto.

SituaciónDónde se produce el cambio principalEjemplo
Página estáticaEl contenido ya está almacenado en el servidor.Una página de contacto fija.
Código en clienteEl navegador modifica el contenido después de recibirlo.Mostrar un mensaje al pulsar un botón.
Generación dinámica en servidorEl servidor ejecuta código y construye la respuesta antes de enviarla.Mostrar productos según una categoría.

🟩 Un ejemplo completo​

Imagina una tienda online con esta dirección:

https://tienda.ejemplo.com/productos?categoria=teclados

Podrían intervenir varias partes:

  1. El navegador envía la petición.
  2. El servidor lee la categoría solicitada.
  3. La aplicación prepara los datos de los teclados.
  4. El servidor genera una respuesta HTML.
  5. El navegador recibe el HTML.
  6. El navegador solicita los recursos adicionales necesarios, como CSS, imágenes o JavaScript.
  7. JavaScript puede añadir posteriormente comportamiento en el propio cliente.

Por tanto, generación en servidor y código en cliente pueden convivir en una misma página. Lo importante es saber qué tarea realiza cada parte.

7️⃣ Errores frecuentes​

🟩 Pensar que una página dinámica es cualquier página que cambia​

Una página puede cambiar en el navegador mediante JavaScript sin que el servidor haya generado una nueva respuesta.

Cuando hablamos de generación dinámica en servidor, nos referimos a que el servidor ejecuta código para preparar el contenido antes de enviarlo.

🟨 Pensar que todo el HTML tiene que estar escrito de antemano​

En una aplicación dinámica, parte del HTML puede construirse utilizando datos disponibles en el momento de procesar la petición.

🟧 Pensar que el navegador conoce el código del servidor​

El navegador recibe la respuesta generada, no el código que se ha ejecutado en el servidor para producirla.

🟥 Pensar que estático y dinámico son opciones incompatibles​

Una aplicación real puede combinar recursos estáticos, páginas generadas en el servidor y comportamiento ejecutado posteriormente en el cliente.

8️⃣ Actividad no evaluable: ¿dónde se genera el contenido?​

Esta actividad sirve para comprobar si se distinguen las diferentes formas de obtener el contenido de una página. No es evaluable y no requiere entrega.

Indica cuál es el comportamiento principal en cada situación: página estática, código en cliente o generación dinámica en servidor.

SituaciónTipo
Una página contacto.html muestra siempre el mismo teléfono y correo.
Al pulsar un botón aparece un mensaje sin realizar una nueva petición al servidor.
Una tienda muestra productos distintos según la categoría solicitada.
Una página de noticias muestra automáticamente las últimas publicaciones disponibles.
Un formulario marca un campo vacío antes de enviarlo.
Una aplicación muestra información diferente según el identificador incluido en la ruta.
Una imagen almacenada en el servidor se entrega directamente al navegador.
tip

En aplicaciones reales pueden intervenir varios mecanismos a la vez. En esta actividad interesa identificar dónde se produce principalmente el comportamiento descrito.
