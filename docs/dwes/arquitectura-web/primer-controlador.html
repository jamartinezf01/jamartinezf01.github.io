Primer controlador en Spring Boot

En los apartados anteriores hemos visto que una aplicación web funciona mediante un intercambio entre un cliente y un servidor. El cliente, normalmente el navegador, envía una petición HTTP. El servidor recibe esa petición, la procesa y devuelve una respuesta.

En una aplicación creada con Spring Boot, una parte importante de ese trabajo lo realizan los controladores. Un controlador es una clase Java que se encarga de atender determinadas rutas de la aplicación.

Dicho de forma sencilla: cuando alguien visita una dirección concreta de nuestra aplicación, Spring Boot busca qué controlador debe responder.

Idea principal

Un controlador permite asociar una ruta web con código Java. Así, cuando el navegador solicita una dirección, Spring Boot puede ejecutar un método y devolver una respuesta.

1️⃣ Qué es un controlador​

Un controlador es una clase Java que forma parte de la aplicación y que se encarga de recibir peticiones web. No recibe las peticiones directamente desde el navegador como si fuera una página HTML, sino que Spring Boot actúa como intermediario.

Cuando llega una petición, Spring Boot analiza la ruta solicitada y comprueba si existe algún método preparado para responder a esa dirección.

Por ejemplo, si el navegador solicita:

http://localhost:8080/saludo

Spring Boot buscará si en nuestra aplicación hay algún controlador que tenga asociada la ruta /saludo.

🟩 El controlador como punto de entrada​

En una aplicación Spring Boot, el controlador suele ser una de las primeras clases que escribimos cuando queremos que nuestra aplicación responda desde el navegador.

No debe verse como una clase cualquiera sin relación con la web. Su función principal es actuar como puerta de entrada a una parte de la aplicación.

Más adelante, los controladores se apoyarán en otras clases para organizar mejor el código, pero en esta unidad empezaremos con ejemplos muy sencillos.

aviso

En esta unidad todavía no vamos a crear aplicaciones completas por capas. De momento nos interesa entender cómo una ruta del navegador puede activar un método Java dentro de Spring Boot.

2️⃣ La anotación @Controller​

Para indicar que una clase Java será un controlador, usamos la anotación @Controller.

Una anotación es una marca especial que añadimos al código para dar información a Spring Boot. En este caso, @Controller le dice a Spring Boot que esa clase puede atender peticiones web.

package com.example.demo;

import org.springframework.stereotype.Controller;

@Controller
public class SaludoController {

}
en este ejemplo

La clase SaludoController es una clase Java normal, pero la anotación @Controller le indica a Spring Boot que debe tenerla en cuenta como controlador web. Por ahora la clase está vacía, así que todavía no responde a ninguna ruta.

🟩 Dónde se coloca el controlador​

Para que Spring Boot detecte correctamente el controlador, la clase debe estar dentro del paquete principal de la aplicación o en un subpaquete suyo.

Por ejemplo, si la clase principal está en:

com.example.demo

podemos crear el controlador en ese mismo paquete:

com.example.demo

O en un subpaquete, por ejemplo:

com.example.demo.controller

Esta segunda opción será más ordenada cuando el proyecto crezca, aunque en los primeros ejemplos podemos mantener una estructura sencilla.

tip

Al empezar, lo importante no es crear muchos paquetes, sino entender qué hace cada clase. Más adelante iremos ordenando mejor el proyecto.

3️⃣ Asociar una ruta con @GetMapping​

Un controlador por sí solo no basta. Necesitamos indicar qué ruta va a atender.

Para responder a una petición de tipo GET, usamos la anotación @GetMapping.

La mayoría de veces que escribimos una dirección en el navegador estamos realizando una petición GET. Por eso es la primera que vamos a utilizar.

package com.example.demo;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ResponseBody;

@Controller
public class SaludoController {

    @GetMapping("/saludo")
    @ResponseBody
    public String saludar() {
        return "Hola desde Spring Boot";
    }
}
en este ejemplo

La anotación @GetMapping("/saludo") indica que el método saludar() responderá cuando el navegador solicite la ruta /saludo. Como además usamos @ResponseBody, el texto que devuelve el método se envía directamente como respuesta HTTP al navegador.

🟩 Probar la ruta en el navegador​

Si la aplicación está arrancada correctamente, podemos abrir el navegador y escribir:

http://localhost:8080/saludo

El navegador debería mostrar:

Hola desde Spring Boot

Aunque parezca algo muy simple, aquí ya está ocurriendo todo el recorrido básico de una aplicación web:

  1. El navegador envía una petición HTTP.
  2. Spring Boot recibe la petición.
  3. El controlador atiende la ruta /saludo.
  4. Se ejecuta el método saludar().
  5. El texto devuelto se envía como respuesta.

La imagen anterior representa el recorrido básico: el navegador solicita una ruta, Spring Boot localiza el controlador correspondiente y el método devuelve una respuesta sencilla.

4️⃣ Para qué sirve @ResponseBody​

En el ejemplo anterior hemos usado @ResponseBody. Esta anotación es importante porque cambia la forma en la que Spring Boot interpreta el valor devuelto por el método.

Cuando un método de un controlador devuelve un String, Spring Boot puede interpretarlo de dos formas distintas:

CasoQué interpreta Spring Boot
Con @ResponseBodyEl texto se devuelve directamente al navegador.
Sin @ResponseBodyEl texto se interpreta como el nombre de una vista o plantilla.

En este primer ejemplo queremos devolver texto directamente, por eso usamos @ResponseBody.

@GetMapping("/saludo")
@ResponseBody
public String saludar() {
    return "Hola desde Spring Boot";
}
en este ejemplo

Como el método tiene @ResponseBody, Spring Boot no busca una plantilla llamada Hola desde Spring Boot. Simplemente envía ese texto como cuerpo de la respuesta HTTP.

🟨 Error frecuente​

Un error muy habitual al empezar es quitar @ResponseBody en un ejemplo como este.

Si escribimos:

@GetMapping("/saludo")
public String saludar() {
    return "Hola desde Spring Boot";
}

Spring Boot puede intentar buscar una vista con ese nombre, y eso no es lo que queremos en este caso.

aviso

Cuando queramos devolver texto directamente desde un controlador con @Controller, usaremos @ResponseBody. Cuando más adelante devolvamos una vista Thymeleaf, no deberemos usar @ResponseBody.

5️⃣ Otra ruta sencilla​

Un mismo controlador puede tener varios métodos, cada uno asociado a una ruta diferente.

package com.example.demo;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ResponseBody;

@Controller
public class SaludoController {

    @GetMapping("/saludo")
    @ResponseBody
    public String saludar() {
        return "Hola desde Spring Boot";
    }

    @GetMapping("/despedida")
    @ResponseBody
    public String despedir() {
        return "Hasta pronto";
    }
}
en este ejemplo

El controlador tiene ahora dos métodos. Si el navegador solicita /saludo, se ejecuta saludar(). Si solicita /despedida, se ejecuta despedir(). Cada ruta tiene su propio método asociado.

🟩 Rutas distintas, respuestas distintas​

Si probamos estas dos direcciones:

http://localhost:8080/saludo
http://localhost:8080/despedida

obtendremos respuestas diferentes.

Esto permite construir poco a poco una aplicación web donde cada ruta representa una acción o una página distinta.

Idea principal

Un controlador puede contener varios métodos. Cada método puede responder a una ruta diferente de la aplicación.

6️⃣ Relación con lo visto hasta ahora​

El primer controlador conecta varios conceptos que ya hemos trabajado en esta unidad.

Cuando escribimos una dirección en el navegador, no estamos ejecutando Java directamente en nuestro equipo. Lo que hacemos es enviar una petición al servidor. Spring Boot recibe esa petición y decide qué método Java debe ejecutarse en el servidor.

Por tanto, el código del controlador se ejecuta en el entorno servidor, no en el navegador.

🟩 Cliente y servidor en este ejemplo​

En el ejemplo de /saludo, el reparto queda así:

ElementoPapel que realiza
NavegadorActúa como cliente y envía la petición.
Spring BootRecibe la petición y gestiona la aplicación.
ControladorAtiende la ruta solicitada.
Método JavaGenera la respuesta.
Respuesta HTTPDevuelve el contenido al navegador.

Este esquema es sencillo, pero será la base de muchos ejemplos posteriores.

7️⃣ Actividad no evaluable: crea tus primeras rutas​

Esta actividad sirve para practicar la creación de rutas sencillas en Spring Boot. No es una actividad evaluable y no requiere entrega, pero conviene realizarla para comprobar que se entiende la relación entre ruta, controlador y respuesta.

🟩 Objetivo​

Crear un controlador con varias rutas GET que devuelvan texto directamente al navegador.

🟨 Contexto​

Imagina que estás empezando una pequeña aplicación para organizar productos de una tienda. De momento no vamos a crear base de datos ni páginas HTML completas. Solo queremos comprobar que Spring Boot puede responder a distintas rutas.

🟧 Pasos guiados​

  1. Crea una clase llamada ProductoController.
  2. Añade la anotación @Controller encima de la clase.
  3. Crea una ruta /productos que devuelva el texto Listado de productos.
  4. Crea una ruta /productos/destacado que devuelva el texto Producto destacado de la semana.
  5. Comprueba ambas rutas desde el navegador.

Un posible punto de partida sería:

package com.example.demo;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ResponseBody;

@Controller
public class ProductoController {

    @GetMapping("/productos")
    @ResponseBody
    public String listarProductos() {
        return "Listado de productos";
    }
}
en este ejemplo

Este código crea un controlador llamado ProductoController. La ruta /productos está asociada al método listarProductos(). Al usar @ResponseBody, el texto se devuelve directamente como respuesta al navegador.

🟥 Comprobación​

Al terminar, deberías poder abrir estas direcciones:

http://localhost:8080/productos
http://localhost:8080/productos/destacado

Y obtener una respuesta de texto diferente en cada una.

🟪 Preguntas de repaso​

  1. ¿Qué anotación indica que una clase es un controlador?
  2. ¿Qué anotación usamos para responder a una petición GET?
  3. ¿Qué ocurre si usamos @Controller pero olvidamos @ResponseBody al devolver texto directo?
  4. ¿Dónde se ejecuta el método Java: en el navegador o en el servidor?
  5. ¿Qué ruta activa el método listarProductos()?
tip

Si una ruta no funciona, revisa tres cosas: que la aplicación esté arrancada, que la dirección escrita en el navegador coincida exactamente con la ruta del @GetMapping y que el controlador esté dentro del paquete que Spring Boot escanea.

8️⃣ En resumen​

Un controlador es una clase Java que permite a Spring Boot responder a peticiones web. Con @Controller indicamos que una clase actuará como controlador, y con @GetMapping asociamos una ruta concreta a un método Java.

Cuando usamos @ResponseBody, el valor devuelto por el método se envía directamente como respuesta al navegador. Esto nos permite empezar con ejemplos muy sencillos antes de trabajar con vistas Thymeleaf y páginas HTML generadas desde el servidor.

En esta unidad no buscamos todavía construir una aplicación completa, sino entender el recorrido básico: el cliente solicita una ruta, Spring Boot la recibe, el controlador ejecuta un método y el servidor devuelve una respuesta.
