Spring Initializr y creación de un proyecto

Después de conocer qué es Spring Boot, necesitamos crear nuestro primer proyecto. Para ello utilizaremos Spring Initializr, una herramienta web que genera la estructura inicial de una aplicación Spring Boot.

Spring Initializr no es un programa que tengamos que instalar. Se utiliza desde el navegador y nos permite seleccionar las opciones principales del proyecto: lenguaje, sistema de construcción, versión de Java, nombre del proyecto y dependencias iniciales.

En esta unidad vamos a crear un proyecto muy sencillo. El objetivo no es conocer todas las opciones disponibles, sino entender qué estamos seleccionando y por qué.

Idea principal

Spring Initializr nos ayuda a crear un proyecto Spring Boot inicial con la estructura, configuración y dependencias básicas para empezar a trabajar sin preparar todo manualmente.

1️⃣ Qué es Spring Initializr​

Spring Initializr es un generador de proyectos Spring Boot. En lugar de crear manualmente todas las carpetas, archivos de configuración y dependencias, podemos completar un formulario y descargar un proyecto inicial preparado para abrirlo en el IDE.

Esto no significa que Spring Initializr programe la aplicación por nosotros. Lo que hace es preparar el punto de partida: estructura del proyecto, archivo pom.xml, clase principal y dependencias seleccionadas.

🟩 Por qué lo usamos al empezar​

Cuando estamos aprendiendo, crear un proyecto desde cero puede ser confuso. Hay que saber qué carpetas crear, qué dependencias añadir, cómo configurar Maven y qué clase principal necesita Spring Boot para arrancar.

Spring Initializr simplifica este inicio y permite que nos centremos antes en lo importante: entender cómo responde la aplicación a peticiones HTTP y cómo se organiza el código.

🟨 Qué no debemos confundir​

Spring Initializr no es el IDE, no es Spring Boot y no es Maven. Es una herramienta web que genera un proyecto inicial.

Podemos verlo así:

ElementoFunción
Spring InitializrGenera la estructura inicial del proyecto.
Spring BootPermite desarrollar y ejecutar la aplicación Java.
MavenGestiona dependencias y construcción del proyecto.
IntelliJ IDEA CommunityPermite abrir, editar y ejecutar el proyecto.
aviso

No hay que instalar Spring Initializr. Lo usaremos desde la web para descargar un proyecto .zip y después lo abriremos con IntelliJ IDEA Community.

2️⃣ Opciones básicas del proyecto​

Al crear un proyecto con Spring Initializr aparecen muchas opciones. En esta primera unidad solo necesitamos comprender las más importantes.

🟩 Project​

En el apartado Project elegiremos el sistema de construcción. En nuestro caso utilizaremos:

Maven

Maven se encargará de gestionar las dependencias del proyecto y de preparar la aplicación para su ejecución. No vamos a profundizar todavía en Maven, pero sí debemos reconocer que el archivo pom.xml será importante.

🟨 Language​

En Language seleccionaremos:

Java

Spring Boot permite trabajar con otros lenguajes compatibles con la JVM, pero en este módulo usaremos Java porque es el lenguaje principal con el que desarrollaremos la parte de servidor.

🟧 Spring Boot​

En el apartado Spring Boot se elige la versión de Spring Boot que usará el proyecto.

Como norma general, utilizaremos una versión estable disponible en Spring Initializr. No es necesario memorizar el número exacto de versión, porque puede cambiar con el tiempo.

tip

Si en clase aparece una versión diferente a la de una captura, no pasa nada. Lo importante es elegir una versión estable indicada por el profesor y mantenerla durante la práctica.

🟥 Packaging​

En Packaging seleccionaremos normalmente:

Jar

Esto permite generar una aplicación ejecutable de forma sencilla, adecuada para nuestras primeras prácticas con Spring Boot.

🟪 Java​

En Java se indica la versión de Java que utilizará el proyecto. Debe ser compatible con la versión instalada en el equipo y con la versión de Spring Boot seleccionada.

En clase se indicará la versión concreta que debe utilizarse para evitar problemas de compatibilidad.

aviso

Uno de los errores más frecuentes al empezar es crear el proyecto con una versión de Java distinta a la instalada en el equipo. Si el proyecto no arranca, esta será una de las primeras cosas que habrá que revisar.

3️⃣ Datos del proyecto​

Spring Initializr también nos pide algunos datos para identificar el proyecto. Estos datos se conocen como Project Metadata.

No hace falta entender todos los detalles desde el primer día, pero sí conviene saber qué representan.

🟩 Group​

El campo Group identifica normalmente a la organización, empresa o dominio al que pertenece el proyecto. En prácticas educativas podemos usar un valor sencillo, por ejemplo:

com.ejemplo

🟨 Artifact​

El campo Artifact suele coincidir con el nombre técnico del proyecto. Por ejemplo:

tienda

🟧 Name​

El campo Name indica el nombre de la aplicación. Puede ser parecido al artifact:

Tienda

🟥 Package name​

El Package name será el paquete base del proyecto Java. Normalmente se construye a partir del group y del artifact.

Por ejemplo:

com.ejemplo.tienda

Las clases que creemos deberán estar dentro de ese paquete o en subpaquetes para que Spring Boot pueda detectarlas correctamente.

Idea principal

El paquete principal es importante porque Spring Boot escanea las clases que están dentro de ese paquete y sus subpaquetes. Por eso conviene crear los controladores dentro de esa estructura.

4️⃣ Dependencias iniciales​

Las dependencias son librerías o módulos que añadimos al proyecto para incorporar funcionalidades.

En Spring Initializr podemos pulsar en Add Dependencies y seleccionar las que necesitemos. Para esta unidad nos interesan especialmente estas dos:

DependenciaPara qué la usaremos
Spring WebCrear aplicaciones web, controladores y rutas.
ThymeleafCrear páginas HTML generadas desde el servidor.

🟩 Spring Web​

La dependencia Spring Web es la más importante para empezar a crear aplicaciones web con Spring Boot. Gracias a ella podremos usar controladores, rutas y respuestas HTTP.

Sin esta dependencia, nuestro proyecto no tendría preparadas las herramientas básicas para atender peticiones web.

🟨 Thymeleaf​

La dependencia Thymeleaf nos permitirá trabajar con plantillas HTML. En esta unidad apenas haremos una primera aproximación, pero en la siguiente unidad será una pieza importante para crear vistas.

aviso

No conviene añadir dependencias “por si acaso”. Cada dependencia debe tener un propósito. En esta unidad no añadiremos JPA, Security ni otras herramientas que todavía no vamos a utilizar.

5️⃣ Generar y descargar el proyecto​

Una vez completadas las opciones, Spring Initializr permite generar el proyecto. Normalmente descargaremos un archivo comprimido .zip.

El proceso será:

1. Completar las opciones del proyecto.
2. Añadir las dependencias necesarias.
3. Pulsar Generate.
4. Descargar el archivo .zip.
5. Descomprimir el proyecto en una carpeta de trabajo.

Conviene guardar los proyectos en una carpeta fácil de localizar. Por ejemplo:

DWES/proyectos/tienda

No es recomendable trabajar directamente dentro de la carpeta de descargas, porque después será más difícil organizar los proyectos.

🟩 Nombre de carpetas​

Al empezar, es mejor evitar nombres de carpetas con espacios, tildes o caracteres especiales.

Por ejemplo, mejor:

tienda-spring

que:

Práctica 1 - Tienda con Spring

Esto puede evitar algunos problemas con rutas, terminales o herramientas de construcción.

6️⃣ Abrir el proyecto en IntelliJ IDEA Community​

Una vez descomprimido el proyecto, lo abriremos con IntelliJ IDEA Community.

Lo importante es abrir la carpeta raíz del proyecto, es decir, la carpeta donde se encuentra el archivo:

pom.xml

Si abrimos una carpeta superior o una carpeta incorrecta, IntelliJ puede no reconocer bien el proyecto Maven.

🟩 Pasos básicos​

El proceso será similar a este:

1. Abrir IntelliJ IDEA Community.
2. Elegir Open.
3. Seleccionar la carpeta del proyecto descomprimido.
4. Esperar a que IntelliJ importe el proyecto Maven.
5. Comprobar que aparece el archivo pom.xml.
6. Localizar la clase principal de la aplicación.

🟨 Esperar a que Maven termine​

Al abrir el proyecto por primera vez, IntelliJ puede tardar un poco en descargar dependencias e indexar archivos. Es normal.

Si intentamos ejecutar el proyecto antes de que termine este proceso, puede parecer que algo falla cuando en realidad el IDE todavía está preparando el proyecto.

tip

Si el proyecto acaba de abrirse, espera a que IntelliJ termine de importar Maven antes de ejecutar la aplicación.

7️⃣ Ejecutar el proyecto por primera vez​

Cuando el proyecto esté abierto correctamente, buscaremos la clase principal. Tendrá un aspecto parecido a este:

package com.ejemplo.tienda;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class TiendaApplication {

    public static void main(String[] args) {
        SpringApplication.run(TiendaApplication.class, args);
    }
}
en este ejemplo

La anotación @SpringBootApplication marca la clase principal de la aplicación. El método main() es el punto de entrada, como en otros programas Java. La llamada SpringApplication.run(...) arranca Spring Boot y pone en marcha la aplicación.

Al ejecutarla, en la consola aparecerán mensajes de arranque. Si todo va bien, veremos que el servidor se ha iniciado y está escuchando en un puerto, normalmente el 8080.

Tomcat started on port 8080
Started TiendaApplication in ... seconds

A partir de ese momento, podremos abrir el navegador y acceder a:

http://localhost:8080

Es posible que todavía no veamos una página propia, porque aún no hemos creado ningún controlador. Eso no significa necesariamente que el proyecto esté mal: simplemente todavía no hemos programado una ruta que devuelva contenido.

8️⃣ Errores frecuentes al crear el primer proyecto​

🟩 Abrir la carpeta equivocada​

Si IntelliJ no muestra bien src/main/java, src/main/resources o pom.xml, puede que se haya abierto una carpeta incorrecta.

Hay que abrir la carpeta raíz del proyecto, no la carpeta de descargas ni una carpeta superior.

🟨 No esperar a que se descarguen las dependencias​

La primera vez que se abre un proyecto, Maven puede necesitar descargar bastantes archivos. Si se interrumpe el proceso o se ejecuta demasiado pronto, pueden aparecer errores temporales.

🟧 Elegir una versión de Java incompatible​

El proyecto debe usar una versión de Java compatible con la que está instalada en el equipo. Si no coinciden, IntelliJ puede mostrar errores o impedir la ejecución.

🟥 Añadir demasiadas dependencias​

Al empezar, no necesitamos añadir todas las dependencias disponibles. Para esta unidad bastará con las que se indiquen en clase, normalmente Spring Web y Thymeleaf.

🟪 Pensar que Spring Initializr ya crea la aplicación completa​

Spring Initializr solo crea el punto de partida. Después tendremos que escribir nuestros controladores, rutas, vistas y lógica de aplicación.

9️⃣ Actividad no evaluable: crea tu primer proyecto​

Esta actividad sirve para practicar la creación de un proyecto Spring Boot desde Spring Initializr. No es evaluable y no requiere entrega, pero es importante realizarla porque será la base de las próximas prácticas.

🟩 Objetivo​

Crear un proyecto Spring Boot básico, abrirlo en IntelliJ IDEA Community y comprobar que se puede ejecutar.

🟨 Configuración orientativa​

Utiliza las opciones indicadas por el profesor. Como referencia, el proyecto puede tener una configuración parecida a esta:

OpciónValor orientativo
ProjectMaven
LanguageJava
PackagingJar
Groupcom.ejemplo
Artifacttienda
NameTienda
DependenciesSpring Web, Thymeleaf

La versión concreta de Spring Boot y de Java se indicará en clase para evitar incompatibilidades.

🟧 Pasos guiados​

  1. Accede a Spring Initializr desde el navegador.
  2. Completa las opciones básicas del proyecto.
  3. Añade las dependencias indicadas.
  4. Genera y descarga el proyecto.
  5. Descomprime el archivo .zip en tu carpeta de trabajo.
  6. Abre el proyecto con IntelliJ IDEA Community.
  7. Espera a que Maven termine de importar las dependencias.
  8. Localiza la clase principal.
  9. Ejecuta la aplicación.
  10. Comprueba en la consola que el servidor ha arrancado.

🟥 Comprobación final​

Antes de continuar, revisa estas preguntas:

  • ¿Dónde está el archivo pom.xml?
  • ¿Qué dependencia permite crear una aplicación web?
  • ¿Qué dependencia usaremos más adelante para generar vistas HTML?
  • ¿Qué clase arranca la aplicación?
  • ¿Qué puerto aparece en la consola al iniciar el proyecto?
  • ¿Qué significa localhost:8080?
tip

No pasa nada si al acceder a http://localhost:8080 todavía no aparece una página propia. Primero necesitamos crear un controlador que responda a una ruta.

🔟 En resumen​

Spring Initializr nos permite crear rápidamente el punto de partida de una aplicación Spring Boot. Desde la web seleccionamos las opciones principales del proyecto, añadimos las dependencias necesarias y descargamos una estructura preparada para abrirla en IntelliJ IDEA Community.

En esta unidad usaremos una configuración sencilla: Java, Maven, empaquetado Jar y las dependencias necesarias para empezar a crear aplicaciones web. Después de abrir el proyecto, Maven descargará las dependencias y podremos ejecutar la clase principal para arrancar Spring Boot.

El siguiente paso será reconocer la estructura del proyecto y, después, crear nuestros primeros controladores y rutas.
