Servidores web y servidores de aplicaciones

Cuando utilizamos una aplicación web solemos fijarnos en el navegador y en la dirección que escribimos. Sin embargo, al otro lado de la comunicación hay una parte fundamental: el servidor.

En una aplicación web, el servidor no siempre se limita a guardar archivos. Puede entregar recursos estáticos, ejecutar código, consultar información y construir respuestas diferentes según la petición recibida.

Para entender mejor cómo se organiza esta parte de una aplicación conviene distinguir entre servidor web y servidor de aplicaciones.

Idea principal

Un servidor web está especializado en recibir peticiones HTTP y devolver recursos web. Un servidor de aplicaciones proporciona un entorno donde se ejecuta la lógica de una aplicación y se generan respuestas dinámicas.

1️⃣ Qué significa servidor​

La palabra servidor puede utilizarse con varios significados. Dependiendo del contexto, puede referirse a una máquina o a un programa.

🟩 Servidor como máquina​

Desde el punto de vista físico, un servidor puede ser un ordenador preparado para ejecutar servicios y permanecer disponible para otros equipos de la red.

Puede encontrarse, por ejemplo:

  • en una empresa.
  • en un centro de datos.
  • en una plataforma en la nube.
  • incluso en nuestro propio equipo durante el desarrollo.

En esta unidad no vamos a estudiar la administración de estas máquinas. Nos interesa comprender qué función desempeñan dentro de una aplicación web.

🟨 Servidor como programa​

También llamamos servidor al software que permanece a la espera de peticiones y genera las respuestas correspondientes.

Por ejemplo:

Cliente: solicita /contacto
Servidor: recibe la petición
Servidor: prepara la respuesta
Cliente: recibe la respuesta
en este ejemplo

El cliente no ejecuta directamente el código que existe en el servidor. Envía una petición y el servidor decide qué debe devolver como respuesta.

🟧 Una misma máquina puede ejecutar varios servidores​

Es importante no identificar automáticamente una máquina con un único servidor.

En un mismo equipo pueden ejecutarse distintos programas servidor al mismo tiempo, cada uno encargado de una función diferente.

Por eso conviene separar estas dos ideas:

Servidor físico o virtual → máquina donde se ejecutan servicios
Servidor software          → programa que atiende peticiones

2️⃣ El servidor web​

Un servidor web es un programa especializado en recibir peticiones HTTP y devolver respuestas HTTP.

Una de sus funciones más habituales es entregar recursos que ya existen como archivos.

🟩 Entrega de recursos estáticos​

Algunos ejemplos de recursos estáticos son:

/index.html
/css/estilos.css
/img/logo.png
/js/app.js

Si el navegador solicita:

GET /css/estilos.css HTTP/1.1

el servidor web puede localizar el archivo y devolverlo directamente.

Una respuesta simplificada podría ser:

HTTP/1.1 200 OK
Content-Type: text/css
en este ejemplo

En este caso no es necesario ejecutar lógica de negocio para construir el contenido. El recurso ya existe y el servidor web lo entrega al cliente.

🟨 Otras tareas habituales​

Además de entregar archivos, un servidor web puede realizar otras tareas relacionadas con la comunicación HTTP, como:

  • gestionar conexiones.
  • aplicar reglas de acceso.
  • redirigir peticiones.
  • gestionar certificados HTTPS.
  • almacenar determinadas respuestas en caché.
  • reenviar peticiones a otra aplicación.

No estudiaremos ahora su configuración. Lo importante es comprender que actúa como punto de entrada de muchas arquitecturas web.

🟧 Algunos servidores web conocidos​

Entre los servidores web más utilizados encontramos:

  • Apache HTTP Server.
  • Nginx.
  • Microsoft IIS.

No necesitamos aprender a administrarlos en esta unidad. Se presentan únicamente para reconocer tecnologías habituales en entornos reales.

3️⃣ El servidor de aplicaciones​

Un servidor de aplicaciones proporciona un entorno donde puede ejecutarse la lógica de una aplicación.

Su función no consiste únicamente en localizar un archivo y devolverlo. Puede ejecutar código, utilizar datos y construir una respuesta en función de la petición recibida.

🟩 Ejecutar lógica en el servidor​

Imagina esta petición:

GET /productos?categoria=teclados

Una aplicación podría realizar internamente un proceso como este:

Recibir la petición
        ↓
Leer la categoría solicitada
        ↓
Obtener los productos correspondientes
        ↓
Preparar la respuesta
        ↓
Devolver el resultado al cliente

El contenido de la respuesta no tiene por qué existir previamente como un archivo completo. Puede generarse en ese momento.

🟨 Servicios que puede proporcionar​

Dependiendo de la tecnología utilizada, el entorno de aplicación puede encargarse también de tareas como:

  • ejecutar el código de la aplicación.
  • gestionar sesiones.
  • coordinar componentes.
  • facilitar conexiones con otros servicios.
  • gestionar determinados recursos compartidos.
  • generar respuestas dinámicas.

Algunas de estas funciones se estudiarán más adelante. En esta unidad basta con comprender su papel general.

🟧 Algunos ejemplos en Java​

En el ecosistema Java existen diferentes tipos de servidores y contenedores para ejecutar aplicaciones web.

Algunos ejemplos son:

  • WildFly.
  • Payara.
  • Open Liberty.
  • Apache Tomcat, utilizado habitualmente como contenedor web para aplicaciones Java.
  • Jetty, también utilizado como servidor y contenedor web ligero.
nota

No necesitamos distinguir ahora todas las categorías técnicas del ecosistema Java. Lo importante es comprender que existen entornos capaces de ejecutar aplicaciones web, no solo de entregar archivos estáticos.

4️⃣ Servidor web y servidor de aplicaciones no hacen exactamente lo mismo​

La diferencia principal puede entenderse comparando sus responsabilidades.

ElementoFunción principalEjemplo de tarea
Servidor webGestionar peticiones HTTP y entregar recursos web.Devolver /img/logo.png.
Servidor de aplicacionesEjecutar la lógica de la aplicación y generar respuestas dinámicas.Preparar el listado de productos de una categoría.

🟩 Un recurso estático​

Si el navegador solicita:

GET /img/logo.png

el servidor web puede devolver directamente el archivo solicitado.

🟨 Una respuesta dinámica​

Si el navegador solicita:

GET /productos?categoria=teclados

la respuesta puede necesitar ejecutar código y consultar información antes de generarse.

Ahí entra en juego la aplicación que se ejecuta en el servidor.

tip

La diferencia no debe entenderse como una frontera absoluta. Las herramientas modernas pueden asumir varias funciones. En esta unidad utilizamos esta separación porque ayuda a comprender las responsabilidades fundamentales de una arquitectura web.

En muchas arquitecturas, el servidor web y la aplicación trabajan de forma coordinada.

El servidor web puede encargarse de recibir las peticiones externas. Si puede resolverlas directamente, devuelve el recurso. Si requieren ejecutar la aplicación, las reenvía al entorno correspondiente y después entrega la respuesta al cliente.

🟩 ¿Por qué separar responsabilidades?​

Cuando una aplicación crece, separar responsabilidades puede facilitar tareas como:

  • gestionar recursos estáticos de forma eficiente.
  • centralizar el acceso HTTP o HTTPS.
  • distribuir peticiones entre varias aplicaciones.
  • aplicar determinadas reglas de seguridad.
  • organizar mejor la infraestructura.

En aplicaciones pequeñas estas piezas pueden estar mucho más integradas, pero las responsabilidades siguen existiendo.

6️⃣ Un mismo resultado puede seguir caminos diferentes​

Desde el punto de vista del navegador, dos respuestas pueden parecer similares aunque se hayan generado de forma distinta.

🟩 Caso 1: archivo estático​

GET /contacto.html
        ↓
Servidor localiza contacto.html
        ↓
Devuelve el archivo

🟨 Caso 2: contenido generado dinámicamente​

GET /productos
        ↓
La aplicación ejecuta código
        ↓
Prepara los datos
        ↓
Genera HTML
        ↓
Devuelve la respuesta

En ambos casos el navegador puede terminar recibiendo HTML, pero el proceso seguido en el servidor es diferente.

Esta idea conecta directamente con lo estudiado en el apartado anterior sobre generación dinámica de páginas.

7️⃣ Errores frecuentes​

🟩 Pensar que servidor significa siempre ordenador​

En desarrollo web, muchas veces hablamos del software servidor, no únicamente de la máquina donde se ejecuta.

🟨 Pensar que todo servidor entrega únicamente archivos​

Una aplicación de servidor puede ejecutar código y construir respuestas dinámicamente antes de enviarlas.

🟧 Pensar que servidor web y servidor de aplicaciones son sinónimos​

Sus funciones pueden solaparse en algunas tecnologías, pero conceptualmente no representan exactamente la misma responsabilidad.

🟥 Pensar que siempre tienen que estar en máquinas distintas​

Servidor web y aplicación pueden ejecutarse en máquinas diferentes, pero también pueden hacerlo en el mismo equipo.

La separación que estamos estudiando es principalmente una separación de responsabilidades.

8️⃣ Actividad no evaluable: identifica quién responde​

Esta actividad sirve para comprobar si se distingue cuándo una petición puede resolverse directamente y cuándo necesita ejecutar lógica de la aplicación. No es evaluable y no requiere entrega.

🟨 Preguntas de comprobación​

  1. ¿Puede un servidor web devolver una imagen sin ejecutar lógica de aplicación?
  2. ¿Qué diferencia hay entre devolver un archivo existente y generar una respuesta dinámicamente?
  3. ¿Servidor web y servidor de aplicaciones tienen que ejecutarse necesariamente en máquinas distintas?
  4. ¿Por qué puede ser útil separar ambas responsabilidades en una aplicación grande?
  5. ¿Puede el navegador saber únicamente observando el HTML final si ese contenido procedía de un archivo estático o se generó dinámicamente?
tip

No busques una regla basada únicamente en la extensión o en la forma de la URL. Lo importante es pensar si el recurso ya existe tal cual o si la aplicación necesita ejecutar código para preparar la respuesta.
