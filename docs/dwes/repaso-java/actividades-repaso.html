Actividades de repaso

Este bloque de repaso se trabajará mediante tres retos prácticos, uno al final de cada sesión.

La intención no es repetir exactamente los ejemplos realizados en los apuntes, sino comprobar si somos capaces de aplicar lo repasado en situaciones algo más abiertas.

Cada reto está organizado en tres niveles de consecución. No es necesario completar siempre el nivel más alto. Lo importante es avanzar hasta el punto en el que el código funcione y se comprenda lo que se ha hecho.

Carácter de los retos

Estos retos son no evaluables.

No existe entrega ni calificación asociada. Su finalidad es recuperar soltura con Java, detectar dudas y llegar al inicio de Spring Boot con una base suficientemente sólida.

1️⃣ Cómo funcionan los niveles​

Cada reto tiene tres niveles.

🟩 Nivel 1 · En marcha​

Permite comprobar que se dominan los elementos esenciales trabajados durante la sesión.

Puede resolverse con apoyo de los apuntes o consultando ejemplos anteriores.

🟨 Nivel 2 · Conseguido​

Supone resolver el problema principal de forma completa y conseguir que el programa funcione correctamente en los casos esperados.

🟧 Nivel 3 · Ampliado​

Añade mejoras, validaciones o funcionalidades nuevas.

Está pensado para quien termine antes o quiera profundizar un poco más.

tip

No se trata de llegar lo más rápido posible al nivel 3.

Es preferible resolver correctamente un nivel y comprender el código antes de añadir más funcionalidades.

1️⃣ Reto 1 · Calculadora de compra​

🟩 Objetivo​

Aplicar variables, operadores, estructuras condicionales, switch, bucles y métodos.

🟨 Contexto​

La tienda quiere disponer de un pequeño programa que calcule el importe final de una compra.

De cada compra conocemos:

nombre del producto
precio por unidad
cantidad
categoría
cliente socio o no

No se proporciona una solución cerrada. Debes decidir cómo organizar el código utilizando lo trabajado durante la sesión.

🟧 Nivel 1 · En marcha​

Crea un programa que:

  • guarde en variables el nombre del producto.
  • almacene su precio.
  • almacene la cantidad comprada.
  • indique si el cliente es socio.
  • calcule el importe total sin descuentos.
  • muestre un resumen de la compra.

Ejemplo de salida:

Producto: Teclado
Precio unidad: 29.95 €
Cantidad: 2
Total: 59.90 €

🟥 Nivel 2 · Conseguido​

Amplía el programa incorporando las siguientes reglas:

  • si se compran 3 o más unidades, se aplica un descuento del 10 %.
  • si el cliente es socio, se aplica un 5 % adicional.
  • el cálculo del total debe realizarse mediante métodos.
  • debe mostrarse el subtotal, el descuento aplicado y el precio final.

No se proporciona la firma exacta de todos los métodos. Decide qué operaciones tiene sentido separar.

Una posible ejecución podría ser:

Producto: Teclado
Precio unidad: 29.95 €
Cantidad: 3

Subtotal: 89.85 €
Descuento: 13.48 €
Total final: 76.37 €
aviso

Piensa antes de programar.

Si aplicas dos descuentos, decide primero cómo se calculan y en qué orden. Lo importante es que tu solución sea coherente y puedas explicar lo que hace.

🟪 Nivel 3 · Ampliado​

Añade una categoría al producto:

INFORMATICA
HOGAR
DEPORTE

Utiliza un switch moderno para aplicar una condición adicional según la categoría.

Por ejemplo:

  • INFORMATICA → sin descuento adicional.
  • HOGAR → 5 % adicional.
  • DEPORTE → 8 % adicional.

Además:

  • impide cantidades menores o iguales que 0.
  • muestra un mensaje claro cuando los datos no son válidos.
  • permite repetir varias compras utilizando un bucle.

🟩 Comprobación del reto​

Antes de dar el reto por terminado, comprueba:

  • El programa compila.
  • Utiliza variables de tipos adecuados.
  • Hay al menos un método con parámetros y valor de retorno.
  • Se utilizan correctamente estructuras if.
  • El switch utiliza la sintaxis moderna con ->.
  • El resultado final tiene sentido.
  • Puedes explicar cómo se calcula el precio final.

2️⃣ Reto 2 · Modelamos la tienda​

🟩 Objetivo​

Aplicar clases, objetos, atributos, constructores, encapsulación, métodos de instancia, relaciones entre objetos y enum.

🟨 Contexto​

La tienda quiere dejar de trabajar con datos sueltos.

Ahora necesita representar productos y otra información relacionada utilizando objetos.

Debes diseñar una pequeña parte del modelo de la aplicación.

🟧 Nivel 1 · En marcha​

Crea una clase:

Producto

Debe almacenar como mínimo:

nombre
precio
stock

La clase debe incluir:

  • atributos private.
  • constructor.
  • getters.
  • un método hayStock().
  • un método venderUnidad().

Desde main, crea al menos tres productos diferentes y realiza varias operaciones con ellos.

tip

No copies directamente la clase completa de los apuntes.

Intenta escribirla desde cero y consulta únicamente cuando no recuerdes alguna parte concreta.

🟥 Nivel 2 · Conseguido​

Amplía el modelo.

Crea una clase:

Categoria

con al menos:

nombre
descripcion

Relaciona cada Producto con una Categoria.

Crea también:

public enum EstadoProducto {
    NUEVO,
    OFERTA,
    AGOTADO
}

Añade el estado al producto.

El programa debe permitir mostrar información semejante a:

Teclado
Categoría: Informática
Precio: 29.95 €
Stock: 8
Estado: OFERTA

Añade también un método:

public void reponerStock(int cantidad)

La cantidad solo debe añadirse si es positiva.

🟪 Nivel 3 · Ampliado​

La tienda empieza a registrar ventas.

Diseña una nueva clase:

Pedido

Un pedido debe estar relacionado, como mínimo, con:

Producto
cantidad

Debe poder calcular su importe total.

Decide qué atributos y métodos necesita.

Como ampliación adicional puedes crear también una clase:

Cliente

y relacionarla con Pedido.

El objetivo es poder representar una situación como:

Cliente: Ana
Producto: Teclado
Cantidad: 2
Total: 59.90 €
Piensa en las responsabilidades

No todas las operaciones tienen que estar en main.

Pregúntate qué objeto debería saber calcular cada cosa y coloca el método donde tenga más sentido.

3️🟩 Preguntas de comprobación​

Antes de terminar, intenta responder sin mirar los apuntes:

  1. ¿Cuál es la diferencia entre una clase y un objeto?
  2. ¿Para qué sirve un constructor?
  3. ¿Qué representa this?
  4. ¿Por qué declaramos los atributos como private?
  5. ¿Qué diferencia hay entre guardar el nombre de una categoría y guardar un objeto Categoria?
  6. ¿Cuándo tiene sentido utilizar un enum?

🟨 Comprobación del reto​

  • Las clases tienen responsabilidades claras.
  • Los atributos son private.
  • Los objetos se crean mediante constructores.
  • Se utilizan getters cuando es necesario.
  • Los métodos modifican el estado del objeto de forma controlada.
  • Existe al menos una relación entre objetos.
  • Se utiliza correctamente un enum.
  • Puedes explicar por qué cada método pertenece a su clase.

3️⃣ Reto 3 · Inventario de la tienda​

🟩 Objetivo​

Aplicar List, ArrayList, recorridos, búsquedas, modificaciones, eliminación y manejo básico de excepciones.

🟨 Contexto​

La tienda ya dispone de objetos Producto.

Ahora necesita gestionar un pequeño inventario en memoria.

Parte de una colección con varios productos diferentes.

Puedes utilizar datos similares a estos:

Teclado      35.00 €    stock 4
Ratón        18.00 €    stock 0
Monitor     160.00 €    stock 6
Webcam       55.00 €    stock 2
Auriculares  42.00 €    stock 8

No es obligatorio utilizar exactamente esos productos.

🟧 Nivel 1 · En marcha​

Crea una colección:

List<Producto> productos = new ArrayList<>();

Añade al menos cinco productos.

Después:

  • muestra todos los productos.
  • muestra cuántos productos hay.
  • busca un producto por nombre.
  • informa si el producto existe o no.

La búsqueda debe realizarse recorriendo la colección.

🟥 Nivel 2 · Conseguido​

Añade las siguientes operaciones:

  • eliminar un producto por nombre.
  • mostrar únicamente productos con stock.
  • contar cuántos productos están agotados.
  • calcular el valor total del inventario.
  • encontrar el producto más caro.

Para calcular el valor del inventario recuerda que cada producto aporta:

precio × stock

No se proporciona la firma exacta de los métodos.

Decide qué operaciones deberían tener su propio método.

tip

Antes de programar el producto más caro, piensa qué información necesitas conservar mientras recorres la lista.

🟪 Nivel 3 · Ampliado​

Añade varias operaciones nuevas.

Reposición de stock​

Busca un producto por nombre y aumenta su stock.

Si no existe, muestra un mensaje claro.

Actualización de precios​

Aumenta un 10 % el precio de todos los productos cuyo precio sea inferior a 50 €.

Informe del inventario​

Genera una salida similar a:

=== INFORME DE INVENTARIO ===

Productos registrados: 5
Productos agotados: 1
Productos con stock: 4
Producto más caro: Monitor
Valor total del almacén: 1.486,00 €

Control de errores​

Parte de un valor recibido como texto:

String cantidadTexto = "abc";

Intenta convertirlo mediante:

Integer.parseInt(cantidadTexto)

Controla el posible error con try y catch.

aviso

Las excepciones no sustituyen a las validaciones.

Utiliza if para situaciones previsibles, como comprobar si existe un producto o si queda stock. Reserva try/catch para operaciones que realmente puedan producir una excepción.

🟩 Comprobación del reto​

  • La colección almacena objetos Producto.
  • Se utiliza for-each cuando no es necesario trabajar con posiciones.
  • La búsqueda devuelve correctamente un producto o null.
  • Se comprueba null antes de utilizar el objeto.
  • Se pueden modificar objetos almacenados en la lista.
  • Se puede eliminar un producto.
  • Se realizan cálculos recorriendo la colección.
  • Se controla al menos una excepción sencilla.
  • Puedes explicar qué ocurre en cada recorrido.

4️⃣ Errores para investigar​

Antes de cerrar el repaso, analiza estos fragmentos.

No los ejecutes inmediatamente. Intenta predecir primero qué ocurrirá.

🟩 Caso 1​

String categoria = "INFORMATICA";

if (categoria == "INFORMATICA") {
    System.out.println("Producto informático");
}

¿Qué cambiarías y por qué?

🟨 Caso 2​

List<Producto> productos = new ArrayList<>();

productos.add(new Producto("Teclado", 30, 5));
productos.add(new Producto("Ratón", 20, 3));

for (int i = 0; i <= productos.size(); i++) {
    System.out.println(productos.get(i).getNombre());
}

El programa termina fallando.

Localiza el problema.

🟧 Caso 3​

Producto producto = buscarProducto(productos, "Monitor");

System.out.println(producto.getPrecio());

¿Qué puede ocurrir si no existe ningún producto llamado "Monitor"?

¿Cómo lo evitarías?

🟥 Caso 4​

Producto p1 = new Producto("Teclado", 30, 5);
Producto p2 = p1;

p2.setPrecio(20);

System.out.println(p1.getPrecio());

¿Qué valor se mostrará?

Intenta explicarlo antes de ejecutar el código.

Objetivo de estos casos

Programar no consiste únicamente en escribir código nuevo.

Saber leer código, anticipar su comportamiento y localizar errores será especialmente importante cuando empecemos a trabajar con aplicaciones Spring Boot más grandes.

6️5️⃣ Comprobación final del repaso​

Al terminar las tres sesiones, comprueba si puedes hacer estas tareas con una ayuda razonable de los apuntes:

  • crear variables y utilizar operadores.
  • escribir condiciones con if.
  • utilizar un switch moderno.
  • crear y llamar métodos.
  • trabajar con parámetros y return.
  • crear una clase desde cero.
  • crear objetos mediante new.
  • utilizar constructores y this.
  • trabajar con atributos private.
  • crear métodos de instancia.
  • relacionar objetos.
  • utilizar un enum.
  • crear una List.
  • recorrer objetos con for-each.
  • buscar y eliminar objetos.
  • modificar objetos almacenados en una colección.
  • comprobar correctamente un valor null.
  • utilizar try y catch en un caso sencillo.
Preparados para Spring Boot

No es necesario dominar Java a la perfección antes de continuar.

El objetivo es que estos conceptos vuelvan a resultar familiares y que podamos leer y escribir código sencillo sin detenernos continuamente en la sintaxis.

A partir de ahora empezaremos a añadir los elementos propios de Spring Boot, pero seguiremos trabajando sobre esta misma base: clases, objetos, métodos y colecciones.
