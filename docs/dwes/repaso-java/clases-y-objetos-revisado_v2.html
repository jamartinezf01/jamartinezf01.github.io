Clases y objetos

En la sesión anterior trabajamos con variables, estructuras de control y métodos. Ahora vamos a recuperar una de las ideas fundamentales de Java: la programación orientada a objetos.

En lugar de manejar datos sueltos, vamos a agrupar información y comportamiento dentro de clases que representen elementos de nuestra aplicación.

Seguiremos utilizando como contexto una tienda sencilla de productos.

Idea principal

En Spring Boot trabajaremos continuamente con clases y objetos.

Por eso, antes de introducir controladores, servicios o repositorios, necesitamos volver a sentirnos cómodos creando objetos, relacionándolos y entendiendo cómo se comportan.

1️⃣ De variables sueltas a una clase​

Imaginemos que queremos representar un producto.

Podríamos empezar así:

Datos de un producto mediante variables independientes
String nombre = "Teclado";
double precio = 29.95;
int stock = 12;
boolean disponible = true;

Esto funciona, pero todos los datos están separados.

Si tuviéramos muchos productos, acabaríamos manejando demasiadas variables independientes.

Una solución más natural es crear una clase:

Primera versión de la clase Producto
public class Producto {

    private String nombre;
    private double precio;
    private int stock;
    private boolean disponible;
}
en este ejemplo

Una clase sirve como plantilla para crear objetos.

En este caso, Producto describe qué información tendrá cualquier producto de nuestra aplicación.

Las variables declaradas dentro de la clase se llaman atributos.

🟩 Clase y objeto​

La clase es la definición:

Definición de una clase
public class Producto {
    private String nombre;
    private double precio;
}

El objeto es una instancia concreta creada a partir de esa clase.

Creación de un objeto
Producto producto1 = new Producto();

Podemos pensar en la clase como un molde y en el objeto como un elemento creado a partir de ese molde.

2️⃣ Atributos y encapsulación​

Los atributos representan el estado de un objeto.

Atributos privados de una clase
public class Producto {

    private String nombre;
    private double precio;
    private int stock;
}

En Java es habitual declarar los atributos como private.

Esto impide que puedan modificarse directamente desde cualquier parte del programa.

Idea principal

La encapsulación consiste en proteger el estado interno de un objeto y controlar cómo se accede a él.

Por ejemplo, evitaremos hacer algo como:

Acceso directo que queremos evitar
producto1.precio = -50;

En su lugar, utilizaremos métodos para consultar o modificar los datos.

3️⃣ Constructores​

Un constructor permite inicializar un objeto en el momento de crearlo.

Constructor de Producto
public class Producto {

    private String nombre;
    private double precio;
    private int stock;

    public Producto(String nombre, double precio, int stock) {
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
    }
}

Ahora podemos crear un producto así:

Crear un objeto utilizando el constructor
Producto producto1 = new Producto("Teclado", 29.95, 12);
en este ejemplo

El constructor tiene el mismo nombre que la clase y no declara ningún tipo de retorno.

Los valores recibidos como parámetros se utilizan para inicializar los atributos del objeto.

🟩 La palabra clave this​

Dentro del constructor aparece varias veces this.

Uso de this
this.nombre = nombre;

Aquí tenemos dos elementos con el mismo nombre:

  • this.nombre es el atributo del objeto.
  • nombre es el parámetro recibido por el constructor.

this hace referencia al objeto actual.

tip

Cuando un parámetro tiene el mismo nombre que un atributo, this permite distinguir claramente entre ambos.

4️⃣ Getters y setters​

Como los atributos son private, necesitamos métodos para acceder a ellos.

🟩 Getters​

Un getter devuelve el valor de un atributo.

Getter de nombre
public String getNombre() {
    return nombre;
}

Podemos utilizarlo así:

Uso de un getter
System.out.println(producto1.getNombre());

🟨 Setters​

Un setter permite modificar un atributo.

Setter de precio
public void setPrecio(double precio) {
    this.precio = precio;
}

Uso:

Uso de un setter
producto1.setPrecio(24.95);
aviso

No todos los atributos tienen que tener necesariamente setter.

Si un dato no debería modificarse libremente, puede ser preferible no proporcionar un método para cambiarlo.

🟧 Validar antes de modificar​

Un setter puede incluir una validación sencilla:

Setter con validación
public void setPrecio(double precio) {
    if (precio >= 0) {
        this.precio = precio;
    }
}

Así evitamos asignar precios negativos.

Idea principal

Los métodos de acceso no solo sirven para leer o escribir datos.

También permiten controlar qué valores son válidos para el objeto.

5️⃣ Métodos de instancia​

Una clase no solo contiene datos. También puede contener comportamiento.

Podemos añadir un método para comprobar si un producto tiene stock:

Método de instancia para comprobar el stock
public boolean hayStock() {
    return stock > 0;
}

O un método para calcular el valor total del stock:

Método de instancia para calcular el valor del stock
public double getValorStock() {
    return precio * stock;
}
en este ejemplo

Estos métodos trabajan con los atributos del propio objeto.

No necesitan recibir precio o stock como parámetros porque esos datos ya forman parte del estado del objeto.

🟩 Diferencia con los métodos static​

En la sesión anterior utilizamos métodos como:

Método static
public static boolean hayStock(int stock)

Ahora podemos trasladar esa lógica al propio objeto:

Método de instancia equivalente
public boolean hayStock() {
    return stock > 0;
}

La llamada también cambia.

Antes:

Llamada a un método static
hayStock(12);

Ahora:

Llamada a un método de instancia
producto1.hayStock();

Esta segunda forma encaja mejor con la programación orientada a objetos.

6️⃣ Una clase Producto más completa​

Vamos a reunir varias de las ideas anteriores.

Clase Producto con estado y comportamiento
public class Producto {

    private String nombre;
    private double precio;
    private int stock;

    public Producto(String nombre, double precio, int stock) {
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }

    public int getStock() {
        return stock;
    }

    public void setPrecio(double precio) {
        if (precio >= 0) {
            this.precio = precio;
        }
    }

    public boolean hayStock() {
        return stock > 0;
    }

    public double getValorStock() {
        return precio * stock;
    }

    public void venderUnidad() {
        if (hayStock()) {
            stock--;
        }
    }

    public void reponerStock(int cantidad) {
        if (cantidad > 0) {
            stock += cantidad;
        }
    }
}
en este ejemplo

La clase Producto agrupa datos y comportamiento.

Los atributos describen el estado del producto.

El constructor inicializa el objeto.

Los getters permiten consultar datos.

El setter controla que el precio no sea negativo.

Los métodos hayStock(), getValorStock(), venderUnidad() y reponerStock() representan operaciones propias del producto.

7️⃣ Crear y utilizar objetos​

Podemos crear varios objetos a partir de la misma clase.

Crear varios objetos Producto
Producto producto1 = new Producto("Teclado", 29.95, 12);
Producto producto2 = new Producto("Ratón", 19.90, 8);

Cada objeto mantiene su propio estado.

Modificar el estado de un objeto
producto1.venderUnidad();
producto1.venderUnidad();

System.out.println(producto1.getStock());
System.out.println(producto2.getStock());

El primer producto tendrá 10 unidades y el segundo seguirá teniendo 8.

Idea principal

Dos objetos creados a partir de la misma clase comparten estructura y comportamiento, pero cada uno mantiene sus propios datos.

8️⃣ Referencias a objetos​

Cuando trabajamos con objetos, las variables no contienen una copia completa del objeto. Contienen una referencia a ese objeto.

Observa este ejemplo:

Dos variables que apuntan al mismo objeto
Producto p1 = new Producto("Teclado", 30, 5);
Producto p2 = p1;

p2.setPrecio(20);

System.out.println(p1.getPrecio());

El resultado será:

Resultado
20.0
en este ejemplo

p1 y p2 hacen referencia al mismo objeto.

La instrucción:

Asignación de una referencia
Producto p2 = p1;

no crea un producto nuevo.

Solo crea una segunda variable que apunta al mismo objeto.

🟩 Crear un objeto diferente​

Si queremos dos objetos independientes, debemos crear dos instancias:

Dos objetos independientes
Producto p1 = new Producto("Teclado", 30, 5);
Producto p2 = new Producto("Teclado", 30, 5);

Aunque tengan los mismos valores, son dos objetos distintos.

aviso

Esta diferencia será importante cuando trabajemos con colecciones.

Una lista almacena referencias a objetos, por lo que modificar un objeto recuperado de una lista modifica ese mismo objeto.

9️⃣ Relaciones entre objetos​

En una aplicación real, los objetos no suelen estar aislados.

Por ejemplo, un producto puede pertenecer a una categoría.

Podemos crear una clase Categoria:

Clase Categoria
public class Categoria {

    private String nombre;

    public Categoria(String nombre) {
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }
}

Después podemos relacionarla con Producto:

Producto relacionado con Categoria
public class Producto {

    private String nombre;
    private double precio;
    private int stock;
    private Categoria categoria;

    public Producto(
            String nombre,
            double precio,
            int stock,
            Categoria categoria) {

        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
        this.categoria = categoria;
    }

    public Categoria getCategoria() {
        return categoria;
    }
}

Podemos utilizarlo así:

Crear objetos relacionados
Categoria informatica = new Categoria("Informática");

Producto teclado = new Producto(
        "Teclado",
        29.95,
        12,
        informatica
);

Y consultar:

Acceder a un objeto relacionado
System.out.println(teclado.getCategoria().getNombre());
en este ejemplo

Producto no guarda únicamente el nombre de la categoría.

Guarda una referencia a un objeto completo de tipo Categoria.

Esto permite representar relaciones entre elementos de nuestra aplicación.

tip

Esta idea será muy importante más adelante.

En aplicaciones Spring Boot será habitual que unas clases trabajen con objetos de otras clases.

🔟 Enumeraciones con enum​

Cuando un valor solo puede pertenecer a un conjunto cerrado de opciones, podemos utilizar un enum.

Por ejemplo, podemos representar el estado de un producto:

Enumeración EstadoProducto
public enum EstadoProducto {
    NUEVO,
    OFERTA,
    AGOTADO
}

Después añadimos ese tipo a nuestra clase:

Uso de un enum como atributo
public class Producto {

    private String nombre;
    private EstadoProducto estado;

    public Producto(String nombre, EstadoProducto estado) {
        this.nombre = nombre;
        this.estado = estado;
    }
}

Y creamos un objeto así:

Crear un producto con un valor del enum
Producto producto = new Producto(
        "Teclado",
        EstadoProducto.OFERTA
);
en este ejemplo

Con enum evitamos escribir valores arbitrarios como "oferta", "OFERTA" o "rebajado".

El programa solo permite utilizar los valores definidos en EstadoProducto.

🟩 switch con enum​

Los enum funcionan muy bien junto con el switch moderno.

switch con un enum
switch (producto.getEstado()) {
    case NUEVO -> System.out.println("Producto nuevo");
    case OFERTA -> System.out.println("Producto con descuento");
    case AGOTADO -> System.out.println("Producto sin stock");
}

1️⃣1️⃣ Herencia​

Hasta ahora todas nuestras clases eran independientes. Sin embargo, a veces varias clases representan elementos relacionados y comparten parte de sus datos o comportamiento.

Imaginemos que en la tienda tenemos productos físicos y productos digitales.

Ambos comparten:

  • un nombre.
  • un precio.
  • operaciones para consultar esos datos.

Podemos representar esas características comunes en una clase base:

Clase base Producto
public class Producto {

    private String nombre;
    private double precio;

    public Producto(String nombre, double precio) {
        this.nombre = nombre;
        this.precio = precio;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }
}

Después podemos crear una clase más específica:

ProductoDigital hereda de Producto
public class ProductoDigital extends Producto {

    private double tamanoMb;

    public ProductoDigital(
            String nombre,
            double precio,
            double tamanoMb) {

        super(nombre, precio);
        this.tamanoMb = tamanoMb;
    }

    public double getTamanoMb() {
        return tamanoMb;
    }
}
en este ejemplo

extends Producto indica que ProductoDigital hereda de Producto.

Esto significa que un ProductoDigital dispone también de los atributos y métodos accesibles definidos en la clase padre.

super(nombre, precio) llama al constructor de Producto para inicializar la parte heredada del objeto.

🟩 Clase padre y clase hija​

En este ejemplo:

Relación de herencia
Producto
   ↑
ProductoDigital

Producto es la clase padre o clase base.

ProductoDigital es la clase hija o subclase.

La herencia expresa una relación de tipo:

Lectura conceptual
ProductoDigital es un Producto
aviso

No utilizaremos herencia simplemente para reutilizar código.

Debe existir una relación conceptual clara entre la clase general y la clase especializada.

1️⃣2️⃣ Sobrescribir métodos con @Override​

Una clase hija puede necesitar un comportamiento diferente al definido en la clase padre.

Podemos añadir a Producto:

Método definido en la clase padre
public double calcularPrecioFinal() {
    return precio;
}

y modificar su comportamiento en ProductoDigital:

Método sobrescrito en ProductoDigital
@Override
public double calcularPrecioFinal() {
    return getPrecio() * 0.95;
}
en este ejemplo

Sobrescribir un método significa proporcionar en la clase hija una nueva implementación de un método heredado.

@Override indica que el método sustituye una implementación definida previamente en una clase padre o en una interfaz.

Además de documentar la intención, permite que el compilador detecte algunos errores si la firma del método no coincide.

1️⃣3️⃣ Clases abstractas​

A veces una clase representa una idea general que resulta útil para compartir estructura y comportamiento, pero no tiene sentido crear objetos directamente de ella.

En ese caso podemos declarar una clase como abstract.

Clase abstracta Producto
public abstract class Producto {

    private String nombre;
    private double precio;

    public Producto(String nombre, double precio) {
        this.nombre = nombre;
        this.precio = precio;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }

    public abstract double calcularPrecioFinal();
}

Ahora no podemos hacer:

Código no permitido con una clase abstracta
// No se puede instanciar directamente una clase abstracta
Producto producto = new Producto("Teclado", 30);

Necesitamos crear objetos de una clase concreta que herede de ella.

Por ejemplo:

Clase concreta ProductoFisico
public class ProductoFisico extends Producto {

    public ProductoFisico(String nombre, double precio) {
        super(nombre, precio);
    }

    @Override
    public double calcularPrecioFinal() {
        return getPrecio() + 4.95;
    }
}

Y:

Clase concreta ProductoDigital
public class ProductoDigital extends Producto {

    public ProductoDigital(String nombre, double precio) {
        super(nombre, precio);
    }

    @Override
    public double calcularPrecioFinal() {
        return getPrecio();
    }
}
Idea principal

Una clase abstracta puede contener:

  • atributos.
  • constructor.
  • métodos ya implementados.
  • métodos abstractos que las clases hijas deberán implementar.

🟩 Métodos abstractos​

Este método:

Método abstracto
public abstract double calcularPrecioFinal();

no contiene una implementación.

La clase abstracta establece que cualquier subclase concreta deberá proporcionar ese comportamiento.

aviso

Una clase abstracta no significa que todos sus métodos tengan que ser abstractos.

Puede combinar comportamiento ya implementado con operaciones que deberán concretar las clases hijas.

1️⃣4️⃣ Polimorfismo​

La herencia nos permite tratar objetos de distintas clases concretas utilizando como referencia un tipo común.

Por ejemplo:

Referencias del tipo de la clase padre
Producto producto1 =
        new ProductoFisico("Teclado", 30);

Producto producto2 =
        new ProductoDigital("Curso Java", 15);

Las dos variables tienen tipo Producto, pero hacen referencia a objetos diferentes.

Podemos llamar al mismo método:

Llamadas polimórficas
System.out.println(producto1.calcularPrecioFinal());
System.out.println(producto2.calcularPrecioFinal());

En cada caso se ejecutará la implementación correspondiente al objeto real.

Idea principal

El polimorfismo permite utilizar una referencia de un tipo general para trabajar con objetos de distintos tipos concretos.

Al llamar a un método sobrescrito, Java ejecuta la versión correspondiente al objeto real.

Esto resulta especialmente útil cuando trabajamos con varios objetos relacionados:

Colección de objetos de distintos tipos
List<Producto> productos = List.of(
        new ProductoFisico("Teclado", 30),
        new ProductoDigital("Curso Java", 15),
        new ProductoFisico("Ratón", 20)
);

Podemos recorrerlos sin preguntar primero qué clase concreta tiene cada uno:

Uso polimórfico de una colección
for (Producto producto : productos) {
    System.out.println(producto.getNombre());
    System.out.println(producto.calcularPrecioFinal());
}
en este ejemplo

Todos los objetos pueden almacenarse en una colección de tipo Producto porque ProductoFisico y ProductoDigital son subclases de Producto.

La llamada a calcularPrecioFinal() utiliza la implementación adecuada para cada objeto.

Esta idea será útil cuando necesitemos procesar distintos tipos de objetos mediante una misma estructura.

1️⃣5️⃣ Interfaces​

Una interfaz permite definir un conjunto de operaciones que una clase se compromete a proporcionar.

Podemos crear una interfaz muy sencilla:

Interfaz Vendible
public interface Vendible {

    boolean hayStock();

    double getPrecio();
}

Después podemos indicar que una clase implementa esa interfaz:

Producto implementa Vendible
public class Producto implements Vendible {

    private String nombre;
    private double precio;
    private int stock;

    public Producto(String nombre, double precio, int stock) {
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
    }

    @Override
    public boolean hayStock() {
        return stock > 0;
    }

    @Override
    public double getPrecio() {
        return precio;
    }
}
en este ejemplo

La interfaz Vendible indica qué operaciones debe proporcionar cualquier clase que la implemente.

Producto se compromete a tener los métodos hayStock() y getPrecio().

La anotación @Override indica que ese método está implementando una operación definida previamente en la interfaz.

🟩 Clase abstracta e interfaz no son lo mismo​

En este repaso solo necesitamos distinguir la idea principal:

Clase abstractaInterfaz
Puede compartir atributos, constructor y comportamiento común.Define principalmente qué operaciones debe proporcionar una clase.
Se utiliza con extends.Se utiliza con implements.
Una clase solo puede extender una clase.Una clase puede implementar varias interfaces.

No necesitamos profundizar ahora en todas las posibilidades de ambos mecanismos.

Para quedarnos con la idea

Utilizaremos una clase abstracta cuando queramos representar una familia de objetos que comparten estructura y parte de su comportamiento.

Utilizaremos una interfaz cuando queramos expresar principalmente un conjunto de operaciones que distintas clases pueden ofrecer.

1️⃣6️⃣ Mostrar un objeto con toString()​

Si hacemos:

Mostrar un objeto
System.out.println(producto);

Java necesita decidir cómo representar ese objeto como texto.

Podemos personalizar esa representación sobrescribiendo toString():

Sobrescribir toString()
@Override
public String toString() {
    return nombre + " - " + precio + " € - Stock: " + stock;
}

Ahora:

Uso de toString()
System.out.println(producto);

podría mostrar:

Resultado
Teclado - 29.95 € - Stock: 12
tip

toString() resulta especialmente útil para comprobar rápidamente el contenido de un objeto mientras programamos o depuramos.

Antes de terminar esta sesión, conviene tener claras estas ideas:

  • una clase define la estructura y comportamiento de un tipo de objeto.
  • un objeto es una instancia concreta de una clase.
  • los atributos representan su estado.
  • un constructor inicializa el objeto.
  • this hace referencia al objeto actual.
  • los getters y setters permiten controlar el acceso a los atributos.
  • los métodos de instancia trabajan con el estado del objeto.
  • dos variables pueden hacer referencia al mismo objeto.
  • una clase puede contener objetos de otras clases.
  • enum permite representar conjuntos cerrados de valores.
  • extends permite crear una clase más específica a partir de otra.
  • super(...) permite inicializar la parte heredada del objeto.
  • @Override indica que estamos sobrescribiendo o implementando un método.
  • una clase abstracta no puede instanciarse directamente.
  • un método abstracto debe ser implementado por las subclases concretas.
  • el polimorfismo permite trabajar con distintos objetos mediante un tipo común.
  • una interfaz define operaciones que una clase puede implementar.
  • una clase abstracta y una interfaz tienen objetivos relacionados, pero no son equivalentes.
  • toString() permite obtener una representación textual útil de un objeto.
