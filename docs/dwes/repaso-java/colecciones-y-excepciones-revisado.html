Colecciones y excepciones

Hasta ahora hemos trabajado con objetos individuales. En una aplicación real necesitaremos manejar grupos de objetos: varios productos, varios pedidos, varios clientes...

Para ello Java proporciona colecciones.

En esta última sesión del repaso recuperaremos especialmente List, ArrayList, Map y HashMap, junto con algunas operaciones habituales sobre ellas. También recordaremos cómo manejar errores mediante excepciones.

Idea principal

Una colección permite trabajar con varios objetos de forma organizada.

No todas las colecciones sirven para lo mismo: algunas mantienen una secuencia de elementos y otras permiten localizar un valor mediante una clave.

1️⃣ ¿Qué es una colección?​

Imaginemos que tenemos varios productos:

Producto teclado = new Producto("Teclado", 29.95, 10);
Producto raton = new Producto("Ratón", 19.90, 8);
Producto monitor = new Producto("Monitor", 149.90, 4);

Podríamos trabajar con cada variable por separado, pero esto deja de ser práctico cuando el número de productos aumenta.

Una colección nos permite agruparlos.

Por ejemplo:

List<Producto> productos = new ArrayList<>();

Ahora todos los productos pueden almacenarse en una única estructura.

🟩 Algunas estructuras habituales​

Java dispone de diferentes tipos de colecciones.

EstructuraIdea principalEjemplo de uso
ListColección ordenada que puede contener elementos repetidosLista de productos
SetColección sin elementos duplicadosConjunto de códigos únicos
MapRelaciona una clave con un valorCódigo de producto → Producto

En este repaso nos centraremos en List y Map.

nota

Set también forma parte del framework de colecciones de Java, pero no profundizaremos en él ahora porque no es imprescindible para comenzar con Spring Boot.

2️⃣ Genéricos: qué significa <Producto>​

En expresiones como:

List<Producto>

o:

Map<String, Producto>

aparece una sintaxis entre < >.

Indica qué tipo de datos puede contener la estructura.

List<Producto> productos;

significa:

esta lista almacenará objetos de tipo Producto.

Y:

Map<String, Producto> productosPorCodigo;

significa:

las claves serán String y los valores serán objetos Producto.

Idea principal

Los genéricos permiten indicar qué tipo de objetos manejará una colección.

No necesitamos profundizar en genéricos ahora. Basta con entender qué significa el tipo escrito entre < >.

3️⃣ List y ArrayList​

List representa una colección ordenada.

Una de sus implementaciones más habituales es ArrayList.

import java.util.ArrayList;
import java.util.List;

List<Producto> productos = new ArrayList<>();
en este ejemplo

List es una interfaz.

ArrayList es una clase que implementa esa interfaz.

Esta forma de declarar la variable nos permite trabajar con las operaciones definidas por List sin depender directamente de una implementación concreta.

Esta idea enlaza con lo visto en la sesión anterior sobre interfaces:

List
  ↑
ArrayList

No necesitamos profundizar más por ahora.

4️⃣ Operaciones básicas con una lista​

🟩 Añadir elementos​

Utilizamos add():

productos.add(teclado);
productos.add(raton);
productos.add(monitor);

También podemos crear el objeto directamente:

productos.add(
    new Producto("Auriculares", 39.95, 6)
);

🟨 Consultar el tamaño​

System.out.println(productos.size());

Si hay cuatro productos, el resultado será:

4

🟧 Acceder a una posición​

Las posiciones comienzan en 0.

Producto primero = productos.get(0);

Podemos utilizar directamente el objeto:

System.out.println(productos.get(0).getNombre());
aviso

Si intentamos acceder a una posición que no existe, Java lanzará una excepción.

Si una lista contiene tres elementos, las posiciones válidas son 0, 1 y 2.

🟥 Comprobar si está vacía​

if (productos.isEmpty()) {
    System.out.println("No hay productos");
}

🟪 Eliminar elementos​

Podemos eliminar un objeto:

productos.remove(teclado);

o una posición:

productos.remove(0);

Conviene fijarse en la diferencia: en un caso eliminamos un objeto y en el otro una posición.

5️⃣ Recorrer una lista​

Una de las operaciones más frecuentes consiste en recorrer sus elementos.

🟩 for-each​

Para trabajar con objetos, suele ser la opción más clara:

for (Producto producto : productos) {
    System.out.println(producto.getNombre());
}
en este ejemplo

En cada vuelta del bucle, producto hace referencia a uno de los objetos almacenados en la lista.

Podemos mostrar varios datos:

for (Producto producto : productos) {
    System.out.println(
        producto.getNombre()
        + " - "
        + producto.getPrecio()
        + " €"
    );
}

🟨 for tradicional​

Si necesitamos trabajar con posiciones:

for (int i = 0; i < productos.size(); i++) {
    Producto producto = productos.get(i);
    System.out.println(i + " - " + producto.getNombre());
}
tip

Si no necesitas conocer la posición, for-each suele ser más sencillo de leer.

6️⃣ Buscar un objeto en una lista​

Podemos recorrer la colección hasta encontrar el objeto que necesitamos.

public static Producto buscarProducto(
        List<Producto> productos,
        String nombre) {

    for (Producto producto : productos) {
        if (producto.getNombre().equalsIgnoreCase(nombre)) {
            return producto;
        }
    }

    return null;
}

Podemos utilizarlo así:

Producto encontrado =
        buscarProducto(productos, "Teclado");

if (encontrado != null) {
    System.out.println(encontrado.getPrecio());
} else {
    System.out.println("Producto no encontrado");
}
en este ejemplo

El método recorre la lista.

Si encuentra un producto cuyo nombre coincide, devuelve ese objeto.

Si termina sin encontrarlo, devuelve null.

aviso

null significa ausencia de objeto.

Antes de llamar a métodos sobre una variable que puede contener null, debemos comprobar su valor.

7️⃣ Modificar objetos almacenados en una lista​

Una lista almacena referencias a objetos.

Por eso, si recuperamos un producto y lo modificamos, el cambio afecta al mismo objeto almacenado en la colección.

Producto producto =
        buscarProducto(productos, "Teclado");

if (producto != null) {
    producto.setPrecio(24.95);
}

No necesitamos volver a añadirlo.

Idea principal

La lista no contiene copias independientes de los objetos.

Contiene referencias a esos objetos.

Esto conecta directamente con lo visto en la sesión anterior sobre referencias.

8️⃣ Filtrar y calcular mientras recorremos​

Recorrer una lista no sirve únicamente para mostrar datos.

También podemos seleccionar elementos o realizar cálculos.

🟩 Productos con stock​

for (Producto producto : productos) {
    if (producto.hayStock()) {
        System.out.println(producto.getNombre());
    }
}

🟨 Contar productos agotados​

int agotados = 0;

for (Producto producto : productos) {
    if (!producto.hayStock()) {
        agotados++;
    }
}

🟧 Acumular el valor del almacén​

double valorTotal = 0;

for (Producto producto : productos) {
    valorTotal += producto.getPrecio() * producto.getStock();
}
en este ejemplo

En estos ejemplos aparecen dos patrones muy habituales:

  • contador: aumenta una cantidad cuando se cumple una condición;
  • acumulador: va sumando resultados durante el recorrido.

Estos patrones volverán a aparecer muchas veces en programación.

9️⃣ Map: trabajar con claves y valores​

Una List resulta adecuada cuando queremos mantener una colección y recorrerla.

Pero a veces conocemos una clave que identifica directamente un objeto.

Por ejemplo:

P001 → Teclado
P002 → Ratón
P003 → Monitor

En estos casos podemos utilizar un Map.

import java.util.HashMap;
import java.util.Map;

Map<String, Producto> productosPorCodigo =
        new HashMap<>();
en este ejemplo

En:

Map<String, Producto>

la clave es un String y el valor asociado es un Producto.

HashMap es una implementación habitual de la interfaz Map.

🔟 Operaciones básicas con Map​

🟩 Añadir elementos con put()​

productosPorCodigo.put("P001", teclado);
productosPorCodigo.put("P002", raton);
productosPorCodigo.put("P003", monitor);

Cada clave está asociada a un valor.

aviso

Las claves de un Map no se repiten.

Si utilizamos otra vez una clave existente con put(), el nuevo valor sustituirá al anterior.

🟨 Recuperar un valor con get()​

Producto producto =
        productosPorCodigo.get("P001");

Si la clave existe, obtenemos el producto asociado.

Si no existe:

Producto producto =
        productosPorCodigo.get("P999");

el resultado será null.

🟧 Comprobar una clave con containsKey()​

if (productosPorCodigo.containsKey("P001")) {
    System.out.println("El producto existe");
}

🟥 Eliminar una entrada​

productosPorCodigo.remove("P002");

🟪 Consultar el tamaño​

System.out.println(productosPorCodigo.size());

1️⃣1️⃣ Recorrer un Map​

Si necesitamos recorrer tanto claves como valores, podemos utilizar entrySet().

for (Map.Entry<String, Producto> entrada
        : productosPorCodigo.entrySet()) {

    String codigo = entrada.getKey();
    Producto producto = entrada.getValue();

    System.out.println(
        codigo + " - " + producto.getNombre()
    );
}
en este ejemplo

Cada entrada contiene:

  • una clave, accesible con getKey();
  • un valor, accesible con getValue().

En este ejemplo la clave es el código y el valor es un objeto Producto.

Si solo necesitamos los productos:

for (Producto producto : productosPorCodigo.values()) {
    System.out.println(producto.getNombre());
}

Y si solo necesitamos los códigos:

for (String codigo : productosPorCodigo.keySet()) {
    System.out.println(codigo);
}

1️⃣2️⃣ ¿List o Map?​

No existe una estructura mejor para todos los casos.

🟩 Utilizar List​

Tiene sentido cuando:

  • queremos mantener una secuencia de elementos;
  • necesitamos recorrer todos los objetos;
  • trabajamos con posiciones;
  • pueden existir elementos repetidos.

Ejemplo:

List<Producto> productos;

🟨 Utilizar Map​

Tiene sentido cuando:

  • cada elemento tiene una clave identificativa;
  • conocemos esa clave;
  • queremos asociar directamente una clave con un objeto.

Ejemplo:

Map<String, Producto> productosPorCodigo;
Idea principal

Una List organiza elementos como una secuencia.

Un Map organiza asociaciones clave → valor.

1️⃣3️⃣ Excepciones: cuando algo sale mal​

Durante la ejecución de un programa pueden producirse situaciones que Java representa mediante excepciones.

Por ejemplo:

int cantidad = Integer.parseInt("cinco");

No es posible convertir "cinco" en un entero.

Java lanzará una NumberFormatException.

Idea principal

Una excepción representa una situación anómala que ocurre durante la ejecución del programa.

1️⃣4️⃣ Capturar una excepción con try y catch​

Podemos controlar el problema anterior:

try {
    int cantidad = Integer.parseInt("cinco");
    System.out.println(cantidad);
} catch (NumberFormatException e) {
    System.out.println("La cantidad debe ser un número");
}
en este ejemplo

El bloque try contiene código que puede producir una excepción.

Si aparece una NumberFormatException, Java interrumpe ese bloque y ejecuta el catch correspondiente.

🟩 Un ejemplo válido​

String cantidadTexto = "5";

try {
    int cantidad = Integer.parseInt(cantidadTexto);

    System.out.println(
        "Cantidad recibida: " + cantidad
    );
} catch (NumberFormatException e) {
    System.out.println("Cantidad no válida");
}

1️⃣5️⃣ No utilizar excepciones para todo​

Las excepciones no sustituyen a las condiciones normales.

Por ejemplo:

if (producto.getStock() > 0) {
    producto.venderUnidad();
}

Aquí sabemos perfectamente qué condición debemos comprobar.

No tendría sentido provocar un error para capturarlo después.

aviso

Utiliza condiciones para situaciones previsibles.

Utiliza excepciones para situaciones excepcionales que puedan ocurrir durante la ejecución.

1️⃣6️⃣ Lanzar una excepción de forma sencilla​

En ocasiones nuestro propio código puede detectar un valor que no debería aceptarse.

Por ejemplo:

public void reponerStock(int cantidad) {

    if (cantidad <= 0) {
        throw new IllegalArgumentException(
            "La cantidad debe ser positiva"
        );
    }

    stock += cantidad;
}
en este ejemplo

throw permite lanzar una excepción.

En este ejemplo se utiliza IllegalArgumentException porque el método ha recibido un argumento que no cumple las condiciones esperadas.

No necesitamos profundizar ahora en tipos de excepciones ni crear excepciones propias.

nota

Más adelante veremos estrategias más completas para gestionar errores en aplicaciones Spring Boot.

Por ahora basta con recordar las ideas básicas de try, catch y throw.

1️⃣7️⃣ Ejemplo integrador​

Vamos a combinar una lista y un mapa.

List<Producto> productos = new ArrayList<>();

productos.add(new Producto("Teclado", 35, 4));
productos.add(new Producto("Ratón", 18, 0));
productos.add(new Producto("Monitor", 160, 6));

Map<String, Producto> productosPorCodigo =
        new HashMap<>();

productosPorCodigo.put("P001", productos.get(0));
productosPorCodigo.put("P002", productos.get(1));
productosPorCodigo.put("P003", productos.get(2));

Ahora podemos recorrer todos los productos:

for (Producto producto : productos) {
    System.out.println(producto);
}

Y recuperar directamente uno por código:

Producto producto =
        productosPorCodigo.get("P003");

if (producto != null) {
    System.out.println(
        "Encontrado: " + producto.getNombre()
    );
}
en este ejemplo

La List resulta cómoda para trabajar con todos los productos.

El Map resulta útil cuando conocemos el código de un producto y queremos localizarlo mediante esa clave.

Ambas estructuras pueden contener referencias a los mismos objetos.

1️⃣8️⃣ Práctica guiada​

🟩 Paso 1. Crear una lista​

Crea una List<Producto> con al menos cinco productos.

Muestra:

  • nombre;
  • precio;
  • stock.

🟨 Paso 2. Obtener información​

Recorre la lista y calcula:

  • número de productos agotados;
  • valor total del stock.

🟧 Paso 3. Buscar un producto​

Crea una búsqueda por nombre.

Si el producto no existe, muestra un mensaje adecuado.

🟥 Paso 4. Crear un mapa por código​

Crea:

Map<String, Producto> productosPorCodigo =
        new HashMap<>();

Asocia códigos como:

P001
P002
P003

a distintos productos.

🟪 Paso 5. Consultar el mapa​

Recupera un producto mediante su código.

Prueba también con un código inexistente.

🟩 Paso 6. Recorrer claves y valores​

Utiliza entrySet() para mostrar:

P001 - Teclado
P002 - Ratón
P003 - Monitor

🟨 Paso 7. Controlar una conversión incorrecta​

Parte de:

String cantidadTexto = "cinco";

Intenta convertirla a int y controla el error mediante try y catch.

1️⃣9️⃣ Qué debes recordar​

Al terminar esta sesión conviene tener claras estas ideas:

  • una colección permite almacenar varios objetos;
  • List representa una secuencia ordenada;
  • ArrayList es una implementación de List;
  • <Producto> indica el tipo de objetos que maneja la colección;
  • add(), get(), remove(), size() e isEmpty() son operaciones habituales;
  • for-each permite recorrer colecciones;
  • una lista almacena referencias a objetos;
  • los contadores y acumuladores permiten obtener información durante un recorrido;
  • Map almacena asociaciones clave-valor;
  • HashMap es una implementación habitual de Map;
  • put(), get(), containsKey() y remove() son operaciones básicas de un mapa;
  • entrySet() permite recorrer claves y valores;
  • null representa ausencia de objeto;
  • try y catch permiten capturar excepciones;
  • throw permite lanzar una excepción cuando detectamos una situación incorrecta.
