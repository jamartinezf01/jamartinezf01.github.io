Clases y objetos

En la sesión anterior trabajamos con variables y métodos de forma independiente. Ahora vamos a recuperar una de las ideas más importantes de Java: la programación orientada a objetos.

En lugar de manejar datos sueltos, vamos a agrupar información y comportamiento dentro de clases que representen elementos reales de nuestra aplicación.

Seguiremos utilizando como hilo conductor una tienda sencilla de productos.

Idea principal

En Spring Boot trabajaremos continuamente con clases y objetos.

Por eso, antes de introducir controladores, servicios o repositorios, necesitamos volver a sentirnos cómodos creando clases, instanciando objetos y relacionándolos entre sí.

1️⃣ De variables sueltas a una clase​

Imaginemos que queremos representar un producto.

Podríamos empezar así:

String nombre = "Teclado";
double precio = 29.95;
int stock = 12;
boolean disponible = true;

Esto funciona, pero tiene un problema: todos esos datos están separados.

Si tuviéramos muchos productos, acabaríamos manejando demasiadas variables independientes.

Una solución más natural es crear una clase.

public class Producto {

    private String nombre;
    private double precio;
    private int stock;
    private boolean disponible;
}
en este ejemplo

Una clase sirve como plantilla para crear objetos.

En este caso, Producto describe qué información tendrá cualquier producto de nuestra aplicación.

Las variables declaradas dentro de la clase se llaman atributos.

🟩 Clase y objeto​

La clase es la definición:

public class Producto {
    private String nombre;
    private double precio;
}

El objeto es una instancia concreta creada a partir de esa clase.

Producto producto1 = new Producto();

Podemos pensar en la clase como un molde y en el objeto como un elemento creado a partir de ese molde.

2️⃣ Atributos y encapsulación​

Los atributos representan el estado de un objeto.

public class Producto {

    private String nombre;
    private double precio;
    private int stock;
}

En Java es habitual declarar los atributos como private.

Esto impide que puedan modificarse directamente desde cualquier parte del programa.

Idea principal

La encapsulación consiste en proteger el estado interno de un objeto y controlar cómo se accede a él.

Por ejemplo, evitaremos hacer algo como:

producto1.precio = -50;

En su lugar, utilizaremos métodos para consultar o modificar los datos.

3️⃣ Constructores​

Un constructor permite inicializar un objeto en el momento de crearlo.

public class Producto {

    private String nombre;
    private double precio;
    private int stock;

    public Producto(String nombre, double precio, int stock) {
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
    }
}

Ahora podemos crear un producto así:

Producto producto1 = new Producto("Teclado", 29.95, 12);
en este ejemplo

El constructor tiene el mismo nombre que la clase y no declara ningún tipo de retorno.

Los valores recibidos como parámetros se utilizan para inicializar los atributos del objeto.

🟩 La palabra clave this​

Dentro del constructor aparece varias veces this.

this.nombre = nombre;

Aquí tenemos dos variables con el mismo nombre:

  • this.nombre es el atributo del objeto;
  • nombre es el parámetro recibido por el constructor.

this hace referencia al objeto actual.

tip

Cuando un parámetro tiene el mismo nombre que un atributo, this permite distinguir claramente entre ambos.

4️⃣ Getters y setters​

Como los atributos son private, necesitamos métodos para acceder a ellos.

🟩 Getters​

Un getter devuelve el valor de un atributo.

public String getNombre() {
    return nombre;
}

Podemos utilizarlo así:

System.out.println(producto1.getNombre());

🟨 Setters​

Un setter permite modificar un atributo.

public void setPrecio(double precio) {
    this.precio = precio;
}

Uso:

producto1.setPrecio(24.95);
aviso

No todos los atributos tienen que tener necesariamente setter.

Si un dato no debería modificarse libremente, puede ser preferible no proporcionar un método para cambiarlo.

🟧 Validar antes de modificar​

Un setter puede incluir una validación sencilla.

public void setPrecio(double precio) {
    if (precio >= 0) {
        this.precio = precio;
    }
}

Así evitamos asignar precios negativos.

Idea principal

Los métodos de acceso no solo sirven para leer o escribir datos.

También permiten controlar qué valores son válidos para el objeto.

5️⃣ Métodos de instancia​

Una clase no solo contiene datos. También puede contener comportamiento.

Podemos añadir un método para comprobar si un producto tiene stock:

public boolean hayStock() {
    return stock > 0;
}

O un método para calcular el valor total del stock:

public double getValorStock() {
    return precio * stock;
}
en este ejemplo

Estos métodos trabajan con los atributos del propio objeto.

No necesitan recibir precio o stock como parámetros porque esos datos ya forman parte del estado del objeto.

🟩 Diferencia con los métodos static​

En la sesión anterior utilizamos métodos como:

public static boolean hayStock(int stock)

Ahora podemos trasladar esa lógica al propio objeto:

public boolean hayStock() {
    return stock > 0;
}

La llamada también cambia.

Antes:

hayStock(12);

Ahora:

producto1.hayStock();

Esta segunda forma encaja mejor con la programación orientada a objetos.

6️⃣ Una clase Producto más completa​

Vamos a reunir varias de las ideas anteriores.

public class Producto {

    private String nombre;
    private double precio;
    private int stock;

    public Producto(String nombre, double precio, int stock) {
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }

    public int getStock() {
        return stock;
    }

    public void setPrecio(double precio) {
        if (precio >= 0) {
            this.precio = precio;
        }
    }

    public boolean hayStock() {
        return stock > 0;
    }

    public double getValorStock() {
        return precio * stock;
    }

    public void venderUnidad() {
        if (hayStock()) {
            stock--;
        }
    }
}
en este ejemplo

La clase Producto agrupa datos y comportamiento.

Los atributos describen el estado del producto.

El constructor inicializa el objeto.

Los getters permiten consultar datos.

El setter de precio controla que no se introduzcan valores negativos.

Los métodos hayStock(), getValorStock() y venderUnidad() representan operaciones propias del producto.

7️⃣ Crear y utilizar objetos​

Podemos crear varios objetos a partir de la misma clase.

Producto producto1 = new Producto("Teclado", 29.95, 12);
Producto producto2 = new Producto("Ratón", 19.90, 8);

Cada objeto mantiene su propio estado.

producto1.venderUnidad();
producto1.venderUnidad();

System.out.println(producto1.getStock());
System.out.println(producto2.getStock());

El primer producto tendrá 10 unidades y el segundo seguirá teniendo 8.

Idea principal

Dos objetos creados a partir de la misma clase comparten estructura y comportamiento, pero cada uno mantiene sus propios datos.

8️⃣ Relaciones entre objetos​

En una aplicación real, los objetos no suelen estar aislados.

Por ejemplo, un producto puede pertenecer a una categoría.

Primero podemos crear una clase Categoria:

public class Categoria {

    private String nombre;

    public Categoria(String nombre) {
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }
}

Después podemos relacionarla con Producto:

public class Producto {

    private String nombre;
    private double precio;
    private int stock;
    private Categoria categoria;

    public Producto(
            String nombre,
            double precio,
            int stock,
            Categoria categoria) {

        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
        this.categoria = categoria;
    }

    public Categoria getCategoria() {
        return categoria;
    }
}
en este ejemplo

Producto no guarda únicamente el nombre de la categoría.

Guarda una referencia a un objeto completo de tipo Categoria.

Esto permite representar relaciones entre elementos de nuestra aplicación.

Podemos utilizarlo así:

Categoria informatica = new Categoria("Informática");

Producto teclado = new Producto(
        "Teclado",
        29.95,
        12,
        informatica
);

Y consultar:

System.out.println(teclado.getCategoria().getNombre());
tip

Esta idea será muy importante más adelante.

En aplicaciones Spring Boot será habitual que unas clases trabajen con objetos de otras clases.

9️⃣ Enumeraciones con enum​

Cuando un valor solo puede pertenecer a un conjunto cerrado de opciones, podemos utilizar un enum.

Por ejemplo, podemos representar el estado de un producto:

public enum EstadoProducto {
    NUEVO,
    OFERTA,
    AGOTADO
}

Después añadimos ese tipo a nuestra clase:

public class Producto {

    private String nombre;
    private EstadoProducto estado;

    public Producto(String nombre, EstadoProducto estado) {
        this.nombre = nombre;
        this.estado = estado;
    }
}

Y creamos un objeto así:

Producto producto = new Producto(
        "Teclado",
        EstadoProducto.OFERTA
);
en este ejemplo

Con enum evitamos escribir valores arbitrarios como "oferta", "OFERTA" o "rebajado".

El programa solo permite utilizar los valores definidos en EstadoProducto.

🟩 switch con enum​

Los enum funcionan muy bien junto con el switch moderno.

switch (producto.getEstado()) {
    case NUEVO -> System.out.println("Producto nuevo");
    case OFERTA -> System.out.println("Producto con descuento");
    case AGOTADO -> System.out.println("Producto sin stock");
}
tip

Cuando trabajamos con enum, no necesitamos comparar cadenas con equals().

Cada valor representa una opción concreta y controlada por Java.

Añade a Producto un método:

public void reponerStock(int cantidad)

aviso

No intentes resolver toda la aplicación de una vez.

Crea primero cada clase, comprueba que compila y después añade las relaciones entre ellas.

1️⃣1️⃣ Qué debes recordar​

Antes de terminar esta sesión, conviene tener claras estas ideas:

  • una clase define la estructura y comportamiento de un tipo de objeto;
  • un objeto es una instancia concreta de una clase;
  • los atributos representan el estado del objeto;
  • un constructor inicializa el objeto;
  • this hace referencia al objeto actual;
  • los getters permiten consultar atributos;
  • los setters permiten modificar atributos de forma controlada;
  • los métodos de instancia trabajan con el estado del objeto;
  • una clase puede contener objetos de otras clases;
  • enum permite representar conjuntos cerrados de valores.
