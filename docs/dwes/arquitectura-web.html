UT1. Arquitectura web

En esta primera unidad vamos a sentar las bases necesarias para entender cómo funciona una aplicación web en entorno servidor. Antes de crear formularios, conectar bases de datos o desarrollar APIs, es importante comprender qué ocurre cuando una persona escribe una dirección en el navegador y recibe una página como respuesta.

A lo largo de la unidad veremos el papel del cliente, del servidor, del protocolo HTTP y de las tecnologías que permiten generar contenido web de forma dinámica. También comenzaremos a trabajar con Spring Boot, que será la tecnología principal del módulo, pero lo haremos de forma progresiva y sin adelantar todavía conceptos que veremos más adelante.

Idea principal

Una aplicación web no es solo una página que se muestra en el navegador. Normalmente intervienen un cliente, un servidor, una petición, una respuesta y una tecnología capaz de procesar información en el servidor antes de devolver el resultado.

1️⃣ Qué vamos a aprender en esta unidad​

Esta unidad tiene un objetivo muy claro: entender la arquitectura básica de una aplicación web y reconocer las tecnologías que intervienen cuando el código se ejecuta en el servidor.

Hasta ahora, es posible que hayas trabajado con páginas HTML, CSS o algo de JavaScript. En esos casos, gran parte del trabajo ocurre en el navegador. Sin embargo, en el desarrollo web en entorno servidor aparece una parte nueva: una aplicación que se ejecuta en un servidor y que decide qué respuesta enviar al cliente.

Durante la unidad aprenderemos a diferenciar entre lo que ocurre en el cliente y lo que ocurre en el servidor. También veremos cómo viajan las peticiones y respuestas HTTP, qué significa generar páginas de forma dinámica y por qué frameworks como Spring Boot facilitan el desarrollo de aplicaciones web.

🟩 Arquitectura cliente-servidor​

El primer paso será comprender el modelo cliente-servidor. El navegador actuará como cliente y realizará peticiones. El servidor recibirá esas peticiones, las procesará y devolverá una respuesta.

Esta idea será la base de todo el módulo. Cada vez que creemos una ruta, un controlador, una vista o una API, estaremos trabajando sobre este mismo modelo.

🟨 Peticiones y respuestas HTTP​

Después estudiaremos el funcionamiento básico de HTTP. No se trata de memorizar todos los detalles del protocolo, sino de entender los elementos que más vamos a usar en clase: métodos como GET, POST, PUT, PATCH o DELETE, códigos de estado, rutas, parámetros y respuestas.

🟧 Generación dinámica de páginas​

También compararemos una página estática con una página generada dinámicamente. Esta diferencia es fundamental para entender por qué necesitamos programación en el servidor.

Una página estática siempre devuelve el mismo contenido. En cambio, una página dinámica puede cambiar según los datos, el usuario, la petición recibida o la lógica de la aplicación.

🟥 Tecnologías de servidor y Spring Boot​

Más adelante revisaremos distintas tecnologías de programación web en entorno servidor. Veremos que existen varias opciones, como Java con Spring Boot, PHP con Laravel, JavaScript con Node.js y Express, Python con Django o C# con ASP.NET Core.

En este módulo usaremos Spring Boot, que es una forma moderna y práctica de crear aplicaciones Java en servidor. Cuando hablemos de Spring en estos apuntes, normalmente nos estaremos refiriendo a Spring Boot, salvo que se indique lo contrario.

🟪 Primer contacto con controladores y rutas​

Por último, crearemos nuestros primeros controladores y rutas. No construiremos todavía una aplicación completa, pero sí veremos cómo una petición puede llegar a un método Java y cómo ese método puede devolver una respuesta.

2️⃣ Resultado de aprendizaje trabajado​

En esta unidad se trabajará principalmente el RA1.

RA principal

RA1. Selecciona las arquitecturas y tecnologías de programación web en entorno servidor, analizando sus capacidades y características propias.

Aunque durante la unidad aparecerán conceptos que más adelante se relacionarán con otros resultados de aprendizaje, los criterios de evaluación utilizados serán los asociados al RA1.

3️⃣ Contenidos de la unidad​

La unidad se organiza en varios apartados que iremos trabajando de forma progresiva. Primero veremos los fundamentos generales de la web y después comenzaremos a aplicarlos con Spring Boot.

🟩 1. Cliente, servidor y HTTP​

Comenzaremos analizando qué papel tiene cada elemento dentro de una aplicación web. Veremos qué hace el navegador, qué hace el servidor y cómo se comunican mediante HTTP.

Este apartado nos ayudará a entender que una aplicación web no se ejecuta completa en un único lugar. Algunas partes se ejecutan en el cliente y otras en el servidor.

🟨 2. Peticiones y respuestas​

A continuación estudiaremos la estructura básica de una petición HTTP y de una respuesta HTTP. Trabajaremos con ejemplos sencillos para interpretar qué ocurre cuando accedemos a una ruta desde el navegador.

También veremos algunos códigos de estado habituales, como 200, 404 o 500, sin entrar todavía en un estudio exhaustivo del protocolo.

🟧 3. Páginas estáticas y páginas dinámicas​

En este punto compararemos páginas HTML estáticas con páginas generadas por una aplicación de servidor. Esta comparación permitirá entender la utilidad de herramientas como Thymeleaf, que veremos con más detalle en la siguiente unidad.

La idea no será profundizar todavía en plantillas, sino comprender por qué una página puede generarse en el servidor antes de enviarse al cliente.

🟥 4. Servidores web, servidores de aplicaciones y tecnologías de servidor​

También estudiaremos la diferencia entre un servidor web y un servidor de aplicaciones. En aplicaciones modernas con Spring Boot, muchas de estas piezas aparecen integradas gracias al servidor embebido.

Además, revisaremos distintas tecnologías de programación en entorno servidor para situar Spring Boot dentro del panorama profesional actual.

🟪 5. Primeros pasos con Spring Boot​

Finalmente, crearemos un primer proyecto sencillo con Spring Boot. Veremos su estructura básica, el papel de Maven, la clase principal de la aplicación y los primeros controladores.

En esta unidad no se pretende dominar Spring Boot, sino entender qué papel ocupa dentro de una arquitectura web.

4️⃣ Herramientas que utilizaremos​

En esta unidad empezaremos a usar algunas herramientas que nos acompañarán durante el módulo. No es necesario dominarlas desde el primer día, pero sí conviene entender para qué sirve cada una.

🟩 IntelliJ IDEA Community​

El IDE de referencia será IntelliJ IDEA Community, en su modalidad gratuita. Lo usaremos para abrir, ejecutar y modificar proyectos Java con Spring Boot.

Otros entornos como Visual Studio Code o Eclipse también pueden utilizarse, pero el alumnado que elija una alternativa deberá configurarla por su cuenta.

🟨 Spring Initializr​

Para crear proyectos Spring Boot usaremos Spring Initializr desde la web. No se trata de una herramienta que haya que instalar, sino de una página que permite generar la estructura inicial del proyecto.

Desde ahí seleccionaremos opciones como el lenguaje, la versión de Java, el sistema de construcción y las dependencias iniciales.

🟧 Maven​

Maven será el sistema de construcción y gestión de dependencias que utilizaremos al comienzo del módulo. En esta unidad lo veremos de forma básica: nos interesa entender que Maven ayuda a descargar librerías, organizar el proyecto y ejecutar la aplicación.

No profundizaremos todavía en configuraciones avanzadas.

aviso

En esta unidad no se trabajarán todavía bases de datos, JPA, seguridad, DTO, transacciones ni APIs REST completas. Esos contenidos aparecerán más adelante, cuando ya tengamos una base suficiente.

5️⃣ Cómo trabajar esta unidad​

Esta unidad combina teoría y práctica. Algunas partes serán más conceptuales, como la explicación de cliente-servidor o la comparación entre tecnologías. Otras serán prácticas, como la creación del primer proyecto Spring Boot o la escritura de los primeros controladores.

Conviene no memorizar los ejemplos sin entenderlos. Lo importante es saber explicar qué está ocurriendo: qué petición llega, qué parte del programa la recibe, qué respuesta se genera y dónde se ejecuta cada fragmento de código.

tip

Una buena forma de comprobar si se ha entendido esta unidad es intentar explicar con tus propias palabras qué ocurre desde que escribes una URL en el navegador hasta que aparece una página en pantalla.

6️⃣ Comprobación inicial​

Antes de avanzar, intenta responder a estas preguntas de forma breve:

  1. ¿Qué diferencia hay entre cliente y servidor en una aplicación web?
  2. ¿Qué papel tiene el navegador?
  3. ¿Por qué una página generada dinámicamente puede ser más útil que una página estática?
  4. ¿Qué diferencia hay entre ejecutar código JavaScript en el navegador y ejecutar código Java en el servidor?
  5. ¿Qué aporta un framework como Spring Boot al desarrollo web en entorno servidor?

No es necesario responder perfectamente a todas al principio. La unidad está pensada precisamente para construir esas respuestas poco a poco.
