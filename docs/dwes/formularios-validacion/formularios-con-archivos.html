6. Formularios con archivos

Hasta ahora hemos trabajado con formularios que envían datos sencillos: texto, números o valores seleccionados. En ocasiones, sin embargo, necesitaremos que el usuario pueda enviar también un archivo, por ejemplo una imagen, un documento o un fichero generado por otra aplicación.

Para hacerlo, el navegador necesita construir la petición de una forma diferente a los formularios que hemos utilizado hasta ahora.

Idea principal

Cuando un formulario incluye archivos, utilizamos normalmente:

multipart/form-data → MultipartFile

El navegador prepara la petición y Spring Boot nos permite acceder al archivo recibido mediante un objeto MultipartFile.

1️⃣ ¿Por qué necesitamos multipart/form-data?​

En los formularios POST sencillos de esta unidad hemos visto que los datos se envían normalmente utilizando application/x-www-form-urlencoded.

Por ejemplo, un formulario con nombre y correo puede representarse de forma simplificada así:

Datos de un formulario sencillo
nombre=Ana&email=ana%40ejemplo.com

Este formato funciona bien para valores de texto, pero no es adecuado para enviar el contenido de un archivo.

Cuando el formulario contiene un <input type="file">, debemos indicar:

Formulario preparado para enviar un archivo
<form action="/documentos/subir"
      method="post"
      enctype="multipart/form-data">

    <label for="archivo">Selecciona un archivo</label>
    <input type="file" id="archivo" name="archivo">

    <button type="submit">Subir archivo</button>
</form>

La novedad está en:

enctype="multipart/form-data"

Este atributo indica al navegador que debe construir una petición dividida en distintas partes. Cada campo del formulario ocupa una parte y el archivo se envía con su propio contenido.

aviso

No necesitamos construir manualmente la petición multipart.

El navegador se encarga de generarla cuando utilizamos enctype="multipart/form-data".

2️⃣ Recibir el archivo en Spring Boot​

Spring Boot permite recibir un archivo mediante la clase MultipartFile.

Podemos hacerlo directamente con @RequestParam:

Recibir un archivo enviado desde el formulario
@PostMapping("/documentos/subir")
public String subirArchivo(
        @RequestParam("archivo") MultipartFile archivo,
        Model model) {

    model.addAttribute("nombreArchivo", archivo.getOriginalFilename());
    model.addAttribute("tamanoArchivo", archivo.getSize());

    return "resultado-subida";
}
en este ejemplo

El atributo name="archivo" del formulario debe coincidir con el nombre indicado en @RequestParam("archivo").

MultipartFile representa el archivo recibido y nos permite consultar información sobre él o acceder a su contenido.

Algunos métodos útiles son:

MétodoUtilidad
isEmpty()Comprueba si realmente se ha recibido contenido.
getOriginalFilename()Obtiene el nombre enviado por el navegador.
getSize()Devuelve el tamaño del archivo en bytes.
getContentType()Indica el tipo de contenido declarado en la petición.
transferTo(...)Permite guardar el archivo recibido.

🟩 Comprobar si se ha seleccionado un archivo​

Antes de trabajar con el fichero conviene comprobar que no esté vacío:

Comprobar que se ha recibido un archivo
@PostMapping("/documentos/subir")
public String subirArchivo(
        @RequestParam("archivo") MultipartFile archivo,
        Model model) {

    if (archivo.isEmpty()) {
        model.addAttribute("error", "Debes seleccionar un archivo.");
        return "subir-documento";
    }

    model.addAttribute("nombreArchivo", archivo.getOriginalFilename());
    model.addAttribute("tamanoArchivo", archivo.getSize());

    return "resultado-subida";
}

Este ejemplo vuelve a utilizar una idea que ya conocemos: tomar una decisión en el controlador según los datos recibidos.

3️⃣ Guardar un archivo de forma sencilla​

Recibir un archivo y guardarlo son dos operaciones diferentes. MultipartFile representa el contenido recibido, pero nosotros decidimos qué hacer con él.

Para una primera prueba podemos guardarlo en una carpeta local del proyecto:

Guardar un archivo recibido en una carpeta local
@PostMapping("/documentos/subir")
public String subirArchivo(
        @RequestParam("archivo") MultipartFile archivo,
        Model model) throws IOException {

    if (archivo.isEmpty()) {
        model.addAttribute("error", "Debes seleccionar un archivo.");
        return "subir-documento";
    }

    Path carpeta = Path.of("uploads");
    Files.createDirectories(carpeta);

    String nombreGuardado = UUID.randomUUID() + ".dat";
    Path destino = carpeta.resolve(nombreGuardado);

    archivo.transferTo(destino);

    model.addAttribute("nombreOriginal", archivo.getOriginalFilename());
    model.addAttribute("nombreGuardado", nombreGuardado);

    return "resultado-subida";
}
en este ejemplo

Path.of("uploads") representa la carpeta donde guardaremos los archivos recibidos.

Files.createDirectories(carpeta) crea esa carpeta si todavía no existe. Si ya existe, no ocurre ningún problema.

UUID.randomUUID() genera un identificador único que utilizamos como nombre del archivo. De esta forma evitamos sobrescribir archivos que pudieran tener el mismo nombre original.

carpeta.resolve(nombreGuardado) construye la ruta completa del archivo dentro de uploads.

Por último, archivo.transferTo(destino) copia el contenido recibido en el MultipartFile hasta esa ubicación del sistema de archivos.

Para este ejemplo necesitaremos los siguientes imports:

Imports utilizados
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.UUID;

import org.springframework.web.multipart.MultipartFile;
aviso

El nombre original de un archivo procede del cliente y no debemos utilizarlo directamente como nombre definitivo en el servidor sin comprobarlo.

Por eso, en este ejemplo generamos un nombre propio mediante UUID y utilizamos el nombre original únicamente como información para mostrar al usuario.

En una aplicación real también tendríamos que decidir qué tipos de archivo aceptamos, cuál es el tamaño máximo permitido, dónde se almacenan y quién puede acceder a ellos. Esas decisiones quedan fuera del objetivo de esta introducción.

4️⃣ Formulario y controlador deben volver a coincidir​

Igual que ocurría con los formularios anteriores, las distintas partes deben encajar:

FormularioControlador
action="/documentos/subir"@PostMapping("/documentos/subir")
method="post"@PostMapping
enctype="multipart/form-data"Petición multipart.
name="archivo"@RequestParam("archivo") MultipartFile archivo

Si olvidamos enctype="multipart/form-data", el formulario no estará configurado correctamente para enviar el archivo.

🟨 Un formulario puede combinar datos y archivos​

No estamos limitados a enviar únicamente un fichero. Podemos combinarlo con campos normales:

Formulario con datos y archivo
<form action="/documentos/subir"
      method="post"
      enctype="multipart/form-data">

    <label for="titulo">Título</label>
    <input type="text" id="titulo" name="titulo">

    <label for="archivo">Archivo</label>
    <input type="file" id="archivo" name="archivo">

    <button type="submit">Enviar</button>
</form>

Y recibir ambos valores:

Recibir un dato de texto y un archivo
@PostMapping("/documentos/subir")
public String subirArchivo(
        @RequestParam String titulo,
        @RequestParam MultipartFile archivo,
        Model model) {

    model.addAttribute("titulo", titulo);
    model.addAttribute("nombreArchivo", archivo.getOriginalFilename());

    return "resultado-subida";
}

El mecanismo sigue siendo el mismo que ya conocemos: los valores enviados por el formulario llegan como datos de la petición HTTP.

5️⃣ Errores frecuentes​

🟩 Olvidar multipart/form-data​

<form action="/documentos/subir" method="post">

Si el formulario envía un archivo, debe incluir:

enctype="multipart/form-data"

🟨 Confundir seleccionar con guardar​

Que el usuario seleccione un archivo y Spring lo reciba como MultipartFile no significa que el fichero quede almacenado permanentemente.

La aplicación debe decidir expresamente qué hacer con él.

🟧 Confiar ciegamente en el nombre o tipo recibido​

getOriginalFilename() y getContentType() contienen información proporcionada durante la petición. No debemos considerarla una garantía de que el archivo sea seguro o tenga realmente el contenido esperado.

En esta unidad solo realizaremos comprobaciones sencillas.
