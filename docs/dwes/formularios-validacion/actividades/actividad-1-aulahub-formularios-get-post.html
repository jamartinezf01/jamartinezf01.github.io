Actividad 1. AulaHub recibe sus primeros formularios

En esta unidad trabajaremos durante varias sesiones sobre AulaHub, una pequeña aplicación web que ofrece talleres tecnológicos.

El proyecto ya tiene una interfaz preparada, varias tarjetas de talleres, estilos CSS y recursos visuales. Sin embargo, todavía hay dos zonas que no hacen nada: el buscador y la inscripción.

En esta primera actividad vamos a conseguir que ambas zonas envíen datos reales al servidor y que Spring Boot pueda recibirlos.

nota

Esta actividad es de entrega obligatoria y forma parte de las actividades de seguimiento de la unidad.

No tendrá una calificación numérica propia. Su realización se registrará como Entregada o NO entregada.

La ampliación es opcional y no será necesaria para continuar con la Actividad 2.

1️⃣ Punto de partida​

No debes crear un proyecto Spring Boot nuevo.

Descarga el proyecto base de AulaHub:

👉 Descargar AulaHub — proyecto base de UT3

Descomprime el archivo y abre el proyecto desde IntelliJ IDEA.

El proyecto ya incluye:

  • Spring Web y Thymeleaf.
  • TallerController.
  • la vista principal talleres.html.
  • las vistas resultado-busqueda.html y resultado-inscripcion.html.
  • una hoja de estilos completa.
  • varias imágenes para los talleres.
  • dos zonas de trabajo preparadas en la página principal.

Antes de modificar nada, ejecuta la aplicación y comprueba estas rutas:

Rutas disponibles al comenzar
/
/talleres

Ambas deben mostrar la página principal de AulaHub.

El controlador inicial contiene únicamente la operación necesaria para mostrar esa página. No elimines esa ruta.

2️⃣ El reto​

La portada de AulaHub debe permitir realizar dos acciones diferentes:

  1. Buscar talleres escribiendo un texto.
  2. Enviar una solicitud de inscripción indicando algunos datos personales y el taller elegido.

Ambas acciones parten de un formulario HTML, pero representan intenciones diferentes.

Antes de programarlas, piensa:

  • ¿cuál de las dos acciones representa una consulta?
  • ¿cuál representa el envío de información para realizar una operación?
  • ¿qué método HTTP utilizarías en cada caso?

Cuando termines, AulaHub deberá tener estos dos recorridos:

3️⃣ Trabajo que debes realizar​

🟩 A. Haz funcionar el buscador de talleres​

Abre talleres.html y localiza esta zona de la página:

Zona preparada en la interfaz
Encuentra un taller
Zona de trabajo: buscador de talleres

Dentro de esa zona existe un comentario que indica dónde debes trabajar.

Construye un formulario que contenga:

  • un campo de texto.
  • un botón con el texto Buscar.

El dato introducido por el usuario debe llamarse:

texto

El formulario debe enviar la información a:

/talleres/buscar

Elige el método HTTP que consideres adecuado para una búsqueda.

Una búsqueda como:

spring boot

debe terminar produciendo una petición equivalente a:

Petición esperada al realizar una búsqueda
GET /talleres/buscar?texto=spring+boot
aviso

No construyas manualmente la cadena ?texto=....

El navegador debe generarla a partir del formulario y del atributo name del control.

🟨 B. Recibe la búsqueda en TallerController​

Añade a TallerController una operación que atienda la petición anterior.

Debe:

  1. recibir el parámetro texto mediante @RequestParam.
  2. añadir ese valor al Model con un nombre que pueda utilizar la vista.
  3. devolver resultado-busqueda.

Después abre resultado-busqueda.html y completa la zona indicada mediante el comentario existente.

La página debe mostrar qué ha buscado el usuario.

Por ejemplo, si la petición es:

/talleres/buscar?texto=java

la vista debe mostrar una información equivalente a:

Información que debe mostrar la vista
Búsqueda de talleres

Criterio recibido: java

Todavía no debes buscar realmente dentro de una colección de talleres.

El objetivo es comprobar que el dato realiza correctamente este recorrido:

input → petición HTTP → @RequestParam → Model → Thymeleaf

Prueba al menos estas búsquedas:

Pruebas mínimas del buscador

4️⃣ Comprueba qué está enviando realmente el navegador​

No basta con que los formularios parezcan funcionar. Vamos a comprobar la relación entre HTML y controlador.

Realiza estas pruebas una cada vez. Después de observar el resultado, restaura el código correcto.

🟩 Cambia temporalmente la ruta​

Haz que el action del formulario de inscripción apunte a una ruta distinta de la atendida por el controlador.

Envía el formulario y observa qué ocurre.

Después restaura la ruta correcta.

🟨 Cambia temporalmente el método HTTP​

Haz que el formulario de inscripción utilice GET, manteniendo el controlador preparado para el método que habías elegido originalmente.

Comprueba qué sucede y restaura después el formulario correcto.

🟧 Cambia temporalmente un name​

Haz que el campo de correo envíe:

Cambio temporal del nombre enviado
name="correo"

mientras el controlador sigue esperando:

email

Comprueba el resultado y restaura después el nombre correcto.

Qué estamos comprobando

Si un formulario no llega correctamente al método esperado, revisa primero estas tres correspondencias:

Relaciones fundamentales
action del formulario  ↔ ruta del controlador
method del formulario  ↔ @GetMapping / @PostMapping
name del control       ↔ @RequestParam

Modificar código al azar suele dificultar encontrar el problema.

🟥 Compara GET y POST en el navegador​

Realiza una búsqueda y una inscripción y compara ambas peticiones.

Debes poder responder:

  • ¿en cuál aparecen los datos en la URL?
  • ¿qué anotación atiende la búsqueda?
  • ¿qué anotación atiende la inscripción?
  • ¿por qué no utilizamos el mismo método HTTP para las dos operaciones?
  • ¿significa que los datos enviados mediante POST estén cifrados? Justifica la respuesta.

5️⃣ Comprobación final​

Antes de dar la actividad por terminada:

  • He partido del proyecto base de AulaHub y no he creado otra aplicación.
  • /talleres sigue mostrando correctamente la página principal.
  • La zona de búsqueda contiene un formulario funcional.
  • La búsqueda utiliza el método HTTP adecuado.
  • El campo de búsqueda envía un parámetro llamado texto.
  • TallerController recibe texto mediante @RequestParam.
  • resultado-busqueda.html muestra el criterio recibido.
  • La zona de inscripción contiene un segundo formulario.
  • El formulario incluye nombre, correo y taller.
  • El taller se selecciona mediante un <select> escrito directamente en HTML.
  • La inscripción utiliza el método HTTP adecuado.
  • TallerController recibe nombre, email y taller mediante @RequestParam.
  • resultado-inscripcion.html muestra los tres datos recibidos.
  • He comprobado qué ocurre cuando no coinciden ruta, método o nombre del parámetro.
  • Puedo explicar la diferencia entre utilizar GET y POST en estos dos formularios.
  • No he utilizado todavía binding con objetos ni validación.

📦 Cómo preparar la entrega​

Comprueba primero que el proyecto compila y se ejecuta correctamente.

Desde la terminal de IntelliJ IDEA, situada en la raíz del proyecto:

Limpiar el proyecto
.\mvnw.cmd clean

Genera después el ZIP:

Crear el ZIP de entrega
tar -a -c -f ..\apellido-nombre-UT3-1.zip pom.xml mvnw mvnw.cmd .mvn src

Entrega:

Nombre del archivo
apellido-nombre-UT3-1.zip

Conserva también el proyecto en tu equipo. La Actividad 2 continuará exactamente desde este estado.
