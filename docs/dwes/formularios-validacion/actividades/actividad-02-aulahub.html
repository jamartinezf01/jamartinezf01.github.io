Actividad 2. Binding con objetos Java

En la actividad anterior hicimos funcionar los formularios de AulaHub con GET, POST y @RequestParam.

Ahora vamos a mejorar únicamente el formulario de inscripción. En lugar de recibir cada dato por separado, Spring Boot agrupará la información en un único objeto Java mediante binding.

Objetivo

Al terminar la actividad debes ser capaz de recibir un formulario como un objeto Java con @ModelAttribute, vincularlo con Thymeleaf mediante th:object y th:field y generar las opciones de un <select> a partir de datos preparados por el controlador.

nota

Esta actividad es de entrega obligatoria y forma parte de las actividades de seguimiento de la unidad.

Se registrará como Entregada o NO entregada. La ampliación es opcional.

1️⃣ Punto de partida​

Continúa con el proyecto terminado de la Actividad 1.

Si no pudiste completarla, utiliza el proyecto de recuperación:

👉 Descargar AulaHub — recuperación de la Actividad 1

Antes de empezar, comprueba que:

  • /talleres carga correctamente.
  • el buscador sigue funcionando mediante GET.
  • el formulario de inscripción envía nombre, email y taller mediante POST.
aviso

No modifiques el buscador.

Seguirá utilizando @RequestParam para que podamos compararlo con el binding del formulario de inscripción.

2️⃣ El reto​

La inscripción deberá pasar de varios parámetros independientes a un único objeto:

PropiedadTipo
nombreString
emailString
tallerString
edadInteger

Además, las opciones del taller dejarán de estar escritas directamente en el HTML y se generarán desde una colección preparada por el controlador.

aviso

En esta actividad todavía no utilizaremos Jakarta Validation, @Valid ni BindingResult.

3️⃣ Trabajo que debes realizar​

🟩 A. Crea InscripcionForm​

Crea una clase InscripcionForm en un paquete adecuado, por ejemplo model.

Debe contener:

Propiedades del formulario
nombre  → String
email   → String
taller  → String
edad    → Integer

Añade constructor sin argumentos, getters y setters.

información

InscripcionForm representa los datos del formulario. No es una entidad JPA ni se almacena todavía en una base de datos.

🟨 B. Prepara el Model​

Modifica el método que muestra /talleres para añadir al Model:

  • un InscripcionForm vacío llamado inscripcion.
  • una colección llamada talleresDisponibles.

Utiliza estos talleres:

  • Desarrollo web con Spring Boot.
  • Videojuegos sencillos con Java.
  • Introducción a la ciberseguridad.
  • Interfaces web claras y accesibles.

Puedes crear la colección con List.of(...).

🟧 C. Vincula el formulario con el objeto​

En talleres.html, modifica solo el formulario de inscripción para que:

  • siga enviando mediante POST.
  • utilice th:action.
  • utilice th:object="${inscripcion}".
  • vincule los campos con th:field.

Debes utilizar estas propiedades:

Campos del formulario
*{nombre}
*{email}
*{edad}
*{taller}

Añade el nuevo campo Edad con type="number".

Cuando utilizas th:field, no necesitas escribir manualmente el name del campo.

🟥 D. Genera el <select> desde el servidor​

Elimina las opciones fijas del taller y conserva únicamente:

Opción inicial
<option value="">Selecciona un taller</option>

Genera el resto recorriendo ${talleresDisponibles} con:

  • th:each.
  • th:value.
  • th:text.

Los nombres de los talleres no deben aparecer escritos uno a uno en el HTML.

🟪 E. Recibe un único objeto en el POST​

Modifica POST /talleres/inscripcion.

Elimina los @RequestParam de nombre, email y taller y recibe un único objeto:

Objeto recibido
@ModelAttribute("inscripcion") InscripcionForm inscripcion

Spring deberá rellenar automáticamente sus propiedades mediante binding.

No vuelvas a añadir nombre, email, edad y taller por separado al Model.

🟩 F. Adapta la vista de resultado​

En resultado-inscripcion.html, deja de utilizar atributos independientes y accede al objeto:

Acceso a los datos recibidos
${inscripcion.nombre}
${inscripcion.email}
${inscripcion.edad}
${inscripcion.taller}

La página debe mostrar correctamente los cuatro valores.

4️⃣ Comprueba que entiendes el binding​

Realiza estas tres comprobaciones:

  1. Inspecciona el HTML generado. Comprueba que un campo escrito con th:field llega al navegador como HTML normal con atributos id y name.
  2. Prueba una correspondencia incorrecta. Cambia temporalmente el nombre de una propiedad de InscripcionForm sin modificar su th:field, observa el resultado y después restaura el código.
  3. Compara las dos soluciones de AulaHub. El buscador sigue utilizando @RequestParam, mientras que la inscripción utiliza @ModelAttribute. Debes poder explicar por qué ambas soluciones tienen sentido.

5️⃣ Comprobación final​

Antes de terminar, comprueba:

  • El buscador sigue funcionando con GET y @RequestParam.
  • Existe InscripcionForm con las cuatro propiedades, constructor, getters y setters.
  • El controlador añade inscripcion y talleresDisponibles al Model.
  • El formulario utiliza th:object y th:field.
  • El <select> se genera con th:each.
  • El POST recibe un único InscripcionForm mediante @ModelAttribute.
  • La vista de resultado obtiene los datos desde ${inscripcion...}.
  • No he añadido todavía validación ni BindingResult.

6️⃣ Ampliación opcional: modalidad​

Añade a InscripcionForm una propiedad:

Nueva propiedad
modalidad

Debe ser un String con dos opciones: Presencial y Online.

Prepara las opciones desde el controlador, envíalas mediante Model y genera otro <select> con th:each. La modalidad seleccionada debe llegar por binding y mostrarse también en la vista de resultado.

Nombre del archivo
