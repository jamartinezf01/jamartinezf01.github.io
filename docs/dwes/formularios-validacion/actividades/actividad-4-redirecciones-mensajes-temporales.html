Actividad 4. Redirecciones y mensajes temporales

En la actividad anterior conseguimos que AulaHub detectara los datos incorrectos, volviera al formulario y mostrara los errores sin perder los valores introducidos.

Ahora vamos a mejorar la rama correcta del formulario: después de una inscripción válida no devolveremos directamente una vista, sino que aplicaremos Post/Redirect/Get (PRG) y mostraremos un mensaje temporal de confirmación.

Objetivo

Al terminar la actividad debes saber distinguir cuándo devolver una vista y cuándo redirigir, aplicar PRG con redirect: y utilizar RedirectAttributes y addFlashAttribute() para transportar un mensaje hasta la siguiente petición.

nota

Esta actividad es de entrega obligatoria y forma parte de las actividades de seguimiento de la unidad.

Se registrará como Entregada o NO entregada. La ampliación es opcional.

1️⃣ Punto de partida​

Continúa con el proyecto terminado de la Actividad 3.

Si no pudiste completarla, utiliza el proyecto de recuperación:

👉 Descargar AulaHub — recuperación de la Actividad 3

Antes de empezar, comprueba que:

  • una inscripción incorrecta vuelve a talleres.html y muestra los errores.
  • los valores válidos introducidos se conservan.
  • talleresDisponibles sigue apareciendo cuando hay errores.
  • una inscripción válida llega todavía a resultado-inscripcion.html.
aviso

No modifiques la rama de errores salvo que sea necesario para corregir algún fallo previo.

En esta actividad trabajaremos principalmente la rama de éxito.

2️⃣ El reto​

Cuando la inscripción sea válida, AulaHub debe terminar el POST mediante una redirección hacia /talleres.

El resultado será este:

  • hay errores → misma vista talleres → se conservan valores y mensajes.
  • no hay errores → mensaje flash → redirect:/talleres → nueva petición GET → formulario limpio y mensaje de confirmación.

3️⃣ Trabajo que debes realizar​

🟩 A. Redirige después de una inscripción correcta​

Modifica el método que procesa POST /talleres/inscripcion para recibir también un RedirectAttributes.

Mantén este comportamiento:

Rama con errores
if (resultado.hasErrors()) {
    prepararDatosFormulario(model);
    return "talleres";
}

Pero sustituye la devolución de resultado-inscripcion de la rama correcta por una redirección a:

Destino después del POST correcto
/talleres

Utiliza para ello el prefijo redirect:.

🟨 B. Añade un mensaje temporal​

Antes de redirigir, utiliza RedirectAttributes para crear un flash attribute llamado:

Nombre del atributo temporal
mensaje

Su contenido puede ser:

Mensaje de confirmación
La inscripción se ha enviado correctamente.

Utiliza addFlashAttribute(). No añadas el mensaje al Model del POST.

🟧 C. Muestra el mensaje en /talleres​

En talleres.html, añade una zona de confirmación que solo aparezca cuando exista mensaje.

Puedes utilizar una estructura equivalente a:

Mensaje mostrado después de la redirección
<div th:if="${mensaje}" class="mensaje-exito">
    <p th:text="${mensaje}"></p>
</div>

Añade en aulahub.css un estilo sencillo para .mensaje-exito que encaje con el diseño actual.

No necesitas recuperar manualmente el flash attribute en el GET /talleres.

🟥 D. Comprueba el patrón Post/Redirect/Get​

Envía una inscripción válida y observa qué ocurre:

  1. el navegador realiza POST /talleres/inscripcion.
  2. el controlador responde con una redirección.
  3. el navegador realiza un nuevo GET /talleres.
  4. la URL final vuelve a ser /talleres.
  5. aparece el mensaje temporal y el formulario vuelve a estar vacío.

Después pulsa Actualizar en el navegador.

La actualización debe repetir el GET /talleres, no el POST de inscripción.

🟪 E. Compara addAttribute() y addFlashAttribute()​

Realiza una prueba temporal añadiendo mediante addAttribute() un atributo llamado estado con el valor ok antes de redirigir.

Observa la URL resultante y comprueba que el dato puede aparecer como parámetro de consulta.

Después elimina esa prueba y deja como solución final únicamente el mensaje creado con addFlashAttribute().

Debes poder explicar esta diferencia:

MétodoUso en esta actividad
addAttribute()Datos que forman parte de la URL de destino.
addFlashAttribute()Datos temporales para la siguiente petición.

4️⃣ Comprueba los dos caminos​

Realiza estas pruebas finales:

  1. Envía un formulario con errores y comprueba que no hay redirección.
  2. Corrige los errores y envía una inscripción válida.
  3. Comprueba que terminas en /talleres y aparece el mensaje de éxito.
  4. Actualiza la página y comprueba que no se vuelve a enviar la inscripción.
  5. Envía otra inscripción válida y verifica que el formulario aparece limpio después de la redirección.
Idea principal

Al terminar esta actividad, AulaHub debe tener dos comportamientos distintos:

errores → misma vista.

éxito → flash attribute → redirect → GET.

5️⃣ Comprobación final​

Antes de terminar:

  • La rama con errores sigue devolviendo directamente talleres.
  • El POST recibe RedirectAttributes.
  • Una inscripción válida utiliza redirect:/talleres.
  • El mensaje se envía mediante addFlashAttribute().
  • talleres.html muestra el mensaje solo cuando existe.
  • Después del éxito la URL final es /talleres.
  • Al actualizar no se repite el POST.
  • Puedo explicar la diferencia entre addAttribute() y addFlashAttribute().

6️⃣ Ampliación opcional: confirmación personalizada​

Haz que el mensaje de éxito incluya el nombre de la persona inscrita, por ejemplo:

Ejemplo de confirmación personalizada
Inscripción enviada correctamente para Ana.

El dato debe utilizarse únicamente para construir el mensaje flash. No añadas sesiones ni almacenamiento permanente.
