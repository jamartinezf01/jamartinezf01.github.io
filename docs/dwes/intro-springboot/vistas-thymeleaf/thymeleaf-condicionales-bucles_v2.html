3.3 Condicionales y bucles

En los apartados anteriores hemos aprendido a enviar datos desde un controlador mediante Model, mostrarlos con Thymeleaf y construir enlaces y rutas dinámicas.

Ahora damos un paso más: una vista no siempre muestra un único objeto ni exactamente el mismo contenido. En muchas páginas necesitamos recorrer una colección de datos y decidir qué elementos deben aparecer según su estado.

Idea principal

Thymeleaf permite generar HTML repetido con th:each y mostrar u ocultar fragmentos mediante th:if y th:unless.

Estas decisiones se toman mientras la plantilla se procesa en el servidor, antes de enviar el HTML al navegador.

1️⃣ Cuando una vista recibe una colección​

Hasta ahora hemos enviado a la vista objetos individuales:

ProductoController.java
model.addAttribute("producto", producto);

Pero una página de catálogo, una agenda o un listado normalmente necesita trabajar con varios objetos.

Por ejemplo, podemos preparar una lista en el controlador:

ProductoController.java
@GetMapping("/productos")
public String listado(Model model) {

    List<Producto> productos = List.of(
            new Producto(1, "Teclado mecánico", 79.90, 8),
            new Producto(2, "Ratón inalámbrico", 34.50, 0),
            new Producto(3, "Monitor 27 pulgadas", 219.00, 5)
    );

    model.addAttribute("productos", productos);

    return "productos";
}
en este ejemplo

El controlador crea una List<Producto> y la añade al Model con el nombre productos.

La vista no recibe tres atributos independientes. Recibe un único atributo llamado productos cuyo valor es una colección de objetos Producto.

La plantilla podrá recorrer esa colección para generar una parte del HTML por cada elemento.

El flujo que vamos a trabajar es:

2️⃣ Recorrer una colección con th:each​

Para repetir un elemento HTML por cada objeto de una colección utilizamos th:each.

La forma básica es:

Sintaxis básica de th:each
<elemento th:each="elementoActual : ${coleccion}">
    ...
</elemento>

Si el modelo contiene:

Atributo enviado a la vista
model.addAttribute("productos", productos);

podemos escribir:

productos.html
<div th:each="producto : ${productos}">
    <h2 th:text="${producto.nombre}">Nombre</h2>
    <p th:text="${producto.precio}">0</p>
</div>

La expresión se lee así:

Lectura de la expresión
por cada producto de productos

En cada iteración, producto representa uno de los objetos de la colección.

Si existen tres objetos, el <div> se procesará tres veces y se generarán tres bloques HTML.

Nombres diferentes

productos es el nombre del atributo almacenado en el Model.

producto es una variable temporal que existe durante cada iteración de th:each.

Podríamos utilizar otro nombre, pero conviene que sea claro y esté en singular.

🟩 Repetir filas de una tabla​

th:each puede colocarse sobre cualquier elemento HTML.

Un caso muy habitual es generar las filas de una tabla:

productos.html
<table>
    <thead>
        <tr>
            <th>ID</th>
            <th>Producto</th>
            <th>Precio</th>
        </tr>
    </thead>
    <tbody>
        <tr th:each="producto : ${productos}">
            <td th:text="${producto.id}">0</td>
            <td th:text="${producto.nombre}">Nombre</td>
            <td th:text="${producto.precio}">0</td>
        </tr>
    </tbody>
</table>

No necesitamos escribir manualmente una fila para cada producto. Thymeleaf genera tantas como elementos haya en la colección.

🟨 Generar enlaces dentro de un bucle​

También podemos utilizar los datos del elemento actual para construir enlaces:

Enlace de detalle dentro de th:each
<div th:each="producto : ${productos}">
    <span th:text="${producto.nombre}">Producto</span>

    <a th:href="@{/productos/{id}(id=${producto.id})}">
        Ver detalle
    </a>
</div>

Para un producto cuyo id sea 7, Thymeleaf generará un enlace equivalente a:

URL generada
/productos/7

Aquí estamos combinando lo aprendido en el apartado anterior con una iteración.

3️⃣ Conocer la posición dentro de la iteración​

A veces no solo necesitamos el objeto actual. También puede ser útil conocer su posición dentro de la colección.

th:each permite declarar una segunda variable llamada variable de estado:

Iteración con variable de estado
<tr th:each="producto, estado : ${productos}">
    ...
</tr>

En este caso:

  • producto es el objeto actual.
  • estado contiene información sobre la iteración.

Entre las propiedades más útiles encontramos:

PropiedadSignificado
estado.indexPosición empezando en 0.
estado.countPosición empezando en 1.
estado.sizeNúmero total de elementos.
estado.firsttrue si es el primer elemento.
estado.lasttrue si es el último elemento.
estado.eventrue en iteraciones pares.
estado.oddtrue en iteraciones impares.

Por ejemplo:

Numerar elementos de una lista
<ol>
    <li th:each="producto, estado : ${productos}">
        <span th:text="${estado.count}">1</span>.
        <span th:text="${producto.nombre}">Producto</span>
    </li>
</ol>

La variable de estado es opcional. Solo la declararemos cuando necesitemos esa información.

4️⃣ Mostrar contenido con th:if​

th:if permite renderizar un elemento únicamente cuando una expresión se evalúa como verdadera.

Supongamos que Producto tiene una propiedad stock.

Podemos escribir:

Mostrar contenido según el stock
<p th:if="${producto.stock > 0}">
    Producto disponible
</p>

Si producto.stock > 0 es verdadero, el <p> aparece en el HTML final.

Si es falso, ese elemento no se incluye en el HTML enviado al navegador.

Relación con las expresiones

Las comparaciones que utilizamos dentro de th:if se apoyan en las expresiones que ya hemos estudiado:

${producto.stock > 0}
${producto.precio < 100}
${disponible}

th:if utiliza el resultado de la expresión para decidir si debe renderizar el elemento.

🟩 Condiciones con valores booleanos​

Si el modelo contiene:

Controlador
model.addAttribute("destacado", true);

podemos escribir directamente:

Condición booleana
<p th:if="${destacado}">
    Producto destacado
</p>

No es necesario escribir:

Comparación innecesaria
<p th:if="${destacado == true}">
    Producto destacado
</p>

Cuando ya tenemos un valor booleano, podemos utilizarlo directamente como condición.

5️⃣ La condición contraria con th:unless​

th:unless funciona como la condición inversa de th:if.

Por ejemplo:

Contenido alternativo
<p th:if="${producto.stock > 0}">
    Disponible
</p>

<p th:unless="${producto.stock > 0}">
    Agotado
</p>

Si hay stock, se muestra el primer párrafo.

Si no lo hay, se muestra el segundo.

Podemos leer th:unless como:

Idea de th:unless
a menos que esta condición sea verdadera
tip

th:unless resulta útil cuando queremos expresar claramente el caso contrario de una condición sencilla.

Si la condición empieza a ser compleja, suele ser preferible revisar la lógica en lugar de construir expresiones difíciles de leer en la plantilla.

6️⃣ Combinar th:each con condiciones​

Una situación muy habitual consiste en recorrer una colección y tomar decisiones para cada objeto.

Por ejemplo:

Listado con disponibilidad
<article th:each="producto : ${productos}">

    <h2 th:text="${producto.nombre}">Producto</h2>

    <p>
        Precio:
        <span th:text="${producto.precio}">0</span> €
    </p>

    <p th:if="${producto.stock > 0}">
        Disponible
    </p>

    <p th:unless="${producto.stock > 0}">
        Agotado
    </p>

</article>

El proceso es diferente para cada objeto:

Procesamiento conceptual
producto 1 → se genera un bloque → se comprueba su stock
producto 2 → se genera un bloque → se comprueba su stock
producto 3 → se genera un bloque → se comprueba su stock

Por eso una misma plantilla puede generar resultados diferentes para los elementos de una colección.

🟩 No confundir ocultar con filtrar​

Si escribimos:

Condición dentro de una iteración
<article
    th:each="producto : ${productos}"
    th:if="${producto.precio < 100}">
    ...
</article>

Thymeleaf recorre la colección y solo genera el <article> cuando la condición es verdadera.

Esto puede ser útil para decisiones sencillas de presentación, pero no significa que la vista deba encargarse de todas las búsquedas o filtros de la aplicación.

aviso

La vista debe ocuparse principalmente de presentar los datos.

Si necesitamos seleccionar productos según reglas importantes de la aplicación, normalmente esa selección debería prepararse antes de llegar a la plantilla.

7️⃣ Qué ocurre cuando una colección está vacía​

Una vista debe comportarse correctamente aunque no haya elementos que mostrar.

Si productos es una lista vacía:

Controlador
List<Producto> productos = List.of();
model.addAttribute("productos", productos);

este bloque:

Iteración sobre una lista vacía
<div th:each="producto : ${productos}">
    <span th:text="${producto.nombre}">Producto</span>
</div>

no genera ningún bloque de producto.

Pero una página completamente vacía puede resultar confusa para el usuario.

Thymeleaf proporciona objetos de utilidad. Para listas podemos utilizar #lists.

Por ejemplo:

Mensaje para una colección vacía
<p th:if="${#lists.isEmpty(productos)}">
    No hay productos disponibles.
</p>

Y podemos mostrar el listado únicamente cuando existen elementos:

Mostrar el listado si hay elementos
<section th:unless="${#lists.isEmpty(productos)}">

    <article th:each="producto : ${productos}">
        <h2 th:text="${producto.nombre}">Producto</h2>
    </article>

</section>
#lists

#lists es uno de los objetos de utilidad que Thymeleaf pone a disposición de las expresiones.

En este punto solo necesitamos #lists.isEmpty(...) para comprobar si una colección está vacía. No necesitamos estudiar todavía todas sus operaciones.

8️⃣ Agrupar contenido sin añadir una etiqueta HTML: th:block​

A veces queremos aplicar una condición a varios elementos sin introducir un <div> adicional en el HTML final.

Thymeleaf dispone de:

Agrupación con th:block
<th:block th:if="${producto.stock > 0}">
    <p>Disponible</p>
    <p>Envío en 24 horas</p>
</th:block>

th:block sirve como contenedor durante el procesamiento de la plantilla, pero no aparece como etiqueta en el HTML final.

Es especialmente útil para agrupar varios elementos bajo una misma condición.

aviso

No debemos utilizar th:block automáticamente para todo.

Si un <section>, <article> o <div> tiene sentido semántico en el HTML, es preferible utilizar ese elemento real.

9️⃣ La vista no sustituye a la lógica de la aplicación​

Thymeleaf permite escribir expresiones, condiciones y recorridos, pero eso no significa que debamos trasladar toda la lógica de Java a la plantilla.

Esta expresión es razonable:

Condición sencilla de presentación
<span th:if="${producto.stock > 0}">
    Disponible
</span>

En cambio, una plantilla llena de cálculos y condiciones encadenadas se vuelve difícil de comprender y mantener.

La responsabilidad debe seguir estando separada:

  • el controlador prepara los datos necesarios para la vista;
  • los objetos representan la información de la aplicación;
  • Thymeleaf decide cómo presentar esos datos;
  • las condiciones de la plantilla deberían estar relacionadas principalmente con la presentación.
peligro

Ocultar un enlace o un botón con th:if no es un mecanismo de seguridad.

La seguridad de una operación debe controlarse en el servidor. Una condición en la vista solo determina qué HTML se muestra.

🔟 Ejemplo: catálogo con disponibilidad​

Supongamos esta clase:

Producto.java
public class Producto {

    private int id;
    private String nombre;
    private double precio;
    private int stock;

    public Producto(int id, String nombre, double precio, int stock) {
        this.id = id;
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
    }

    public int getId() {
        return id;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }

    public int getStock() {
        return stock;
    }
}

El controlador prepara una colección:

ProductoController.java
@Controller
@RequestMapping("/productos")
public class ProductoController {

    @GetMapping
    public String listado(Model model) {

        List<Producto> productos = List.of(
                new Producto(1, "Teclado mecánico", 79.90, 8),
                new Producto(2, "Ratón inalámbrico", 34.50, 0),
                new Producto(3, "Monitor 27 pulgadas", 219.00, 5)
        );

        model.addAttribute("productos", productos);

        return "productos";
    }
}

La plantilla puede combinar iteraciones, condiciones y enlaces dinámicos:

productos.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Catálogo de productos</title>
    <link rel="stylesheet" th:href="@{/css/estilos.css}">
</head>
<body>

    <h1>Catálogo de productos</h1>

    <p th:if="${#lists.isEmpty(productos)}">
        No hay productos disponibles.
    </p>

    <section th:unless="${#lists.isEmpty(productos)}">

        <article th:each="producto, estado : ${productos}">

            <h2 th:text="${producto.nombre}">
                Nombre del producto
            </h2>

            <p>
                Producto
                <span th:text="${estado.count}">1</span>
                de
                <span th:text="${estado.size}">0</span>
            </p>

            <p>
                Precio:
                <span th:text="${producto.precio}">0</span> €
            </p>

            <p th:if="${producto.stock > 0}">
                Disponible
            </p>

            <p th:unless="${producto.stock > 0}">
                Agotado
            </p>

            <a th:href="@{/productos/{id}(id=${producto.id})}">
                Ver detalle
            </a>

        </article>

    </section>

</body>
</html>
en este ejemplo

th:each recorre la colección productos y crea un bloque por cada objeto.

La variable estado permite conocer la posición actual y el tamaño total de la colección.

th:if y th:unless muestran mensajes distintos según el valor de stock.

@{/productos/{id}(id=${producto.id})} genera un enlace diferente para cada producto utilizando su identificador.

La comprobación con #lists.isEmpty(productos) permite mostrar un mensaje alternativo si la colección no contiene elementos.

Este ejemplo reúne los elementos principales que necesitamos para generar vistas a partir de colecciones sin trasladar a la plantilla responsabilidades que corresponden a otras partes de la aplicación.

1️⃣1️⃣ Errores frecuentes​

🟩 Utilizar el nombre de la colección dentro del bucle​

Incorrecto:

Uso incorrecto dentro de th:each
<div th:each="producto : ${productos}">
    <span th:text="${productos.nombre}">Producto</span>
</div>

Dentro de la iteración debemos utilizar el objeto actual:

Uso correcto
<div th:each="producto : ${productos}">
    <span th:text="${producto.nombre}">Producto</span>
</div>

🟨 Olvidar enviar la colección al modelo​

Si la plantilla espera:

${productos}

el controlador debe poner a disposición de la vista un atributo con ese nombre:

Controlador
model.addAttribute("productos", productos);

🟧 Crear manualmente bloques repetidos​

No tiene sentido escribir:

Código repetitivo que debemos evitar
<article>Producto 1...</article>
<article>Producto 2...</article>
<article>Producto 3...</article>

si todos los elementos siguen la misma estructura.

Ese es precisamente el problema que resuelve th:each.

🟥 Convertir la plantilla en un programa complejo​

Una expresión como:

Condición sencilla
<p th:if="${producto.stock > 0}">Disponible</p>

es adecuada.

Si necesitamos muchas condiciones encadenadas, transformaciones o cálculos, debemos preguntarnos si esa información debería llegar ya preparada desde Java.

🟪 Confundir una condición visual con seguridad​

Este código:

Ocultar un enlace
<a th:if="${puedeEditar}" th:href="@{/editar}">
    Editar
</a>

puede evitar que el enlace aparezca en la página, pero no protege por sí mismo la ruta /editar.

La autorización real debe comprobarse en el servidor cuando estudiemos seguridad.
