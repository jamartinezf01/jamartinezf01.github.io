3.4 Fragmentos y reutilización de plantillas

A medida que una aplicación crece, es habitual que varias páginas compartan elementos como la cabecera, el menú de navegación o el pie de página.

Podríamos copiar esos bloques en todas las plantillas, pero pronto aparecería un problema: cada vez que quisiéramos cambiar uno de ellos tendríamos que modificar varios archivos.

Thymeleaf permite evitar esta repetición mediante fragmentos reutilizables.

Idea principal

Un fragmento es una parte de una plantilla que puede definirse una sola vez y reutilizarse desde otras vistas.

En esta unidad trabajaremos principalmente con:

th:fragment
th:replace

1️⃣ El problema de repetir HTML​

Supongamos que nuestra aplicación tiene estas tres vistas:

Plantillas de la aplicación
inicio.html
catalogo.html
detalle-producto.html

Todas necesitan mostrar el mismo menú:

Navegación repetida
<nav>
    <a th:href="@{/}">Inicio</a>
    <a th:href="@{/catalogo}">Catálogo</a>
    <a th:href="@{/contacto}">Contacto</a>
</nav>

Podríamos copiar ese código en las tres páginas, pero estaríamos duplicando la misma estructura.

Si más adelante añadimos una nueva opción:

Novedades

tendríamos que recordar modificar todas las plantillas.

Problema
inicio.html
    └── menú

catalogo.html
    └── menú

detalle-producto.html
    └── menú
aviso

Copiar y pegar pequeñas cantidades de HTML puede parecer cómodo al principio, pero cuanto más se repite una estructura, más difícil resulta mantenerla.

La solución será definir el menú una sola vez y reutilizarlo.

2️⃣ Crear un fragmento con th:fragment​

Podemos crear una carpeta específica para los elementos reutilizables:

Organización de plantillas
src/main/resources/templates/
├── fragments/
│   └── cabecera.html
├── inicio.html
├── catalogo.html
└── detalle-producto.html

Dentro de cabecera.html podemos definir un fragmento:

fragments/cabecera.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">

<body>

<header th:fragment="cabecera">

    <h1>Inventario Arcano</h1>

    <nav>
        <a th:href="@{/}">Inicio</a>
        <a th:href="@{/catalogo}">Catálogo</a>
        <a th:href="@{/contacto}">Contacto</a>
    </nav>

</header>

</body>
</html>

La parte importante es:

Definición del fragmento
<header th:fragment="cabecera">

Con th:fragment estamos dando un nombre al bloque reutilizable.

En este caso el nombre es:

cabecera
en este ejemplo

El archivo se llama cabecera.html, pero el fragmento también necesita un nombre propio.

Esto permite que un mismo archivo pueda contener varios fragmentos si fuese necesario.

3️⃣ Utilizar un fragmento con th:replace​

Una vez definido el fragmento, podemos utilizarlo desde otra plantilla.

Por ejemplo, en catalogo.html:

catalogo.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">

<head>
    <meta charset="UTF-8">
    <title>Catálogo</title>
</head>

<body>

<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

<main>
    <h2>Catálogo de productos</h2>
</main>

</body>
</html>

La expresión:

Referencia al fragmento
~{fragments/cabecera :: cabecera}

se puede leer así:

Interpretación
fragments/cabecera
        ↓
archivo de plantilla

cabecera
        ↓
fragmento que queremos utilizar

No escribimos la extensión .html.

🟩 Qué hace th:replace​

th:replace sustituye completamente el elemento donde aparece por el fragmento seleccionado.

Partimos de:

Plantilla antes de procesarse
<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

y Thymeleaf lo sustituye por el contenido definido en el fragmento:

Resultado simplificado
<header>
    <h1>Inventario Arcano</h1>

    <nav>
        ...
    </nav>
</header>
info

El navegador no recibe th:replace.

Thymeleaf procesa la plantilla en el servidor y envía al navegador el HTML final ya construido.

4️⃣ Reutilizar el mismo fragmento en varias páginas​

Podemos utilizar exactamente la misma expresión en todas las vistas que necesiten la cabecera:

Uso en inicio.html
<header th:replace="~{fragments/cabecera :: cabecera}">
</header>
Uso en catalogo.html
<header th:replace="~{fragments/cabecera :: cabecera}">
</header>
Uso en detalle-producto.html
<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

Ahora la estructura queda así:

Estructura con fragmentos
fragments/cabecera.html
        │
        ├── inicio.html
        ├── catalogo.html
        └── detalle-producto.html

Si modificamos el menú en cabecera.html, el cambio se reflejará en todas las páginas que utilicen ese fragmento.

tip

Los fragmentos resultan especialmente útiles para elementos que aparecen repetidos en muchas vistas:

  • cabeceras.
  • menús de navegación.
  • pies de página.
  • bloques de información comunes.

5️⃣ Crear varios fragmentos​

No estamos limitados a una única parte reutilizable.

Podemos crear también un pie de página:

fragments/pie.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">

<body>

<footer th:fragment="pie">
    <p>Inventario Arcano</p>
</footer>

</body>
</html>

Y utilizarlo desde una vista:

Incluir el pie
<footer th:replace="~{fragments/pie :: pie}">
</footer>

Una página podría quedar así:

Plantilla con cabecera y pie reutilizables
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">

<head>
    <meta charset="UTF-8">
    <title>Detalle de producto</title>
</head>

<body>

<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

<main>

    <h2 th:text="${producto.nombre}">
        Producto
    </h2>

    <p>
        Precio:
        <span th:text="${producto.precio}">0</span>
    </p>

</main>

<footer th:replace="~{fragments/pie :: pie}">
</footer>

</body>
</html>

La parte específica de cada página permanece dentro de <main>, mientras que los elementos comunes se reutilizan.

6️⃣ Un mismo archivo puede contener varios fragmentos​

También podemos agrupar varios fragmentos relacionados dentro de un mismo archivo.

Por ejemplo:

fragments/comunes.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">

<body>

<header th:fragment="cabecera">
    <h1>Inventario Arcano</h1>
</header>

<nav th:fragment="navegacion">
    <a th:href="@{/}">Inicio</a>
    <a th:href="@{/catalogo}">Catálogo</a>
</nav>

<footer th:fragment="pie">
    <p>Inventario Arcano</p>
</footer>

</body>
</html>

Después podemos seleccionar el fragmento concreto que necesitamos:

Usar la cabecera
<header th:replace="~{fragments/comunes :: cabecera}">
</header>
Usar la navegación
<nav th:replace="~{fragments/comunes :: navegacion}">
</nav>
Usar el pie
<footer th:replace="~{fragments/comunes :: pie}">
</footer>
Nombre del archivo y nombre del fragmento

En:

~{fragments/comunes :: navegacion}

fragments/comunes indica dónde está la plantilla.

navegacion indica qué fragmento queremos utilizar dentro de ella.

7️⃣ th:replace frente a copiar y pegar​

La principal ventaja de los fragmentos no es escribir menos código una sola vez, sino mantener una única versión de las partes comunes.

Sin fragmentos:

Sin reutilización
cabecera modificada
        ↓
hay que cambiarla en:
inicio.html
catalogo.html
detalle-producto.html
...

Con fragmentos:

Con reutilización
cabecera modificada
        ↓
fragments/cabecera.html
        ↓
todas las páginas utilizan la nueva versión

Esto hace que las plantillas sean más fáciles de mantener y reduce errores por diferencias entre páginas.

8️⃣ Qué debe ir en un fragmento​

No todo debe convertirse en fragmento.

Tiene sentido extraer una parte cuando:

  • aparece en varias páginas.
  • representa una sección claramente identificable.
  • queremos mantenerla desde un único lugar.
  • su reutilización hace las plantillas más fáciles de leer.

Por ejemplo, una cabecera común es una buena candidata:

Buen candidato a fragmento
<header>
    ...
</header>

En cambio, un pequeño texto utilizado una sola vez no necesita convertirse en un fragmento.

aviso

Crear fragmentos para cada pequeño elemento puede hacer que una plantilla sea más difícil de seguir.

El objetivo es reutilizar estructuras comunes, no dividir el HTML en piezas innecesariamente pequeñas.

9️⃣ Fragmentos y datos dinámicos​

Un fragmento también puede utilizar datos disponibles en el Model.

Supongamos que el controlador añade:

Dato enviado al Model
model.addAttribute("tituloAplicacion", "Inventario Arcano");

El fragmento puede acceder a ese atributo igual que cualquier otra parte de una plantilla:

Fragmento con un dato dinámico
<header th:fragment="cabecera">

    <h1 th:text="${tituloAplicacion}">
        Aplicación
    </h1>

</header>
info

Los fragmentos siguen formando parte de la plantilla que Thymeleaf está procesando.

Por tanto, pueden utilizar expresiones ${...}, enlaces @{...} y otros atributos de Thymeleaf igual que el resto de la vista.

En esta unidad no necesitamos crear fragmentos con parámetros ni mecanismos más avanzados. Nos basta con comprender cómo definir una parte reutilizable y utilizarla desde distintas plantillas.

🔟 Ejemplo: reorganizar Inventario Arcano​

Imaginemos que tenemos:

Situación inicial
catalogo.html
detalle-producto.html
resultado-busqueda.html

y las tres páginas contienen la misma cabecera y navegación.

Podemos reorganizar las plantillas así:

Estructura reorganizada
templates/
├── fragments/
│   ├── cabecera.html
│   └── pie.html
├── catalogo.html
├── detalle-producto.html
└── resultado-busqueda.html

En cabecera.html:

fragments/cabecera.html
<header th:fragment="cabecera">

    <h1>Inventario Arcano</h1>

    <nav>
        <a th:href="@{/}">Inicio</a>
        <a th:href="@{/catalogo}">Catálogo</a>
        <a th:href="@{/gremio}">Gremio</a>
        <a th:href="@{/contacto}">Contacto</a>
    </nav>

</header>

En cada vista:

Uso de la cabecera común
<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

Y para el pie:

Uso del pie común
<footer th:replace="~{fragments/pie :: pie}">
</footer>

De esta forma:

Resultado
cabecera.html
     ↓
misma navegación para todas las vistas

cada página
     ↓
mantiene únicamente su contenido específico

pie.html
     ↓
mismo pie para todas las vistas

1️⃣1️⃣ Errores frecuentes​

🟩 Repetir el mismo código aunque ya existe un fragmento​

Si hemos creado una cabecera común, no tiene sentido volver a escribirla manualmente en algunas páginas.

La finalidad del fragmento es que exista una única versión de esa estructura.

🟨 Escribir la extensión .html​

No necesitamos:

Referencia incorrecta
th:replace="~{fragments/cabecera.html :: cabecera}"

Utilizaremos:

Referencia al fragmento
th:replace="~{fragments/cabecera :: cabecera}"

🟧 Confundir el archivo con el nombre del fragmento​

En:

Referencia completa
~{fragments/cabecera :: cabecera}

la primera parte localiza la plantilla y la segunda selecciona el fragmento definido mediante th:fragment.

🟥 Olvidar xmlns:th​

Las plantillas que utilizan atributos de Thymeleaf deben mantener:

Declaración de Thymeleaf
<html lang="es" xmlns:th="http://www.thymeleaf.org">

🟪 Crear demasiados fragmentos​

No necesitamos convertir cada <div>, <p> o pequeño bloque en un fragmento independiente.

Conviene reservarlos para estructuras realmente reutilizables y que tengan sentido como parte común de la interfaz.
