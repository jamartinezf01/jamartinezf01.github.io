3.4 Fragmentos y reutilización de plantillas

A medida que una aplicación incorpora más vistas, es habitual que algunas partes de la interfaz se repitan: una cabecera, un menú de navegación, un pie de página o un bloque de encabezado.

Copiar esas estructuras en varias plantillas funciona al principio, pero complica el mantenimiento. Si cambiamos un enlace o un texto común, tendríamos que modificar todas las copias.

Thymeleaf evita esa duplicación mediante fragmentos reutilizables.

Idea principal

Un fragmento es una parte de una plantilla que definimos una vez y reutilizamos desde otras vistas.

En este apartado trabajaremos con:

Atributos principales
th:fragment
th:replace
th:insert

1️⃣ Definir un fragmento​

Supongamos que varias páginas necesitan la misma cabecera. Podemos guardarla en un archivo independiente:

Organización de plantillas
src/main/resources/templates/
├── fragments/
│   └── cabecera.html
├── inicio.html
├── productos.html
└── producto.html

En fragments/cabecera.html definimos el fragmento:

fragments/cabecera.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<body>

<header th:fragment="cabecera">

    <h1>Catálogo de productos</h1>

    <nav>
        <a th:href="@{/}">Inicio</a>
        <a th:href="@{/productos}">Productos</a>
    </nav>

</header>

</body>
</html>

La parte fundamental es:

Definición del fragmento
<header th:fragment="cabecera">

th:fragment asigna un nombre al bloque que queremos reutilizar.

en este ejemplo

El archivo se llama cabecera.html, pero el fragmento tiene además un nombre propio: cabecera.

Esto permite indicar de forma explícita qué bloque queremos reutilizar.

2️⃣ Reutilizar un fragmento​

Para incorporar un fragmento a otra plantilla podemos utilizar th:replace o th:insert.

🟩 th:replace​

Reutilizar una cabecera
<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

La referencia:

Referencia al fragmento
fragments/cabecera :: cabecera

se interpreta así:

fragments/cabecera   → plantilla donde está definido
cabecera             → fragmento que queremos utilizar

No escribimos la extensión .html.

th:replace sustituye completamente el elemento donde aparece por el fragmento seleccionado.

Si escribimos:

Elemento que será sustituido
<div th:replace="~{fragments/cabecera :: cabecera}">
</div>

el <div> desaparece y en su lugar se genera el <header> definido en el fragmento.

🟨 th:insert​

También podemos escribir:

Insertar un fragmento
<div th:insert="~{fragments/cabecera :: cabecera}">
</div>

En este caso el <div> se conserva y el fragmento se inserta dentro.

La diferencia puede resumirse así:

AtributoResultado
th:replaceSustituye el elemento exterior por el fragmento.
th:insertConserva el elemento exterior e inserta el fragmento dentro.
consejo

Para cabeceras, menús y pies suele resultar más limpio th:replace.

Utilizaremos th:insert cuando queramos conservar deliberadamente el elemento exterior.

información

El navegador no recibe th:fragment, th:replace ni th:insert.

Thymeleaf procesa estas instrucciones en el servidor y envía HTML normal.

3️⃣ Organizar partes comunes​

Una aplicación puede reutilizar varias zonas de la interfaz.

Por ejemplo:

Estructura de fragmentos
templates/
├── fragments/
│   ├── cabecera.html
│   └── pie.html
├── inicio.html
├── productos.html
└── producto.html

El pie puede definirse así:

fragments/pie.html
<footer th:fragment="pie">
    <p>Catálogo de productos</p>
</footer>

Y reutilizarse desde cualquier vista:

Reutilizar el pie
<footer th:replace="~{fragments/pie :: pie}">
</footer>

🟩 Varios fragmentos en un mismo archivo​

También podemos definir varios fragmentos dentro de una misma plantilla:

fragments/comunes.html
<header th:fragment="cabecera">
    <h1>Catálogo de productos</h1>
</header>

<nav th:fragment="navegacion">
    <a th:href="@{/}">Inicio</a>
    <a th:href="@{/productos}">Productos</a>
</nav>

<footer th:fragment="pie">
    <p>Catálogo de productos</p>
</footer>

Después seleccionamos el que necesitamos por su nombre:

Seleccionar un fragmento
<nav th:replace="~{fragments/comunes :: navegacion}">
</nav>

Para empezar, suele resultar más claro mantener en archivos separados las zonas principales de la interfaz.

4️⃣ Fragmentos con datos dinámicos​

Un fragmento forma parte de la vista que Thymeleaf está procesando y puede utilizar datos dinámicos.

🟩 Utilizar datos del Model​

Si el controlador añade:

Dato enviado al Model
model.addAttribute("tituloAplicacion", "Catálogo de productos");

el fragmento puede utilizarlo:

Fragmento con datos del Model
<header th:fragment="cabecera">
    <h1 th:text="${tituloAplicacion}">
        Catálogo
    </h1>
</header>

Los fragmentos pueden utilizar las mismas expresiones Thymeleaf que el resto de la plantilla: ${...}, @{...}, th:text, th:href, th:src, condiciones o clases dinámicas.

🟨 Recibir parámetros​

A veces queremos reutilizar la misma estructura, pero con contenidos diferentes en cada página.

Podemos definir parámetros en el propio fragmento:

Fragmento parametrizado
<section th:fragment="encabezado(titulo, subtitulo)">
    <h1 th:text="${titulo}">Título</h1>
    <p th:text="${subtitulo}">Subtítulo</p>
</section>

Los parámetros son:

Parámetros
titulo
subtitulo

Podemos pasar valores directamente:

Pasar valores al fragmento
<section th:replace="~{fragments/comunes :: encabezado(
        'Productos disponibles',
        'Consulta nuestro catálogo'
    )}">
</section>

La misma estructura puede reutilizarse con otros valores:

Reutilizar con otros parámetros
<section th:replace="~{fragments/comunes :: encabezado(
        'Detalle del producto',
        'Información del producto seleccionado'
    )}">
</section>

🟧 Pasar valores del Model​

También podemos utilizar atributos del Model como argumentos:

Controlador
model.addAttribute("tituloPagina", "Productos disponibles");
model.addAttribute("descripcionPagina", "Consulta nuestro catálogo");
Parámetros procedentes del Model
<section th:replace="~{fragments/comunes :: encabezado(
        ${tituloPagina},
        ${descripcionPagina}
    )}">
</section>
en este ejemplo

El fragmento define la estructura reutilizable.

La plantilla que lo utiliza decide qué valores recibe.

Esto permite reutilizar una misma estructura sin obligarnos a mostrar siempre el mismo contenido.

consejo

No todos los fragmentos necesitan parámetros.

Una cabecera o un pie completamente comunes pueden reutilizarse sin ellos.

5️⃣ Cuándo conviene utilizar fragmentos​

Tiene sentido crear un fragmento cuando una parte:

  • aparece en varias vistas.
  • representa una zona claramente identificable de la interfaz.
  • debe mantenerse desde un único lugar.
  • reutiliza la misma estructura con contenidos diferentes.

Cabeceras, menús, pies o encabezados de página suelen ser buenos candidatos.

aviso

No conviene convertir cada <div>, <p> o enlace en un fragmento.

El objetivo es reutilizar estructuras comunes con sentido, no dividir el HTML en piezas innecesariamente pequeñas.

6️⃣ Errores frecuentes​

🟩 Confundir archivo y nombre del fragmento​

En:

Referencia completa
~{fragments/cabecera :: cabecera}

la primera parte localiza la plantilla y la segunda selecciona el fragmento.

🟨 Escribir la extensión .html​

Evitaremos:

Referencia incorrecta
th:replace="~{fragments/cabecera.html :: cabecera}"

Utilizaremos:

Referencia correcta
th:replace="~{fragments/cabecera :: cabecera}"

🟧 Confundir th:replace y th:insert​

th:replace sustituye el elemento exterior.

th:insert lo conserva e introduce el fragmento dentro.

Elegir uno u otro sin tener en cuenta esta diferencia puede provocar contenedores innecesarios.

🟥 No proporcionar los parámetros definidos​

Si un fragmento declara:

Fragmento con parámetros
<section th:fragment="encabezado(titulo, subtitulo)">

debemos pasar ambos valores cuando lo reutilizamos.

🟪 Seguir copiando HTML después de crear el fragmento​

Si una cabecera ya existe como fragmento, las demás plantillas deben reutilizarla.

Mantener copias manuales volvería a introducir el problema de mantenimiento que queríamos evitar.
