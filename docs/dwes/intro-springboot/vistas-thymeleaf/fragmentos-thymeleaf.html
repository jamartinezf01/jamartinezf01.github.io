3.4 Fragmentos y reutilización de plantillas

A medida que una aplicación incorpora más vistas, es normal que algunas partes se repitan: una cabecera, un menú de navegación, un pie de página o determinados bloques comunes.

Podríamos copiar ese HTML en todas las plantillas, pero aparecería un problema de mantenimiento: cualquier cambio tendría que repetirse en varios archivos.

Thymeleaf permite resolverlo mediante fragmentos reutilizables.

Idea principal

Un fragmento es una parte de una plantilla que definimos una sola vez y que después podemos reutilizar desde otras vistas.

En este apartado trabajaremos principalmente con:

Atributos principales
th:fragment
th:replace

1️⃣ Por qué necesitamos fragmentos​

Continuamos con el mismo ejemplo utilizado en los apartados anteriores: una pequeña aplicación de productos con distintas vistas.

Podríamos tener esta estructura:

Plantillas de la aplicación
src/main/resources/templates/
├── inicio.html
├── productos.html
└── producto.html

Las tres páginas pueden necesitar el mismo encabezado:

Cabecera repetida
<header>
    <h1>Catálogo de productos</h1>

    <nav>
        <a th:href="@{/}">Inicio</a>
        <a th:href="@{/productos}">Productos</a>
        <a th:href="@{/contacto}">Contacto</a>
    </nav>
</header>

Si copiamos este bloque en todas las vistas, cualquier modificación del menú obliga a cambiar varios archivos.

Por ejemplo, añadir un nuevo enlace implicaría localizar todas las copias de la cabecera y mantenerlas sincronizadas.

La idea que buscamos es distinta:

aviso

Los fragmentos no sirven para dividir una página en muchas piezas pequeñas sin necesidad.

Su utilidad aparece cuando una estructura se repite y queremos mantener una única versión de ella.

2️⃣ Definir y reutilizar un fragmento​

Vamos a extraer la cabecera común a un archivo independiente.

Podemos organizar las plantillas así:

Organización con fragmentos
src/main/resources/templates/
├── fragments/
│   └── cabecera.html
├── inicio.html
├── productos.html
└── producto.html

🟩 Definir el fragmento con th:fragment​

En fragments/cabecera.html escribimos la estructura reutilizable:

fragments/cabecera.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<body>

<header th:fragment="cabecera">

    <h1>Catálogo de productos</h1>

    <nav>
        <a th:href="@{/}">Inicio</a>
        <a th:href="@{/productos}">Productos</a>
        <a th:href="@{/contacto}">Contacto</a>
    </nav>

</header>

</body>
</html>

La parte importante es:

Definición del fragmento
<header th:fragment="cabecera">

th:fragment asigna un nombre al bloque que queremos reutilizar.

En este caso el fragmento se llama:

cabecera
en este ejemplo

El archivo se llama cabecera.html, pero el fragmento necesita además un nombre propio.

Esto permite seleccionar de forma explícita qué parte de una plantilla queremos reutilizar.

🟨 Reutilizarlo con th:replace​

En productos.html podemos sustituir una cabecera escrita manualmente por:

productos.html
<header th:replace="~{fragments/cabecera :: cabecera}">
</header>
en este ejemplo

La expresión se puede leer así:

fragments/cabecera
        ↓
plantilla donde está definido

cabecera
        ↓
fragmento que queremos utilizar

No escribimos la extensión .html.

th:replace sustituye completamente el elemento donde aparece por el fragmento seleccionado.

Por tanto, este código:

<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

terminará generando un HTML equivalente a:

<header>
    <h1>Catálogo de productos</h1>

    <nav>
        <a href="/">Inicio</a>
        <a href="/productos">Productos</a>
        <a href="/contacto">Contacto</a>
    </nav>
</header>
info

El navegador no recibe th:fragment ni th:replace.

Thymeleaf procesa estas instrucciones en el servidor y envía HTML normal en la respuesta.

3️⃣ Organizar las partes comunes de la interfaz​

Una aplicación puede reutilizar más de una zona común.

Por ejemplo, además de la cabecera podemos crear un pie de página:

Estructura de plantillas
templates/
├── fragments/
│   ├── cabecera.html
│   └── pie.html
├── inicio.html
├── productos.html
└── producto.html

🟩 Un fragmento para el pie​

Podemos definir:

fragments/pie.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<body>

<footer th:fragment="pie">
    <p>Catálogo de productos</p>
</footer>

</body>
</html>

Y utilizarlo en una vista:

Reutilizar el pie
<footer th:replace="~{fragments/pie :: pie}">
</footer>

Una plantilla completa podría quedar así:

producto.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Detalle del producto</title>
</head>
<body>

<header th:replace="~{fragments/cabecera :: cabecera}">
</header>

<main>

    <h2 th:text="${producto.nombre}">
        Nombre del producto
    </h2>

    <p>
        Precio:
        <span th:text="${producto.precio}">0</span> €
    </p>

</main>

<footer th:replace="~{fragments/pie :: pie}">
</footer>

</body>
</html>

🟨 Varios fragmentos en un mismo archivo​

También es posible definir varios fragmentos dentro de una misma plantilla.

Por ejemplo:

fragments/comunes.html
<header th:fragment="cabecera">
    <h1>Catálogo de productos</h1>
</header>

<nav th:fragment="navegacion">
    <a th:href="@{/}">Inicio</a>
    <a th:href="@{/productos}">Productos</a>
</nav>

<footer th:fragment="pie">
    <p>Catálogo de productos</p>
</footer>

Podríamos seleccionar cada uno por su nombre:

Seleccionar un fragmento concreto
<nav th:replace="~{fragments/comunes :: navegacion}">
</nav>

No necesitamos utilizar esta organización siempre. Para empezar, suele resultar más fácil mantener archivos como cabecera.html y pie.html separados.

4️⃣ Fragmentos y datos dinámicos​

Un fragmento sigue formando parte de la vista que Thymeleaf está procesando. Por eso puede acceder a los datos disponibles en el Model.

Supongamos que un controlador añade:

Dato añadido al Model
model.addAttribute("tituloAplicacion", "Catálogo de productos");

El fragmento puede utilizar ese dato:

Fragmento con contenido dinámico
<header th:fragment="cabecera">

    <h1 th:text="${tituloAplicacion}">
        Catálogo
    </h1>

    <nav>
        <a th:href="@{/}">Inicio</a>
        <a th:href="@{/productos}">Productos</a>
    </nav>

</header>

También puede utilizar otras expresiones Thymeleaf que ya conocemos, como:

Expresiones que pueden aparecer en un fragmento
${...}
@{...}
th:text
th:href
th:src
info

Un fragmento no es un tipo especial de página.

Es una parte reutilizable de una plantilla y puede utilizar las mismas expresiones Thymeleaf que el resto de la vista.

Por ahora no necesitamos fragmentos con parámetros ni mecanismos más avanzados. Nuestro objetivo es dominar dos operaciones:

Objetivo de este apartado
definir → th:fragment
reutilizar → th:replace

🟩 Cuándo conviene crear un fragmento​

Tiene sentido extraer una parte cuando:

  • aparece en varias vistas.
  • representa una zona claramente identificable de la interfaz.
  • queremos modificarla desde un único lugar.
  • su reutilización hace las plantillas más fáciles de mantener.

Una cabecera, un menú o un pie suelen ser buenos candidatos.

En cambio, un pequeño bloque que aparece una sola vez no necesita convertirse en fragmento.

5️⃣ Errores frecuentes​

🟩 Confundir el archivo con el nombre del fragmento​

En:

Referencia completa
~{fragments/cabecera :: cabecera}

la primera parte localiza la plantilla y la segunda selecciona el fragmento definido mediante th:fragment.

🟨 Escribir la extensión .html​

No utilizaremos:

Referencia que evitaremos
th:replace="~{fragments/cabecera.html :: cabecera}"

Trabajaremos con:

Referencia al fragmento
th:replace="~{fragments/cabecera :: cabecera}"

🟧 Seguir copiando el HTML después de crear el fragmento​

Si la cabecera ya existe como fragmento, las demás plantillas deben reutilizarla.

Mantener algunas copias manuales volvería a introducir el mismo problema que queríamos resolver.

🟥 Olvidar la declaración de Thymeleaf​

Las plantillas que utilizan atributos th:* deben incluir:

Declaración de Thymeleaf
<html lang="es" xmlns:th="http://www.thymeleaf.org">

🟪 Crear fragmentos innecesariamente pequeños​

No necesitamos convertir cada <div>, <p> o enlace en un fragmento independiente.

La finalidad es reutilizar estructuras comunes con sentido, no dividir el HTML en piezas cada vez más pequeñas.
