3.1 Modelo y datos de la vista

Hasta ahora hemos utilizado controladores para atender rutas y recibir información desde la URL. El siguiente paso consiste en hacer que una página HTML pueda mostrar datos preparados por el controlador.

En Spring MVC, esa comunicación entre el controlador y la vista se realiza habitualmente mediante un objeto Model.

Idea principal

Cuando un controlador devuelve una vista, Model permite acompañarla con los datos que Thymeleaf necesitará para generar el HTML final.

1️⃣ Del controlador a la vista​

Supongamos que el navegador solicita:

Petición
/productos/7

El controlador puede obtener el identificador, preparar los datos del producto y enviarlos a una plantilla.

En este punto no necesitamos una base de datos. Los datos pueden construirse directamente en Java para centrarnos en cómo llegan hasta la vista.

2️⃣ Qué es Model​

Model es una interfaz de Spring MVC que actúa como contenedor de los datos que el controlador pone a disposición de la vista.

Su clase pertenece al paquete:

Import de Model
import org.springframework.ui.Model;

Spring puede proporcionarlo directamente como parámetro del método:

ProductoController.java
@GetMapping("/productos/{id}")
public String detalle(@PathVariable int id, Model model) {
    return "producto";
}

Aquí:

  • id procede de la petición HTTP.
  • model lo proporciona Spring MVC.

No necesitamos crear el objeto manualmente.

Código incorrecto
// No debemos hacer esto
Model model = new Model();

Model es una interfaz y Spring se encarga de proporcionar la implementación necesaria.

Importante

Model no representa una página HTML ni genera la respuesta.

Su función es mantener los datos que estarán disponibles mientras Thymeleaf procesa la vista.

3️⃣ Añadir datos con addAttribute()​

La operación que utilizaremos con más frecuencia es:

Añadir un atributo al modelo
model.addAttribute("nombre", valor);

Cada atributo tiene:

  • un nombre, que utilizará la vista para localizarlo.
  • un valor, que es el dato que queremos enviar.

Por ejemplo:

ProductoController.java
@Controller
public class ProductoController {

    @GetMapping("/productos/{id}")
    public String detalle(@PathVariable int id, Model model) {

        model.addAttribute("id", id);
        model.addAttribute("nombre", "Teclado mecánico");
        model.addAttribute("precio", 79.90);

        return "producto";
    }
}

El contenido del Model podría imaginarse así:

NombreValor
id7
nombre"Teclado mecánico"
precio79.90

Los valores no tienen que ser únicamente String. Podemos enviar números, booleanos, objetos Java o colecciones.

🟩 El nombre del atributo importa​

Si escribimos:

Controlador
model.addAttribute("nombreProducto", "Teclado mecánico");

la vista deberá utilizar exactamente:

${nombreProducto}

nombre y nombreProducto serían atributos distintos.

consejo

Conviene utilizar nombres claros y coherentes con el dato que contienen.

4️⃣ Recuperar datos desde Thymeleaf​

Supongamos que el controlador añade:

Datos enviados a la vista
model.addAttribute("nombre", "Teclado mecánico");
model.addAttribute("precio", 79.90);

return "producto";

y tenemos:

Plantilla
src/main/resources/templates/producto.html

Podemos mostrar esos valores con th:text:

producto.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Detalle del producto</title>
</head>
<body>

    <h1 th:text="${nombre}">
        Nombre del producto
    </h1>

    <p>
        Precio:
        <span th:text="${precio}">0</span> €
    </p>

</body>
</html>

La declaración:

Declaración de Thymeleaf
<html lang="es" xmlns:th="http://www.thymeleaf.org">

identifica los atributos th:* que Thymeleaf procesará en el servidor. No necesitamos profundizar ahora en los espacios de nombres XML.

La expresión:

Expresión básica
th:text="${nombre}"

indica que Thymeleaf debe sustituir el contenido del elemento por el atributo nombre disponible en la vista.

Existe, por tanto, una relación directa:

Correspondencia
model.addAttribute("nombre", "Teclado mecánico")
                         ↓
                     ${nombre}

🟨 Contenido HTML de respaldo​

En:

Contenido de respaldo
<h1 th:text="${nombre}">
    Nombre del producto
</h1>

Nombre del producto es HTML normal.

Cuando Thymeleaf procesa la plantilla, ese contenido se sustituye por el valor de ${nombre}.

Si el controlador envía:

Dato del modelo
model.addAttribute("nombre", "Teclado mecánico");

el navegador recibirá un resultado equivalente a:

HTML resultante
<h1>Teclado mecánico</h1>
aviso

El navegador recibe HTML ya generado.

No recibe th:text, ${...} ni otras instrucciones Thymeleaf pendientes de procesar.

5️⃣ El flujo completo de una petición​

Podemos reunir todo el proceso con una petición como:

Petición
GET /productos/7?moneda=eur

El controlador recibe los datos de la petición, prepara la información de la vista y la añade al Model:

ProductoController.java
@Controller
@RequestMapping("/productos")
public class ProductoController {

    @GetMapping("/{id}")
    public String detalle(
            @PathVariable int id,
            @RequestParam(defaultValue = "eur") String moneda,
            Model model) {

        String nombre = "Teclado mecánico";
        double precio = 79.90;

        model.addAttribute("id", id);
        model.addAttribute("nombre", nombre);
        model.addAttribute("precio", precio);
        model.addAttribute("moneda", moneda);

        return "producto";
    }
}

La plantilla podrá utilizar esos atributos:

producto.html
<h1 th:text="${nombre}">Nombre</h1>

<p>
    Identificador:
    <span th:text="${id}">0</span>
</p>

<p>
    Precio:
    <span th:text="${precio}">0</span>
    <span th:text="${moneda}">eur</span>
</p>

El recorrido es:

Recorrido de los datos
petición HTTP
      ↓
@PathVariable / @RequestParam
      ↓
controlador
      ↓
Model
      ↓
plantilla Thymeleaf
      ↓
HTML generado
      ↓
respuesta HTTP

La URL contiene información de la petición, el controlador decide qué hacer con ella y la vista se encarga de presentar el resultado.

6️⃣ Enviar un objeto completo a la vista​

En ejemplos pequeños podemos enviar varios atributos independientes. Sin embargo, cuando los datos están relacionados suele ser más natural agruparlos en un objeto.

Por ejemplo:

Producto.java
public class Producto {

    private int id;
    private String nombre;
    private double precio;

    public Producto(int id, String nombre, double precio) {
        this.id = id;
        this.nombre = nombre;
        this.precio = precio;
    }

    public int getId() {
        return id;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }
}

El controlador puede añadir el objeto completo:

ProductoController.java
@GetMapping("/{id}")
public String detalle(@PathVariable int id, Model model) {

    Producto producto =
            new Producto(id, "Teclado mecánico", 79.90);

    model.addAttribute("producto", producto);

    return "producto";
}

La vista accede a sus propiedades:

producto.html
<h1 th:text="${producto.nombre}">
    Nombre
</h1>

<p>
    Código:
    <span th:text="${producto.id}">0</span>
</p>

<p>
    Precio:
    <span th:text="${producto.precio}">0</span> €
</p>

🟩 Propiedades y getters​

Cuando escribimos:

Acceso a una propiedad
${producto.nombre}

Thymeleaf interpreta nombre como una propiedad JavaBean y obtiene su valor mediante getNombre().

La correspondencia es:

Propiedades JavaBean
${producto.id}      → getId()
${producto.nombre}  → getNombre()
${producto.precio}  → getPrecio()

Por eso utilizaremos:

${producto.nombre}

y no:

${producto.getNombre()}

para acceder normalmente a una propiedad desde la plantilla.

nota

Producto es aquí una clase Java sencilla utilizada para representar datos.

No estamos introduciendo todavía entidades JPA, repositorios, DTO ni persistencia.

7️⃣ Qué significa devolver una vista​

Cuando un método de un @Controller devuelve:

Nombre lógico de la vista
return "producto";

Spring MVC no envía la palabra producto al navegador.

El proceso simplificado es:

  1. Spring ejecuta el método asociado a la petición.
  2. El controlador añade los datos necesarios al Model.
  3. "producto" se interpreta como el nombre lógico de una vista.
  4. Spring localiza la plantilla.
  5. Thymeleaf la procesa utilizando los datos del modelo.
  6. Se genera HTML normal.
  7. Ese HTML se envía al navegador.

Con la configuración habitual:

Nombre lógico y archivo
return "producto"
        ↓
src/main/resources/templates/producto.html

No utilizaremos:

Formas incorrectas
return "producto.html";
return "templates/producto.html";

🟩 Model pertenece a una petición concreta​

Los atributos del Model sirven para generar la respuesta de esa petición.

Por ejemplo:

Primera petición
/productos/4

puede generar un modelo con:

id = 4

y una petición posterior:

Segunda petición
/productos/9

generará los datos necesarios para esa nueva respuesta.

aviso

Model no es un almacenamiento permanente ni una variable global compartida por todos los usuarios.

No sustituye a una base de datos, una sesión ni ningún mecanismo de persistencia.

8️⃣ Model y una clase de datos no son lo mismo​

La palabra modelo puede resultar confusa porque aparece con distintos significados.

En este apartado utilizamos:

Model de Spring MVC
org.springframework.ui.Model

para entregar información a la vista.

Por otra parte, podemos tener clases propias como:

Clases de nuestra aplicación
Producto
Usuario
Ruta
Evento

que representan datos del dominio de la aplicación.

Por ejemplo:

Objeto dentro del Model
Producto producto =
        new Producto(7, "Teclado mecánico", 79.90);

model.addAttribute("producto", producto);

Aquí:

  • Producto representa un dato de nuestra aplicación.
  • Model es el mecanismo utilizado para entregar ese dato a la vista.

No son el mismo concepto.

9️⃣ Errores frecuentes​

🟩 Utilizar nombres distintos en el controlador y en la vista​

Controlador:

Controlador
model.addAttribute("nombreProducto", "Teclado");

Vista:

Vista
<span th:text="${nombre}">
    Producto
</span>

nombre y nombreProducto son atributos diferentes.

🟨 Utilizar @ResponseBody cuando queremos devolver una vista​

Incorrecto:

Código incorrecto
@GetMapping("/producto")
@ResponseBody
public String producto(Model model) {
    model.addAttribute("nombre", "Teclado");
    return "producto";
}

Con @ResponseBody, el navegador recibiría:

producto

en lugar de renderizar producto.html.

Para devolver una vista Thymeleaf:

Controlador correcto
@GetMapping("/producto")
public String producto(Model model) {
    model.addAttribute("nombre", "Teclado");
    return "producto";
}
aviso

Cuando un método de un @Controller devuelve el nombre de una vista Thymeleaf, no debe utilizar @ResponseBody.

🟧 Escribir HTML dentro del controlador​

No debemos construir páginas concatenando cadenas:

Código que debemos evitar
@GetMapping("/producto")
@ResponseBody
public String producto() {
    return "<h1>Teclado mecánico</h1>"
            + "<p>Precio: 79.90 €</p>";
}

En MVC:

  • el controlador prepara los datos.
  • la plantilla se encarga de presentarlos.

🟥 Pensar que Model almacena datos entre peticiones​

Dato añadido al Model
model.addAttribute("producto", producto);

no guarda permanentemente el objeto. Solo lo pone a disposición de la vista durante esa petición.

🟪 Crear una ruta distinta para cada dato​

No necesitamos:

/producto1
/producto2
/producto3

si la única diferencia es el identificador.

Podemos utilizar:

Patrón de ruta
/productos/{id}

recibir el valor con @PathVariable y preparar el modelo correspondiente.
