3.2 Expresiones Thymeleaf

En el apartado anterior ya utilizamos ${...} y th:text para mostrar en una plantilla los datos añadidos al Model. También vimos cómo acceder a propiedades de objetos, por ejemplo con ${producto.nombre}.

Ahora ampliaremos esa sintaxis para trabajar con valores y construir URL, enlaces y referencias a recursos de forma dinámica.

Idea principal

En este apartado utilizaremos principalmente:

Expresiones principales
${...}  → utilizar datos disponibles en la vista
@{...}  → construir URL de la aplicación y referencias a recursos

1️⃣ Trabajar con valores dentro de ${...}​

Una expresión como:

Acceso a un dato del modelo
<span th:text="${producto.precio}">0</span>

recupera un valor disponible en la vista.

Además de variables y propiedades, podemos utilizar literales y operaciones sencillas.

🟩 Literales​

Podemos escribir valores directamente dentro de una expresión:

Ejemplos de literales
'texto'
42
19.95
true
false

Los textos se escriben normalmente entre comillas simples:

Texto literal
<p th:text="'Catálogo de productos'">Catálogo</p>

Si el contenido es completamente fijo, no necesitamos Thymeleaf:

HTML más sencillo
<p>Catálogo de productos</p>

Utilizaremos expresiones cuando el contenido dependa realmente de datos dinámicos.

🟨 Operaciones aritméticas​

Thymeleaf integrado con Spring permite utilizar expresiones compatibles con Spring Expression Language (SpEL):

Operación aritmética
<span th:text="${producto.precio * 1.21}">0</span>

Los operadores aritméticos habituales son:

OperaciónOperador
Suma+
Resta-
Multiplicación*
División/
Resto%

Estas operaciones resultan adecuadas para transformaciones sencillas de presentación.

aviso

Que una operación pueda escribirse en una plantilla no significa que debamos trasladar allí toda la lógica de la aplicación.

Los cálculos importantes y las decisiones propias del funcionamiento de la aplicación deben realizarse fuera de la vista.

🟧 Comparaciones y operadores lógicos​

También podemos realizar comparaciones:

Comparación
<span th:text="${producto.stock > 0}">false</span>

o combinar condiciones:

Expresión lógica
<span th:text="${producto.disponible and producto.stock > 0}">
    false
</span>

Los operadores más habituales son:

TipoOperadores
Comparación>, <, >=, <=, ==, !=
Lógicosand, or, not

En el siguiente apartado utilizaremos estas expresiones para tomar decisiones dentro de la plantilla.

2️⃣ Diferenciar ${...} y @{...}​

Las dos expresiones tienen funciones distintas:

ExpresiónUso principalEjemplo
${...}Leer o utilizar datos de la vista.${producto.nombre}
@{...}Construir una URL.@{/productos}

Ambas pueden aparecer en una misma etiqueta, pero cumplen funciones diferentes:

URL que utiliza un dato
<a th:href="@{/productos/{id}(id=${producto.id})}">
    Ver producto
</a>

Aquí:

Qué hace cada expresión
${producto.id}  → obtiene el identificador
@{...}          → construye la URL utilizando ese dato

3️⃣ Construir enlaces con th:href​

En HTML podemos escribir una URL directamente:

Enlace HTML
<a href="/productos">Productos</a>

También podemos dejar que Thymeleaf la construya:

Enlace con Thymeleaf
<a th:href="@{/productos}">Productos</a>

Después del procesamiento, el navegador recibe HTML normal:

HTML generado
<a href="/productos">Productos</a>
Idea principal

href y src pertenecen a HTML y contienen una URL ya escrita.

th:href y th:src pertenecen a Thymeleaf y permiten construir esa URL antes de enviar el HTML al navegador.

La expresión @{...} indica qué URL debe generar Thymeleaf.

🟩 ¿Por qué utilizar @{...}?​

Una URL fija como esta es válida:

URL fija
<a href="/productos">Productos</a>

Pero @{...} resulta especialmente útil cuando:

  • la URL contiene datos del Model.
  • necesitamos parámetros de consulta.
  • necesitamos variables dentro de la ruta.
  • queremos referenciar recursos de la aplicación.
  • la aplicación puede desplegarse bajo un contexto distinto de la raíz.

Por ejemplo:

URL dinámica
<a th:href="@{/productos/{id}(id=${producto.id})}">
    Ver producto
</a>

Si producto.id vale 7, Thymeleaf generará:

HTML generado
<a href="/productos/7">
    Ver producto
</a>

🟨 El contexto de la aplicación​

Durante el desarrollo solemos ejecutar la aplicación en:

Aplicación en la raíz
http://localhost:8080/

Pero también podría desplegarse bajo un contexto:

Aplicación bajo un contexto
http://servidor/tienda/

Una URL escrita como:

Ruta absoluta escrita en HTML
<a href="/productos">Productos</a>

parte de la raíz del servidor.

En cambio:

URL de la aplicación
<a th:href="@{/productos}">Productos</a>

permite que Thymeleaf tenga en cuenta el contexto donde está desplegada la aplicación.

No necesitamos configurar ahora un contexto diferente. Lo importante es entender que @{...} expresa una URL perteneciente a nuestra aplicación.

🟧 Contenido HTML de respaldo​

Podemos conservar un href normal junto a th:href:

Enlace con valor de respaldo
<a href="/productos"
   th:href="@{/productos}">
    Productos
</a>

Si Thymeleaf procesa la plantilla, prevalecerá el valor generado por th:href.

No es obligatorio duplicar siempre ambos atributos.

4️⃣ Parámetros y variables en las URL​

Las expresiones @{...} permiten construir URL dinámicas sin concatenar cadenas manualmente.

🟩 Parámetros de consulta​

Si el Model contiene:

Controlador
model.addAttribute("categoria", "teclados");

podemos escribir:

Enlace con parámetro
<a th:href="@{/productos(categoria=${categoria})}">
    Ver teclados
</a>

Thymeleaf generará:

URL generada
/productos?categoria=teclados

Podemos incluir varios parámetros:

Enlace con varios parámetros
<a th:href="@{/productos(
        categoria=${categoria},
        orden=${orden}
    )}">
    Aplicar filtros
</a>

Si:

Datos disponibles
categoria = "teclados"
orden = "precio"

se generará una URL equivalente a:

Resultado
/productos?categoria=teclados&orden=precio
aviso

Cuando utilizamos esta sintaxis no escribimos manualmente ? ni &.

Los parámetros se indican entre paréntesis dentro de @{...}.

🟨 Variables de ruta​

Si el controlador atiende:

ProductoController.java
@GetMapping("/productos/{id}")
public String detalle(@PathVariable int id, Model model) {
    // ...
}

podemos construir el enlace así:

Enlace con variable de ruta
<a th:href="@{/productos/{id}(id=${producto.id})}">
    Ver detalle
</a>

Si producto.id vale 7, Thymeleaf generará:

URL generada
/productos/7

La sintaxis separa claramente:

Estructura y valor
/productos/{id}    → estructura de la ruta
id=${producto.id}  → valor que sustituye {id}

Esto encaja directamente con @PathVariable.

🟧 Combinar ruta y query string​

También podemos combinar ambos mecanismos:

Ruta y parámetro de consulta
<a th:href="@{/productos/{id}(
        id=${producto.id},
        moneda='eur'
    )}">
    Ver precio en euros
</a>

Para un producto con id = 7 puede generarse:

URL resultante
/productos/7?moneda=eur

El controlador puede recibir ambos valores:

ProductoController.java
@GetMapping("/productos/{id}")
public String detalle(
        @PathVariable int id,
        @RequestParam(defaultValue = "eur") String moneda,
        Model model) {
    // ...
}

La relación completa es:

Relación entre vista y controlador
th:href con @{...}
        ↓
/productos/7?moneda=eur
        ↓
petición HTTP
        ↓
@PathVariable int id
@RequestParam String moneda

5️⃣ Referenciar recursos estáticos​

@{...} también permite construir URL para recursos almacenados en static.

Podemos escribir:

Imagen con HTML
<img src="/img/logo-catalogo.png" alt="Logotipo del catálogo">

o:

Imagen con Thymeleaf
<img th:src="@{/img/logo-catalogo.png}" alt="Logotipo del catálogo">

En el segundo caso, Thymeleaf construye la URL como una URL propia de la aplicación.

Supongamos esta estructura:

Recursos del proyecto
src/main/resources/static/
├── css/
│   └── estilos.css
└── img/
    └── logo-catalogo.png

Spring Boot los publica sin incluir static en la URL:

Correspondencia
src/main/resources/static/css/estilos.css
                    ↓
             /css/estilos.css

src/main/resources/static/img/logo-catalogo.png
                    ↓
             /img/logo-catalogo.png
aviso

static forma parte de la estructura interna del proyecto, pero no forma parte de la URL pública.

🟩 CSS con th:href​

Enlace a CSS
<link
    rel="stylesheet"
    th:href="@{/css/estilos.css}">

🟨 Imágenes con th:src​

Imagen estática
<img
    th:src="@{/img/logo-catalogo.png}"
    alt="Logotipo del catálogo">

Podemos quedarnos con esta comparación:

CódigoQuién construye la URLUso habitual
href="/productos"Nosotros.Enlace fijo.
src="/img/logo.png"Nosotros.Recurso fijo.
th:href="@{/productos}"Thymeleaf.Enlace interno.
th:href="@{/productos/{id}(id=${producto.id})}"Thymeleaf con datos de la vista.Enlace dinámico.
th:src="@{/img/logo.png}"Thymeleaf.Recurso de la aplicación.
Para recordar

${...} responde a «¿qué dato quiero utilizar?».

@{...} responde a «¿qué URL quiero construir?».

th:href y th:src indican en qué atributo HTML debe colocarse esa URL.

6️⃣ Combinar texto fijo y valores dinámicos​

Una página suele mezclar contenido fijo con datos procedentes del Model.

La forma más legible suele ser dejar el texto fijo en HTML y utilizar Thymeleaf solo para el dato:

Texto fijo y dato dinámico
<p>
    Precio:
    <span th:text="${producto.precio}">0</span> €
</p>

También podemos concatenar:

Concatenación
<p th:text="'Producto: ' + ${producto.nombre}">
    Producto
</p>
consejo

Si el texto fijo puede escribirse directamente como HTML y el dato dinámico puede aislarse en un <span>, esa solución suele ser más fácil de leer y mantener.

7️⃣ th:text trata los datos como texto​

Supongamos que el Model contiene:

Contenido del atributo
<strong>Oferta</strong>

y la vista utiliza:

Uso de th:text
<p th:text="${mensaje}">Mensaje</p>

th:text trata ese contenido como texto, no como etiquetas HTML que deban formar parte de la página.

Thymeleaf dispone también de th:utext, que inserta contenido HTML sin escapar, pero no lo necesitaremos en esta unidad.

peligro

No utilices th:utext con contenido procedente de usuarios sin comprender previamente sus implicaciones de seguridad.

Para mostrar datos normales utilizaremos th:text.

8️⃣ Errores frecuentes​

🟩 Confundir ${...} y @{...}​

Incorrecto para construir una URL:

Uso incorrecto
<a th:href="${'/productos'}">Productos</a>

Correcto:

Uso correcto
<a th:href="@{/productos}">Productos</a>

${...} se utiliza para datos; @{...} para URL.

🟨 Construir rutas concatenando cadenas​

Evitaremos:

Concatenación poco adecuada
<a th:href="'/productos/' + ${producto.id}">
    Ver detalle
</a>

Utilizaremos:

Variable de ruta
<a th:href="@{/productos/{id}(id=${producto.id})}">
    Ver detalle
</a>

🟧 Escribir manualmente la query string​

Evitaremos:

Query string manual
<a th:href="'/productos?categoria=' + ${categoria}">
    Filtrar
</a>

Utilizaremos:

Parámetro de consulta
<a th:href="@{/productos(categoria=${categoria})}">
    Filtrar
</a>

🟥 Incluir /static en la URL​

Incorrecto:

Ruta incorrecta
<link rel="stylesheet" th:href="@{/static/css/estilos.css}">

Correcto:

Ruta correcta
<link rel="stylesheet" th:href="@{/css/estilos.css}">

🟪 Utilizar un dato que no existe​

Si escribimos:

Expresión
<span th:text="${producto.nombre}">Nombre</span>

la vista necesita un atributo llamado producto con una propiedad accesible llamada nombre.

La expresión no crea ese objeto: debe haber sido preparado previamente por el controlador.
