3.3 Condicionales y bucles

En los apartados anteriores hemos aprendido a enviar datos desde un controlador mediante Model, mostrarlos con Thymeleaf y construir enlaces y rutas dinámicas.

Ahora damos un paso más. Una vista no siempre muestra un único objeto ni exactamente el mismo contenido. En muchas páginas necesitamos recorrer una colección de datos y decidir qué partes del HTML deben aparecer según el valor de esos datos.

Idea principal

Thymeleaf permite generar HTML repetido con th:each y tomar decisiones de presentación mediante atributos como th:if, th:unless o th:switch.

Estas decisiones se toman mientras la plantilla se procesa en el servidor. El navegador recibe después un documento HTML normal.

1️⃣ Cuando una vista recibe una colección​

Hasta ahora hemos enviado a la vista objetos individuales:

Atributo individual enviado al Model
model.addAttribute("producto", producto);

Pero una página de catálogo, una agenda o un listado normalmente necesita trabajar con varios objetos.

Podemos preparar una colección en Java:

ProductoController.java
@GetMapping("/productos")
public String listado(Model model) {

    List<Producto> productos = List.of(
            new Producto(1, "Teclado mecánico", 79.90, 8),
            new Producto(2, "Ratón inalámbrico", 34.50, 0),
            new Producto(3, "Monitor 27 pulgadas", 219.00, 5)
    );

    model.addAttribute("productos", productos);

    return "productos";
}
en este ejemplo

El controlador crea una List<Producto> y la añade al Model con el nombre productos.

La vista no recibe tres atributos independientes. Recibe un único atributo llamado productos cuyo valor es una colección de objetos.

Thymeleaf podrá recorrer esa colección y generar una parte del HTML por cada elemento.

El recorrido que vamos a trabajar es:

2️⃣ Recorrer una colección con th:each​

Para repetir un elemento HTML por cada objeto de una colección utilizamos th:each.

La forma básica es:

Sintaxis básica de th:each
<elemento th:each="elementoActual : ${coleccion}">
    ...
</elemento>

Si el Model contiene:

Atributo enviado a la vista
model.addAttribute("productos", productos);

podemos escribir:

productos.html
<div th:each="producto : ${productos}">
    <h2 th:text="${producto.nombre}">Nombre</h2>
    <p th:text="${producto.precio}">0</p>
</div>

La expresión:

Lectura de la expresión
producto : ${productos}

puede leerse como:

Interpretación
por cada producto de productos

En cada iteración, producto representa uno de los objetos de la colección.

Si existen tres objetos, Thymeleaf procesará el <div> tres veces y generará tres bloques HTML.

Dos nombres diferentes

productos es el nombre del atributo almacenado en el Model.

producto es una variable temporal que representa al objeto actual durante cada iteración de th:each.

Conviene utilizar el plural para la colección y el singular para el elemento actual.

🟩 Repetir filas de una tabla​

th:each puede colocarse sobre cualquier elemento HTML.

Por ejemplo, podemos generar automáticamente las filas de una tabla:

Tabla generada a partir de una colección
<table>
    <thead>
        <tr>
            <th>ID</th>
            <th>Producto</th>
            <th>Precio</th>
        </tr>
    </thead>

    <tbody>
        <tr th:each="producto : ${productos}">
            <td th:text="${producto.id}">0</td>
            <td th:text="${producto.nombre}">Nombre</td>
            <td th:text="${producto.precio}">0</td>
        </tr>
    </tbody>
</table>

No necesitamos escribir manualmente una fila para cada producto. La plantilla describe cómo debe mostrarse un producto y Thymeleaf repite esa estructura tantas veces como sea necesario.

🟨 Generar enlaces dentro de un bucle​

Dentro de una iteración podemos utilizar los datos del objeto actual para construir enlaces diferentes:

Enlace de detalle dentro de th:each
<div th:each="producto : ${productos}">

    <span th:text="${producto.nombre}">
        Producto
    </span>

    <a th:href="@{/productos/{id}(id=${producto.id})}">
        Ver detalle
    </a>

</div>

Si uno de los productos tiene:

Identificador del producto
id = 7

Thymeleaf generará para ese elemento una URL equivalente a:

URL generada
/productos/7

Esto combina dos mecanismos que ya conocemos:

Qué hace cada expresión
${producto.id}                     → obtiene un dato
@{/productos/{id}(...)}            → construye una URL
th:each                            → repite el bloque para cada producto

3️⃣ Conocer la posición dentro de la iteración​

En algunas páginas no solo necesitamos conocer el objeto actual. También puede ser útil saber qué posición ocupa dentro de la colección.

th:each permite declarar una segunda variable denominada variable de estado:

Iteración con variable de estado
<tr th:each="producto, estado : ${productos}">
    ...
</tr>

En este ejemplo:

  • producto es el objeto actual.
  • estado contiene información sobre la iteración.

Entre sus propiedades más útiles encontramos:

PropiedadSignificado
estado.indexPosición empezando en 0.
estado.countPosición empezando en 1.
estado.sizeNúmero total de elementos.
estado.firsttrue si es el primer elemento.
estado.lasttrue si es el último elemento.
estado.eventrue en iteraciones pares.
estado.oddtrue en iteraciones impares.

Por ejemplo:

Numerar los productos
<ol>
    <li th:each="producto, estado : ${productos}">
        <span th:text="${estado.count}">1</span>.
        <span th:text="${producto.nombre}">Producto</span>
    </li>
</ol>

También podemos mostrar la posición actual y el número total de elementos:

Posición y tamaño de la colección
<p th:each="producto, estado : ${productos}">
    Producto
    <span th:text="${estado.count}">1</span>
    de
    <span th:text="${estado.size}">0</span>:
    <span th:text="${producto.nombre}">Producto</span>
</p>
tip

La variable de estado es opcional.

Si únicamente necesitamos recorrer los elementos, utilizaremos:

th:each="producto : ${productos}"

Solo añadiremos la segunda variable cuando realmente necesitemos información sobre la iteración.

4️⃣ Tomar decisiones en la plantilla​

Una vista también puede decidir si una parte del HTML debe aparecer según los datos disponibles.

Estas decisiones deben ser sencillas y estar relacionadas principalmente con la presentación.

🟩 Mostrar contenido con th:if​

th:if renderiza un elemento únicamente cuando la expresión indicada se evalúa como verdadera.

Supongamos que Producto tiene una propiedad stock:

Mostrar contenido según el stock
<p th:if="${producto.stock > 0}">
    Producto disponible
</p>

Si producto.stock > 0 es verdadero, el párrafo aparecerá en el HTML final.

Si es falso, ese elemento no se enviará al navegador.

Podemos utilizar comparaciones que ya conocemos:

Ejemplos de condiciones
${producto.stock > 0}
${producto.precio < 100}
${producto.id == 3}

También podemos utilizar directamente un valor booleano.

Si el controlador añade:

Valor booleano enviado desde Java
model.addAttribute("destacado", true);

la vista puede escribir:

Condición booleana
<p th:if="${destacado}">
    Producto destacado
</p>

No necesitamos comparar explícitamente con true.

Comparación innecesaria
<p th:if="${destacado == true}">
    Producto destacado
</p>
tip

Si una expresión ya devuelve un valor booleano, suele ser más claro utilizarla directamente.

🟨 Mostrar el caso contrario con th:unless​

th:unless funciona como la condición inversa de th:if.

Contenido alternativo
<p th:if="${producto.stock > 0}">
    Disponible
</p>

<p th:unless="${producto.stock > 0}">
    Agotado
</p>

Podemos leer th:unless como:

Idea de th:unless
mostrar este elemento a menos que la condición sea verdadera

En este caso:

Resultado
stock > 0  → Disponible
stock <= 0 → Agotado

th:unless resulta útil cuando queremos expresar de forma sencilla el caso contrario de una condición.

🟧 Elegir entre varios casos con th:switch y th:case​

th:if resulta cómodo cuando tenemos una condición concreta. Sin embargo, algunas veces un mismo dato puede tener varios valores posibles.

Supongamos que un producto tiene una propiedad rareza que puede valer:

Valores posibles
comun
raro
epico

Podemos utilizar th:switch y th:case:

Mostrar un texto según la rareza
<div th:switch="${producto.rareza}">

    <span th:case="'comun'">
        Objeto común
    </span>

    <span th:case="'raro'">
        Objeto raro
    </span>

    <span th:case="'epico'">
        Objeto épico
    </span>

    <span th:case="*">
        Rareza desconocida
    </span>

</div>
en este ejemplo

th:switch indica qué valor vamos a comprobar.

Cada th:case representa una posibilidad.

El caso * actúa como opción por defecto cuando ninguno de los casos anteriores coincide.

No necesitamos sustituir todos los th:if por th:switch. Lo utilizaremos cuando existan varias alternativas para un mismo dato y esa forma resulte más clara.

🟥 Modificar una clase CSS según los datos​

Las condiciones no siempre tienen que mostrar u ocultar elementos. A veces queremos mantener el elemento y cambiar únicamente su aspecto.

Para ello podemos utilizar th:classappend.

Por ejemplo:

Añadir una clase CSS según el stock
<article
    class="producto"
    th:classappend="${producto.stock == 0} ? 'agotado' : ''">

    <h2 th:text="${producto.nombre}">
        Producto
    </h2>

</article>

Si el producto no tiene stock, Thymeleaf añadirá la clase agotado a la clase que ya existía.

El HTML resultante podría ser:

HTML generado
<article class="producto agotado">
Para qué utilizarlo

th:classappend resulta útil cuando el estado de un objeto debe reflejarse visualmente mediante CSS.

No sustituye a th:if: con th:if decidimos si un elemento existe; con th:classappend mantenemos el elemento y modificamos sus clases.

5️⃣ Combinar th:each con condiciones​

Una situación muy habitual consiste en recorrer una colección y tomar una decisión para cada objeto.

Listado con disponibilidad
<article th:each="producto : ${productos}">

    <h2 th:text="${producto.nombre}">
        Producto
    </h2>

    <p>
        Precio:
        <span th:text="${producto.precio}">0</span> €
    </p>

    <p th:if="${producto.stock > 0}">
        Disponible
    </p>

    <p th:unless="${producto.stock > 0}">
        Agotado
    </p>

</article>

Thymeleaf realiza el proceso de forma independiente para cada objeto:

Procesamiento conceptual
producto 1 → genera su bloque → comprueba su stock
producto 2 → genera su bloque → comprueba su stock
producto 3 → genera su bloque → comprueba su stock

Por eso una misma plantilla puede producir resultados distintos para los diferentes elementos de una colección.

🟩 No confundir ocultar con filtrar​

Podemos escribir:

Condición dentro de una iteración
<article
    th:each="producto : ${productos}"
    th:if="${producto.precio < 100}">

    ...

</article>

Thymeleaf recorre la colección y genera el <article> únicamente para los productos cuyo precio sea inferior a 100.

Esto puede ser válido para una decisión sencilla de presentación, pero debemos distinguirlo de una búsqueda o filtro propio de la lógica de la aplicación.

aviso

La vista debe ocuparse principalmente de presentar los datos.

Si necesitamos seleccionar productos aplicando reglas importantes de la aplicación, normalmente esa selección debería realizarse en Java antes de enviar los datos a la plantilla.

6️⃣ Qué ocurre cuando una colección está vacía​

Una vista debe comportarse correctamente aunque no haya elementos que mostrar.

Supongamos que el controlador envía una lista vacía:

Colección vacía
List<Producto> productos = List.of();

model.addAttribute("productos", productos);

Este bloque:

Iteración sobre una lista vacía
<div th:each="producto : ${productos}">
    <span th:text="${producto.nombre}">
        Producto
    </span>
</div>

simplemente no generará ningún producto.

Pero dejar la página vacía puede resultar confuso.

Thymeleaf proporciona varios objetos de utilidad que podemos utilizar dentro de las expresiones. Para trabajar con listas disponemos de #lists.

Podemos comprobar si una colección está vacía:

Mensaje para una colección vacía
<p th:if="${#lists.isEmpty(productos)}">
    No hay productos disponibles.
</p>

Y mostrar el listado únicamente cuando existan elementos:

Mostrar el listado cuando existen productos
<section th:unless="${#lists.isEmpty(productos)}">

    <article th:each="producto : ${productos}">
        <h2 th:text="${producto.nombre}">
            Producto
        </h2>
    </article>

</section>
Sobre #lists

#lists es uno de los objetos de utilidad que Thymeleaf pone a disposición de las expresiones.

En esta unidad solo necesitamos reconocer su existencia y utilizar #lists.isEmpty(...).

No es necesario estudiar todas sus operaciones.

7️⃣ Agrupar contenido con th:block​

A veces queremos aplicar una condición a varios elementos sin introducir un <div> adicional en el HTML final.

Thymeleaf dispone de th:block:

Agrupar varios elementos bajo una condición
<th:block th:if="${producto.stock > 0}">

    <p>Disponible.</p>
    <p>Envío en 24 horas.</p>

</th:block>

th:block actúa como contenedor mientras Thymeleaf procesa la plantilla, pero no aparece como una etiqueta en el HTML resultante.

aviso

No debemos utilizar th:block automáticamente para todo.

Si un <section>, <article> o <div> tiene sentido semántico en el documento HTML, es preferible utilizar ese elemento real.

8️⃣ La vista no sustituye a la lógica de Java​

Thymeleaf permite utilizar expresiones, condiciones e iteraciones, pero eso no significa que debamos trasladar toda la lógica de la aplicación a la plantilla.

Esta condición es razonable:

Condición sencilla de presentación
<span th:if="${producto.stock > 0}">
    Disponible
</span>

Su finalidad es decidir cómo presentar un dato que ya conocemos.

En cambio, una plantilla llena de operaciones, comparaciones encadenadas o reglas complejas resulta difícil de comprender y mantener.

Podemos separar las responsabilidades así:

Responsabilidades
Java
├── prepara los objetos.
├── aplica la lógica de la aplicación.
└── envía los datos necesarios al Model.

Thymeleaf
├── muestra esos datos.
├── recorre colecciones.
├── construye enlaces.
└── toma decisiones sencillas de presentación.
peligro

Ocultar un enlace o un botón mediante th:if no es un mecanismo de seguridad.

Una condición en la vista únicamente determina qué HTML se muestra. La autorización real de una operación debe controlarse en el servidor.

9️⃣ Ejemplo completo: catálogo con disponibilidad​

Vamos a reunir ahora los elementos principales en un ejemplo único.

La clase Producto dispone de:

Producto.java
public class Producto {

    private int id;
    private String nombre;
    private double precio;
    private int stock;
    private String rareza;

    public Producto(
            int id,
            String nombre,
            double precio,
            int stock,
            String rareza) {

        this.id = id;
        this.nombre = nombre;
        this.precio = precio;
        this.stock = stock;
        this.rareza = rareza;
    }

    public int getId() {
        return id;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }

    public int getStock() {
        return stock;
    }

    public String getRareza() {
        return rareza;
    }
}

El controlador prepara una colección y la envía mediante Model:

ProductoController.java
@Controller
@RequestMapping("/productos")
public class ProductoController {

    @GetMapping
    public String listado(Model model) {

        List<Producto> productos = List.of(
                new Producto(
                        1,
                        "Teclado mecánico",
                        79.90,
                        8,
                        "comun"
                ),
                new Producto(
                        2,
                        "Ratón inalámbrico",
                        34.50,
                        0,
                        "raro"
                ),
                new Producto(
                        3,
                        "Monitor 27 pulgadas",
                        219.00,
                        5,
                        "epico"
                )
        );

        model.addAttribute("productos", productos);

        return "productos";
    }
}

La plantilla puede combinar iteraciones, condiciones, clases dinámicas y enlaces:

productos.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Catálogo de productos</title>

    <link
        rel="stylesheet"
        th:href="@{/css/estilos.css}">
</head>

<body>

    <h1>Catálogo de productos</h1>

    <p th:if="${#lists.isEmpty(productos)}">
        No hay productos disponibles.
    </p>

    <section th:unless="${#lists.isEmpty(productos)}">

        <article
            th:each="producto, estado : ${productos}"
            class="producto"
            th:classappend="${producto.stock == 0} ? 'agotado' : ''">

            <h2 th:text="${producto.nombre}">
                Nombre del producto
            </h2>

            <p>
                Producto
                <span th:text="${estado.count}">1</span>
                de
                <span th:text="${estado.size}">0</span>
            </p>

            <p>
                Precio:
                <span th:text="${producto.precio}">0</span> €
            </p>

            <p th:if="${producto.stock > 0}">
                Disponible
            </p>

            <p th:unless="${producto.stock > 0}">
                Agotado
            </p>

            <div th:switch="${producto.rareza}">
                <span th:case="'comun'">Común</span>
                <span th:case="'raro'">Raro</span>
                <span th:case="'epico'">Épico</span>
                <span th:case="*">Sin clasificar</span>
            </div>

            <a th:href="@{/productos/{id}(id=${producto.id})}">
                Ver detalle
            </a>

        </article>

    </section>

</body>
</html>
en este ejemplo

th:each recorre la colección productos y crea un <article> por cada objeto.

La variable estado permite conocer la posición actual y el número total de elementos.

th:if y th:unless muestran mensajes diferentes según el valor de stock.

th:switch y th:case permiten representar varias alternativas para la propiedad rareza.

th:classappend añade la clase agotado cuando el producto no tiene existencias.

@{/productos/{id}(id=${producto.id})} genera un enlace diferente para cada producto utilizando su identificador.

La comprobación con #lists.isEmpty(productos) permite mostrar un mensaje alternativo cuando la colección está vacía.

🔟 Errores frecuentes​

🟩 Utilizar el nombre de la colección dentro del bucle​

Incorrecto:

Uso incorrecto dentro de th:each
<div th:each="producto : ${productos}">
    <span th:text="${productos.nombre}">
        Producto
    </span>
</div>

Dentro de la iteración debemos utilizar el objeto actual:

Uso correcto
<div th:each="producto : ${productos}">
    <span th:text="${producto.nombre}">
        Producto
    </span>
</div>

🟨 Olvidar enviar la colección al Model​

Si la plantilla espera:

Dato esperado por la plantilla
${productos}

el controlador debe poner a disposición de la vista un atributo con ese nombre:

Atributo necesario
model.addAttribute("productos", productos);

🟧 Crear manualmente elementos que deberían repetirse​

No tiene sentido escribir:

Código repetitivo
<article>Producto 1...</article>
<article>Producto 2...</article>
<article>Producto 3...</article>

si todos los productos siguen la misma estructura.

Ese es precisamente el problema que resuelve th:each.

🟥 Utilizar demasiadas condiciones en la plantilla​

Una expresión como:

Condición sencilla
<p th:if="${producto.stock > 0}">
    Disponible
</p>

es adecuada.

Si necesitamos muchas condiciones encadenadas, transformaciones o cálculos, debemos plantearnos si esa información debería llegar ya preparada desde Java.

🟪 Confundir una condición visual con seguridad​

Este código:

Ocultar un enlace
<a
    th:if="${puedeEditar}"
    th:href="@{/editar}">
    Editar
</a>

puede evitar que el enlace aparezca en la página, pero no protege por sí mismo la ruta /editar.

La seguridad real de la operación debe comprobarse en el servidor.
