3.3 Condicionales y bucles

Hasta ahora hemos utilizado Thymeleaf para mostrar datos enviados mediante Model y construir enlaces dinámicos.

En una aplicación real también necesitamos trabajar con colecciones de objetos y decidir cómo debe mostrarse cada elemento según sus datos.

Idea principal

En este apartado utilizaremos principalmente:

Elementos que vamos a trabajar
th:each        → recorrer colecciones
th:if          → mostrar contenido si se cumple una condición
th:unless      → mostrar contenido cuando no se cumple
th:switch      → elegir entre varias alternativas
th:class       → establecer una clase CSS
th:classappend → añadir una clase CSS

Estas instrucciones se procesan en el servidor. El navegador recibe únicamente el HTML resultante.

1️⃣ Recorrer colecciones con th:each​

Una vista puede recibir una colección de objetos desde el controlador.

Por ejemplo:

ProductoController.java
@GetMapping("/productos")
public String listado(Model model) {

    List<Producto> productos = List.of(
            new Producto(1, "Teclado mecánico", 79.90, 8, "comun"),
            new Producto(2, "Ratón inalámbrico", 34.50, 0, "raro"),
            new Producto(3, "Monitor 27 pulgadas", 219.00, 5, "epico")
    );

    model.addAttribute("productos", productos);

    return "productos";
}

La vista recibe un único atributo llamado productos cuyo valor es una colección.

Para recorrerla utilizamos th:each:

Recorrer una colección
<article th:each="producto : ${productos}">
    <h2 th:text="${producto.nombre}">
        Producto
    </h2>

    <p>
        Precio:
        <span th:text="${producto.precio}">0</span> €
    </p>
</article>

La expresión:

Lectura de th:each
producto : ${productos}

puede leerse como:

por cada producto de productos

productos es la colección recibida mediante Model y producto representa el objeto actual en cada iteración.

🟩 Generar enlaces dentro del bucle​

Podemos utilizar los datos del objeto actual para construir una URL diferente para cada elemento:

Enlace de detalle
<a th:href="@{/productos/{id}(id=${producto.id})}">
    Ver detalle
</a>

Si el id vale 7, Thymeleaf generará:

/productos/7

2️⃣ Conocer la posición de una iteración​

Cuando necesitamos información sobre la posición actual, th:each permite añadir una variable de estado:

Iteración con variable de estado
<article th:each="producto, estado : ${productos}">
    <span th:text="${estado.count}">1</span>
    de
    <span th:text="${estado.size}">0</span>
</article>

Las propiedades más útiles son:

PropiedadSignificado
estado.indexPosición empezando en 0.
estado.countPosición empezando en 1.
estado.sizeNúmero total de elementos.
estado.firstIndica si es el primer elemento.
estado.lastIndica si es el último elemento.
estado.evenIndica si la iteración es par.
estado.oddIndica si la iteración es impar.
consejo

La variable de estado es opcional. Si solo necesitamos recorrer la colección, no hace falta declararla.

3️⃣ Mostrar contenido según una condición​

Una plantilla también puede decidir si determinados elementos deben aparecer según los datos.

🟩 th:if​

th:if genera el elemento únicamente cuando la condición es verdadera:

Mostrar contenido según el stock
<p th:if="${producto.stock > 0}">
    Disponible
</p>

También podemos utilizar directamente valores booleanos:

Condición booleana
<p th:if="${producto.destacado}">
    Producto destacado
</p>

🟨 th:unless​

th:unless expresa el caso contrario:

Dos situaciones posibles
<p th:if="${producto.stock > 0}">
    Disponible
</p>

<p th:unless="${producto.stock > 0}">
    Agotado
</p>

Podemos leer th:unless como:

mostrar este elemento a menos que la condición sea verdadera

🟧 th:switch y th:case​

Cuando un dato puede tener varias alternativas, th:switch suele resultar más claro que encadenar varios th:if.

Elegir entre varios valores
<div th:switch="${producto.rareza}">

    <span th:case="'comun'">Común</span>
    <span th:case="'raro'">Raro</span>
    <span th:case="'epico'">Épico</span>
    <span th:case="*">Sin clasificar</span>

</div>

th:switch indica qué valor comprobamos y cada th:case representa una posibilidad.

El caso * actúa como opción por defecto.

4️⃣ Modificar clases CSS desde Thymeleaf​

No todas las decisiones implican mostrar u ocultar contenido. A veces queremos mantener el elemento y cambiar únicamente su apariencia.

Para ello podemos modificar dinámicamente el atributo class.

🟩 Sustituir la clase con th:class​

th:class establece el valor completo del atributo:

Clase calculada
<p th:class="${producto.stock > 0} ? 'disponible' : 'agotado'">
    Estado del producto
</p>

Si hay stock, el HTML generado puede ser:

Resultado
<p class="disponible">
    Estado del producto
</p>

Si no hay stock:

Resultado
<p class="agotado">
    Estado del producto
</p>

🟨 Añadir una clase con th:classappend​

Si el elemento ya tiene una clase que queremos conservar, utilizamos th:classappend:

Añadir una clase
<article
    class="producto"
    th:classappend="${producto.stock == 0} ? 'agotado' : ''">

    <h2 th:text="${producto.nombre}">
        Producto
    </h2>

</article>

Cuando stock vale 0, Thymeleaf genera:

HTML generado
<article class="producto agotado">
Diferencia importante

th:class establece el valor completo de class.

th:classappend conserva las clases existentes y añade otra.

🟧 Utilizar directamente un dato como clase​

Una propiedad también puede utilizarse directamente como nombre de clase:

Clase a partir de un dato
<span
    class="rareza"
    th:classappend="${producto.rareza}"
    th:text="${producto.rareza}">
    Rareza
</span>

Si:

producto.rareza = "raro"

el resultado será:

HTML resultante
<span class="rareza raro">
    raro
</span>

Después, el CSS puede definir estilos diferentes:

estilos.css
.rareza.comun {
    /* estilo para productos comunes */
}

.rareza.raro {
    /* estilo para productos raros */
}

.rareza.epico {
    /* estilo para productos épicos */
}
en este ejemplo

Thymeleaf no modifica la hoja CSS.

Lo que hace es generar un atributo class distinto según los datos. Después, el navegador aplica las reglas CSS correspondientes.

5️⃣ Combinar bucles y condiciones​

Lo habitual es utilizar estos mecanismos juntos.

Por ejemplo:

Catálogo dinámico
<article
    th:each="producto : ${productos}"
    class="producto"
    th:classappend="${producto.stock == 0} ? 'agotado' : ''">

    <h2 th:text="${producto.nombre}">
        Producto
    </h2>

    <p>
        Precio:
        <span th:text="${producto.precio}">0</span> €
    </p>

    <p th:if="${producto.stock > 0}">
        Disponible
    </p>

    <p th:unless="${producto.stock > 0}">
        Agotado
    </p>

    <a th:href="@{/productos/{id}(id=${producto.id})}">
        Ver detalle
    </a>

</article>

Thymeleaf repite el bloque una vez por producto y evalúa las condiciones de forma independiente en cada iteración.

aviso

Ocultar un elemento con th:if no equivale a filtrar los datos de la aplicación.

Si necesitamos aplicar una regla importante de selección, normalmente será mejor preparar previamente la colección en Java.

6️⃣ Colecciones vacías​

Una colección puede no contener elementos. En ese caso conviene que la vista muestre un mensaje en lugar de dejar un espacio vacío.

Podemos comprobarlo con el objeto de utilidad #lists:

Mensaje para una lista vacía
<p th:if="${#lists.isEmpty(productos)}">
    No hay productos disponibles.
</p>

Y mostrar el listado solo cuando existan datos:

Mostrar el listado
<section th:unless="${#lists.isEmpty(productos)}">

    <article th:each="producto : ${productos}">
        <h2 th:text="${producto.nombre}">
            Producto
        </h2>
    </article>

</section>
información

En esta unidad solo necesitamos conocer #lists.isEmpty(...).

7️⃣ Agrupar contenido con th:block​

A veces queremos aplicar una condición a varios elementos sin introducir un contenedor adicional en el HTML final.

Para ello podemos utilizar th:block:

Agrupar varios elementos
<th:block th:if="${producto.stock > 0}">

    <p>Disponible.</p>
    <p>Envío en 24 horas.</p>

</th:block>

th:block existe mientras Thymeleaf procesa la plantilla, pero desaparece del HTML generado.

consejo

No debemos utilizar th:block automáticamente.

Si un <section>, <article> o <div> tiene sentido semántico en la página, es preferible utilizar ese elemento real.

8️⃣ Separar presentación y lógica​

Thymeleaf permite utilizar condiciones y expresiones, pero la vista no debe convertirse en el lugar donde se concentra toda la lógica de la aplicación.

Una condición como esta es adecuada:

Decisión de presentación
<span th:if="${producto.stock > 0}">
    Disponible
</span>

La plantilla solo decide cómo presentar un dato que ya conoce.

Podemos repartir las responsabilidades así:

Responsabilidades
Java
├── prepara los objetos.
├── aplica la lógica de la aplicación.
└── envía los datos al Model.

Thymeleaf
├── muestra los datos.
├── recorre colecciones.
├── construye enlaces.
├── aplica condiciones sencillas.
└── modifica la presentación.
peligro

Ocultar un enlace mediante th:if no protege una ruta.

La seguridad debe comprobarse siempre en el servidor.

9️⃣ Errores frecuentes​

🟩 Utilizar la colección en lugar del elemento actual​

Dentro de:

Iteración
<div th:each="producto : ${productos}">

debemos acceder a:

${producto.nombre}

y no a:

${productos.nombre}

🟨 Olvidar enviar la colección al Model​

Si la plantilla utiliza:

${productos}

el controlador debe haber añadido un atributo con ese nombre:

Controlador
model.addAttribute("productos", productos);

🟧 Confundir th:class y th:classappend​

Si ya existe:

Clase existente
<article class="producto">

th:class puede sustituir ese valor.

Si queremos conservar producto y añadir otra clase, utilizaremos th:classappend.

🟥 Añadir demasiada lógica a la plantilla​

Las condiciones sencillas de presentación son apropiadas.

Si aparecen muchas comparaciones, cálculos o reglas encadenadas, probablemente parte de esa lógica debería resolverse previamente en Java.

🟪 Confundir presentación con seguridad​

Un elemento oculto mediante th:if no impide que alguien intente acceder directamente a la URL asociada.

La protección real debe realizarse en el servidor.
