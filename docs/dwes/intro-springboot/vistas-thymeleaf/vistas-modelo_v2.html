3.1 Modelo y datos de la vista

Hasta ahora hemos utilizado controladores para atender rutas y recibir información desde la URL. El siguiente paso consiste en hacer que una página HTML pueda mostrar datos calculados o recibidos por el controlador.

En Spring MVC, esa comunicación entre el controlador y la vista se realiza habitualmente mediante un objeto Model.

Idea principal

Cuando un controlador devuelve una vista, Model permite acompañar esa vista con los datos que Thymeleaf necesitará para generar el HTML final.

1️⃣ Del controlador a una página dinámica​

Una plantilla Thymeleaf puede contener HTML prácticamente fijo, pero su utilidad aparece cuando parte del contenido depende de la petición.

Por ejemplo, si el navegador solicita:

Petición
/productos/7

el controlador puede obtener el identificador 7, preparar los datos del producto y enviarlos a una plantilla.

El flujo que queremos conseguir es:

En este punto no estamos trabajando todavía con una base de datos. Los datos pueden estar escritos directamente en el controlador o construirse de forma sencilla para centrarnos en cómo llegan hasta la vista.

2️⃣ Qué es Model en Spring MVC​

Model es una interfaz de Spring MVC que actúa como un contenedor de datos que el controlador pone a disposición de la vista.

Su clase pertenece al paquete:

Import de Model
import org.springframework.ui.Model;

No necesitamos crear el objeto manualmente. Spring MVC puede proporcionarlo directamente como parámetro del método del controlador.

ProductoController.java
@GetMapping("/productos/{id}")
public String detalle(@PathVariable int id, Model model) {
    return "producto";
}

En este método aparecen dos tipos de información diferentes:

  • id procede de la petición HTTP.
  • model lo proporciona Spring para que podamos preparar los datos que utilizará la vista.
Importante

Model no representa una página HTML ni genera la respuesta por sí mismo. Su función es mantener los datos que estarán disponibles mientras se procesa la vista.

🟩 No se instancia con new​

No debemos escribir algo como:

Código incorrecto
// No debemos crear Model de esta forma
Model model = new Model();

Model es una interfaz y, además, no necesitamos ocuparnos de crear su implementación.

Cuando Spring MVC ejecuta el método del controlador, prepara el objeto correspondiente y lo entrega automáticamente.

Esta forma de trabajar es habitual en Spring: el framework puede proporcionar determinados objetos cuando los declaramos como parámetros del método.

3️⃣ Añadir datos al modelo​

La operación que utilizaremos con más frecuencia es:

Añadir un atributo al modelo
model.addAttribute("nombre", valor);

Cada atributo tiene dos partes:

  • un nombre, que utilizará la vista para localizar el dato;
  • un valor, que es el dato que queremos poner a disposición de la plantilla.

Por ejemplo:

ProductoController.java
@Controller
public class ProductoController {

    @GetMapping("/productos/{id}")
    public String detalle(@PathVariable int id, Model model) {

        model.addAttribute("id", id);
        model.addAttribute("nombre", "Teclado mecánico");
        model.addAttribute("precio", 79.90);

        return "producto";
    }
}
en este ejemplo

La petición determina el valor de id mediante @PathVariable.

Después, el controlador añade tres atributos al modelo. Los nombres id, nombre y precio son las claves que utilizará posteriormente la plantilla.

Finalmente, return "producto" indica el nombre lógico de la vista. Al no utilizar @ResponseBody, el String devuelto no se envía como texto al navegador: Spring MVC lo interpreta como una vista que debe renderizar.

El contenido del modelo en ese momento puede imaginarse así:

Nombre del atributoValor
id7
nombre"Teclado mecánico"
precio79.90

El modelo no obliga a trabajar únicamente con String. Los valores pueden ser números, booleanos, objetos Java, colecciones u otros tipos.

🟨 El nombre del atributo importa​

El nombre utilizado en addAttribute() es el identificador con el que Thymeleaf buscará posteriormente ese dato.

Si escribimos:

Controlador
model.addAttribute("nombreProducto", "Teclado mecánico");

la vista tendrá que utilizar exactamente nombreProducto.

Un nombre diferente representa un atributo diferente.

Por esta razón conviene utilizar nombres claros y coherentes con el dato que contienen.

4️⃣ Recuperar los datos desde Thymeleaf​

Para comprobar que los datos han llegado a la vista necesitamos utilizar una primera expresión de Thymeleaf.

Supongamos que tenemos:

ProductoController.java
model.addAttribute("nombre", "Teclado mecánico");
model.addAttribute("precio", 79.90);

return "producto";

y la plantilla:

Ubicación de la plantilla
src/main/resources/templates/producto.html

Podemos mostrar los valores mediante th:text:

producto.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Detalle del producto</title>
</head>
<body>

    <h1 th:text="${nombre}">Nombre del producto</h1>

    <p>
        Precio:
        <span th:text="${precio}">0</span> €
    </p>

</body>
</html>

La línea:

Declaración de Thymeleaf
<html lang="es" xmlns:th="http://www.thymeleaf.org">

declara el espacio de nombres que utilizaremos para los atributos propios de Thymeleaf, como th:text. En nuestros ejemplos la incluiremos en el elemento <html> de las plantillas que utilicen Thymeleaf.

No es necesario profundizar ahora en los espacios de nombres XML. Para esta unidad basta con reconocer que xmlns:th identifica los atributos th:* que Thymeleaf procesará en el servidor.

Aquí aparecen dos elementos nuevos:

Expresión básica de Thymeleaf
th:text="${nombre}"

th:text indica que Thymeleaf debe sustituir el contenido del elemento por el valor obtenido de la expresión.

Expresión
${nombre}

busca dentro de los datos disponibles para la vista un atributo llamado nombre.

Por tanto, existe una correspondencia directa:

Correspondencia entre controlador y vista
model.addAttribute("nombre", "Teclado mecánico")
                         ↓
                    ${nombre}
En este apartado

Utilizaremos únicamente las expresiones necesarias para comprobar cómo llegan los datos a la plantilla.

La sintaxis de las expresiones de Thymeleaf se estudiará con más detalle en el siguiente apartado de la unidad.

🟩 El contenido HTML de respaldo​

En este ejemplo:

Fragmento de plantilla
<h1 th:text="${nombre}">Nombre del producto</h1>

el texto:

Nombre del producto

es contenido HTML normal.

Cuando Thymeleaf procesa la plantilla en el servidor, th:text sustituye ese contenido por el valor de ${nombre}.

Si el controlador ha enviado:

Atributo del modelo
model.addAttribute("nombre", "Teclado mecánico");

el navegador recibirá un resultado equivalente a:

HTML resultante
<h1>Teclado mecánico</h1>

El navegador no necesita interpretar th:text ni ${nombre}. Thymeleaf ya los ha procesado en el servidor antes de enviar la respuesta.

aviso

El navegador recibe HTML resultante, no una plantilla Thymeleaf pendiente de procesar.

Las expresiones th:* se procesan en el servidor.

5️⃣ El flujo completo de una petición​

Vamos a reunir ahora los conceptos de los apartados anteriores.

Tenemos esta petición:

Petición
GET /productos/7?moneda=eur

Queremos obtener:

  • el identificador desde la ruta;
  • la moneda desde la query string;
  • preparar algunos datos;
  • enviarlos a una vista.

El controlador podría ser:

ProductoController.java
@Controller
@RequestMapping("/productos")
public class ProductoController {

    @GetMapping("/{id}")
    public String detalle(
            @PathVariable int id,
            @RequestParam(defaultValue = "eur") String moneda,
            Model model) {

        String nombre = "Teclado mecánico";
        double precio = 79.90;

        model.addAttribute("id", id);
        model.addAttribute("nombre", nombre);
        model.addAttribute("precio", precio);
        model.addAttribute("moneda", moneda);

        return "producto";
    }
}
en este ejemplo

@PathVariable obtiene 7 a partir del segmento de la ruta.

@RequestParam obtiene eur a partir de la query string. Si moneda no aparece, se utiliza el valor por defecto.

El controlador prepara los datos que necesita la página y los añade al Model.

Finalmente devuelve "producto", por lo que Spring MVC busca la plantilla correspondiente y Thymeleaf la procesa utilizando los atributos del modelo.

La plantilla puede utilizar esos datos:

producto.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Producto</title>
</head>
<body>

    <h1 th:text="${nombre}">Nombre</h1>

    <p>
        Identificador:
        <span th:text="${id}">0</span>
    </p>

    <p>
        Precio:
        <span th:text="${precio}">0</span>
        <span th:text="${moneda}">eur</span>
    </p>

</body>
</html>

Este ejemplo conecta varias piezas que ya conocemos:

Esta separación es importante. La URL contiene información de la petición, el controlador decide qué hacer con ella y la vista se encarga de presentar el resultado.

6️⃣ Enviar un objeto completo a la vista​

Añadir muchos atributos independientes es suficiente para ejemplos pequeños, pero una aplicación suele trabajar con datos relacionados entre sí.

Podemos representar un producto mediante una clase Java sencilla:

Producto.java
public class Producto {

    private int id;
    private String nombre;
    private double precio;

    public Producto(int id, String nombre, double precio) {
        this.id = id;
        this.nombre = nombre;
        this.precio = precio;
    }

    public int getId() {
        return id;
    }

    public String getNombre() {
        return nombre;
    }

    public double getPrecio() {
        return precio;
    }
}

El controlador puede añadir el objeto completo:

ProductoController.java
@GetMapping("/{id}")
public String detalle(@PathVariable int id, Model model) {

    Producto producto =
            new Producto(id, "Teclado mecánico", 79.90);

    model.addAttribute("producto", producto);

    return "producto";
}

Ahora el modelo contiene un único atributo llamado producto cuyo valor es un objeto Java.

Thymeleaf puede acceder a sus propiedades:

producto.html
<h1 th:text="${producto.nombre}">Nombre</h1>

<p>
    Código:
    <span th:text="${producto.id}">0</span>
</p>

<p>
    Precio:
    <span th:text="${producto.precio}">0</span> €
</p>

🟩 Cómo accede Thymeleaf a las propiedades del objeto​

Cuando escribimos una expresión como:

Acceso a una propiedad
${producto.nombre}

Thymeleaf interpreta nombre como una propiedad JavaBean del objeto producto. En una clase como la de este ejemplo, esa propiedad se obtiene a través de su método getNombre().

Del mismo modo:

Relación entre expresión y getter
${producto.id}      → getId()
${producto.nombre}  → getNombre()
${producto.precio}  → getPrecio()

Por eso los métodos get de la clase no son un detalle innecesario: permiten que tecnologías como Thymeleaf puedan consultar las propiedades del objeto de una forma estándar.

aviso

No debemos escribir ${producto.getNombre()} para mostrar una propiedad sencilla. En las plantillas utilizaremos normalmente la notación de propiedad ${producto.nombre} y dejaremos que Thymeleaf resuelva el getter correspondiente.

en este ejemplo

El atributo que hemos añadido al modelo se llama producto.

La expresión ${producto.nombre} parte de ese objeto y accede a su propiedad nombre.

En este momento solo necesitamos entender la relación entre el objeto enviado por el controlador y los datos mostrados por la plantilla. En el siguiente apartado profundizaremos en las expresiones de Thymeleaf.

nota

Esta clase Producto es únicamente un objeto Java utilizado para el ejemplo.

No estamos introduciendo todavía entidades JPA, repositorios, DTO ni persistencia en base de datos.

7️⃣ Qué ocurre internamente cuando devolvemos una vista​

Cuando un método de un @Controller devuelve:

Nombre lógico de la vista
return "producto";

Spring MVC no envía literalmente la palabra producto al navegador.

El proceso, de forma simplificada, es el siguiente:

  1. Spring MVC ejecuta el método asociado a la petición.
  2. El método añade los datos necesarios al Model.
  3. El valor "producto" se interpreta como el nombre lógico de una vista.
  4. Spring localiza la plantilla correspondiente.
  5. Thymeleaf procesa la plantilla utilizando los atributos del modelo.
  6. El resultado es HTML normal.
  7. Ese HTML se envía en la respuesta HTTP.

Con la configuración habitual de Spring Boot y Thymeleaf:

Nombre lógico y archivo
return "producto"
        ↓
src/main/resources/templates/producto.html

No debemos escribir:

Formas que no utilizaremos
return "producto.html";
return "templates/producto.html";

En nuestros controladores utilizaremos el nombre lógico de la vista.

🟩 Model pertenece a una petición concreta​

Los atributos que añadimos al Model sirven para generar la respuesta asociada a esa petición.

Por ejemplo:

Primera petición
/productos/4

puede generar un modelo con:

id = 4

y una petición posterior:

Segunda petición
/productos/9

generará los datos necesarios para esa nueva respuesta.

No debemos entender Model como un lugar de almacenamiento permanente ni como una variable global compartida por todos los usuarios.

aviso

Model permite trasladar datos desde el controlador hasta la vista durante el procesamiento de una petición.

No sustituye a una base de datos, una sesión ni ningún mecanismo de persistencia.

8️⃣ Ejemplo: ficha de videojuego​

Vamos a construir una página cuyo contenido dependa del identificador y de una opción recibidos en la petición.

La aplicación debe aceptar:

Peticiones de ejemplo
/juegos/3
/juegos/3?idioma=en

El controlador puede ser:

JuegoController.java
@Controller
@RequestMapping("/juegos")
public class JuegoController {

    @GetMapping("/{id}")
    public String detalle(
            @PathVariable int id,
            @RequestParam(defaultValue = "es") String idioma,
            Model model) {

        model.addAttribute("id", id);
        model.addAttribute("titulo", "Nebula Quest");
        model.addAttribute("genero", "Aventura");
        model.addAttribute("edadRecomendada", 12);
        model.addAttribute("idioma", idioma);

        return "juego";
    }
}

Y la plantilla:

juego.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Ficha del juego</title>
</head>
<body>

    <h1 th:text="${titulo}">Título del juego</h1>

    <p>
        Identificador:
        <span th:text="${id}">0</span>
    </p>

    <p>
        Género:
        <span th:text="${genero}">Sin género</span>
    </p>

    <p>
        Edad recomendada:
        <span th:text="${edadRecomendada}">0</span>
    </p>

    <p>
        Idioma solicitado:
        <span th:text="${idioma}">es</span>
    </p>

</body>
</html>

Comprueba primero:

Primera petición
/juegos/3

y después:

Segunda petición
/juegos/3?idioma=en

Observa qué parte de la página permanece igual y qué valores dependen de la información que el controlador ha añadido al modelo.

tip

Para comprobar que realmente entiendes el flujo, cambia uno de los nombres utilizados en addAttribute() sin modificar la plantilla y observa el resultado.

Después corrígelo haciendo que el nombre utilizado por el controlador y el utilizado por Thymeleaf vuelvan a coincidir.

🔟 Model no es lo mismo que una clase de datos​

La palabra modelo puede resultar confusa porque aparece con distintos significados en desarrollo de software.

En este apartado estamos utilizando específicamente:

Tipo utilizado
org.springframework.ui.Model

Este Model es el objeto que utilizamos para poner información a disposición de la vista.

Por otra parte, podemos tener clases propias como:

Clases de nuestra aplicación
Producto
Usuario
Ruta
Evento

que representan información del dominio de la aplicación.

Por ejemplo:

Objeto dentro del Model
Producto producto =
        new Producto(7, "Teclado mecánico", 79.90);

model.addAttribute("producto", producto);

Aquí:

  • Producto representa un dato de nuestra aplicación.
  • Model es el mecanismo utilizado para entregar ese dato a la vista.

No son el mismo concepto.

9️⃣ Errores frecuentes​

🟩 Añadir un atributo con un nombre y buscar otro​

Controlador:

ProductoController.java
model.addAttribute("nombreProducto", "Teclado");

Vista:

producto.html
<span th:text="${nombre}">Producto</span>

nombre y nombreProducto son atributos distintos. La plantilla debe utilizar el mismo nombre definido en el controlador.

🟨 Utilizar @ResponseBody cuando queremos una vista​

Código incorrecto para devolver una vista
@GetMapping("/producto")
@ResponseBody
public String producto(Model model) {
    model.addAttribute("nombre", "Teclado");
    return "producto";
}

En este caso, @ResponseBody indica que el valor devuelto debe escribirse directamente en el cuerpo de la respuesta.

El navegador recibiría:

producto

en lugar de renderizar producto.html.

Para devolver una vista:

Controlador que devuelve una vista
@GetMapping("/producto")
public String producto(Model model) {
    model.addAttribute("nombre", "Teclado");
    return "producto";
}
aviso

Cuando un método de un @Controller devuelve el nombre de una vista Thymeleaf, no debe utilizar @ResponseBody.

🟧 Escribir HTML dentro del controlador​

No debemos construir una página concatenando cadenas:

Código que debemos evitar
@GetMapping("/producto")
@ResponseBody
public String producto() {
    return "<h1>Teclado mecánico</h1>"
            + "<p>Precio: 79.90 €</p>";
}

Aunque técnicamente se puede devolver contenido de esta forma, mezcla las responsabilidades del controlador y de la vista.

En una aplicación MVC:

  • el controlador prepara y selecciona los datos;
  • la plantilla se encarga de presentar esos datos mediante HTML.

🟥 Pensar que Model almacena datos entre peticiones​

Este código:

Añadir un dato al modelo
model.addAttribute("producto", producto);

no guarda permanentemente el producto.

El atributo se utiliza para renderizar la vista de esa petición.

La persistencia de datos se abordará más adelante con mecanismos específicos.

🟪 Crear una ruta distinta para cada dato que queremos mostrar​

No necesitamos crear:

/producto1
/producto2
/producto3

si la diferencia entre las páginas es únicamente el identificador del producto.

Podemos utilizar:

Patrón de ruta
/productos/{id}

recibir el identificador con @PathVariable y construir el modelo correspondiente.
