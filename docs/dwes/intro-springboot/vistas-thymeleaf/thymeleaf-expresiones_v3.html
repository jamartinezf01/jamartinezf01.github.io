3.2 Expresiones Thymeleaf

En el apartado anterior ya utilizamos ${...} y th:text para mostrar en una plantilla los datos que un controlador había añadido al Model. También vimos cómo acceder a propiedades de objetos, por ejemplo con ${producto.nombre}.

No vamos a repetir ese recorrido. A partir de aquí ampliaremos esa sintaxis para trabajar con valores dentro de las expresiones y, sobre todo, para construir URL, enlaces y referencias a recursos de forma dinámica.

Idea principal

En este apartado trabajaremos principalmente con dos tipos de expresiones:

  • ${...} para utilizar datos disponibles en la vista.
  • @{...} para construir URL de la aplicación y referencias a recursos.

1️⃣ Trabajar con valores dentro de ${...}​

Ya sabemos que una expresión como:

Acceso a un dato del modelo
<span th:text="${producto.precio}">0</span>

permite recuperar un valor disponible en la vista.

Además de acceder a variables y propiedades, podemos utilizar literales y operaciones sencillas dentro de la expresión.

🟩 Literales​

Un literal es un valor escrito directamente en la expresión.

Podemos encontrar, por ejemplo:

Ejemplos de literales
'texto'
42
19.95
true
false

Los textos se escriben normalmente entre comillas simples:

Texto literal
<p th:text="'Catálogo de productos'">Catálogo</p>

Sin embargo, si el contenido es completamente fijo, no necesitamos Thymeleaf:

HTML más sencillo
<p>Catálogo de productos</p>

Utilizaremos expresiones cuando el contenido dependa realmente de datos dinámicos.

🟨 Operaciones aritméticas​

Thymeleaf integrado con Spring permite utilizar expresiones compatibles con Spring Expression Language (SpEL).

Por ejemplo:

Operación aritmética
<span th:text="${producto.precio * 1.21}">0</span>

También podemos utilizar:

OperaciónOperador
Suma+
Resta-
Multiplicación*
División/
Resto%

Estas operaciones son útiles para transformaciones muy sencillas de presentación.

aviso

Que una operación pueda escribirse en una plantilla no significa que deba colocarse allí toda la lógica de la aplicación.

Los cálculos importantes y las decisiones propias del funcionamiento de la aplicación deben realizarse fuera de la vista.

🟧 Comparaciones y operadores lógicos​

También podemos construir expresiones como:

Comparación
<span th:text="${producto.stock > 0}">false</span>

O combinar condiciones:

Expresión lógica
<span th:text="${producto.disponible and producto.stock > 0}">false</span>

Los operadores más habituales son:

TipoEjemplos
Comparación>, <, >=, <=, ==, !=
Lógicosand, or, not

Por ahora solo necesitamos reconocer estas expresiones. En el siguiente apartado las utilizaremos con atributos específicos para tomar decisiones dentro de la plantilla.

2️⃣ ${...} y @{...} no hacen lo mismo​

Hasta ahora hemos utilizado principalmente expresiones de variable:

Expresión de variable
${...}

Ahora aparece un segundo tipo muy importante:

Expresión de URL
@{...}

La diferencia fundamental es:

ExpresiónUso principalEjemplo
${...}Leer o utilizar datos disponibles en la vista.${producto.nombre}
@{...}Construir una URL.@{/productos}

Esta distinción será importante durante toda la unidad. Una expresión de datos y una expresión de URL pueden aparecer incluso dentro de una misma etiqueta, pero cumplen funciones diferentes.

3️⃣ Construir enlaces con th:href​

En HTML podemos crear un enlace de forma habitual:

Enlace HTML
<a href="/productos">Productos</a>

Dentro de una plantilla Thymeleaf utilizaremos normalmente:

Enlace con Thymeleaf
<a th:href="@{/productos}">Productos</a>

th:href sustituye el valor del atributo href cuando Thymeleaf procesa la plantilla.

La expresión:

URL Thymeleaf
@{/productos}

representa una URL de la propia aplicación.

info

th:href no provoca por sí mismo ninguna petición mientras se genera la página.

Thymeleaf construye el atributo href del HTML. La nueva petición se producirá cuando el usuario pulse el enlace en el navegador.

🟩 Contenido HTML de respaldo en enlaces​

Podemos escribir ambos atributos:

Enlace con valor de respaldo
<a href="/productos"
   th:href="@{/productos}">
    Productos
</a>

Si la plantilla se procesa mediante Thymeleaf, prevalecerá el valor de th:href.

En nuestros ejemplos no será obligatorio duplicar siempre ambos atributos. Lo importante es comprender que th:href genera el href del HTML resultante.

4️⃣ Añadir parámetros de consulta a una URL​

Las expresiones @{...} permiten añadir parámetros de consulta sin concatenar manualmente cadenas.

Supongamos que el modelo contiene:

Controlador
model.addAttribute("categoria", "teclados");

Podemos construir:

Enlace con parámetro de consulta
<a th:href="@{/productos(categoria=${categoria})}">
    Ver teclados
</a>

Thymeleaf generará una URL equivalente a:

URL generada
/productos?categoria=teclados

Aquí se combinan dos expresiones:

  • @{...} construye la URL.
  • ${categoria} obtiene el valor que debe utilizarse.

🟩 Varios parámetros​

Podemos incluir varios valores:

Enlace con varios parámetros
<a th:href="@{/productos(
        categoria=${categoria},
        orden=${orden}
    )}">
    Aplicar filtros
</a>

Si:

Datos disponibles
categoria = "teclados"
orden = "precio"

la URL será equivalente a:

Resultado
/productos?categoria=teclados&orden=precio

Thymeleaf se ocupa de construir correctamente la query string a partir de esos parámetros.

aviso

No incluimos manualmente ? y & cuando utilizamos esta sintaxis.

Los parámetros se escriben entre paréntesis dentro de la expresión de URL.

5️⃣ Construir URL con variables de ruta​

También podemos utilizar datos dinámicos como parte de la propia ruta.

Supongamos que el controlador atiende:

ProductoController.java
@GetMapping("/productos/{id}")
public String detalle(@PathVariable int id, Model model) {
    // ...
}

Y la plantilla dispone de un objeto cuyo identificador es 7.

Podemos escribir:

Enlace con variable de ruta
<a th:href="@{/productos/{id}(id=${producto.id})}">
    Ver detalle
</a>

Thymeleaf generará:

URL generada
/productos/7

La expresión mantiene separadas dos ideas:

Estructura y valor
/productos/{id}       ← estructura de la ruta
id=${producto.id}     ← valor que sustituye {id}

Esto encaja directamente con lo que ya aprendimos sobre @PathVariable.

🟨 Combinar variable de ruta y query string​

Una URL puede contener ambas cosas:

Ruta y parámetro de consulta
<a th:href="@{/productos/{id}(
        id=${producto.id},
        moneda='eur'
    )}">
    Ver precio en euros
</a>

Si producto.id vale 7, Thymeleaf puede generar:

URL resultante
/productos/7?moneda=eur

El controlador puede recibir esos datos con:

ProductoController.java
@GetMapping("/productos/{id}")
public String detalle(
        @PathVariable int id,
        @RequestParam(defaultValue = "eur") String moneda,
        Model model) {
    // ...
}

La relación completa es:

Relación entre vista y controlador
th:href con @{...}
        ↓
/productos/7?moneda=eur
        ↓
petición HTTP
        ↓
@PathVariable int id
@RequestParam String moneda

6️⃣ Referenciar recursos estáticos​

Las expresiones @{...} no sirven únicamente para enlaces entre páginas. También permiten construir las URL de los recursos almacenados en static.

Supongamos esta estructura:

Recursos del proyecto
src/main/resources/static/
├── css/
│   └── estilos.css
└── img/
    └── logo-catalogo.png

Spring Boot sirve normalmente estos archivos mediante URL que parten del contenido de static, no incluyendo el nombre de esa carpeta.

Por tanto:

Correspondencia
src/main/resources/static/css/estilos.css
                    ↓
            /css/estilos.css

src/main/resources/static/img/logo-catalogo.png
                    ↓
            /img/logo-catalogo.png
aviso

static forma parte de la estructura interna del proyecto, pero no forma parte de la URL pública del recurso.

🟩 Hoja de estilos con th:href​

Podemos enlazar una hoja de estilos así:

Enlace a CSS
<link
    rel="stylesheet"
    th:href="@{/css/estilos.css}">

🟨 Imagen con th:src​

Para una imagen utilizaremos th:src:

Imagen estática
<img
    th:src="@{/img/logo-catalogo.png}"
    alt="Logotipo del catálogo">

th:href y th:src siguen la misma idea: Thymeleaf calcula el valor final del atributo HTML correspondiente.

7️⃣ Combinar texto fijo y valores dinámicos​

Una página suele mezclar contenido fijo con datos procedentes del modelo.

La opción más sencilla y legible suele ser utilizar HTML normal para el texto fijo y reservar Thymeleaf para el valor dinámico:

Texto fijo y dato dinámico
<p>
    Precio:
    <span th:text="${producto.precio}">0</span> €
</p>

También podemos concatenar valores dentro de una expresión:

Concatenación
<p th:text="'Producto: ' + ${producto.nombre}">
    Producto
</p>

Pero no conviene convertir todas las frases de la página en expresiones innecesariamente complejas.

tip

Si el texto fijo puede escribirse directamente como HTML y el dato dinámico puede aislarse en un elemento como <span>, esa solución suele ser más fácil de leer y mantener.

8️⃣ th:text trata los datos como texto​

Ya conocemos th:text, pero hay una característica importante que conviene entender.

Supongamos que el modelo contiene:

Contenido del atributo
<strong>Oferta</strong>

Y la vista utiliza:

Uso de th:text
<p th:text="${mensaje}">Mensaje</p>

th:text trata ese valor como texto, no como etiquetas HTML que deban formar parte de la página.

Esto es una propiedad deseable cuando mostramos datos que no deberían convertirse en código HTML.

Thymeleaf dispone también de th:utext, que inserta contenido HTML sin escapar, pero no lo necesitaremos en esta unidad.

peligro

No utilices th:utext con contenido procedente de usuarios sin comprender previamente sus implicaciones de seguridad.

Para mostrar datos normales utilizaremos th:text.

9️⃣ Ejemplo: navegación de un catálogo​

Supongamos que el controlador prepara esta página:

ProductoController.java
@GetMapping("/productos/{id}")
public String detalle(
        @PathVariable int id,
        @RequestParam(defaultValue = "eur") String moneda,
        Model model) {

    Producto producto =
            new Producto(id, "Teclado mecánico", 79.90);

    model.addAttribute("producto", producto);
    model.addAttribute("moneda", moneda);

    return "producto";
}

La plantilla puede utilizar expresiones de datos y expresiones de URL en una misma página:

producto.html
<!DOCTYPE html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Detalle del producto</title>

    <link
        rel="stylesheet"
        th:href="@{/css/estilos.css}">
</head>
<body>

    <h1 th:text="${producto.nombre}">
        Nombre del producto
    </h1>

    <p>
        Identificador:
        <span th:text="${producto.id}">0</span>
    </p>

    <p>
        Precio:
        <span th:text="${producto.precio}">0</span>
        <span th:text="${moneda}">eur</span>
    </p>

    <a th:href="@{/productos}">
        Volver al catálogo
    </a>

    <a th:href="@{/productos/{id}(
            id=${producto.id},
            moneda='usd'
        )}">
        Ver precio en dólares
    </a>

</body>
</html>
en este ejemplo

Las expresiones ${producto.nombre}, ${producto.id} y ${producto.precio} utilizan datos disponibles en la vista.

${moneda} accede a otro atributo del modelo.

@{/css/estilos.css} construye la URL de un recurso estático.

@{/productos} genera un enlace a otra ruta de la aplicación.

El último th:href construye una URL que combina la variable de ruta id con el parámetro de consulta moneda. Cuando el usuario pulse el enlace, esa URL generará una nueva petición que volverá a ser atendida por el controlador.

🔟 Errores frecuentes al trabajar con expresiones y URL​

🟩 Confundir ${...} y @{...}​

Incorrecto para construir un enlace:

Uso incorrecto
<a th:href="${'/productos'}">Productos</a>

Para una URL utilizaremos:

Uso correcto
<a th:href="@{/productos}">Productos</a>

${...} se utiliza para datos; @{...} para URL.

🟨 Construir una ruta concatenando cadenas​

Podría intentarse algo como:

Concatenación poco adecuada
<a th:href="'/productos/' + ${producto.id}">
    Ver detalle
</a>

Para una variable de ruta es más claro utilizar:

Variable de ruta
<a th:href="@{/productos/{id}(id=${producto.id})}">
    Ver detalle
</a>

La estructura de la URL queda explícita y separada del valor que se inserta.

🟧 Escribir manualmente la query string​

Evita construir:

Query string construida manualmente
<a th:href="'/productos?categoria=' + ${categoria}">
    Filtrar
</a>

Thymeleaf dispone de una sintaxis específica:

Parámetro de consulta
<a th:href="@{/productos(categoria=${categoria})}">
    Filtrar
</a>

🟥 Incluir /static en la URL​

Incorrecto:

Ruta incorrecta
<link rel="stylesheet" th:href="@{/static/css/estilos.css}">

Correcto:

Ruta correcta
<link rel="stylesheet" th:href="@{/css/estilos.css}">

La carpeta static no aparece en la URL pública.

🟪 Utilizar un dato que no existe​

Si escribimos:

Expresión
<span th:text="${producto.nombre}">Nombre</span>

la vista necesita disponer de un atributo llamado producto con una propiedad accesible llamada nombre.

La expresión no crea ese objeto. Debe haber sido preparado previamente por el controlador.
