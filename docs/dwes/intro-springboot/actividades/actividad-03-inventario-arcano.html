Actividad 3. Los datos llegan a la vista

En la actividad anterior conseguimos que las URL de Inventario Arcano transportaran información hasta los controladores. Pudimos recibir identificadores, parámetros de consulta y distintos tipos de datos, pero las nuevas operaciones devolvían respuestas de texto para comprobar fácilmente qué estaba recibiendo Spring MVC.

Ahora vamos a dar el siguiente paso: esos datos dejarán de mostrarse como texto de comprobación y pasarán a formar parte de páginas HTML generadas con Thymeleaf.

Seguiremos trabajando sobre el mismo proyecto. No debes crear una aplicación nueva.

Objetivo

Modificar Inventario Arcano para que los controladores preparen datos, los añadan a un Model y devuelvan vistas Thymeleaf capaces de mostrar tanto atributos sencillos como objetos Java completos.

nota

Esta actividad es de entrega obligatoria. Entra dentro de las actividades de seguimiento y será evaluada como Entregada o NO entregada.

La parte de ampliación es opcional y no será necesaria para poder continuar con la Actividad 2.

1️⃣ Punto de partida​

Debes comenzar con la aplicación resultante de la Actividad 2.

Proyecto de recuperación

Si no pudiste completar correctamente la actividad anterior, puedes utilizar este proyecto como punto de partida:

👉 Descargar Inventario Arcano — recuperación de la Actividad 2

Contiene únicamente el estado mínimo esperado al finalizar la Actividad 2. No incluye su ampliación opcional ni resuelve ningún apartado de esta actividad.

Si tu propio proyecto funciona correctamente, continúa trabajando sobre él.

Antes de modificar nada, comprueba que siguen funcionando:

Rutas ya existentes
/catalogo
/catalogo/pociones
/catalogo/pergaminos
/catalogo/artefactos
/catalogo/recomendados
/catalogo/objeto/7
/catalogo/buscar?texto=cristal
/catalogo/rareza/epica

En este momento algunas de las últimas rutas muestran respuestas de texto porque utilizan @ResponseBody.

Eso era útil para estudiar cómo llegaban los datos desde la petición. Ahora queremos que una parte de esas operaciones termine en una vista Thymeleaf.

aviso

No elimines las rutas y vistas de las actividades anteriores.

La aplicación debe seguir creciendo sobre el mismo proyecto.

2️⃣ La nueva necesidad de Inventario Arcano​

La tienda ya puede recibir peticiones como:

/catalogo/objeto/7
/catalogo/objeto/7?moneda=gemas

pero una respuesta como esta:

Consulta de objeto arcano
Identificador: 7
Moneda: gemas
Cantidad: 1
Envolver: false

no es una página adecuada para un usuario.

Queremos transformar esa consulta en una ficha real de producto.

El recorrido cambia de forma importante: la información que llega en la petición ya no termina en una respuesta de texto, sino que se transforma en datos que una plantilla Thymeleaf utilizará para generar la página.

La URL seguirá aportando información, pero ahora el controlador tendrá que preparar los datos que utilizará la vista.

3️⃣ Requisito 1: crear la clase ProductoMagico​

Crea una clase Java llamada:

ProductoMagico

Puedes situarla en un paquete propio para las clases que representan datos de la aplicación.

La clase deberá contener, como mínimo:

PropiedadTipo
idint.
nombreString.
categoriaString.
rarezaString.
preciodouble.
descripcionString.

Deberá disponer de:

  • un constructor que permita inicializar todas las propiedades.
  • un método get para cada propiedad.

Por ejemplo, Thymeleaf tendrá que poder utilizar expresiones como:

Propiedades que utilizará la vista
${producto.id}
${producto.nombre}
${producto.categoria}
${producto.rareza}
${producto.precio}
${producto.descripcion}
Dos conceptos distintos

En esta actividad aparecerán juntos:

ProductoMagico

y:

org.springframework.ui.Model

ProductoMagico representa información de nuestra aplicación.

Model es el mecanismo que utilizaremos para poner esa información a disposición de una vista.

4️⃣ Requisito 2: preparar varios productos mágicos​

La ficha de producto debe cambiar según el identificador recibido.

Prepara, como mínimo, tres productos diferentes. Puedes elegir sus nombres y características, pero deben pertenecer al universo de Inventario Arcano.

Por ejemplo, podrías trabajar con ideas como:

idProductoCategoría
1Poción de visión nocturnaPociones.
2Pergamino de retornoPergaminos.
3Brújula astralArtefactos.

No es obligatorio utilizar estos productos.

Lo importante es que estas peticiones no terminen mostrando exactamente los mismos datos:

/catalogo/objeto/1
/catalogo/objeto/2
/catalogo/objeto/3

Decide cómo seleccionarás o construirás el ProductoMagico correspondiente a partir del id.

Todavía no estamos utilizando base de datos ni repositorios. Los productos pueden estar definidos mediante código Java sencillo.

aviso

No crees una ruta diferente para cada producto.

Debe seguir existiendo un único patrón:

/catalogo/objeto/{id}

El identificador recibido determinará qué datos prepara el controlador.

5️⃣ Requisito 3: convertir el detalle de objeto en una vista​

Modifica la operación que ya atiende:

Ruta existente
GET /catalogo/objeto/{id}

Queremos dejar de devolver una respuesta de texto y utilizar una vista Thymeleaf.

La operación deberá recibir:

  • id mediante @PathVariable.
  • moneda mediante @RequestParam, con valor por defecto oro.
  • un objeto Model proporcionado por Spring MVC.

El controlador deberá:

  1. Obtener o construir el ProductoMagico correspondiente al identificador.
  2. Añadir el producto completo al modelo con el nombre:
producto
  1. Añadir también la moneda con el nombre:
moneda
  1. Devolver el nombre lógico de la nueva vista.
peligro

Cuando el método devuelve una vista Thymeleaf no debe utilizar @ResponseBody.

Si lo mantienes, Spring enviará el nombre de la vista como texto en lugar de procesar la plantilla.

🟩 Resultado esperado en el modelo​

Para una petición como:

/catalogo/objeto/2?moneda=gemas

podemos imaginar un modelo similar a:

AtributoValor
productoObjeto ProductoMagico con id = 2.
moneda"gemas".

No necesitas añadir por separado al modelo nombre, categoria, rareza, precio y descripcion.

Esos datos ya forman parte del objeto producto.

6️⃣ Requisito 4: crear la ficha Thymeleaf del producto​

Crea una nueva plantilla para mostrar el detalle de un producto.

Puedes llamarla:

detalle-producto.html

La plantilla deberá incluir la declaración necesaria para utilizar atributos th:*:

Declaración de Thymeleaf
<html lang="es" xmlns:th="http://www.thymeleaf.org">

La página deberá mostrar mediante th:text, como mínimo:

  • identificador.
  • nombre.
  • categoría.
  • rareza.
  • precio.
  • descripción.
  • moneda seleccionada.

Por ejemplo, para obtener el nombre deberás partir del objeto recibido:

Acceso a una propiedad del objeto
<h1 th:text="${producto.nombre}">Nombre del producto</h1>

y para un atributo independiente:

Acceso a un atributo sencillo
<span th:text="${moneda}">oro</span>

🟩 Contenido HTML de respaldo​

Mantén contenido HTML normal dentro de los elementos que utilizan th:text.

Por ejemplo:

<p>
    Rareza:
    <span th:text="${producto.rareza}">Sin clasificar</span>
</p>

Ese contenido permite reconocer la estructura de la página aunque observemos el archivo HTML sin ejecutar la aplicación.

🟨 Mantener la identidad visual​

Utiliza la hoja de estilos y los recursos ya incorporados en Inventario Arcano.

No necesitas crear un diseño nuevo. La ficha debe parecer parte de la misma aplicación.

En esta fase el trabajo importante está en el recorrido de los datos desde Java hasta la plantilla.

7️⃣ Requisito 5: transformar la búsqueda en una vista de resultados​

En la Actividad 2 creamos:

Ruta existente
GET /catalogo/buscar

y utilizamos una respuesta de texto para comprobar los parámetros recibidos.

Ahora modifica esa operación para que devuelva una vista llamada, por ejemplo:

resultado-busqueda

Mantén los mismos parámetros de la actividad anterior:

ParámetroComportamiento
textoObligatorio.
categoriaOpcional.
rarezaValor por defecto todas.
precioMaxValor por defecto 250.
ordenValor por defecto nombre.
soloDisponiblesValor por defecto false.

Añade al Model los datos necesarios para que la nueva página pueda mostrar los criterios con los que se realizaría la búsqueda.

Por ejemplo:

Petición
/catalogo/buscar?texto=cristal&categoria=artefactos&rareza=rara&precioMax=120

debería terminar mostrando una página con información equivalente a:

Texto buscado: cristal
Categoría: artefactos
Rareza: rara
Precio máximo: 120.0
Orden: nombre
Solo disponibles: false
En esta actividad

Todavía no necesitamos mostrar una colección de productos encontrados.

La página representa los criterios de búsqueda recibidos por el controlador. Más adelante trabajaremos con colecciones y repetición de elementos en Thymeleaf.

🟩 El parámetro opcional​

Recuerda que categoria puede no aparecer:

/catalogo/buscar?texto=cristal

El controlador debe preparar un valor adecuado para que la vista pueda mostrar el criterio utilizado sin depender de que la plantilla tenga que resolver ese caso.

8️⃣ Requisito 6: comprobar que una misma vista recibe datos diferentes​

Una plantilla dinámica no debería estar ligada a una única petición concreta.

Prueba consecutivamente:

/catalogo/objeto/1
/catalogo/objeto/2
/catalogo/objeto/3

Las tres peticiones deben terminar utilizando la misma plantilla, pero mostrando datos diferentes.

Haz también la prueba con:

/catalogo/objeto/2?moneda=gemas

y después:

/catalogo/objeto/2?moneda=oro

La ficha debe mostrar el mismo producto, pero la moneda recibida deberá cambiar.

🟩 Comprueba también el alcance del Model​

Carga:

/catalogo/objeto/1

y después:

/catalogo/objeto/3

Comprueba que la segunda respuesta contiene los datos preparados para esa nueva petición.

No necesitas almacenar los atributos del Model en variables globales ni conservarlos manualmente entre peticiones.

9️⃣ Requisito 7: integrar las nuevas vistas en la navegación existente​

En catalogo.html ya disponemos de una zona de acceso a las consultas desarrolladas en la actividad anterior.

Actualízala para que existan enlaces de prueba hacia, al menos:

/catalogo/objeto/1
/catalogo/objeto/2
/catalogo/objeto/3?moneda=gemas
/catalogo/buscar?texto=cristal
/catalogo/buscar?texto=pergamino&categoria=pergaminos&rareza=rara

Al seguir estos enlaces ya no deberíamos llegar a respuestas de texto en las operaciones que has transformado.

Deberemos obtener páginas HTML procesadas por Thymeleaf.

No necesitas construir esos enlaces a partir de datos dinámicos. En esta actividad pueden seguir siendo enlaces HTML normales.

🔟 Pruebas mínimas obligatorias​

Comprueba primero las fichas:

Detalle de productos
/catalogo/objeto/1
/catalogo/objeto/2
/catalogo/objeto/3
/catalogo/objeto/2?moneda=gemas

Verifica que:

  • se utiliza la misma plantilla para todas.
  • cambia el objeto producto.
  • cambia la moneda cuando se modifica el parámetro.
  • el navegador recibe una página HTML y no el nombre lógico de la vista.

Comprueba después la búsqueda:

Resultados de búsqueda
/catalogo/buscar?texto=cristal
/catalogo/buscar?texto=pocion&categoria=pociones
/catalogo/buscar?texto=libro&rareza=rara&precioMax=120
/catalogo/buscar?texto=anillo&orden=precio&soloDisponibles=true

Finalmente, vuelve a recorrer algunas rutas anteriores:

Rutas que deben seguir funcionando
/catalogo
/catalogo/pociones
/catalogo/pergaminos
/catalogo/artefactos
/catalogo/recomendados
/gremio

1️⃣1️⃣ Requisitos técnicos​

La solución deberá cumplir todos estos requisitos:

  • Continuar sobre el proyecto Inventario Arcano de la Actividad 2.
  • Mantener operativas las rutas y vistas existentes.
  • Crear una clase ProductoMagico con constructor y getters.
  • Utilizar un único patrón /catalogo/objeto/{id} para consultar productos.
  • Utilizar Model como parámetro proporcionado por Spring MVC.
  • Añadir al modelo tanto atributos sencillos como un objeto Java completo.
  • Utilizar model.addAttribute() para poner los datos a disposición de las vistas.
  • Devolver nombres lógicos de vista desde los métodos que renderizan Thymeleaf.
  • No utilizar @ResponseBody en esos métodos.
  • Incluir xmlns:th en las plantillas que utilizan Thymeleaf.
  • Mostrar datos mediante th:text.
  • Acceder a las propiedades del producto con expresiones como ${producto.nombre}.
  • Mantener la lógica de preparación de datos en Java y la presentación en las plantillas HTML.
  • Conservar la hoja de estilos y los recursos visuales ya utilizados por la aplicación.
peligro

No construyas HTML concatenando cadenas dentro del controlador.

El controlador debe preparar los datos y elegir la vista. La plantilla es la responsable de generar la presentación HTML.

1️⃣2️⃣ Comprobación final​

Antes de dar la actividad por terminada, comprueba:

  • He continuado trabajando sobre el proyecto anterior.
  • He creado la clase ProductoMagico.
  • La clase tiene constructor y getters para sus propiedades.
  • Al menos tres identificadores producen productos diferentes.
  • /catalogo/objeto/{id} sigue siendo una única ruta parametrizada.
  • El método de detalle recibe un Model.
  • El producto completo se añade al modelo como producto.
  • La moneda se añade como un atributo independiente.
  • El método devuelve una vista y ya no utiliza @ResponseBody.
  • La plantilla utiliza xmlns:th.
  • La ficha utiliza th:text para mostrar los datos.
  • Las propiedades se consultan mediante ${producto.propiedad}.
  • /catalogo/buscar devuelve ahora una vista Thymeleaf.
  • La vista de búsqueda muestra los criterios recibidos.
  • categoria puede seguir omitiéndose.
  • He comprobado que diferentes peticiones generan diferentes datos en la misma plantilla.
  • Las rutas anteriores del proyecto continúan funcionando.
  • No he generado HTML desde el controlador.

1️⃣3️⃣ Ampliación opcional: encargo de un objeto mágico​

Si terminas la parte obligatoria, añade una operación para preparar el resumen de un encargo.

La ampliación no será necesaria para comenzar la Actividad 4.

La ruta será:

Ruta de ampliación
/catalogo/encargo/{id}

y podrá recibir:

ParámetroTipoValor por defecto
cantidadint1.
monedaStringoro.

Por ejemplo:

/catalogo/encargo/2
/catalogo/encargo/2?cantidad=3
/catalogo/encargo/3?cantidad=2&moneda=gemas

El controlador deberá:

  1. Obtener el ProductoMagico correspondiente al identificador.
  2. Calcular en Java el importe resultante de multiplicar su precio por la cantidad.
  3. Añadir al Model:
    • el producto.
    • la cantidad.
    • la moneda.
    • el importe calculado.
  4. Devolver una vista Thymeleaf denominada, por ejemplo, resumen-encargo.

La vista deberá mostrar esos datos utilizando th:text.

🟩 Qué queremos practicar​

La ampliación no introduce un mecanismo nuevo.

Obliga a combinar correctamente lo que ya hemos utilizado:

@PathVariable
        +
@RequestParam
        +
objeto Java
        +
Model
        +
vista Thymeleaf

El cálculo se realiza en Java y la plantilla se limita a presentar el resultado.

📦 Cómo preparar la entrega​

Antes de entregar, comprueba que el proyecto compila y se ejecuta correctamente.

Preparar la entrega

Abre la terminal de IntelliJ IDEA desde:

View → Tool Windows → Terminal

Sitúate en la carpeta raíz del proyecto, donde se encuentra pom.xml.

Primero elimina los archivos generados durante la compilación:

Limpiar el proyecto
.\mvnw.cmd clean

Después genera directamente el archivo ZIP de entrega:

Crear el ZIP
tar -a -c -f ..\apellido-nombre-UT2-3.zip pom.xml mvnw mvnw.cmd .mvn src

El archivo apellido-nombre-UT2-3.zip se creará en la carpeta inmediatamente superior a la del proyecto.

El ZIP debe contener una estructura similar a:

Contenido de la entrega
pom.xml
mvnw
mvnw.cmd
.mvn/
src/
Antes de entregar

No incluyas archivos o carpetas generados automáticamente por Maven, IntelliJ IDEA o Git, como:

Archivos que no deben entregarse
target/
.idea/
.git/
out/
*.iml

No entregues únicamente la carpeta src.

El archivo pom.xml y el wrapper de Maven (mvnw, mvnw.cmd y .mvn/) forman parte del proyecto y permiten reconstruirlo correctamente en otro equipo.

Antes de subir el archivo, abre el ZIP y comprueba que contiene todos los elementos indicados.

Nombra el archivo siguiendo este formato:

Nombre del archivo
apellido-nombre-UT2-3.zip
