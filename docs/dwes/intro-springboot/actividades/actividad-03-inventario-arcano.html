Actividad 3. Los datos llegan a la vista

En la actividad anterior conseguimos que Inventario Arcano recibiera información mediante parámetros y variables de ruta. Para comprobar esos datos utilizábamos respuestas de texto.

Ahora vamos a dar el siguiente paso: el controlador preparará los datos, los añadirá a un Model y devolverá una vista Thymeleaf que los mostrará en HTML.

Seguiremos trabajando sobre el mismo proyecto. No debes crear una aplicación nueva.

Objetivo

Al finalizar la actividad debes comprender este recorrido:

petición
   ↓
controlador
   ↓
Model
   ↓
vista Thymeleaf
   ↓
HTML

También trabajarás con un objeto Java completo dentro del Model, no solo con valores sencillos.

nota

Esta actividad es de entrega obligatoria. Entra dentro de las actividades de seguimiento y será evaluada como Entregada o NO entregada.

La ampliación es opcional y no será necesaria para continuar con la Actividad 4.

1️⃣ Punto de partida​

Continúa con el proyecto resultante de la Actividad 2.

Proyecto de recuperación

Si no pudiste completar correctamente la actividad anterior, puedes utilizar:

👉 Descargar Inventario Arcano — recuperación de la Actividad 2

Contiene únicamente el estado mínimo esperado al finalizar la Actividad 2.

Antes de empezar, comprueba al menos:

Rutas que ya deben funcionar
/catalogo
/catalogo/objeto/7
/catalogo/buscar?texto=cristal
/catalogo/rareza/epica

Algunas de estas rutas todavía devuelven texto mediante @ResponseBody. En esta actividad transformaremos parte de ellas en páginas HTML.

2️⃣ El reto​

Queremos pasar de una respuesta como:

Consulta de objeto arcano
Identificador: 7
Moneda: gemas

a una ficha HTML generada con Thymeleaf.

La idea es que el controlador deje de construir la respuesta final y se limite a preparar los datos que necesita la vista.

3️⃣ Trabajo que debes realizar​

🟩 A. Crea la clase ProductoMagico​

Crea una clase Java llamada:

ProductoMagico

con estas propiedades:

PropiedadTipo
idint
nombreString
categoriaString
rarezaString
preciodouble
descripcionString

Añade:

  • un constructor que reciba todas las propiedades.
  • un getter para cada propiedad.

El constructor deberá permitir crear un producto indicando todos sus datos:

Constructor de ProductoMagico
public ProductoMagico(
        int id,
        String nombre,
        String categoria,
        String rareza,
        double precio,
        String descripcion) {

    this.id = id;
    this.nombre = nombre;
    this.categoria = categoria;
    this.rareza = rareza;
    this.precio = precio;
    this.descripcion = descripcion;
}

Thymeleaf utilizará expresiones como:

${producto.id}
${producto.nombre}
${producto.precio}
Dos conceptos diferentes

ProductoMagico representa datos de nuestra aplicación.

Model es el objeto que Spring MVC utiliza para poner esos datos a disposición de una vista.

Para esta actividad utiliza estos tres productos:

idNombreCategoríaRarezaPrecioDescripción
1Poción de visión nocturnaPocionesComún35.0Permite distinguir formas y caminos en lugares con muy poca luz.
2Pergamino de retornoPergaminosRaro62.5Un pergamino utilizado por viajeros para marcar un punto de regreso.
3Brújula astralArtefactosÉpico145.0Una brújula encantada cuya aguja señala el lugar elegido por su portador.

Puedes crearlos directamente en Java:

Productos de prueba
ProductoMagico producto1 = new ProductoMagico(
        1,
        "Poción de visión nocturna",
        "Pociones",
        "Común",
        35.0,
        "Permite distinguir formas y caminos en lugares con muy poca luz."
);

ProductoMagico producto2 = new ProductoMagico(
        2,
        "Pergamino de retorno",
        "Pergaminos",
        "Raro",
        62.5,
        "Un pergamino utilizado por viajeros para marcar un punto de regreso."
);

ProductoMagico producto3 = new ProductoMagico(
        3,
        "Brújula astral",
        "Artefactos",
        "Épico",
        145.0,
        "Una brújula encantada cuya aguja señala el lugar elegido por su portador."
);

La ruta seguirá siendo siempre:

/catalogo/objeto/{id}

El id recibido determinará qué producto prepara el controlador.

🟨 B. Convierte el detalle del producto en una vista Thymeleaf​

Modifica la operación que atiende:

GET /catalogo/objeto/{id}

El método debe recibir:

  • id mediante @PathVariable.
  • moneda mediante @RequestParam, con valor por defecto oro.
  • un Model.

Después:

  1. Obtén el ProductoMagico correspondiente al id.
  2. Añádelo al modelo con el nombre producto.
  3. Añade también moneda.
  4. Devuelve el nombre de una vista, por ejemplo detalle-producto.

Para:

/catalogo/objeto/2?moneda=gemas

el Model debería contener:

AtributoValor
productoObjeto ProductoMagico con id = 2
moneda"gemas"
peligro

Si el método devuelve una vista Thymeleaf, no debe utilizar @ResponseBody.

Si lo mantienes, Spring enviará el nombre de la vista como texto.

Crea detalle-producto.html y muestra mediante th:text:

  • identificador.
  • nombre.
  • categoría.
  • rareza.
  • precio.
  • descripción.
  • moneda.

Por ejemplo:

Acceso a datos del Model
<h1 th:text="${producto.nombre}">
    Nombre del producto
</h1>

<p>
    Precio:
    <span th:text="${producto.precio}">0</span>
    <span th:text="${moneda}">oro</span>
</p>

Mantén la hoja de estilos y los recursos visuales que ya utiliza Inventario Arcano.

🟧 C. Convierte también la búsqueda en una vista​

La ruta:

GET /catalogo/buscar

debe dejar de devolver una respuesta de texto.

Mantén los parámetros que ya utilizabas:

ParámetroComportamiento
textoObligatorio
categoriaOpcional
rarezaPor defecto todas
precioMaxPor defecto 250
ordenPor defecto nombre
soloDisponiblesPor defecto false

Añade al Model los datos necesarios y devuelve una vista, por ejemplo:

resultado-busqueda

Para una petición como:

/catalogo/buscar?texto=cristal&categoria=artefactos&rareza=rara&precioMax=120

la página debe mostrar información equivalente a:

Texto buscado: cristal
Categoría: artefactos
Rareza: rara
Precio máximo: 120.0
Orden: nombre
Solo disponibles: false
En esta actividad

Todavía no tienes que mostrar una colección de resultados.

La vista solo muestra los criterios de búsqueda que ha preparado el controlador.

Recuerda que categoria puede no aparecer en la petición. El controlador debe preparar un valor adecuado para que la vista pueda mostrar ese criterio sin errores.

🟥 D. Comprueba que una misma vista sirve para datos diferentes​

Prueba:

Detalle
/catalogo/objeto/1
/catalogo/objeto/2
/catalogo/objeto/3
/catalogo/objeto/2?moneda=gemas

La misma plantilla detalle-producto.html debe mostrar distintos productos según el id.

Prueba también:

Búsqueda
/catalogo/buscar?texto=cristal
/catalogo/buscar?texto=pocion&categoria=pociones
/catalogo/buscar?texto=libro&rareza=rara&precioMax=120

Actualiza catalogo.html para que tenga enlaces sencillos desde los que puedas probar estas nuevas páginas.

En esta actividad los enlaces todavía pueden escribirse con HTML normal:

<a href="/catalogo/objeto/1">Ver objeto 1</a>

La construcción dinámica de URL con Thymeleaf será el objetivo de la siguiente actividad.

4️⃣ Comprobación final​

Antes de dar la actividad por terminada:

  • He creado ProductoMagico con un constructor que recibe todos sus atributos y con sus getters.
  • Al menos tres identificadores muestran productos diferentes.
  • El detalle utiliza Model.
  • El objeto completo se añade como producto.
  • La moneda se añade como atributo independiente.
  • El método de detalle devuelve una vista y no utiliza @ResponseBody.
  • detalle-producto.html utiliza th:text.
  • La búsqueda devuelve una vista Thymeleaf.
  • La vista de búsqueda muestra los criterios recibidos.
  • Las rutas anteriores de la aplicación siguen funcionando.
  • No genero HTML concatenando cadenas dentro del controlador.

5️⃣ Ampliación opcional: encargo de un objeto mágico​

Añade una ruta:

/catalogo/encargo/{id}

que pueda recibir:

cantidad → por defecto 1
moneda   → por defecto oro

Por ejemplo:

/catalogo/encargo/2?cantidad=3&moneda=gemas

El controlador deberá:

  1. Obtener el producto correspondiente.
  2. Calcular en Java precio × cantidad.
  3. Añadir al Model el producto, la cantidad, la moneda y el importe.
  4. Devolver una vista resumen-encargo.

La vista se limitará a mostrar esos datos mediante th:text.
