Actividad 5. El catálogo cobra vida

Hasta ahora Inventario Arcano ya puede recibir información desde una URL, enviar datos a las vistas mediante Model y construir enlaces dinámicos con Thymeleaf.

El catálogo, sin embargo, sigue teniendo una limitación importante: los productos aparecen escritos de forma individual en el HTML.

En esta actividad vamos a convertirlo en un catálogo realmente dinámico. El controlador enviará una colección de objetos ProductoMagico y Thymeleaf generará automáticamente una tarjeta por cada producto.

Objetivo

Transformar catalogo.html para que reciba una List<ProductoMagico> y genere el contenido mediante th:each, utilizando además la variable de estado, th:if, th:unless, th:block y th:switch para adaptar la presentación a los datos de cada producto.

nota

Esta actividad es de entrega obligatoria. Forma parte de las actividades de seguimiento y se registrará como Entregada o NO entregada.

La ampliación es opcional y no forma parte de los requisitos de la actividad.

1️⃣ Punto de partida​

Debes continuar con la aplicación obtenida al finalizar la Actividad 4.

Proyecto de recuperación

Si no pudiste completar correctamente la actividad anterior, puedes utilizar este proyecto como punto de partida:

👉 Descargar Inventario Arcano — recuperación de la Actividad 4

Contiene únicamente el estado mínimo esperado al finalizar la Actividad 4.

Si tu propio proyecto funciona correctamente, continúa trabajando sobre él.

Antes de empezar, comprueba que siguen funcionando al menos estas rutas:

Rutas de partida
/catalogo
/catalogo/objeto/1
/catalogo/objeto/2?moneda=gemas
/catalogo/buscar?texto=cristal

También debes comprobar que:

  • la ficha de producto sigue utilizando Model.
  • los enlaces dinámicos se generan con th:href.
  • la hoja de estilos continúa cargándose.
  • las imágenes siguen mostrándose correctamente.

2️⃣ El reto​

Hasta ahora podríamos tener en catalogo.html varios bloques escritos manualmente:

Catálogo escrito a mano
<article>
    <h2>Poción de visión nocturna</h2>
    ...
</article>

<article>
    <h2>Pergamino de retorno</h2>
    ...
</article>

<article>
    <h2>Brújula astral</h2>
    ...
</article>

Ese planteamiento no escala. Si aparecen diez productos, tendríamos que escribir diez bloques casi iguales.

Queremos pasar a esta idea:

La plantilla ya no necesitará conocer de antemano cuántos productos existen.

3️⃣ Trabajo a realizar​

🟩 A. Prepara los productos​

Añade una nueva propiedad a ProductoMagico:

Nueva propiedad de ProductoMagico
private int stock;

Actualiza también:

  • el constructor, para que reciba stock.
  • el getter getStock().
aviso

Al cambiar el constructor tendrás que actualizar los lugares donde ya creabas objetos ProductoMagico.

La aplicación debe volver a compilar antes de continuar.

Para esta actividad utiliza estos cuatro productos:

idNombreCategoríaRarezaPrecioStock
1Poción de visión nocturnaPocionesComún35.08
2Pergamino de retornoPergaminosRaro62.50
3Brújula astralArtefactosÉpico145.03
4Cristal de la LunaArtefactosRaro95.01

Los cuatro identificadores deben seguir funcionando también en:

Fichas de detalle
/catalogo/objeto/1
/catalogo/objeto/2
/catalogo/objeto/3
/catalogo/objeto/4

No necesitamos todavía base de datos. Los datos pueden seguir preparándose directamente en Java.

Ahora modifica el método que atiende:

GET /catalogo

para crear una:

List<ProductoMagico>

con los cuatro productos anteriores.

Añádela al Model con el nombre:

productos

El resultado conceptual debe ser:

Contenido del Model
productos → List<ProductoMagico>

y el método debe seguir devolviendo:

return "catalogo";

🟨 B. Genera el catálogo con th:each​

Abre catalogo.html.

Elimina los bloques de productos escritos de forma individual y deja una sola estructura de tarjeta.

Esa tarjeta debe repetirse utilizando:

Iteración del catálogo
th:each="producto, estado : ${productos}"

Cada tarjeta deberá mostrar:

  • nombre.
  • categoría.
  • rareza.
  • precio.
  • stock.

Los datos deben proceder del objeto actual de la iteración:

Objeto actual
producto

No debes escribir manualmente cuatro tarjetas diferentes.

peligro

El objetivo es que exista una única estructura HTML y que Thymeleaf la repita automáticamente.

Si en catalogo.html aparecen cuatro tarjetas escritas a mano, este apartado no está resuelto.

Utiliza también la variable estado para mostrar una información equivalente a:

Posición dentro del catálogo
Objeto 1 de 4
Objeto 2 de 4
Objeto 3 de 4
Objeto 4 de 4

Para ello necesitarás:

estado.count
estado.size

No calcules estos valores en el controlador.

Cada tarjeta debe incluir además un enlace:

Ver detalle

que genere:

/catalogo/objeto/{id}

utilizando el identificador del producto actual.

Por ejemplo:

Enlace de detalle dentro del bucle
<a th:href="@{/catalogo/objeto/{id}(id=${producto.id})}">
    Ver detalle
</a>

El mismo código deberá generar URL diferentes para cada producto.

🟧 C. Adapta la presentación a los datos​

Cada tarjeta del catálogo debe mostrar información diferente según el stock.

Si:

producto.stock > 0

debe aparecer:

Disponible
Unidades: 5

o la cantidad que corresponda.

Agrupa esas dos líneas mediante:

<th:block th:if="...">

Cuando el producto esté agotado, muestra:

Agotado

utilizando th:unless.

Añade también una segunda condición sencilla:

producto.precio < 70

Cuando se cumpla, muestra una marca como:

Precio especial

mediante th:if.

🟥 Mostrar la rareza con th:switch​

La propiedad rareza puede tener distintos valores.

Utiliza th:switch y th:case para mostrar un texto diferente según la rareza del producto.

La estructura puede ser semejante a:

Mostrar una alternativa según la rareza
<div th:switch="${producto.rareza}">

    <span th:case="'Común'">Objeto común</span>

    <span th:case="'Raro'">Objeto raro</span>

    <span th:case="'Épico'">Objeto épico</span>

    <span th:case="*">Rareza desconocida</span>

</div>
Qué estamos practicando

Aquí utilizamos dos formas diferentes de tomar decisiones:

  • th:if y th:unless para condiciones verdaderas o falsas.
  • th:switch y th:case cuando un mismo dato puede tener varias alternativas.

🟪 D. Comprueba el catálogo y el caso vacío​

Una vista debe seguir siendo comprensible aunque no haya productos.

Añade un mensaje como:

No hay objetos disponibles en el inventario.

que aparezca únicamente cuando la colección esté vacía.

Utiliza:

#lists.isEmpty(productos)

junto con th:if.

El bloque que contiene las tarjetas debe mostrarse únicamente cuando existan productos, utilizando th:unless.

Para comprobarlo, sustituye temporalmente la colección del controlador por:

Prueba temporal de catálogo vacío
List<ProductoMagico> productos = List.of();

Recarga:

/catalogo

y comprueba que:

  • aparece el mensaje de catálogo vacío.
  • no se genera ninguna tarjeta.
  • la página mantiene su estructura general.

Después restaura los cuatro productos antes de terminar la actividad.

🟩 Comprueba también el HTML generado​

No te limites a mirar el resultado visual.

Inspecciona el HTML que recibe el navegador.

Aunque la plantilla contenga una sola tarjeta con:

th:each="producto, estado : ${productos}"

el HTML final debe contener cuatro tarjetas.

Comprueba además un producto con stock y el producto agotado.

El navegador debe recibir únicamente el HTML que Thymeleaf haya decidido generar.

4️⃣ Antes de terminar​

Comprueba que se cumplen todos estos puntos:

  • ProductoMagico incluye la propiedad stock.
  • El constructor y getStock() están actualizados.
  • El catálogo recibe una List<ProductoMagico> con los cuatro productos indicados.
  • La colección se añade al Model con el nombre productos.
  • Existe una sola estructura de tarjeta repetida mediante th:each.
  • La iteración utiliza estado.count y estado.size.
  • Cada tarjeta genera dinámicamente su enlace de detalle.
  • Los productos disponibles muestran su stock.
  • El producto con stock = 0 muestra Agotado.
  • Los productos con precio inferior a 70 muestran la marca correspondiente.
  • La rareza se presenta mediante th:switch y th:case.
  • La vista muestra un mensaje adecuado cuando la lista está vacía.
  • Las rutas y vistas de las actividades anteriores continúan funcionando.
  • El navegador recibe HTML normal y no instrucciones Thymeleaf sin procesar.

5️⃣ Ampliación opcional: una clase visual para los productos agotados​

Si terminas la parte obligatoria, utiliza th:classappend para añadir una clase CSS a los productos sin stock.

Por ejemplo:

Clase CSS añadida según el stock
<article
    class="producto"
    th:classappend="${producto.stock == 0} ? ' agotado' : ''">

    ...

</article>

Añade después a la hoja de estilos una regla sencilla para .agotado.

La ampliación debe modificar únicamente la presentación. No es necesario introducir nueva lógica en Java.
