Primer proyecto con Spring Boot

En la unidad anterior estudiamos cómo funciona una aplicación web desde el punto de vista de la arquitectura: cliente, servidor, peticiones HTTP, respuestas, rutas y generación dinámica de contenido.

A partir de ahora vamos a empezar a construir aplicaciones web reales con Java. Para ello utilizaremos Spring Boot como tecnología principal del módulo.

En este primer apartado todavía no vamos a crear controladores ni vistas. Antes necesitamos entender qué es Spring, qué aporta Spring Boot, cómo se crea un proyecto, qué papel cumple Maven y qué elementos aparecen cuando ejecutamos la aplicación por primera vez.

Idea principal

Spring Boot nos permite comenzar una aplicación basada en Spring con una configuración inicial razonable, dependencias compatibles y un servidor web integrado, evitando gran parte del trabajo manual que sería necesario antes de empezar a desarrollar.

1️⃣ Spring y Spring Boot no son lo mismo​

Es habitual escuchar simplemente “Spring” para referirse a todo el ecosistema, pero conviene distinguir desde el principio entre Spring Framework y Spring Boot.

🟩 Qué es Spring​

Spring Framework es un framework para desarrollar aplicaciones Java. Está formado por distintos módulos que proporcionan soluciones para necesidades habituales como aplicaciones web, validación, acceso a datos, transacciones, pruebas o integración con otras tecnologías.

Una de las ideas centrales de Spring es que muchas tareas de infraestructura pueden ser gestionadas por el propio framework.

En una aplicación Java tradicional solemos crear directamente los objetos que necesitamos y establecer manualmente sus relaciones. Spring introduce un contenedor capaz de crear y gestionar objetos de la aplicación y ayudar a relacionarlos entre sí.

Esta idea está relacionada con dos conceptos que aparecerán más adelante:

  • Inversión de control (IoC).
  • Inyección de dependencias (DI).
nota

No necesitamos dominar todavía IoC ni la inyección de dependencias.

Por ahora basta con entender que Spring puede encargarse de crear y gestionar muchos objetos de nuestra aplicación en lugar de obligarnos a hacerlo todo manualmente.

Spring no es una única herramienta para hacer páginas web. Es un ecosistema amplio del que iremos utilizando distintas partes según las necesidades del módulo.

🟨 Entonces, ¿qué es Spring Boot?​

Spring Boot es una herramienta construida sobre Spring que simplifica la creación, configuración y ejecución de aplicaciones.

Spring proporciona los mecanismos y componentes. Spring Boot facilita que podamos empezar a utilizarlos sin tener que realizar una gran cantidad de configuración inicial.

Podemos verlo de forma simplificada así:

Spring Boot nos ayuda especialmente mediante:

  • autoconfiguración, preparando configuraciones habituales según las dependencias presentes en el proyecto.
  • starters, que agrupan dependencias relacionadas con una finalidad concreta.
  • gestión coherente de versiones, evitando que tengamos que elegir manualmente la versión de muchas librerías.
  • servidor web embebido, que permite ejecutar una aplicación web directamente.
  • aplicaciones ejecutables, que pueden empaquetarse y arrancarse de forma sencilla.
Qué problema resuelve Spring Boot

Sin Spring Boot, crear una aplicación web con Spring podría exigir bastante configuración previa: seleccionar librerías, comprobar versiones compatibles, configurar componentes web y preparar un servidor donde ejecutar la aplicación.

Spring Boot reduce buena parte de ese trabajo inicial y aplica convenciones razonables.

aviso

Spring Boot no hace desaparecer Spring ni sustituye los conceptos que hay debajo.

Lo que hace es facilitar su configuración y permitirnos empezar con una estructura preparada. A medida que avancemos iremos comprendiendo mejor qué está gestionando Spring por nosotros.

2️⃣ Autoconfiguración y servidor embebido​

Dos ideas de Spring Boot que conviene comprender desde el principio son la autoconfiguración y el servidor embebido.

🟩 Autoconfiguración​

Spring Boot analiza las dependencias y la configuración del proyecto e intenta preparar automáticamente aquello que normalmente necesita la aplicación.

Por ejemplo, si incorporamos las dependencias necesarias para construir una aplicación web, Spring Boot puede preparar buena parte de la infraestructura web sin que tengamos que configurarla manualmente desde cero.

Esto no significa que Spring Boot “adivine” cualquier configuración ni que no podamos modificarla. Significa que proporciona valores y configuraciones habituales por defecto, que podremos cambiar cuando lo necesitemos.

tip

Una buena forma de entender la filosofía de Spring Boot es esta:

configurar automáticamente lo habitual y permitir personalizarlo cuando sea necesario.

🟨 El servidor web embebido​

Una aplicación web necesita un servidor capaz de recibir peticiones HTTP y devolver respuestas.

Spring Boot puede incluir ese servidor dentro de la propia aplicación. A esto lo llamamos servidor embebido.

nota

No tenemos que instalar y configurar manualmente un servidor externo para comenzar a desarrollar.

El servidor sigue existiendo. La diferencia es que forma parte de la aplicación y se pone en marcha junto con ella.

3️⃣ Spring Initializr: crear el punto de partida​

Para crear nuestros proyectos utilizaremos Spring Initializr desde la web.

Spring Initializr

👉 Abrir Spring Initializr para crear y descargar el proyecto Spring Boot.

Spring Initializr es un generador de proyectos Spring Boot. A partir de las opciones que seleccionemos genera una estructura inicial preparada para trabajar.

Entre otras cosas crea:

  • la estructura de carpetas.
  • el archivo de construcción de Maven.
  • la clase principal de la aplicación.
  • la configuración básica.
  • las dependencias seleccionadas.

Spring Initializr no es un programa que tengamos que instalar.

aviso

No debemos confundir Spring Initializr con Spring Boot, Maven o IntelliJ IDEA.

ElementoFunción
Spring InitializrGenera el proyecto inicial.
Spring BootFacilita la creación y ejecución de la aplicación basada en Spring.
MavenGestiona la construcción del proyecto y sus dependencias.
IntelliJ IDEAPermite editar, ejecutar y trabajar con el código.

🟩 Qué elegimos al crear un proyecto​

Spring Initializr muestra varias opciones. Cada una describe una característica del proyecto que vamos a generar.

OpciónSelección / ejemploPara qué sirve
ProjectMavenIndica el sistema de construcción. Maven gestionará dependencias, compilación, pruebas y empaquetado.
LanguageJavaIndica el lenguaje de programación que utilizaremos en el proyecto.
Spring BootVersión estable indicada en claseDetermina la versión de Spring Boot y un conjunto compatible de versiones para muchas librerías.
Groupcom.ejemploIdentifica normalmente la organización o espacio al que pertenece el proyecto.
ArtifactcatalogoIdentificador técnico del proyecto y, normalmente, del artefacto generado.
NameCatalogoNombre descriptivo de la aplicación.
DescriptionAplicación de catálogoBreve descripción informativa del proyecto.
Package namecom.ejemplo.catalogoDefine el paquete Java base en el que se organizará la aplicación.
PackagingJarIndica cómo se empaquetará la aplicación. Utilizaremos JAR para poder ejecutarla directamente con Spring Boot.
JavaVersión indicada en claseDefine la versión de Java que utilizará el proyecto. Debe ser compatible con Spring Boot, el JDK instalado y el configurado en IntelliJ IDEA.
aviso

Para las prácticas del módulo utilizaremos versiones estables de Spring Boot.

Conviene evitar versiones identificadas como SNAPSHOT, milestone o preview salvo que exista una razón concreta para utilizarlas.

El package name tendrá especial importancia. La clase principal se situará en este paquete y las clases de la aplicación se organizarán normalmente dentro de él o de sus subpaquetes.

🟨 Las dependencias iniciales​

Una aplicación no contiene por sí sola todas las funcionalidades que puede necesitar. Añadimos dependencias para incorporar librerías y componentes ya desarrollados.

Para comenzar esta unidad seleccionaremos:

DependenciaPara qué la necesitaremos
Spring WebCrear una aplicación web, atender peticiones HTTP y trabajar con controladores y rutas.
ThymeleafGenerar páginas HTML dinámicas desde el servidor.

Thymeleaf todavía no se utilizará en este apartado, pero formará parte del proyecto que iremos ampliando durante la unidad.

aviso

No debemos añadir dependencias “por si acaso”.

En este momento no necesitamos JPA, Spring Security ni otras funcionalidades que estudiaremos más adelante.

4️⃣ Maven: construir el proyecto y gestionar dependencias​

Al crear el proyecto hemos elegido Maven como sistema de construcción.

Maven no pertenece a Spring Boot. Es una herramienta independiente utilizada ampliamente en proyectos Java.

Su función no se limita a descargar librerías. Maven organiza y automatiza distintas tareas necesarias para construir el proyecto.

🟩 Qué hace Maven​

Durante el curso utilizaremos Maven principalmente para:

  • describir el proyecto.
  • declarar las dependencias necesarias.
  • descargar esas dependencias desde repositorios.
  • compilar el código.
  • ejecutar pruebas cuando corresponda.
  • empaquetar la aplicación.

Podemos simplificar parte de su trabajo así:

Maven posee un ciclo de vida más amplio, pero no necesitamos estudiarlo completo en este momento.

🟨 El archivo pom.xml​

En la raíz del proyecto encontraremos:

Archivo pom.xml
pom.xml

POM significa Project Object Model. Este archivo describe el proyecto y contiene información utilizada por Maven.

Entre otras cosas puede indicar:

  • identificación del proyecto.
  • versión de Java.
  • dependencias.
  • plugins utilizados durante la construcción.
  • configuración relacionada con el empaquetado.

Un fragmento de dependencias puede tener este aspecto:

Fragmento de pom.xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-thymeleaf</artifactId>
    </dependency>
</dependencies>
en este ejemplo

Cada dependencia queda identificada mediante unas coordenadas.

Aquí aparecen groupId y artifactId, que permiten identificar la librería que necesita el proyecto.

No necesitamos memorizar ahora la sintaxis completa del pom.xml, pero sí saber localizar estas dependencias y entender qué representan.

🟧 Dependencias transitivas​

Cuando declaramos una dependencia, esa librería puede necesitar otras para funcionar.

Maven puede resolver y descargar automáticamente esas dependencias transitivas.

Por eso, añadir una única dependencia al pom.xml puede provocar que Maven descargue varias librerías relacionadas.

Resolución de dependencias transitivas
Nuestra aplicación
       ↓
spring-boot-starter-web
       ↓
otras dependencias necesarias
       ↓
Maven las resuelve automáticamente

Esto evita que tengamos que localizar manualmente todas las librerías que necesita cada componente.

🟥 Gestión de versiones en Spring Boot​

En muchos proyectos Spring Boot veremos dependencias sin una versión escrita directamente en cada una de ellas.

Esto es posible porque Spring Boot proporciona una gestión de dependencias que establece versiones compatibles para muchas librerías habituales.

Así evitamos tener que decidir manualmente qué combinación de versiones funciona correctamente.

Idea principal

Maven gestiona las dependencias y construye el proyecto. Spring Boot añade una gestión coherente de muchas versiones y proporciona dependencias preparadas para funcionalidades habituales.

5️⃣ Los starters de Spring Boot​

Spring Boot utiliza dependencias llamadas starters.

Un starter es una dependencia pensada como punto de entrada para una funcionalidad concreta. En lugar de localizar una a una todas las librerías necesarias, declaramos el starter correspondiente.

Por ejemplo:

Starter para aplicaciones web
spring-boot-starter-web

indica que queremos preparar el proyecto para desarrollar una aplicación web.

Lo mismo ocurre con:

Starter para Thymeleaf
spring-boot-starter-thymeleaf

que incorpora lo necesario para utilizar Thymeleaf con Spring Boot.

nota

No necesitamos memorizar los starters disponibles ni las librerías concretas que incluye cada uno.

Lo importante es comprender que un starter representa una funcionalidad que queremos incorporar al proyecto.

6️⃣ Generar y abrir el proyecto​

Una vez completadas las opciones de Spring Initializr, pulsaremos Generate.

El proceso será:

Proceso de generación e importación
Completar Spring Initializr
        ↓
Generate
        ↓
Descargar .zip
        ↓
Descomprimir el proyecto
        ↓
Abrir la carpeta raíz en IntelliJ IDEA
        ↓
Maven importa y descarga las dependencias

Conviene guardar los proyectos en una carpeta de trabajo organizada y no trabajar directamente dentro de Descargas.

🟩 Abrir la carpeta correcta​

En IntelliJ IDEA debemos abrir la carpeta raíz del proyecto, es decir, la carpeta donde se encuentra:

Archivo que identifica la raíz del proyecto
pom.xml

Si abrimos únicamente src o una carpeta superior, IntelliJ puede no reconocer correctamente el proyecto Maven.

🟨 La primera importación​

La primera vez que abrimos el proyecto, Maven puede necesitar descargar bastantes archivos.

Durante ese proceso IntelliJ también indexará el proyecto. Es normal que tarde más que en aperturas posteriores.

tip

Antes de ejecutar por primera vez, conviene esperar a que Maven termine de importar las dependencias y a que IntelliJ finalice la indexación principal.

7️⃣ La estructura esencial del proyecto​

Al abrir el proyecto aparecen varias carpetas y archivos. No necesitamos trabajar con todos ellos desde el primer momento.

Podemos reducir mentalmente el proyecto a esta estructura:

Estructura básica del proyecto
catalogo/
│
├── src/
│   ├── main/
│   │   ├── java/
│   │   │   └── com/ejemplo/catalogo/
│   │   │       └── CatalogoApplication.java
│   │   │
│   │   └── resources/
│   │       ├── static/
│   │       ├── templates/
│   │       └── application.properties
│   │
│   └── test/
│
├── mvnw
├── mvnw.cmd
└── pom.xml

🟩 src/main/java​

Aquí se encuentra el código Java de la aplicación.

Dentro aparecerá el paquete principal y, al principio, la clase que permite arrancar Spring Boot.

Ruta del código Java
src/main/java/com/ejemplo/catalogo/

En los siguientes apartados iremos creando aquí controladores y otras clases Java.

🟨 src/main/resources​

Esta carpeta contiene recursos y archivos de configuración que utiliza la aplicación.

Nos interesan especialmente:

ElementoFunción
application.propertiesConfiguración de la aplicación.
templates/Plantillas HTML que procesará Thymeleaf.
static/Recursos estáticos como CSS, imágenes o JavaScript.

Por ahora solo necesitamos situarlos. Los utilizaremos con detalle más adelante.

🟧 src/test​

Esta zona se utiliza para las pruebas automatizadas.

Spring Initializr genera una estructura inicial, aunque todavía no vamos a trabajar con ella en profundidad.

🟥 mvnw, mvnw.cmd y .mvn​

El proyecto puede incluir un Maven Wrapper.

Sus archivos principales son:

Archivos de Maven Wrapper
mvnw
mvnw.cmd
.mvn/

El wrapper permite ejecutar Maven utilizando la configuración incluida en el propio proyecto, sin depender exclusivamente de una instalación global de Maven realizada manualmente.

En Windows encontraremos normalmente mvnw.cmd; en Linux y macOS, mvnw.

No necesitamos estudiar todavía su funcionamiento interno, pero sí saber que no son archivos sobrantes.

Para orientarnos al principio

Podemos quedarnos con estas referencias:

  • código Java → src/main/java.
  • plantillas, recursos y configuración → src/main/resources.
  • configuración de Maven y dependencias → pom.xml.
  • arranque de la aplicación → clase principal.
  • ejecución de Maven desde el proyecto → Maven Wrapper.

8️⃣ La clase principal y @SpringBootApplication​

Spring Initializr crea una clase principal similar a esta:

CatalogoApplication.java
package com.ejemplo.catalogo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class CatalogoApplication {

    public static void main(String[] args) {
        SpringApplication.run(CatalogoApplication.class, args);
    }
}
en este ejemplo

@SpringBootApplication marca la clase principal de la aplicación Spring Boot y activa varias funcionalidades necesarias para arrancarla y configurarla.

El método main() sigue siendo el punto de entrada habitual de una aplicación Java.

SpringApplication.run(...) inicia Spring Boot y crea el entorno en el que funcionará nuestra aplicación.

Si el proyecto es web, durante ese proceso también se pone en marcha el servidor embebido.

No necesitamos descomponer todavía internamente @SpringBootApplication. Lo haremos cuando esos detalles ayuden a comprender conceptos posteriores.

9️⃣ Primera ejecución​

Una vez importadas las dependencias podemos ejecutar la clase principal desde IntelliJ IDEA.

En la consola aparecerán numerosos mensajes. Al principio no necesitamos interpretar cada línea.

Debemos buscar principalmente señales que indiquen que la aplicación ha arrancado correctamente.

Podremos encontrar mensajes similares a:

Salida de la consola al arrancar
Tomcat started on port 8080
Started CatalogoApplication in ... seconds
en este ejemplo

El puerto identifica el punto en el que el servidor está esperando conexiones.

Si utiliza el puerto 8080, podremos acceder desde el navegador a http://localhost:8080.

🟩 Una página visible para comprobar que funciona​

Para que la primera ejecución tenga un resultado visible en el navegador, crearemos una página estática muy sencilla.

Dentro de src/main/resources/static crearemos el archivo index.html:

src/main/resources/static/index.html
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Mi primera aplicación Spring Boot</title>
    <style>
        body {
            font-family: Arial, sans-serif;
            max-width: 760px;
            margin: 80px auto;
            padding: 0 24px;
        }

        .estado {
            padding: 24px;
            border: 2px solid #4caf72;
            border-radius: 12px;
            background: #f3fbf6;
        }
    </style>
</head>
<body>

    <main class="estado">
        <h1>Mi primera aplicación Spring Boot</h1>
        <p>El servidor está funcionando correctamente.</p>
        <p>Spring Boot está sirviendo esta página desde <code>static</code>.</p>
    </main>

</body>
</html>

Spring Boot puede servir directamente los recursos situados en src/main/resources/static. Al existir un archivo llamado index.html, podremos utilizarlo como página inicial de comprobación.

Después ejecutamos CatalogoApplication y abrimos:

Dirección de la aplicación
http://localhost:8080

Ahora tendremos dos evidencias de que la aplicación está funcionando:

  • en IntelliJ IDEA, la consola indica que el servidor ha arrancado.
  • en el navegador, aparece nuestra página de comprobación.
Qué estamos comprobando

Todavía no hemos creado ningún controlador ni estamos utilizando Thymeleaf.

La página se muestra porque index.html es un recurso estático. Más adelante haremos que las peticiones lleguen a código Java y que Spring genere respuestas dinámicas.

🔟 application.properties​

Dentro de src/main/resources encontraremos normalmente:

Archivo de configuración
application.properties

Este archivo permite modificar distintas opciones de configuración de la aplicación.

Por ejemplo, podemos cambiar el puerto del servidor:

src/main/resources/application.properties
server.port=8081
en este ejemplo

Después de reiniciar la aplicación, el servidor utilizará el puerto 8081 en lugar del puerto configurado por defecto.

La dirección para probarla será entonces http://localhost:8081.

No vamos a llenar este archivo de propiedades desde el principio. Lo iremos ampliando cuando aparezcan necesidades concretas.

1️⃣1️⃣ Práctica guiada: crear y reconocer nuestro proyecto​

Esta práctica se realizará durante la explicación y no constituye una actividad independiente.

El objetivo es terminar el apartado con un proyecto Spring Boot correctamente creado y sabiendo identificar sus elementos esenciales.

🟩 Crear el proyecto​

Desde Spring Initializr:

  1. Selecciona Maven.
  2. Selecciona Java.
  3. Utiliza la versión estable de Spring Boot indicada en clase.
  4. Completa Group, Artifact, Name y Package name.
  5. Selecciona empaquetado Jar.
  6. Selecciona la versión de Java indicada.
  7. Añade Spring Web y Thymeleaf.
  8. Genera el proyecto.

Antes de descargarlo, comprueba que sabes explicar qué significa cada opción seleccionada.

🟨 Abrir y reconocer la estructura​

Después de descomprimir el proyecto:

  1. Abre en IntelliJ IDEA la carpeta que contiene pom.xml.
  2. Espera a que Maven finalice la importación.
  3. Localiza src/main/java.
  4. Localiza src/main/resources.
  5. Localiza la clase principal.
  6. Abre pom.xml e identifica los starters añadidos.
  7. Localiza mvnw o mvnw.cmd.
  8. Comprueba dónde se encuentran templates, static y application.properties.

🟧 Crear una página de comprobación​

Crea src/main/resources/static/index.html utilizando la página de comprobación del apartado anterior.

Antes de ejecutar, comprueba que puedes explicar por qué este archivo se encuentra dentro de static y qué esperamos que ocurra al acceder a /.

🟥 Ejecutar la aplicación​

Ejecuta la clase principal y revisa la consola.

Después abre http://localhost:8080 en el navegador.

Comprueba:

  • que la aplicación arranca sin errores.
  • qué servidor web aparece en la salida.
  • qué puerto está utilizando.
  • que el proceso continúa ejecutándose y queda esperando peticiones.
  • que el navegador muestra la página index.html.

🟪 Modificar la configuración​

Añade temporalmente a application.properties:

src/main/resources/application.properties
server.port=8081

Reinicia la aplicación y comprueba en la consola que el puerto ha cambiado.

Después elimina la propiedad para volver a la configuración inicial.

tip

Esta práctica no pretende que memoricemos archivos ni opciones.

Debemos terminar sabiendo qué herramienta hemos utilizado, qué decisiones hemos tomado al crear el proyecto, qué papel cumple Maven, dónde está cada elemento esencial y qué ocurre cuando ejecutamos una aplicación Spring Boot.
