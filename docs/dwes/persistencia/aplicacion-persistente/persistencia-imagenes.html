2.4. Persistencia de imágenes en aplicaciones web

En MiColección ya podemos crear y editar videojuegos. Ahora queremos que cada videojuego pueda tener una portada, elegida desde el navegador, y que siga disponible cuando reiniciemos la aplicación.

Antes de programar, conviene entender que la imagen puede almacenarse en lugares distintos:

En la primera alternativa, MySQL contiene la imagen completa en una columna binaria de tipo BLOB. En la segunda, MySQL guarda solo una referencia y los bytes de la imagen se conservan fuera de la base de datos. En este apartado desarrollaremos la segunda opción, que nos permitirá aprender también a gestionar archivos desde Java.

Idea principal

La aplicación necesita dos datos relacionados: el archivo real, almacenado fuera de MySQL, y su nombre, guardado mediante JPA en la entidad Videojuego. Conservar uno sin el otro puede provocar que la portada deje de mostrarse.

1️⃣ ¿Dónde puede estar el archivo?​

🟩 No tiene por qué estar junto al proyecto​

Durante el desarrollo, Spring Boot se ejecuta en nuestro ordenador y puede guardar portadas en C:/datos/mi-coleccion/portadas. Cuando desplegamos la aplicación, la carpeta puede encontrarse en el servidor donde se ejecuta Spring Boot o en un almacenamiento al que ese servidor tenga acceso.

UbicaciónCómo accede Spring BootEjemplo
Carpeta del propio servidorCon Path y Files, como cualquier carpeta del sistema./var/lib/mi-coleccion/portadas.
Carpeta compartida de otro servidor o NASMediante una carpeta de red montada en el sistema y con permisos adecuados./mnt/portadas.
Bucket de almacenamiento en la nubeMediante la API o el SDK del proveedor; no es una carpeta normal de Java.Amazon S3 u otro servicio compatible.
Servidor de archivos con API HTTPMediante peticiones HTTP al servicio que guarda los archivos.Servicio de almacenamiento independiente.

En un bucket, MySQL suele almacenar una clave de objeto que permite localizar la imagen. Según la configuración, Spring Boot puede recuperar el archivo o proporcionar una URL temporal de acceso. No vamos a implementar esta solución: primero aprenderemos el mecanismo básico con una carpeta.

aviso

Files.write() sirve para una carpeta local o una carpeta de red montada. No sirve directamente para subir un archivo a un bucket S3: para eso necesitaríamos una integración distinta.

🟨 Configuramos una carpeta persistente​

En application.properties conservamos la configuración de MySQL y añadimos:

src/main/resources/application.properties
app.portadas.directorio=${IMAGENES_DIR:C:/datos/mi-coleccion/portadas}
spring.servlet.multipart.max-file-size=1MB
spring.servlet.multipart.max-request-size=2MB

app.portadas.directorio es una propiedad creada para nuestra aplicación. La variable IMAGENES_DIR permite cambiar la ubicación sin modificar Java: por ejemplo, en un servidor Linux podría valer /var/lib/mi-coleccion/portadas. La cuenta que ejecuta Spring Boot debe poder escribir en esa ubicación.

Las portadas no se guardarán en src/main/resources/static/, porque esa carpeta contiene recursos distribuidos con el proyecto, no archivos recibidos mientras funciona la aplicación.

2️⃣ Guardamos la referencia mediante JPA y enviamos el archivo​

🟩 Ampliamos Videojuego​

Añadimos esta propiedad y sus métodos de acceso a la entidad existente. No sustituimos los atributos del videojuego ni creamos otra tabla:

Cambios en modelo/Videojuego.java
@Column(name = "imagen_nombre", length = 50)
private String imagenNombre;

public String getImagenNombre() {
    return imagenNombre;
}

public void setImagenNombre(String imagenNombre) {
    this.imagenNombre = imagenNombre;
}

El nombre puede ser 79dff143-49b6-43db-8237-5a610f0fca1d.jpg. Es una cadena de texto, no una imagen. Si el videojuego aún no tiene portada, la columna podrá contener NULL. En nuestra base de prácticas, ddl-auto=update puede añadir la nueva columna; después comprobaremos su existencia en MySQL.

🟨 Añadimos un formulario de subida​

En videojuegos/formulario.html, después del formulario CRUD y fuera de él, añadimos esta sección. modoEdicion e idEdicion ya están disponibles en la vista de edición:

Fragmento para videojuegos/formulario.html
<section th:if="${modoEdicion}">
    <h2>Portada del videojuego</h2>

    <div th:if="${videojuego.imagenNombre != null}">
        <img th:src="@{/videojuegos/{id}/portada(id=${idEdicion})}"
             alt="Portada del videojuego" style="max-width: 180px;">
    </div>
    <p th:if="${videojuego.imagenNombre == null}">Todavía no tiene portada.</p>

    <form th:action="@{/videojuegos/{id}/portada(id=${idEdicion})}"
          method="post" enctype="multipart/form-data">
        <label for="portada">Elegir una imagen JPG o PNG:</label>
        <input id="portada" type="file" name="portada"
               accept="image/jpeg,image/png" required>
        <button type="submit">Guardar portada</button>
    </form>
    <p th:if="${mensaje}" th:text="${mensaje}"></p>
    <p th:if="${error}" th:text="${error}"></p>
</section>

type="file" permite seleccionar el archivo; enctype="multipart/form-data" hace que el navegador envíe su contenido. Spring MVC lo recibirá como un MultipartFile. El atributo accept ayuda al usuario, pero no evita que alguien envíe un archivo incorrecto: el servidor debe validarlo.

3️⃣ Creamos un servicio para guardar y recuperar portadas​

El controlador no debe escribir archivos ni consultar el repositorio directamente. Crearemos PortadaService, que localizará el videojuego, guardará el archivo en la carpeta configurada y actualizará solo su referencia en MySQL.

Para que el ejemplo sea manejable, implementaremos la primera subida de una portada. La sustitución y la eliminación física de archivos se comentarán después.

src/main/java/com/dwes/mi_coleccion/servicios/PortadaService.java
package com.dwes.mi_coleccion.servicios;

import com.dwes.mi_coleccion.modelo.Videojuego;
import com.dwes.mi_coleccion.repositorios.VideojuegoRepository;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import javax.imageio.ImageIO;
import java.io.ByteArrayInputStream;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;
import java.util.NoSuchElementException;
import java.util.Optional;
import java.util.UUID;

@Service
public class PortadaService {

    private final VideojuegoRepository repositorio;
    private final Path carpeta;

    public PortadaService(VideojuegoRepository repositorio,
            @Value("${app.portadas.directorio}") String directorio) {
        this.repositorio = repositorio;
        this.carpeta = Path.of(directorio).toAbsolutePath().normalize();
    }

    public void guardar(Long id, MultipartFile archivo) throws IOException {
        Videojuego juego = repositorio.findById(id)
                .orElseThrow(() -> new NoSuchElementException("Videojuego inexistente."));

        if (juego.getImagenNombre() != null) {
            throw new IllegalStateException("Este videojuego ya tiene portada.");
        }
        if (archivo.isEmpty() || archivo.getSize() > 1024 * 1024) {
            throw new IllegalArgumentException("La imagen debe ocupar 1 MB como máximo.");
        }

        byte[] datos = archivo.getBytes();
        String extension = comprobarFormato(datos);
        String nombre = UUID.randomUUID() + "." + extension;

        Files.createDirectories(carpeta);
        Path destino = carpeta.resolve(nombre);
        Files.write(destino, datos, StandardOpenOption.CREATE_NEW,
                StandardOpenOption.WRITE);

        try {
            juego.setImagenNombre(nombre);
            repositorio.saveAndFlush(juego);
        } catch (RuntimeException e) {
            try {
                Files.deleteIfExists(destino);
            } catch (IOException falloLimpieza) {
                e.addSuppressed(falloLimpieza);
            }
            throw e;
        }
    }

    public Optional<PortadaRecuperada> obtener(Long id) throws IOException {
        Optional<Videojuego> resultado = repositorio.findById(id);
        if (resultado.isEmpty() || resultado.get().getImagenNombre() == null) {
            return Optional.empty();
        }

        String nombre = resultado.get().getImagenNombre();
        if (!nombre.matches("[a-f0-9-]{36}\\.(jpg|png)")) {
            return Optional.empty();
        }
        Path ruta = carpeta.resolve(nombre).normalize();
        if (!ruta.startsWith(carpeta) || !Files.isRegularFile(ruta)) {
            return Optional.empty();
        }

        String tipo = nombre.endsWith(".png") ? "image/png" : "image/jpeg";
        return Optional.of(new PortadaRecuperada(Files.readAllBytes(ruta), tipo));
    }

    private String comprobarFormato(byte[] datos) throws IOException {
        boolean jpg = datos.length >= 3
                && (datos[0] & 255) == 255 && (datos[1] & 255) == 216
                && (datos[2] & 255) == 255;
        boolean png = datos.length >= 8 && (datos[0] & 255) == 137
                && datos[1] == 80 && datos[2] == 78 && datos[3] == 71
                && datos[4] == 13 && datos[5] == 10
                && datos[6] == 26 && datos[7] == 10;

        if ((!jpg && !png) || ImageIO.read(new ByteArrayInputStream(datos)) == null) {
            throw new IllegalArgumentException("Solo se admiten imágenes JPG o PNG válidas.");
        }
        return jpg ? "jpg" : "png";
    }
}

El método obtener() devuelve un objeto que agrupa los bytes y el tipo de imagen. Creamos este record de Java 21:

src/main/java/com/dwes/mi_coleccion/servicios/PortadaRecuperada.java
package com.dwes.mi_coleccion.servicios;

public record PortadaRecuperada(byte[] datos, String tipo) { }
en este ejemplo

@Service identifica la clase de servicio. @Value lee la carpeta configurada; Files.write() guarda el archivo, y UUID.randomUUID() genera un nombre prácticamente único. Después, saveAndFlush() solicita guardar la referencia del archivo en MySQL.

Antes de escribir, comprobamos el tamaño, la firma inicial del formato y que Java pueda interpretar la imagen. Es una validación básica para esta práctica; en una aplicación pública harían falta controles adicionales.

Si falla el guardado de MySQL, intentamos borrar el archivo recién creado. Esto no convierte las operaciones sobre disco y MySQL en una única transacción.

4️⃣ Creamos el controlador y entendemos ResponseEntity​

🟩 ¿Por qué no devolvemos una vista Thymeleaf?​

El VideojuegoController que ya tenemos seguirá gestionando el CRUD. Añadiremos PortadaController para atender dos peticiones: subir la portada y recuperarla.

Cuando un controlador devuelve "videojuegos/formulario", Spring MVC interpreta el texto como una vista. Pero cuando el navegador encuentra una etiqueta <img>, realiza otra petición para obtener los bytes de la imagen, no otra página HTML.

Para esa respuesta utilizaremos ResponseEntity<T>, que permite indicar:

Parte de la respuesta HTTPEjemplo
Estado200 OK si la imagen existe; 404 Not Found si falta.
CabeceraContent-Type: image/png para indicar el formato.
CuerpoLos bytes del archivo.

ResponseEntity<byte[]> significa que el cuerpo de la respuesta será un array de bytes. ok() crea una respuesta correcta, contentType() indica qué enviamos y body() incorpora el contenido. No añadimos @ResponseBody, porque ResponseEntity ya se encarga de construir la respuesta HTTP.

🟨 Implementamos PortadaController​

src/main/java/com/dwes/mi_coleccion/controladores/PortadaController.java
package com.dwes.mi_coleccion.controladores;

import com.dwes.mi_coleccion.servicios.PortadaRecuperada;
import com.dwes.mi_coleccion.servicios.PortadaService;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.multipart.MultipartFile;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import java.io.IOException;
import java.util.NoSuchElementException;
import java.util.Optional;

@Controller
@RequestMapping("/videojuegos")
public class PortadaController {

    private final PortadaService servicio;

    public PortadaController(PortadaService servicio) {
        this.servicio = servicio;
    }

    @PostMapping("/{id}/portada")
    public String subir(@PathVariable Long id,
                        @RequestParam("portada") MultipartFile archivo,
                        RedirectAttributes redirect) {
        try {
            servicio.guardar(id, archivo);
            redirect.addFlashAttribute("mensaje", "Portada guardada.");
        } catch (IllegalArgumentException | IllegalStateException
                 | NoSuchElementException e) {
            redirect.addFlashAttribute("error", e.getMessage());
        } catch (IOException e) {
            redirect.addFlashAttribute("error", "No se pudo guardar la portada.");
        }
        return "redirect:/videojuegos/" + id + "/editar";
    }

    @GetMapping("/{id}/portada")
    public ResponseEntity<byte[]> mostrar(@PathVariable Long id) {
        try {
            Optional<PortadaRecuperada> imagen = servicio.obtener(id);
            if (imagen.isEmpty()) {
                return ResponseEntity.notFound().build();
            }
            return ResponseEntity.ok()
                    .contentType(MediaType.parseMediaType(imagen.get().tipo()))
                    .body(imagen.get().datos());
        } catch (IOException e) {
            return ResponseEntity.internalServerError().build();
        }
    }
}
en este ejemplo

El método subir() recibe el MultipartFile, llama al servicio y redirige a la edición, donde podrá verse el resultado. El método mostrar() responde a GET /videojuegos/{id}/portada con la imagen. Si el archivo o la referencia no existen, devuelve 404.

El controlador no necesita saber en qué carpeta está la portada: eso corresponde al servicio.

5️⃣ Comprobamos la persistencia y sus límites​

Después de subir una portada, abrimos la carpeta configurada y comprobamos que contiene el archivo. En MySQL ejecutamos:

Comprobar la referencia almacenada
SELECT id, titulo, imagen_nombre
FROM videojuegos;

En la base de datos veremos el nombre del archivo, no sus bytes. Si reiniciamos Spring Boot, la portada debe seguir apareciendo. Podemos abrir directamente la URL /videojuegos/1/portada, sustituyendo 1 por el identificador real, para comprobar la respuesta del controlador.

aviso

Este ejemplo no sustituye portadas ni borra automáticamente el archivo al eliminar un videojuego. Para hacerlo tendríamos que coordinar la actualización de MySQL con la eliminación del archivo anterior. @Transactional no deshace por sí sola lo que haya hecho Files.write() o Files.delete().

Las imágenes se conservarán siempre que existan la base de datos y la carpeta o almacenamiento externo. Si movemos Spring Boot a otro servidor, tendremos que trasladar los archivos o mantener accesible el almacenamiento anterior. También necesitaremos copias de seguridad y permisos adecuados.

🟩 Otra posibilidad: guardar los bytes en MySQL​

Como vimos en la ilustración inicial, MySQL dispone del tipo BLOB para guardar contenido binario. Esa alternativa evita mantener una carpeta aparte, pero aumenta el tamaño de la base de datos. No la implementaremos aquí ni necesitamos aprender nuevas anotaciones para hacerlo en esta unidad. Puede consultarse en la documentación oficial de MySQL sobre BLOB.
