1.2. Instalación de MySQL y conexión desde Spring Boot

En el apartado anterior hemos visto por qué necesitamos conservar los datos de nuestras aplicaciones. Ahora prepararemos el entorno para trabajar con MySQL, que instalaremos directamente en Windows como un servicio del sistema operativo.

Nuestra aplicación Spring Boot seguirá ejecutándose desde IntelliJ IDEA. Ambos programas estarán en el mismo ordenador y se comunicarán mediante el puerto 3306. No necesitamos un servidor remoto ni herramientas adicionales para empezar.

Idea principal

Al terminar este apartado tendremos MySQL instalado y en funcionamiento, una base de datos llamada mi_coleccion, un usuario específico para la aplicación y un proyecto Spring Boot preparado para conectarse.

Primero configuraremos MySQL. No necesitamos tener creado todavía ningún proyecto Java.

1️⃣ Cómo funcionará nuestro entorno​

MySQL es un servidor de bases de datos, aunque lo instalemos en nuestro propio ordenador. Windows puede mantenerlo ejecutándose como un servicio: un programa que funciona independientemente de IntelliJ IDEA.

Cuando iniciemos nuestra aplicación, Spring Boot se conectará al servidor MySQL mediante la dirección localhost y el puerto 3306. Dentro de ese servidor estará nuestra base de datos mi_coleccion.

2️⃣ Instalamos MySQL Community Server​

🟩 Descargamos el instalador oficial​

Utilizaremos MySQL Community Server 8.4 LTS, en su edición gratuita. Desde la página oficial de descargas de MySQL 8.4 para Windows, elegimos el paquete Windows (x86, 64-bit), MSI Installer. No necesitamos descargar el archivo ZIP ni instalar MySQL Workbench.

Ejecutamos el instalador MSI. Al terminar, se ofrecerá abrir MySQL Configurator, que nos permitirá configurar el servidor. Es importante utilizar el configurador: instalar los archivos no basta para que MySQL quede preparado para funcionar.

consejo

En MySQL 8.4 el procedimiento habitual utiliza el instalador MSI y MySQL Configurator. Algunos tutoriales antiguos hablan de MySQL Installer, que correspondía a versiones anteriores y puede mostrar pantallas diferentes.

🟨 Configuramos el servidor​

Seguimos el asistente de MySQL Configurator y comprobamos estas opciones:

  • Puerto TCP/IP: 3306, salvo que esté ocupado por otra instalación.
  • Cuenta root: establecemos una contraseña de administración y la conservamos de forma segura.
  • Servicio de Windows: habilitamos su creación y dejamos activado el inicio automático, si el equipo lo permite.
  • Nombre del servicio: habitualmente MySQL84, aunque debemos comprobar el nombre real que muestra el asistente.

Aplicamos la configuración y comprobamos que el asistente inicia correctamente el servicio. No necesitamos modificar parámetros avanzados ni crear todavía más usuarios desde el instalador.

aviso

La instalación necesita permisos suficientes en Windows. Si el equipo está administrado por el centro educativo y no podemos instalar programas o crear servicios, tendremos que solicitar ayuda al personal responsable.

Si ya tenemos otro MySQL escuchando en el puerto 3306, debemos detenerlo o escoger un puerto diferente. Dos servidores no pueden utilizar simultáneamente el mismo puerto y dirección.

3️⃣ Comprobamos el servicio y entramos en MySQL​

🟩 Verificamos que MySQL funciona​

Abrimos PowerShell y comprobamos el servicio:

Get-Service -Name MySQL84

Si el nombre utilizado en el instalador es otro, podemos localizar los servicios de MySQL con:

Get-Service *mysql*

El estado esperado es Running. Si necesitamos iniciarlo y tenemos permisos, podemos hacerlo desde Servicios de Windows (services.msc) o mediante PowerShell como administrador:

Start-Service -Name MySQL84

Ahora comprobamos que tenemos disponible el cliente de MySQL:

mysql --version

Si PowerShell indica que no reconoce mysql, el servidor puede estar instalado correctamente y simplemente faltar su carpeta bin en la variable PATH. Podemos ejecutar el cliente indicando su ruta habitual, sin modificar todavía el sistema:

& "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" --version

Para utilizar los comandos abreviados mysql y mysqldump en el resto de la unidad, añadiremos al PATH de usuario esta carpeta, si coincide con nuestra instalación:

C:\Program Files\MySQL\MySQL Server 8.4\bin

Se hace desde Editar las variables de entorno del sistema → Variables de entorno → Path (usuario) → Nuevo. Después cerramos y volvemos a abrir PowerShell. Alternativamente, podemos seguir utilizando la ruta completa del ejecutable.

🟨 Accedemos con el administrador​

Desde una nueva ventana de PowerShell ejecutamos:

mysql -u root -p

Introducimos la contraseña de root cuando se solicite. El cliente no la muestra al escribirla. En la consola de MySQL podemos comprobar el servidor:

SELECT VERSION(), @@port;

Cuando aparezca el indicador mysql>, ya estaremos utilizando el cliente SQL conectado al servidor. Los comandos SQL que se presentan a continuación se escriben aquí, no directamente en PowerShell.

4️⃣ Creamos la base de datos y el usuario de la aplicación​

🟩 Preparamos mi_coleccion​

Con la sesión de administrador abierta ejecutamos:

CREATE DATABASE mi_coleccion
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;

CREATE USER 'coleccion_app'@'localhost'
IDENTIFIED BY 'SUSTITUIR_POR_UNA_CONTRASENA_PROPIA';

GRANT ALL PRIVILEGES ON mi_coleccion.*
TO 'coleccion_app'@'localhost';
en este ejemplo

CREATE DATABASE prepara la base de datos donde guardaremos los videojuegos. Hemos elegido utf8mb4 para admitir caracteres Unicode.

CREATE USER crea coleccion_app, una cuenta distinta de root. Debemos sustituir la contraseña de ejemplo por una nuestra. GRANT le concede permisos únicamente sobre mi_coleccion, necesarios también para que Hibernate cree o adapte tablas durante estas prácticas. Es una cuenta de desarrollo, con más permisos de los que necesitaría una aplicación desplegada en producción; en un entorno real limitaríamos los permisos y gestionaríamos los cambios de esquema por separado.

No necesitamos ejecutar FLUSH PRIVILEGES después de estas instrucciones: los cambios realizados mediante CREATE USER y GRANT se aplican directamente.

aviso

Los comandos anteriores están pensados para una instalación nueva. Si mi_coleccion o coleccion_app ya existen, MySQL puede indicarlo. No borraremos ni recrearemos una base de datos existente sin comprobar antes qué información contiene.

Salimos del cliente con EXIT; y comprobamos que el usuario puede entrar en su base de datos:

mysql -u coleccion_app -p mi_coleccion

Después de introducir la contraseña del nuevo usuario ejecutamos:

SELECT DATABASE();
SHOW TABLES;

La primera consulta debe indicar mi_coleccion. Es normal que la segunda todavía no muestre ninguna tabla: aún no hemos creado entidades JPA. Para salir escribimos EXIT;.

5️⃣ Creamos y conectamos el proyecto Spring Boot​

🟩 Preparamos el proyecto con Spring Initializr​

Ahora sí creamos el proyecto desde Spring Initializr. Utilizaremos:

OpciónValor
ProjectMaven.
LanguageJava.
Spring BootVersión estable de la serie 4.1.x compatible con los ejemplos (preparados con 4.1.1).
Java21.
Group / Artifactcom.dwes / mi-coleccion.
DependenciesSpring Web, Thymeleaf, Spring Data JPA, MySQL Driver y Validation.

Generamos el proyecto, descomprimimos el ZIP y abrimos su carpeta desde IntelliJ IDEA, en su edición gratuita. MySQL ya está funcionando como servicio de Windows, por lo que no tenemos que guardar ningún archivo de configuración del servidor dentro del proyecto Java.

Dependencia web en Spring Boot 4

En Spring Initializr seleccionaremos la opción Spring Web. En las versiones actuales de Spring Boot 4, su dependencia específica para aplicaciones con controladores MVC es spring-boot-starter-webmvc. Por tanto, si encontramos ese nombre en pom.xml, es el esperado: permite seguir utilizando @Controller y las vistas Thymeleaf.

Las dependencias principales de persistencia aparecen en pom.xml:

pom.xml (fragmento de dependencies)
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
en este ejemplo

Spring Data JPA proporciona la infraestructura de entidades y repositorios. MySQL Driver incorpora el controlador JDBC necesario para comunicarse con el servidor. Maven seleccionará las versiones compatibles con Spring Boot.

🟨 Configuramos la conexión​

Creamos o modificamos este archivo en el proyecto:

src/main/resources/application.properties
spring.application.name=mi-coleccion

spring.datasource.url=jdbc:mysql://localhost:3306/mi_coleccion
spring.datasource.username=coleccion_app
spring.datasource.password=${DB_PASSWORD}

spring.jpa.hibernate.ddl-auto=update

La dirección localhost:3306 indica que el servidor MySQL se ejecuta en el mismo ordenador. La propiedad DB_PASSWORD es una variable de entorno que debe contener la contraseña de coleccion_app que acabamos de definir, no la de root.

En IntelliJ IDEA entramos en Run → Edit Configurations, seleccionamos la configuración de la aplicación y añadimos la variable en Environment variables. Si aparece un único campo de texto, la escribimos con la forma DB_PASSWORD=tu_contraseña; si aparece una tabla, utilizamos DB_PASSWORD como nombre y la contraseña como valor.

¿Y si MySQL estuviera en otro ordenador?

En ese caso sustituiríamos localhost por la dirección IP o el nombre DNS del servidor y utilizaríamos el puerto correspondiente. Además, habría que configurar el acceso remoto y los permisos. En esta unidad mantendremos MySQL y Spring Boot en el mismo equipo.

🟧 ¿Para qué sirve ddl-auto=update?​

Esta propiedad permite que Hibernate intente adaptar las tablas a las entidades JPA de nuestra aplicación. La utilizaremos para facilitar las prácticas.

aviso

update no sustituye a un sistema de migraciones y no garantiza que todos los cambios en un esquema existente se apliquen como esperamos. Tampoco utilizaremos create ni create-drop sobre bases de datos cuyos registros queramos conservar, porque podrían eliminar información.

6️⃣ Comprobamos el funcionamiento y resolvemos incidencias​

Con el servicio MySQL iniciado y la variable DB_PASSWORD configurada, ejecutamos Spring Boot desde IntelliJ IDEA. Si la aplicación arranca sin errores de conexión, tendremos preparado el entorno.

Todavía no tienen por qué existir tablas: aparecerán cuando definamos nuestras primeras entidades JPA.

Un aviso que puede aparecer

Spring Boot puede mostrar una advertencia sobre spring.jpa.open-in-view. No significa que haya fallado la conexión. Estudiaremos sus consecuencias cuando trabajemos con entidades relacionadas.

🟩 Problemas habituales​

Si ocurre esto...Qué comprobaremos
MySQL no acepta conexiones.Que su servicio de Windows esté en estado Running.
El puerto 3306 está ocupado.Que no exista otro MySQL u otro programa utilizándolo. Si cambiamos el puerto, también adaptaremos la URL JDBC.
PowerShell no reconoce mysql.La variable PATH o la ruta completa de mysql.exe.
Aparece Access denied.El usuario, la contraseña, los permisos y el nombre de la cuenta (coleccion_app frente a root).
Spring Boot no conecta.spring.datasource.url, DB_PASSWORD, el servicio de MySQL y las dependencias Maven.
Antes de continuar

Debemos poder comprobar el servicio MySQL, entrar con coleccion_app, consultar mi_coleccion y ejecutar Spring Boot con la conexión configurada.
