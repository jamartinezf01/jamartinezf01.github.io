Fases del proyecto

El Proyecto Intermodular se desarrollará a lo largo de todo el curso siguiendo un recorrido organizado en seis fases. Cada una responde a una pregunta distinta y nos ayuda a avanzar desde una idea inicial hasta una solución web terminada, probada, desplegada y defendida.

Las fases nos sirven para ordenar el trabajo, pero no deben entenderse como bloques completamente cerrados. Durante el desarrollo podremos revisar requisitos, modificar decisiones de diseño, replantear tareas o volver sobre aspectos anteriores si el proyecto lo necesita.

Idea clave

No avanzamos simplemente de una fase a otra para no volver atrás.

Analizamos, diseñamos, desarrollamos, comprobamos y mejoramos de forma continua hasta llegar al proyecto final.

1️⃣ El recorrido completo​

FasePregunta principalResultado
F1. Análisis y definición¿Qué problema queremos resolver y para quién?Proyecto definido
F2. Diseño y planificación¿Cómo vamos a construir la solución?Proyecto diseñado y planificado
F3. Desarrollo¿Podemos convertir el diseño en una aplicación funcional?MVP y evolución de la aplicación
F4. Pruebas y calidad¿Funciona como debería?Aplicación comprobada y corregida
F5. Despliegue¿Podemos ponerla en funcionamiento fuera del entorno de desarrollo?Aplicación desplegada
F6. Memoria y defensa¿Podemos documentar y justificar el trabajo realizado?Proyecto documentado y defendido

2️⃣ Cómo se distribuyen durante el curso​

EvaluaciónFases implicadasHito principal
1.ª evaluaciónF1. Análisis y definición + F2. Diseño y planificaciónProyecto definido, diseñado y planificado
2.ª evaluaciónF3. DesarrolloMVP funcional
3.ª evaluaciónContinuación de F3 + F4. Pruebas + F5. Despliegue + F6. Memoria y defensaProyecto final

La F3 aparece en dos evaluaciones porque el desarrollo no termina con el MVP. A partir de esa primera versión funcional continuaremos trabajando hasta completar la solución prevista.

3️⃣ Un proceso que se revisa continuamente​

Aunque utilicemos seis fases para organizar el proyecto, será normal volver sobre decisiones anteriores.

Una prueba puede obligarnos a modificar una funcionalidad. Un problema durante el desarrollo puede llevarnos a cambiar parte del diseño. Una decisión de despliegue puede exigir ajustar la arquitectura prevista.

Por eso, el recorrido real se parece más a:

definimos → diseñamos → desarrollamos → comprobamos → corregimos → mejoramos → desplegamos → documentamos → defendemos

que a una secuencia en la que cada fase queda cerrada para siempre.

Para quedarnos con una idea

Cada fase responde a una pregunta diferente, pero todas forman parte del mismo proyecto.

Lo importante no es completar seis documentos: es utilizar cada fase para tomar mejores decisiones y construir una solución cada vez más completa.

4️⃣ Qué encontrarás en cada fase​

En las páginas siguientes desarrollaremos cada fase con más detalle.

En cada una encontrarás:

  • qué queremos conseguir.
  • qué trabajo debemos realizar.
  • qué actividades forman parte de la fase.
  • qué debemos entregar.
  • qué presentación o demostración realizaremos.
  • qué parte podrá incorporarse después a la memoria final.
  • y qué debemos comprobar antes de dar la fase por terminada.
