Proyecto Intermodular 2.º DAW · Curso 2026-2027

Durante este curso se va a trabajar de una forma algo diferente a la habitual.

En este módulo no se seguirá un temario tradicional basado únicamente en explicaciones, ejercicios y exámenes. El objetivo será diseñar, planificar y desarrollar un proyecto web en equipo, utilizando conocimientos y competencias adquiridos a lo largo del ciclo.

Este proyecto acompañará al grupo durante buena parte del curso y permitirá trabajar de forma integrada contenidos relacionados con el desarrollo de aplicaciones web.

1️⃣ ¿Qué es el Proyecto Intermodular?​

🟩 Una idea general​

El Proyecto Intermodular es un módulo en el que cada equipo desarrollará su propia aplicación web a partir de una necesidad o problema detectado en su entorno.

Esto significa que el trabajo no consistirá solo en programar una aplicación, sino también en:

  • analizar una situación real.
  • identificar una necesidad.
  • plantear una propuesta.
  • organizar el trabajo.
  • tomar decisiones.
  • revisar el avance.
  • y presentar el resultado final.

El proyecto, por tanto, no se limita al producto final. También importa cómo se piensa, cómo se organiza y cómo se construye.

🟦 La idea clave del módulo​

PROBLEMA
   ↓
NECESIDAD
   ↓
PROPUESTA
   ↓
PLANIFICACIÓN
   ↓
DESARROLLO
   ↓
SEGUIMIENTO
   ↓
PROYECTO FINAL

La aplicación es importante, pero el proyecto es mucho más que programar.

2️⃣ ¿Qué se va a hacer en este módulo?​

🟩 Un proyecto que irá creciendo​

El proyecto se construirá progresivamente durante el curso. Para hacerlo posible, el trabajo pasará por cuatro grandes momentos:

🔎 Explorar​

Primero habrá que detectar una necesidad, conocer a quién afecta y comprender qué problema merece la pena resolver.

🧩 Diseñar y planificar​

Después se definirá qué se quiere construir, se tomarán decisiones y se organizarán tareas, responsabilidades y tiempos.

💻 Construir​

Con el proyecto ya definido comenzará el desarrollo de la aplicación, poniendo en práctica conocimientos adquiridos en los distintos módulos del ciclo.

🔄 Revisar y mejorar​

Durante todo el proceso habrá que comprobar cómo avanza el proyecto, solucionar dificultades, documentar las decisiones y preparar la presentación del resultado.

tip

No se hará todo esto de golpe.

El proyecto irá creciendo paso a paso durante el curso.

3️⃣ Cada equipo desarrollará su propia aplicación​

🟩 Organización general​

Cada equipo desarrollará un proyecto diferente.

Los grupos estarán formados por 2 o 3 personas, y cada uno tendrá que diseñar una propuesta propia a partir de una necesidad detectada.

Eso significa que no todos los equipos crearán la misma aplicación ni resolverán el mismo problema.

Los proyectos podrán surgir de ámbitos muy diferentes: deporte, educación, cultura, turismo, asociaciones, pequeños negocios, ocio, gestión de actividades, organización de recursos, servicios a la comunidad...

El ámbito no es lo importante. Lo importante será encontrar una necesidad con suficiente recorrido para convertirse en un proyecto web.

🌍 Relación con los Objetivos de Desarrollo Sostenible​

Además de responder a una necesidad concreta, el proyecto deberá estar relacionado de forma justificada con uno o varios Objetivos de Desarrollo Sostenible (ODS) de la Agenda 2030.

No se trata de elegir un ODS al final simplemente para cumplir el requisito. La relación deberá tener sentido con el problema que se pretende resolver y con el impacto que podría tener la solución propuesta.

👉 Consulta aquí los 17 Objetivos de Desarrollo Sostenible de Naciones Unidas

tip

Primero se identifica el problema y después se analiza qué ODS están realmente relacionados con él.

No todos los proyectos tienen que relacionarse con los mismos ODS.

🟧 Qué se busca realmente​

No hace falta encontrar una idea revolucionaria.

Lo que se busca es una idea realista, con suficiente recorrido para trabajar sobre ella durante el curso y con la que se pueda construir un buen proyecto web.

important

No se valorará que una idea “suene muy moderna” si después no hay un problema claro detrás.

Lo importante no es impresionar con el tema, sino plantear un proyecto viable y bien pensado.

4️⃣ No se empieza diciendo “quiero hacer una app de…”​

🟩 Un error muy habitual​

Cuando se propone un proyecto, es muy frecuente empezar diciendo:

  • “una app de recetas”.
  • “una tienda online”.
  • “una web de videojuegos”.
  • “una aplicación para apuntar tareas”.

Ese planteamiento parece lógico, pero en realidad todavía no explica qué problema se quiere resolver.

🟥 La idea equivocada​

Decir “quiero hacer una aplicación de...” no es lo mismo que identificar una necesidad.

Primero hay que responder a preguntas como:

  • ¿quién tiene el problema?
  • ¿qué ocurre exactamente?
  • ¿cómo se resuelve ahora?
  • ¿qué dificultades provoca?
  • ¿por qué merecería la pena mejorarlo?

5️⃣ Primero hay que entender el problema​

🟩 Un ejemplo sencillo​

Imaginemos esta situación:

Un pequeño gimnasio organiza las reservas de sus clases mediante mensajes de WhatsApp.

Cada vez que una persona quiere apuntarse, tiene que escribir para preguntar si quedan plazas. La persona responsable responde los mensajes uno a uno y después actualiza una hoja de cálculo manualmente.

¿Qué está ocurriendo?

Este sistema puede provocar pérdida de tiempo, errores, reservas duplicadas y falta de información clara sobre las plazas disponibles.

Ahí es donde empieza a aparecer una necesidad que merece la pena analizar.

🟦 Lo importante del ejemplo​

Ahora sí hay una situación concreta sobre la que trabajar.

Todavía no hace falta decidir cómo será la aplicación. Antes hay que comprender quién tiene el problema, qué ocurre exactamente, cómo se gestiona ahora y qué mejoraría si se encontrara una solución adecuada.

info

En las primeras sesiones no se buscará todavía “la aplicación definitiva”.

Se buscarán buenos problemas sobre los que construir un proyecto.

6️⃣ Cuatro preguntas para empezar bien​

🟩 Preguntas que ayudarán en las primeras sesiones​

Antes de pensar en una aplicación, conviene analizar la necesidad mediante algunas preguntas básicas.

🟦 Las preguntas explicadas​

🟩 1. ¿Quién tiene el problema?​

Hay que identificar a las personas, grupos, asociaciones, negocios o colectivos afectados.

🟩 2. ¿Qué problema tiene exactamente?​

Conviene describir el problema de forma concreta, sin empezar todavía a enumerar funcionalidades.

🟩 3. ¿Cómo se resuelve ahora?​

Puede que actualmente el proceso se realice en papel, mediante hojas de cálculo, mensajes, formularios aislados o combinando varias herramientas diferentes. Incluso puede ocurrir que no exista ningún procedimiento organizado.

🟩 4. ¿Qué mejoraría si lo solucionamos?​

Responder a esta pregunta ayuda a valorar si ese problema merece convertirse realmente en un proyecto.

7️⃣ ¿Cómo se va a trabajar?​

🟩 Una dinámica general​

Durante buena parte del módulo el trabajo será práctico.

Habrá momentos de explicación, orientación y revisión, pero progresivamente se irá dando más protagonismo al trabajo de los equipos.

🟦 Qué significa esto en la práctica​

A lo largo del proceso será necesario tomar decisiones en equipo, organizar tareas, revisar avances, resolver dudas y mejorar aquello que no funcione.

No se tratará solo de “repartir partes y ya está”. Será importante que todas las personas del equipo comprendan el proyecto y se impliquen en él.

🟧 Una idea importante sobre el trabajo en equipo​

Trabajar en grupo no significa simplemente repartir el frontend, el backend y la base de datos entre distintas personas.

Un proyecto compartido exige comunicación, coordinación, responsabilidad, seguimiento y participación real.

aviso

Un equipo funciona mejor cuando todas las personas saben qué se está haciendo y pueden explicar las decisiones tomadas.

8️⃣ ¿Y cómo se evaluará?​

🟩 Lo que ya se puede adelantar​

La evaluación del módulo no dependerá únicamente de cómo quede la aplicación final.

También se tendrá en cuenta el proceso de trabajo desarrollado a lo largo del curso.

🟨 Lo que todavía está pendiente de concretar​

El equipo docente tiene que terminar de definir aspectos como:

  • los requisitos mínimos que aportará cada módulo implicado.
  • las evidencias que se recogerán.
  • los instrumentos de evaluación.
  • y la organización concreta de la calificación.

Cuando estos aspectos estén definidos, se comunicarán con claridad al grupo.

nota

Aunque algunos aspectos de la evaluación todavía no estén cerrados, el módulo puede comenzar con normalidad.

Las primeras sesiones servirán precisamente para iniciar el trabajo del proyecto: observar, analizar y detectar necesidades.

9️⃣ Primera actividad del módulo​

🟩 Tu primer reto: observar​

Todavía no hay que pensar en una aplicación.

Durante unos minutos, observa situaciones que conozcas de cerca: el instituto, un trabajo, una asociación, un deporte, un comercio, una afición, tu entorno familiar o cualquier actividad cotidiana.

¿Qué estamos buscando?

Situaciones en las que algo resulte lento, repetitivo, manual, incómodo, confuso, difícil de organizar o propenso a errores.

Ahí puede esconderse una buena necesidad para un proyecto.

🟦 Detecta tres problemas​

Para cada uno responde:

  1. ¿Quién tiene el problema?
  2. ¿Qué ocurre exactamente?
  3. ¿Cómo se resuelve actualmente?
  4. ¿Qué dificultades provoca?

Después compartirás tus propuestas con tu equipo y seleccionaréis tres problemas candidatos.

🌍 Y una primera mirada a los ODS​

Para cada problema, piensa también si puede estar relacionado con alguno de los Objetivos de Desarrollo Sostenible.

De momento no hace falta decidirlo definitivamente. Bastará con identificar posibles relaciones que después habrá que justificar.

importante

Hoy no hay que elegir la aplicación.

Hoy hay que encontrar problemas que merezca la pena investigar.

Una conclusión sencilla

Un buen proyecto no empieza preguntando:

“¿Qué aplicación se puede programar?”

Empieza preguntando:

“¿Qué problema merece la pena resolver?”

Para quedarse con la idea

Si el problema está bien planteado, será mucho más fácil pensar una solución útil, organizar el proyecto, justificar las decisiones y construir una aplicación con sentido.

Primera meta del módulo​

Durante las primeras sesiones no se buscará todavía la aplicación definitiva.

La primera meta será aprender a observar la realidad, detectar necesidades, describir problemas y convertir esas observaciones en posibles ideas de proyecto.

Idea fundamental

Primero se entiende el problema. Después se diseña la solución.
