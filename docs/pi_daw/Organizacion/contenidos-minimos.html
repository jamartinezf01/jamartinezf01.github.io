Contenidos mínimos del proyecto

El Proyecto Intermodular debe integrar aprendizajes procedentes de los distintos módulos del ciclo. Como punto de partida, utilizaremos una propuesta inicial basada en la relación de contenidos recogida en la guía de trabajo del proyecto.

Documento provisional

Este documento es un borrador de trabajo.

Los contenidos que aparecen a continuación no son todavía definitivos. Cada docente deberá revisar, concretar y validar qué aprendizajes de su módulo considera imprescindibles dentro del proyecto.

La versión definitiva se publicará cuando estos contenidos hayan sido acordados por el equipo docente.

1️⃣ Propuesta inicial de contenidos mínimos​

🟦 Bases de Datos​

El proyecto deberá trabajar los siguientes aspectos:

  • Diseño relacional del modelo de datos.
  • Creación de la base de datos y de las tablas.
  • Creación correcta de claves primarias y foráneas.
  • Consultas SQL.
  • Integración de la base de datos con la aplicación web.

🟩 Sistemas Informáticos​

El proyecto deberá incluir un análisis de la infraestructura necesaria y una justificación razonada de la arquitectura utilizada.

Deberán contemplarse los siguientes aspectos:

  • Arquitectura elegida: cliente-servidor, despliegue local, arquitectura en la nube, microservicios u otra solución adecuada al proyecto.
  • Requisitos hardware y software necesarios para el correcto funcionamiento del entorno.
  • Instalación y configuración del sistema o entorno de ejecución.
  • Configuración de red cuando sea necesaria para asegurar la comunicación entre los distintos servicios.
  • Aplicación de medidas básicas de seguridad, incluyendo la configuración de firewall y el control de puertos cuando proceda.

🟨 Entornos de Desarrollo​

El alumnado deberá seleccionar y justificar un entorno de desarrollo adecuado para el proyecto.

También deberá:

  • Configurar correctamente el entorno de trabajo.
  • Documentar el proceso de preparación del entorno cuando sea necesario.
  • Utilizar control de versiones mediante Git.

🟪 Programación​

El proyecto deberá reflejar una organización adecuada del código y aplicar criterios de programación coherentes.

Como referencia inicial se plantean los siguientes aspectos:

  • Estructuración en paquetes.
  • Incorporación de diagramas estandarizados cuando aporten información útil, como casos de uso o diagramas de secuencia.
  • Documentación interna del código.
  • Posible utilización de sistemas de documentación automática.
  • Aplicación de principios de programación estructurada.
  • Uso de criterios estandarizados para nombrar identificadores.

🟧 Desarrollo Web en Entorno Cliente (DWEC)​

Como mínimo, el frontend deberá incorporar:

  • Desarrollo de la parte cliente de la aplicación.
  • Programación en JavaScript.
  • Validaciones.
  • Manipulación del DOM relacionada con las funcionalidades de la aplicación.
  • Uso de frameworks de JavaScript.

🟦 Desarrollo Web en Entorno Servidor (DWES)​

  • Desarrollo del backend.
  • Implementación de la lógica de negocio.
  • Gestión de usuarios.
  • Desarrollo de servicios web.

🟩 Despliegue de Aplicaciones Web​

Como propuesta inicial, la aplicación deberá desplegarse utilizando tecnología de contenedores con Docker.

La guía plantea una infraestructura mínima mediante Docker Compose, con al menos dos servicios:

  • Un servidor web.
  • Un sistema gestor de bases de datos.

Además, el proyecto deberá incluir un repositorio público en GitHub que permita mantener las distintas versiones durante el ciclo de vida del desarrollo.

El repositorio deberá incorporar también los recursos necesarios para el despliegue, incluyendo el fichero docker-compose.yaml.

El README.md deberá recoger, al menos:

  1. Descripción del proyecto.
  2. Stack tecnológico.
  3. Arquitectura del sistema.
  4. Aspectos de seguridad.
  5. Proceso de despliegue.
  6. Dificultades encontradas.
  7. Posibles funcionalidades futuras.
Pendiente de revisión

Este apartado es especialmente concreto en la guía de partida y deberá revisarse con el profesorado de Despliegue para confirmar qué elementos se mantienen como mínimos definitivos.

🟨 Optativa — Python​

Python tendrá una función auxiliar dentro del Proyecto Intermodular.

El proyecto podrá incorporar:

  • Algún script desarrollado en Python relacionado con tareas auxiliares del proyecto.
  • Una breve explicación de su utilidad.
  • Integración del script dentro del repositorio.

Los scripts podrán utilizarse, entre otras posibilidades, para:

  • Generar o cargar datos de prueba.
  • Trabajar con ficheros CSV, JSON o XML.
  • Validar o comprobar datos.
  • Automatizar tareas relacionadas con la preparación del entorno.
  • Consumir APIs externas.
  • Generar informes o exportaciones.
  • Realizar comprobaciones o pruebas básicas.

Los scripts deberán incluir comentarios básicos y una breve documentación que explique su finalidad, forma de ejecución y utilidad dentro del proyecto.

🟪 Diseño de Interfaces Web​

El proyecto deberá aplicar criterios de diseño que permitan construir una interfaz usable y coherente.

Como referencia inicial se plantean los siguientes aspectos:

  • Interfaces sencillas y usables.
  • Información clara y suficiente para el usuario.
  • Separación entre estructura, estilos y funcionalidad.
  • Estilos uniformes y coherentes entre las distintas páginas.
  • Diseño responsivo.
  • Uso de frameworks o librerías de diseño web cuando resulte adecuado.

🟧 Lenguajes de Marcas y Sistemas de Gestión de Información​

El proyecto deberá aplicar una estructuración adecuada de la aplicación web.

Se plantean como contenidos iniciales:

  • Uso de HTML5 y etiquetas semánticas.
  • Aplicación de hojas de estilo CSS.
  • Definición coherente de colores, tipografías y distribución de elementos.
  • Uso de formatos estructurados para el intercambio de información entre las distintas partes de la aplicación cuando sea necesario.

🟩 Sostenibilidad aplicada al sistema productivo​

La aportación de este módulo al Proyecto Intermodular se centrará en la aplicación de los Objetivos de Desarrollo Sostenible (ODS) al proyecto desarrollado.

Cada grupo deberá identificar qué ODS guardan una relación real con su propuesta y explicar de qué manera el proyecto contribuye, directa o indirectamente, a alguno de sus objetivos o metas.

No se tratará de mencionar un ODS de forma genérica, sino de justificar su relación con el problema abordado, la solución propuesta o las decisiones tomadas durante el desarrollo.

Como contenido mínimo se plantea:

  • Identificación de uno o varios ODS relacionados con el proyecto.
  • Justificación de la relación entre el proyecto y los ODS seleccionados.
  • Incorporación de esta reflexión en la documentación del proyecto.
Idea clave

La relación con los ODS debe ser coherente y justificable. No es necesario forzar la vinculación con varios objetivos si solo uno de ellos encaja realmente con el proyecto.

:::

2️⃣ Qué significa que un contenido sea mínimo​

Un contenido mínimo no implica necesariamente utilizar una herramienta concreta ni desarrollar todos los proyectos de la misma manera.

Lo importante será que el proyecto permita evidenciar el aprendizaje correspondiente. La forma de hacerlo dependerá de la naturaleza de cada aplicación y de las decisiones técnicas adoptadas por el grupo.

En lugar de exigir...Podremos concretar...
Una tecnología concretaQué aprendizaje o competencia debe demostrarse
Una misma solución para todosQué resultado mínimo debe alcanzar el proyecto
Un número fijo de elementosQué funcionalidad o evidencia debe estar presente

3️⃣ Revisión y versión definitiva​

Antes de considerar cerrados estos contenidos, cada docente deberá revisar el apartado correspondiente a su módulo y decidir:

Aspecto a concretar
Qué es imprescindibleContenidos que deben estar presentes en todos los proyectos.
Qué es recomendableElementos que aportan valor, pero que dependerán de las características del proyecto.
Cómo se evidenciaQué producto, funcionalidad, documento o actuación permitirá comprobarlo.
En qué fase apareceMomento del proyecto en el que debería comenzar a integrarse o quedar completado.
Idea clave

Hasta que finalice esta revisión, el contenido anterior debe entenderse únicamente como una propuesta inicial de trabajo.

Los contenidos mínimos definitivos serán los que se publiquen tras la revisión y acuerdo del profesorado de los módulos implicados.
