Temporalización del proyecto

El Proyecto Intermodular se desarrolla durante todo el curso. El objetivo no es construir la aplicación de una sola vez, sino avanzar de forma progresiva: primero definiremos qué queremos hacer, después diseñaremos la solución y, a partir de ahí, comenzaremos su desarrollo hasta llegar a una versión final probada, desplegada y documentada.

Durante el curso trabajaremos en seis fases:

Idea clave

Las fases nos ayudan a organizar el trabajo, pero no son compartimentos independientes. En algunos momentos podremos seguir desarrollando funcionalidades mientras comenzamos las pruebas, revisar decisiones anteriores o actualizar la documentación a medida que evoluciona el proyecto.

1️⃣ Primera evaluación: definimos y diseñamos​

Durante la primera evaluación nos centraremos en comprender bien el proyecto antes de comenzar a desarrollarlo. Trabajaremos principalmente las dos primeras fases.

🟩 Fase 1. Análisis y definición​

Partiremos de una necesidad o problema y concretaremos qué queremos resolver, para quién y con qué alcance. En esta fase definiremos los objetivos del proyecto, identificaremos a sus usuarios, estableceremos los requisitos principales y analizaremos soluciones existentes que puedan servirnos como referencia.

También delimitaremos qué queremos incluir en el proyecto y qué quedará fuera de su alcance. Esta decisión será importante más adelante, porque nos permitirá comprobar si el desarrollo avanza de acuerdo con lo previsto.

🟨 Fase 2. Diseño y planificación​

Una vez definido el proyecto, decidiremos cómo vamos a construirlo. Diseñaremos las funcionalidades principales, la estructura de la aplicación, los wireframes, el modelo de datos y la arquitectura general de la solución.

También elegiremos las tecnologías y herramientas que utilizaremos y organizaremos el trabajo que tendremos que realizar durante las siguientes evaluaciones.

Al terminar esta evaluación deberíamos poder responder con claridad a dos preguntas:

¿Qué vamos a construir?

¿Cómo pensamos construirlo?

2️⃣ Segunda evaluación: construimos el MVP​

Durante la segunda evaluación comenzaremos el desarrollo de la aplicación. Entraremos de lleno en la Fase 3. Desarrollo y empezaremos a convertir el análisis y el diseño anteriores en una aplicación funcional.

El objetivo de esta evaluación no será terminar el proyecto completo, sino alcanzar un MVP, es decir, una primera versión funcional que permita demostrar las funcionalidades esenciales.

¿Qué entendemos por MVP?

Un MVP (Producto Mínimo Viable) no es una aplicación a medio hacer ni una colección de pantallas desconectadas.

Debe permitir completar un recorrido funcional básico y demostrar que la idea principal del proyecto funciona.

A lo largo de esta evaluación iremos construyendo la estructura del proyecto, la persistencia de datos, las funcionalidades principales y la interfaz necesaria para utilizarlas. El repositorio deberá reflejar la evolución real del trabajo realizado por el grupo.

Importante

Llegar al MVP no significa que el proyecto esté terminado. Durante la tercera evaluación continuaremos desarrollando funcionalidades, corrigiendo problemas y mejorando la aplicación.

3️⃣ Tercera evaluación: completamos y cerramos el proyecto​

La tercera evaluación parte del MVP desarrollado anteriormente. La Fase 3 continuará durante este periodo, porque todavía podremos incorporar funcionalidades previstas, mejorar las existentes o corregir decisiones tomadas durante el desarrollo.

A medida que la aplicación se acerque a su versión final, comenzaremos las fases de pruebas y calidad. Comprobaremos que el sistema responde a los requisitos definidos, registraremos los problemas detectados y realizaremos las correcciones necesarias.

Después prepararemos el despliegue para que la aplicación pueda ejecutarse fuera de nuestro entorno de desarrollo y, finalmente, organizaremos la documentación generada durante todo el curso para elaborar la memoria y preparar la defensa final.

La documentación final no se construirá completamente desde cero en esta fase. Parte de ella procederá del análisis, el diseño, el desarrollo, las pruebas y el despliegue que habremos ido realizando anteriormente.

4️⃣ El recorrido completo​

La distribución general del proyecto a lo largo del curso será la siguiente:

Para quedarnos con una idea

Durante el curso seguiremos este recorrido:

definimos → diseñamos → desarrollamos → obtenemos un MVP → continuamos desarrollando → probamos → desplegamos → documentamos → defendemos

5️⃣ Las fases pueden solaparse​

Aunque utilizamos una secuencia de fases para organizar el proyecto, en un desarrollo real es normal volver sobre decisiones anteriores.

Durante el desarrollo podemos descubrir que un requisito necesita modificarse. Al implementar una pantalla podemos comprobar que el diseño inicial debe ajustarse. Las pruebas pueden obligarnos a volver al código y el despliegue puede revelar configuraciones que todavía necesiten corrección.

Por tanto, avanzar de fase no significa que todo lo anterior quede cerrado definitivamente. El proyecto evolucionará durante todo el curso y la documentación deberá reflejar también esa evolución.

6️⃣ Presentamos nuestro progreso​

A lo largo del proyecto realizaremos pequeñas presentaciones en clase asociadas a las distintas fases. No todas tendrán el mismo formato ni la misma duración.

En las primeras fases nos servirán para explicar y justificar nuestras decisiones. Durante el desarrollo utilizaremos las presentaciones para mostrar el progreso del proyecto y, cuando lleguemos al MVP, realizaremos una demostración funcional. Finalmente, la última presentación corresponderá a la defensa del proyecto terminado.

Estas presentaciones también nos permitirán comprobar que todos los integrantes del grupo conocen y comprenden el trabajo realizado.

Idea clave

El proyecto se realizará preferentemente en grupos de 2 o 3 personas, pero todos los integrantes deben conocer el conjunto del proyecto y ser capaces de explicar las decisiones y el trabajo realizado.

7️⃣ Fechas e hitos​

Las fechas concretas de las actividades, presentaciones y entregas se indicarán durante el curso. Cada fase tendrá sus propias actividades, entregables y plazos.

De esta forma podremos conocer en todo momento en qué punto del proyecto estamos, qué debemos tener terminado y cuál es el siguiente paso.
