1. Antes de diseñar

Antes de elegir una paleta de colores, buscar una tipografía o empezar a crear botones, conviene responder a tres preguntas: qué problema resuelve la aplicación, quién va a utilizarla y qué imagen se quiere transmitir.

Una web puede estar bien programada y, aun así, resultar difícil de entender o transmitir una sensación poco adecuada. También puede ser visualmente atractiva, pero obligar a realizar demasiados pasos para completar una tarea. Por eso, las primeras decisiones de diseño deben tener en cuenta tanto la apariencia como el uso de la aplicación.

En este apartado se explica cómo definir una dirección visual para un proyecto web y cómo observar otras interfaces para aprender de sus decisiones, sin copiarlas.

1️⃣ Identidad visual y experiencia de usuario​

Aunque están relacionadas, la identidad visual, la interfaz de usuario (UI) y la experiencia de usuario (UX) no significan lo mismo.

Concepto¿A qué se refiere?Ejemplo en una web de reservas
Identidad visualConjunto de decisiones que dan una apariencia reconocible al proyecto: colores, tipografías, imágenes, iconos y estilo de los componentes.Utilizar una paleta azul y gris, una tipografía sobria y botones con esquinas ligeramente redondeadas.
Interfaz de usuario (UI)Elementos y pantallas mediante los que una persona consulta información e interactúa con la aplicación.Calendario, lista de actividades, formulario y botones para seleccionar y confirmar una reserva.
Experiencia de usuario (UX)Experiencia global al utilizar el producto: facilidad para completar tareas, claridad, esfuerzo requerido, respuestas del sistema y adecuación a las necesidades.Encontrar una actividad disponible, reservarla sin confusiones y recibir una confirmación comprensible.

Estos conceptos se influyen entre sí, pero no son intercambiables. La identidad visual contribuye a la percepción de una interfaz. La experiencia de usuario depende también de los contenidos, la navegación, el funcionamiento del sistema y la secuencia de pasos necesarios para completar una tarea.

Un ejemplo: reservar una actividad​

Se comparan dos versiones ficticias de una pantalla de reserva:

  • Versión A. Utiliza colores atractivos e ilustraciones cuidadas, pero presenta tres botones con el mismo protagonismo. No muestra el precio ni las plazas disponibles y tampoco incluye una confirmación visible.
  • Versión B. Mantiene una apariencia sencilla y coherente. Muestra desde el principio la fecha, el precio y las plazas disponibles. La acción principal es fácil de identificar y, al finalizar, aparece una confirmación clara.

La primera puede llamar la atención visualmente, pero la segunda facilita mejor la tarea planteada. Por tanto, una buena identidad visual no sustituye a una experiencia de usuario bien diseñada.

Idea importante

El objetivo no es elegir entre una web atractiva y una web fácil de usar. Ambas cualidades deben trabajarse juntas. Los colores, la tipografía y los componentes visuales tienen que ayudar a comprender la interfaz, no dificultarla.

2️⃣ Cómo influyen el proyecto y su público​

El diseño no debería comenzar seleccionando un color favorito. Una misma combinación puede encajar en un proyecto y resultar poco adecuada en otro. Para decidir el estilo, conviene analizar el contexto.

La finalidad de la aplicación​

No necesita el mismo tratamiento visual una aplicación administrativa que una web de entretenimiento. En una plataforma de gestión suele ser prioritario localizar datos y completar operaciones con precisión. En una web promocional puede tener más protagonismo la fotografía, el mensaje comercial y la presentación del contenido.

Esto no implica que una aplicación administrativa deba ser aburrida ni que una web juvenil tenga que utilizar colores intensos. La finalidad orienta las decisiones, pero no determina una única estética válida.

Las personas que van a utilizarla​

El diseño debe tener en cuenta las necesidades reales de las personas usuarias, no únicamente su edad o una supuesta preferencia estética.

Conviene preguntarse:

  • ¿Qué vienen a hacer? Consultar información, reservar, comprar, aprender o gestionar datos.
  • ¿Con qué frecuencia? Una aplicación diaria puede requerir una navegación distinta a la de un trámite ocasional.
  • ¿En qué dispositivo y situación? Una persona puede usar el móvil mientras se desplaza o un ordenador durante su jornada de trabajo.
  • ¿Qué dificultades pueden encontrar? Problemas de visión, poca familiaridad con el servicio, información compleja o tareas largas.

Tres proyectos diferentes​

Tres proyectos ficticios muestran decisiones distintas según la finalidad: facilitar trámites, fomentar el aprendizaje diario o presentar un servicio de pagos para empresas.
Web realNecesidad principalDecisiones de diseño que se pueden observar
GOV.UKAcceder a información y realizar trámites.Estructura clara, lenguaje directo, jerarquía de títulos y acciones fáciles de localizar.
DuolingoAprender mediante actividades frecuentes.Personalidad reconocible, ilustraciones, colores vivos y recursos que hacen más amable la experiencia.

Las diferencias no se deben solo al sector. También responden a qué tarea debe resolver cada persona y cómo se quiere presentar el servicio.

Para tener en cuenta

No debe deducirse que una web funciona bien solo porque su diseño parezca profesional. Las capturas permiten analizar decisiones visibles, pero no demuestran por sí mismas su facilidad de uso. Para valorar la experiencia real también hay que probar la navegación y las tareas.

3️⃣ La personalidad visual de una web​

La personalidad visual es la impresión general que produce la combinación de colores, tipografías, imágenes, espacios y componentes. Es útil describirla mediante dos o tres adjetivos antes de empezar a diseñar.

Por ejemplo, un equipo podría decidir que su aplicación debe resultar clara, cercana y actual. Esas palabras servirán después para comparar paletas, fuentes y estilos de botones y comprobar si responden a una misma intención.

Estilos que pueden servir de referencia​

El contenido de la tarjeta se mantiene: «Yoga al aire libre», sábado a las 10:00 y 8 €. Lo que cambia es su tratamiento visual.

No son categorías cerradas. Una misma web puede combinar, por ejemplo, un estilo minimalista con una personalidad tecnológica. Lo importante es que las decisiones no se contradigan sin una razón clara.

Referencias reales​

Para observar cómo se construyen distintas personalidades visuales, pueden compararse estos sitios:

  • Linear: ejemplo de estética tecnológica y contenida, con gran importancia de la tipografía, el contraste y la presentación del producto.
  • Headspace: ejemplo de lenguaje visual cercano, con recursos gráficos expresivos y una identidad fácilmente reconocible.
  • Aesop: ejemplo de presentación editorial, con protagonismo de la fotografía, los espacios y una composición cuidada.

Se trata de ejemplos de recursos visuales, no de modelos que haya que reproducir literalmente. El contenido, las capturas y las campañas de estas webs pueden cambiar con el tiempo.

La comparativa muestra seis propuestas ficticias para una misma actividad. Cada estilo combina recursos visuales propios con aspectos que conviene vigilar al diseñar.

Traducir los adjetivos en decisiones​

Elegir tres palabras no basta. Debe poder explicarse cómo se van a reflejar en la interfaz.

Estas relaciones son orientativas, no leyes universales. Un botón redondeado no convierte automáticamente una web en cercana, del mismo modo que un fondo oscuro no la convierte en tecnológica.

4️⃣ Cómo buscar referencias y analizarlas sin copiarlas​

Antes de crear las primeras pantallas conviene revisar webs que resuelvan problemas parecidos o que utilicen recursos visuales interesantes. El objetivo de buscar referencias no es encontrar una plantilla para reproducir, sino identificar decisiones que puedan justificarse y adaptarse al proyecto.

Dónde buscar​

  • Webs de servicios reales. Permiten estudiar componentes, contenido, navegación y decisiones visuales en su contexto.
  • Awwwards. Ofrece ejemplos de diseño web con planteamientos visuales variados. Conviene valorarlos críticamente, ya que una interfaz espectacular no siempre resulta adecuada para una aplicación funcional.
  • Mobbin. Reúne referencias de pantallas y flujos de productos digitales.
  • Behance. Permite explorar propuestas de identidad visual e interfaces. Algunos trabajos son conceptos y no aplicaciones publicadas.

Qué observar en una referencia​

Una captura no debería analizarse únicamente diciendo que «queda bonita». Conviene revisar cinco aspectos:

  1. Color. Qué tonos dominan, dónde aparecen los acentos y si los textos se distinguen bien.
  2. Tipografía. Cómo se diferencian títulos, párrafos, enlaces y pequeñas etiquetas.
  3. Jerarquía. Qué elemento llama primero la atención y cuál parece ser la acción principal.
  4. Composición. Cómo se agrupa la información, qué espacios se dejan y qué elementos se repiten.
  5. Componentes. Qué aspecto tienen botones, tarjetas, formularios y navegación y si mantienen un mismo criterio.

Ejemplo guiado: analizar una pantalla de Stripe​

En una captura de la página de inicio de Stripe se pueden identificar distintas decisiones:

  • Titular protagonista. El texto de mayor tamaño comunica la propuesta principal antes que los detalles secundarios.
  • Botón de acción destacado. La llamada a la acción se diferencia visualmente de los enlaces de navegación.
  • Color utilizado con intención. Los acentos y los degradados aportan personalidad, mientras la información se mantiene agrupada.
  • Secciones diferenciadas. La composición ayuda a distinguir el mensaje principal de otros contenidos y recursos.

Estas observaciones son útiles porque pueden traducirse a decisiones propias. Por ejemplo, para una aplicación de reservas puede interesar una acción principal claramente identificable. Eso no significa que deba utilizar el mismo degradado, la misma composición ni la misma tipografía que Stripe.

Las anotaciones permiten describir recursos concretos —titular, acción principal, color y composición— que pueden adaptarse a otros proyectos sin reproducir la web original.

De la referencia a una decisión propia​

Para aprovechar una referencia, conviene distinguir qué recurso resulta útil y cómo se adaptará:

ObservaciónDecisión aplicable a otro proyecto
La acción principal destaca frente a las secundarias.Diseñar un botón principal fácilmente reconocible en cada pantalla.
Las tarjetas repiten sus tamaños, bordes y espacios.Definir reglas comunes para los componentes reutilizables.
Los títulos y textos tienen una jerarquía consistente.Crear una escala tipográfica antes de maquetar todas las páginas.
La navegación agrupa opciones relacionadas.Organizar las secciones según las tareas de las personas usuarias.

Inspirarse no es copiar. Pueden estudiarse criterios generales, pero no conviene reproducir exactamente la composición, los textos, las ilustraciones o la identidad de otra marca. Además de perder personalidad propia, podría implicar el uso indebido de materiales ajenos.
