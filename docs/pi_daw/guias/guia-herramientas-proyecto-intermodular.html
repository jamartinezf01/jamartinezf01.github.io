Guía de herramientas para el Proyecto Intermodular

A lo largo del Proyecto Intermodular necesitaremos organizar el trabajo del equipo, representar ideas, diseñar la solución, desarrollar de forma colaborativa y preparar las presentaciones asociadas a las distintas actividades.

Existen muchas herramientas que pueden ayudarnos en estas tareas. En esta guía recogemos algunas opciones que pueden resultar útiles durante el proyecto y explicamos en qué momento pueden tener más sentido.

Idea clave

Las herramientas que aparecen en esta guía son recomendaciones.

No es obligatorio utilizar ninguna de ellas salvo que en una actividad concreta se indique expresamente lo contrario. Cada grupo podrá utilizar otras herramientas equivalentes siempre que permitan realizar correctamente el trabajo solicitado y compartirlo con el resto del equipo.

1️⃣ Qué herramientas podemos necesitar​

No necesitamos utilizar todas las herramientas desde el principio. Las iremos incorporando cuando aparezca una necesidad concreta dentro del proyecto.

NecesidadHerramientas que podemos utilizar
Organizar tareas y responsabilidadesTrello, GitHub Projects u otras herramientas equivalentes.
Preparar presentacionesPresentaciones de Google, Canva, PowerPoint u otras alternativas.
Crear diagramas y esquemasdraw.io / diagrams.net u otras herramientas de diagramación.
Diseñar interfaces y prototiposFigma u otras herramientas de prototipado.
Compartir y versionar el códigoGitHub, GitHub Desktop y Git.
Registrar incidencias y tareas técnicasGitHub Issues, GitHub Projects u otras herramientas de seguimiento.

tip

La elección de una herramienta debe responder siempre a una necesidad del proyecto. No utilizaremos una aplicación simplemente porque exista o porque otro grupo la esté utilizando.

2️⃣ Trello: organizamos el trabajo del equipo​

Trello permite organizar tareas mediante tableros formados por listas y tarjetas.

Puede resultarnos útil desde las primeras actividades para saber:

  • Qué tareas están pendientes.
  • Qué se está realizando en ese momento.
  • Quién es responsable de cada tarea.
  • Qué tareas necesitan revisión.
  • Qué trabajo se ha terminado.

🟦 Un tablero sencillo para empezar​

No necesitamos crear una organización compleja. Podemos comenzar con cuatro estados:

Pendiente → En proceso → En revisión → Terminado

Cada tarjeta puede representar una tarea concreta del proyecto.

Por ejemplo:

  • Definir la necesidad que intenta resolver el proyecto.
  • Redactar los objetivos.
  • Identificar los usuarios.
  • Revisar los requisitos.
  • Preparar la presentación de la actividad.

Siempre que sea posible, una tarea debería indicar:

  • Qué hay que hacer.
  • Quién se responsabiliza inicialmente de ella.
  • En qué estado se encuentra.
  • Cuándo debe estar terminada si existe una fecha concreta.

🟩 Acceso​

  • Trello en castellano.
  • Trello para navegador, escritorio y móvil.
aviso

Si utilizamos un tablero de tareas, debe reflejar el trabajo real del equipo. No tiene sentido actualizarlo únicamente justo antes de una entrega.

3️⃣ Herramientas de presentación: explicamos nuestro trabajo​

Las actividades del proyecto incluyen presentaciones asociadas a las entregas. Por tanto, necesitaremos una herramienta que nos permita preparar y compartir esas presentaciones desde las primeras fases.

Podemos utilizar, entre otras opciones:

  • Presentaciones de Google.
  • Canva.
  • PowerPoint u otra herramienta equivalente.

🟦 Presentaciones de Google​

Presentaciones de Google funciona desde el navegador y permite que varias personas editen el mismo documento.

Puede resultar útil para:

  • Trabajar de forma simultánea.
  • Añadir comentarios.
  • Compartir la presentación mediante un enlace.
  • Mantener una única versión del archivo.
  • Consultar los cambios realizados.

🟩 Canva​

Canva permite crear presentaciones a partir de distintos diseños y trabajar también de forma colaborativa.

Podemos utilizarlo desde el navegador o instalar su aplicación:

  • Crear presentaciones con Canva.
  • Descargar Canva para Windows.

🟨 La herramienta no es lo más importante​

Independientemente de la aplicación elegida, tendremos que cuidar el contenido.

Como criterio general:

  • Cada diapositiva debe tener una finalidad clara.
  • Evitaremos los párrafos largos.
  • Los diagramas, prototipos y capturas deben ser legibles.
  • Todo el equipo debe conocer el contenido presentado.
  • La presentación debe corresponderse con el trabajo realmente realizado.

4️⃣ draw.io / diagrams.net: representamos información​

draw.io / diagrams.net es una herramienta para crear diagramas.

A lo largo del proyecto puede ayudarnos a representar, entre otras cosas:

  • Procesos.
  • Relaciones entre elementos.
  • Casos de uso.
  • Modelos de datos.
  • Diagramas de flujo.
  • Arquitectura de la aplicación.
  • Esquemas de despliegue.

No todos los proyectos necesitarán los mismos diagramas. Utilizaremos únicamente aquellos que ayuden a comprender, justificar o documentar una decisión.

🟦 Un ejemplo​

Podríamos representar inicialmente una aplicación mediante un esquema sencillo:

Usuario → Aplicación web → Servidor → Base de datos

Más adelante ese esquema podría evolucionar e incorporar componentes más concretos.

🟩 Acceso​

  • Abrir draw.io / diagrams.net en español.

La versión web es suficiente para la mayoría de los trabajos del proyecto.

5️⃣ Figma: diseñamos antes de desarrollar​

Figma puede resultarnos especialmente útil durante la Fase 2. Diseño y planificación, cuando necesitamos decidir cómo será la interacción del usuario con la aplicación antes de comenzar a desarrollarla.

Con una herramienta de este tipo podemos crear:

  • Wireframes.
  • Bocetos de pantallas.
  • Diseños de interfaz.
  • Componentes reutilizables.
  • Prototipos navegables.
  • Flujos de navegación.

🟦 Wireframe y prototipo no son lo mismo​

Un wireframe representa la estructura de una pantalla: qué elementos contiene y dónde se sitúan.

Un prototipo permite simular parte de la navegación o interacción entre varias pantallas antes de que exista la aplicación real.

Por ejemplo:

Inicio → listado → detalle → formulario

Este recorrido puede ayudarnos a comprobar si la navegación resulta comprensible antes de implementarla.

🟩 Acceso y descarga​

  • Figma en castellano.
  • Descargas oficiales de Figma.

Figma puede utilizarse desde el navegador, por lo que instalar la aplicación de escritorio es opcional.

Idea clave

El objetivo del prototipo no es conseguir una pantalla bonita. Debe ayudarnos a comprobar qué necesita hacer el usuario, qué información encontrará y cómo se desplazará por la aplicación.

6️⃣ GitHub y GitHub Desktop: trabajamos sobre un repositorio común​

Cuando pasemos del diseño al desarrollo necesitaremos compartir el código y registrar su evolución.

GitHub permite alojar repositorios Git y colaborar sobre ellos. GitHub Desktop proporciona una interfaz gráfica para realizar muchas operaciones habituales de Git.

🟦 Qué nos aporta un repositorio​

Un repositorio compartido nos permite:

  • Mantener el código del proyecto en un lugar común.
  • Registrar quién realizó cada cambio.
  • Consultar el historial.
  • Trabajar con ramas cuando sea necesario.
  • Incorporar cambios realizados por otros integrantes.
  • Recuperar versiones anteriores.
  • Revisar cambios antes de integrarlos.

🟩 Operaciones que debemos reconocer​

Al comenzar a trabajar con Git debemos distinguir, como mínimo:

  • Clone: obtener una copia local de un repositorio remoto.
  • Commit: registrar un conjunto de cambios en el historial local.
  • Pull: obtener e integrar cambios del repositorio remoto.
  • Push: enviar al repositorio remoto los commits realizados localmente.
  • Branch: crear una línea de trabajo separada.

🟩 Acceso e instalación​

  • Documentación de GitHub Desktop en castellano.
  • Instalación de GitHub Desktop.
  • Descarga oficial de GitHub Desktop.
  • GitHub.
aviso

Antes de comenzar a desarrollar en grupo conviene comprobar que todos los integrantes pueden acceder al repositorio y realizar correctamente las operaciones básicas de trabajo colaborativo.

7️⃣ GitHub Issues y Projects: registramos el trabajo técnico​

Durante el desarrollo aparecerán tareas relacionadas directamente con el código: funcionalidades pendientes, errores, mejoras o incidencias detectadas durante las pruebas.

GitHub dispone de herramientas que permiten relacionar ese trabajo con el propio repositorio.

🟦 Issues​

Una issue puede utilizarse para registrar:

  • Una funcionalidad pendiente.
  • Un error.
  • Una mejora.
  • Una tarea técnica.
  • Una incidencia encontrada durante las pruebas.

Una issue puede incluir una descripción, etiquetas, una persona responsable y referencias a otros cambios del repositorio.

  • Documentación de GitHub Issues en castellano.

🟩 Projects​

GitHub Projects permite organizar issues y otras tareas mediante distintas vistas.

  • Documentación de GitHub Projects en castellano.

🟨 ¿Trello o GitHub Projects?​

No es necesario utilizar ambos ni duplicar toda la información.

Por ejemplo, un equipo podría utilizar:

  • Trello para la organización general del proyecto.
  • GitHub Issues / Projects para las tareas directamente relacionadas con el desarrollo, los errores y las pruebas.

Otro equipo podría trabajar únicamente con una de estas herramientas o utilizar una alternativa equivalente.

Lo importante es que el sistema elegido permita conocer qué trabajo existe, quién lo está realizando y en qué estado se encuentra.

8️⃣ Antes de incorporar una herramienta​

Antes de empezar a utilizar una aplicación nueva conviene comprobar:

  • Sabemos qué necesidad queremos resolver con ella.
  • Todo el equipo puede acceder a la herramienta.
  • Sabemos compartir el trabajo generado.
  • La herramienta permite exportar o conservar la información que necesitamos.
  • No estamos duplicando innecesariamente el trabajo en varias aplicaciones.
  • Tenemos claro quién se encargará de mantener actualizada la información.

El objetivo es disponer de un conjunto de herramientas que facilite el trabajo del equipo y permita seguir la evolución real del proyecto, no utilizar el mayor número posible de aplicaciones.
