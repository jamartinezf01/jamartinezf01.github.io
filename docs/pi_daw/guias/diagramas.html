Diagramas y modelos para diseñar el proyecto

Durante la Fase 2 vamos a utilizar distintos diagramas y modelos para pensar, explicar y comprobar el diseño del proyecto antes de empezar a programarlo.

No todos representan lo mismo ni persiguen el mismo objetivo. Un diagrama de casos de uso nos ayuda a comprender quién utilizará el sistema y para qué. Un diagrama de arquitectura explica cómo se organiza técnicamente la solución. El modelo de datos representa la información que tendremos que almacenar. Los componentes funcionales nos permiten dividir la aplicación en bloques de trabajo. Los diagramas de secuencia muestran cómo colaboran esas partes en una operación concreta. Finalmente, el Gantt nos ayuda a ordenar temporalmente el trabajo necesario para llegar al MVP.

importante

No hacemos diagramas simplemente porque formen parte de la documentación.

Los utilizamos para tomar decisiones antes de programar, detectar problemas y explicar el diseño de nuestra solución.

En estas guías utilizaremos como ejemplo Materialia Joven, la aplicación ficticia de gestión de materiales compartidos que aparece en los ejemplos de las actividades del proyecto.

Del ejemplo básico al proyecto real

En cada guía comenzaremos con una representación sencilla que nos permita entender la idea principal.

Después veremos cómo esa misma representación evoluciona hasta un ejemplo completo de Materialia Joven, con un nivel de detalle similar al que puede aparecer en la Actividad 4.

El objetivo no es hacer diagramas cada vez más complejos, sino aprender a añadir detalle solo cuando ayuda a explicar mejor el proyecto.

Cómo utilizar estas guías

No es necesario trabajar todo el contenido de una vez.

Consultaremos cada guía cuando necesitemos elaborar la representación correspondiente durante el diseño del proyecto.

1️⃣ Antes de empezar​

🟩 Un diagrama debe ayudar a entender​

Un buen diagrama no es el que contiene más cajas, flechas o símbolos. Es el que consigue explicar una parte del sistema de forma más clara que un párrafo largo.

Antes de añadir cualquier elemento conviene preguntarse qué información aporta. Si una flecha, una relación o un bloque no ayuda a comprender una decisión, probablemente no sea necesario.

Un diagrama debe simplificar una idea, no hacerla más difícil de entender.

Por eso no todos los proyectos necesitarán exactamente el mismo nivel de detalle. Dos equipos pueden representar correctamente su solución de formas distintas si ambos consiguen explicar con claridad cómo funciona.

🟦 Qué herramienta utilizar​

La herramienta es secundaria. Podemos trabajar con diagrams.net, una herramienta UML, un editor de diseño o una aplicación que genere diagramas a partir de texto.

Lo importante es que el resultado sea claro, legible y editable, y que el equipo comprenda qué representa cada elemento.

aviso

Generar automáticamente un diagrama no sustituye al diseño.

Si el equipo no puede explicar por qué aparece una relación, una dependencia o un componente, el diagrama no está cumpliendo su función.

🟧 Mantener coherencia entre diagramas​

Todos los diagramas de un mismo proyecto deben describir la misma solución desde perspectivas diferentes.

Si en los requisitos aparece que un socio puede solicitar una reserva, esa funcionalidad debería reaparecer de alguna forma en los casos de uso, en las pantallas, en los datos, en los componentes, en los diagramas de secuencia y finalmente en la planificación.

Podemos imaginarlo así:

requisito → caso de uso → pantalla → componente → datos → proceso → MVP → tarea

Esta posibilidad de seguir una misma funcionalidad a través de las distintas decisiones del proyecto recibe el nombre de trazabilidad.

2️⃣ Guías disponibles​

Cada guía puede consultarse de forma independiente, según lo que necesite el equipo para diseñar su proyecto.

RepresentaciónPregunta que nos ayuda a responder
Diagrama de casos de uso¿Quién utiliza el sistema y qué puede hacer?
Diagrama de arquitectura¿Qué partes técnicas tendrá la solución y cómo se relacionan?
Modelo E/R y modelo relacional¿Qué información necesitamos guardar y cómo se relaciona?
